** TODO [#B] Skill vendoring improvements :project-convention:
:PROPERTIES:
:CUSTOM_ID: 98cf369c-83aa-4961-bf8b-2fa3aca8b2f3
:CREATED: [2026-07-31 Fri 13:17]

:LOGBOOK:
- Created [2026-07-31 Fri 13:17]

Vendored third-party skills (dirge, find-skills, skill-creator, herdr) currently sit hand-copied inside the published `skills/` tree with no recorded provenance. Two constraints shape the fix:

1. Vendored skills must stay manageable by `npx skills` (add/update). That rules out the herdr-style in-file vendor header: any local edit changes the file, so `skills-lock.json` `computedHash` never matches upstream and an update overwrites the header regardless. Provenance therefore has to live outside the skill bodies, in `skills-lock.json`.
2. Vendored skills must NOT be republished by `npx skills add cormacc/dotagents`, while all agent config stays maintainable within this single repo.

`herdr` is a permanent exception to (1): its `SKILL.md` sits at its repo root, so `npx skills add ogulcancelik/herdr` installs the entire Rust project (Cargo.toml, flake.nix, src/, docs/). It stays hand-vendored with its existing header until upstream packages it under a `skills/` subdirectory.

Verified findings behind this task:
- `skills-lock.json` (v1) records `source`, `sourceType`, `skillPath`, `computedHash` per skill. `computedHash` is a content hash of the installed skill, confirmed by an update that rewrote only the hashes. This is the correct drift signal and the intended design: it answers "has this skill changed?", which is the only question that matters for a vendored copy. Do NOT track upstream repo commits — a SHA churns on every unrelated commit to the source repo while saying nothing about whether the skill itself moved. The provisional README "Revision" column is therefore wrong and should be dropped rather than backfilled.
- `npx skills add cormacc/dotagents --list` reports 16 skills, including all 4 vendored ones: they are currently republished to consumers, who get stale copies rather than upstream.
- `npx skills add` installs into `<project>/.agents/skills/` or `~/.agents/skills/`. Since `agents.nix` symlinks `~/.agents/skills` at this repo's `skills/`, a global install writes straight into the published tree — the likely origin of the current state.
- Attribution gap: herdr ships a LICENSE upstream that did not come across with its SKILL.md.
