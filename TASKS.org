Evaluate writing pi tool-orchestration scripts in Clojure via SCI (https://github.com/babashka/sci) instead of JavaScript.

Findings so far (pi 0.99.2, 2026-10-01):
- The built-in `codemode` tool is JavaScript only: its schema has one `code` field ("Raw JavaScript source") and each script runs in a fresh QuickJS WebAssembly sandbox (`@earendil-works/pi-codemode`, heap-limited). No language option or extension prelude.
- `docs/extensions.md` says `codemode` uses only `prepareLoadout`, `exposure` and `ctx.executeTool()`, "so another tool can implement the same behavior under a different name". A `cljmode`-style extension tool could evaluate Clojure with SCI in Node and expose callable tools as functions over `ctx.executeTool()`.
- npm has no `@babashka/sci` or `@borkdude/sci`; SCI-based packages `nbb` (1.6.214, Node) and `scittle` (0.8.33, browser script tags) exist.

Open questions for a spike:
- Async tool calls from SCI (promesa in nbb?) and how cleanly scripts chain them.
- Isolation: a Node-hosted SCI tool runs in the pi process, not QuickJS; confirm what SCI exposes by default.
- Whether loading SCI inside the QuickJS sandbox is feasible at all (bundle size per fresh sandbox, heap limit, browser globals in scittle).
- Benefit versus cost: models write JS orchestration fluently; the gain is human readability of agent scripts, not tokens.
