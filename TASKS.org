#+IMPORT: [[plan:2026-08-16-herdr-plugin-wrapper-for-herdr-orch.org]]
Package herdr-orch as a Herdr plugin wrapper without replacing the existing skill as the orchestration core.

Initial scope:
- Package the herdr-orch skill, its scripts and traits, and the Pi interactive trait-expansion extension.
- Preserve the current local development flow. `~/.agents/skills/herdr-orch` and `~/.pi/agent/extensions` continue to resolve through the live dotagents checkout. `herdr plugin link` must use that working tree without replacing those links.
- Separate GitHub-install build work from harness setup. Herdr runs manifest build commands only during GitHub installation. `plugin link` does not run them. Build commands receive no plugin runtime context and must not install or replace global harness configuration.
- Define a safe activation and diagnostic surface because Herdr does not automatically register packaged skills or Pi extensions.

Likely later scope:
- Add a Herdr plugin pane that renders a hierarchical tree of orchestration sessions.
- Derive hierarchy primarily from the herdr-orch ledger and contract. Link `:parent-session` to `:child-session`, group continued rounds with `:continues`, and treat pane labels as display metadata or a diagnostic fallback only.
- Join ledger nodes to live Herdr pane and agent state for navigation and status.
- Add Claude Code and Codex `UserPromptSubmit` adapters for interactive trait context injection. Preserve project-trust boundaries when resolving project traits.

Known constraints and candidate direction:
- The current Pi adapter resolves the interpolator through `~/.agents/skills/herdr-orch/scripts/traits`; packaged resolution must retain that live path and add an explicit or package-relative fallback.
- herdr-orch currently requires Herdr 0.9.1 or later and Babashka. Its Bash launchers currently imply Linux and macOS support.
- A single source repository can expose separate native package interfaces for Herdr, Pi, and Agent Skills. The Herdr plugin should remain an adapter and distribution surface rather than becoming the canonical implementation.
- Herdr plugin v1 supports terminal panes, actions, event hooks, runtime context, and socket access. It does not provide arbitrary native non-terminal plugin UI. A session tree therefore belongs in a plugin terminal pane.

- The record packages only the traits extension. It does not mention the herdr-orch proxy extension `pi/extensions/herdr-orch` (since 2ee159a, extended with the `/oh` listing in bf3c620); decide whether the plugin packages it.
- `resolveTraitsBinary` in `pi/extensions/traits/index.ts` returns only the home path; the planned env-override and extension-relative fallbacks are still to do.
