** Search patterns and renames

This rule group was removed from =home/AGENTS.md=. The evidence is kept for a future rule.

- A search pattern from data can start with =-=, which a command can consume as an option. E.g. =grep -qxF "$line"= fails for a line that starts with =---= or =- =. It prints a usage error for each such line, while the loop treats the line as a mismatch. Pass the pattern with =grep -e "$pat"= or after =--=.
- This defect affects only some inputs. A successful spot-check does not prove that the command is correct, and the remaining misreads can appear to be valid findings.
- BSD =sed= on macOS does not support =\b=, and it can silently match nothing. A pattern that prefixes another token can also rewrite that token. One rename missed two call sites and changed an unrelated =%focusx= token.
- Babashka is preferable because its Java regular expressions support =\b= on every platform. First count matches with =(re-seq #"%focus\b" text)=, then rewrite with =str/replace=, then search again for the old name.
- A word boundary after a non-word character never matches. E.g. =\bname!\b= finds nothing because the boundary after =!= requires a following word character. For identifiers that end in =!=, =?=, or =-=, omit the final =\b=.
- Searching again for the old identifier before the tests run prevents a bulk rename that silently misses most call sites.

** Prompts, credentials, and shell quoting

Part of this rule group was removed from =home/AGENTS.md=. Only the narrow-token credential rule remains there.

- One =grep -A6= command printed a live HTTP secret from a registry configuration into the session transcript. The query did not need the surrounding lines.
- Markdown-derived text commonly contains backticks and =$=, and double quotes permit command substitution, so shell search patterns need single quotes.
- =printf "$text"= can silently corrupt =%= sequences and still exit 0. E.g. ="85% coverage"= prints =85overage=, =%focused= prints =0.000000ocused=, and =%no-bullshit= prints =o-bullshit=. Of these examples, only =%read-only= and =%prune= fail with an error. Percentages occur in prose more often than trait tokens, so this rule is not specific to traits.
- An apostrophe terminates a single-quoted argument, and Bash can then execute the remaining text. This error truncated one =ot create --body= argument, and Bash executed its remaining text. Writing the prose to a file with a quoted heredoc and passing ="$(cat file)"= avoids it, because shell command substitution does not scan its output again.
