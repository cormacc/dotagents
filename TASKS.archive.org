#+IMPORT: [[file:design/log/2026-05-12-tasks-read-section.org]]
Expose a primitive that returns a single top-level section of a change-record file (`* Summary`, `* Context`, `* Plan`, `* Implementation`, `* Validation`, `* Open questions`), including any nested subheadings up to the next level-1 boundary, so agents on resume / review can fetch just the surface the `org-tasks` protocol declares "eagerly loaded" without pulling the entire ledger into context.

Motivation:
- `org-tasks` § *Resuming and agent memory* says only `* Summary` (and `* Context` when promoted, plus `OPEN` items under `* Open questions`) should be eagerly loaded; `* Implementation` and completed plan-task bodies are explicitly "defer until needed".
- Today the `tasks` extension exposes no read tool, so agents either `read` the whole file (expensive when records carry a 150+ line Implementation ledger) or do a `rg` + ranged `read` two-step.
- The closure-refresh helpers in `summary.ts` already know how to locate `* Summary`; section extraction is the same shape generalised over a heading name.

Acceptance criteria:
- New tool (working name `tasks_read_section`) accepts `{ file, section }` where `section` is one of the canonical change-record sections plus arbitrary level-1 headings (so third-party sections round-trip).
- Returns the section heading plus body up to (but not including) the next level-1 heading, with nested `**`/`***` subheadings preserved verbatim.
- Returns a structured "not found" result (not an exception) when the section is absent, so callers can fall back gracefully.
- `section` defaults to `Summary` for the common case.
- Unit tests cover: section present, section absent, section is the last in the file, file with no headings, and a section whose body contains literal `* ` characters in source blocks (must not terminate the slice early).
- README documents the tool alongside `tasks_insert_task` and links the `org-tasks` resume checklist.
