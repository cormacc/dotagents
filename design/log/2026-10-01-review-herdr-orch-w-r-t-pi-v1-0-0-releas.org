* Intent
Re-baseline herdr-orch against Pi 1.0.0 and Herdr 0.9.3: record what the upstream deltas since Pi 0.85.1 and Herdr 0.9.1 mean for the =oh= CLI, the Pi tool proxy, and the managed Pi state integration, and ship only the small compatibility and efficiency changes the evidence justifies -- a refreshed vendored Herdr skill, spawn envelopes that report the model routing they performed, a current Pi dev pin, and a README review table that states the reviewed and minimum required Pi and Herdr versions.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* README

The review found no breaking upstream change touching herdr-orch. Pi 0.85.1 -> 1.0.0 removed or changed APIs (=shouldStopAfterTurn=, =turn_end= boundary shapes, =context= handler semantics, fail-closed =user_bash=, JSON-only =ToolCall.arguments=, =--no-extensions= disabling built-ins, fullscreen TUI default) that no local extension uses; the only pi flags =oh= passes to a child are =--model= and =--thinking=, both unchanged in 1.0.0. Herdr 0.9.1 -> 0.9.3 left every CLI verb =oh= invokes unchanged, left the managed =herdr-agent-state.ts= asset at integration revision 9, and shipped two favourable lifecycle fixes. Codemode is an upstream Pi feature (0.99.0; leaner in 1.0.0), not a third-party extension; no implementation change follows from it. Shipped: a vendored Herdr skill at v0.9.3, routing keys on the spawn entry, a Pi 1.0.0 dev pin, a README table of reviewed and minimum versions, and short model aliases.

** Decisions
- Codemode: no implementation change :: Codemode is upstream Pi (=packages/codemode= first commit =8562bcf6= "feat(coding-agent): codemode and MCP", shipped 0.99.0, leaner in 1.0.0). Delegation already runs through =oh= via =bash=; a parent that wants to batch =status=/=collect --any= calls can do so today with =tools.bash= in one script and needs nothing from herdr-orch. Rejected: a codemode-exposed =oh task= tool (same objection as the model-facing tool, below); rewriting the proxy to call =herdr= over its socket API (contract.md already rejects a socket-protocol gate; logic stays in Babashka).
- Delegation stays off the model tool surface :: Re-affirms [[file:2026-08-01-herdr-orch-absorb-pi-herdr-coverage-into.org][2026-08-01]]. Loading the skill is the gate that teaches envelope, ledger, and closure rules; a discoverable tool is the documented route to uncaptured children. Rejected: =herdr_task= tool with =exposure: "model-only"= or =deferred= -- both are still model-reachable.
- No =/oh= slash command :: User decision (2026-10-02). The measured delegation overhead is first-spawn skill/persona reads and assignment composition, not model routing, so a user-invoked command would remove turns only in the rare case where the user already knows persona, model, and task. The routing keys on the spawn envelope are the whole efficiency change. Rejected: a user-invoked =/oh= in the proxy extension; a prompt template in =pi/prompts/=.
- Minimum Pi version is 0.80.4 :: Derived from API use, not enforced at runtime. The Herdr-managed =herdr-agent-state.ts= (integration revision 9) subscribes to =agent_settled=, added in Pi 0.80.4 (=packages/coding-agent/CHANGELOG.md= § 0.80.4; absent from =v0.80.3:packages/coding-agent/src/core/extensions/types.ts=). Its other requirements are older: =ctx.mode= (0.78.1), =@earendil-works/*= scope (0.74.0), =typebox= 1.x (0.69.0). Root model and effort inheritance through =PI_MODEL=/=PI_REASONING_LEVEL= needs 0.82.0 (bash tool environment); on an older root, a root child takes the persona value, else the harness default model and =medium= effort.
- Spawn envelopes report routing :: The ledger entry records =:kind= and pre-alias =:model= but not the translated =:model-args=; =--print-prompt= is the only way to see them, and previews were the measured routing turns. Reporting the same three keys the preview computes (=:model-canonical=, =:model-args=, =:effort-args=) costs one =assoc= at the existing choke point and makes the preview unnecessary after the fact.
- Dev pin tracks the reviewed Pi :: Tests import =DEFAULT_MAX_BYTES=/=DEFAULT_MAX_LINES= at runtime from the pinned 0.80.10 package while the integration tests spawn the PATH =pi= (0.99.2) and =jira/tools.ts= uses 0.99.0 APIs (=exposure=, =ctx.executeTool=). Pin 1.0.0 so the two agree; the lock also moves the =pi-ai= and =pi-tui= peers (declared =*=) to 1.0.0, because the extensions import =StringEnum= from the top-level =pi-ai= at runtime. Rejected: leave it (silent drift already spans 20 minor versions).
- Proxy tool exposure unchanged :: =herdr_layout=/=herdr_pane=/=herdr_agent= keep their current exposure. =exposure: "codemode"= or =deferred= would remove three declarations and ten guideline lines from every system prompt, but the model would then reach the tools only through codemode scripts or =tool_search=.
- Herdr minimum stays 0.9.1 :: Settle waits accept =idle= or =done=, so the 0.9.2 first-task-done fix is not needed for correctness. Every verb =oh= calls is unchanged in 0.9.2/0.9.3 (=docs/next/.../cli-reference.mdx= diff is additive: =machine status|reconnect=, =pane report-agent*= with =-- RESUME_COMMAND=, =terminal.mouse=). The =completion_seq= field (commit =2836010=) is additive.

** Pi 0.85.1 -> 1.0.0 (393 commits; tags verified with =git merge-base --is-ancestor= in a blobless bare clone)
- Non-breaking :: No local extension uses =shouldStopAfterTurn= (removed 0.87.0), constructs or exhaustively switches on =TurnEndEvent=/=ExtensionEvent= (0.87.0), registers a =context= handler (system messages hidden 0.87.0), or handles =user_bash= (fail-closed 0.86.0). Sweep: =git ls-files 'pi/extensions/**/*.ts'= grep with =registerTool= as the positive control (12 files).
- Non-breaking :: =--no-extensions= also disables built-in extensions (0.99.0 § Changed). =oh= passes only =--model= and =--thinking= to a pi child (=subagents/config.edn= =:harnesses :pi=); both flags exist in =v1.0.0:packages/coding-agent/docs/cli.md=.
- Favourable :: 0.99.2 § Fixed: tool schemas with =minimum=/=maximum= are sent non-strict to Anthropic. =herdr_pane= and =herdr_agent= declare =Type.Integer({ minimum: 1 })= parameters.
- Non-breaking, caveat :: 1.0.0 § Changed: TUI defaults to fullscreen (=tuiMode=). Lifecycle is hook-authoritative (herdr-agent-state.ts) and results travel through =RESULT= files, so delegation is unaffected; raw reads of a pi child may return only visible rows (unverified live).
- Non-breaking :: 1.0.0 § Fixed: =--provider= without =--model= now errors. =oh= never passes =--provider=.
- Confirmed :: Codemode is upstream: =packages/codemode= (first commit =8562bcf6=, 2026-09-29), 0.99.0 § New Features, 1.0.0 § New Features "Leaner codemode", reference =packages/coding-agent/docs/codemode.md=. The 0.99.2 -> 1.0.0 diff of =packages/coding-agent/src/core/extensions/= is empty, so the installed 0.99.2 exercises the same extension layer as 1.0.0.
- Upstream-only :: 0.86.0 § Added: =pi.on()= returns an unsubscribe function. Relevant to the README § Known gaps item on undisposed listeners in Herdr's asset; no local action because the asset is never patched locally.

** Herdr 0.9.1 -> 0.9.3 (96 commits)
