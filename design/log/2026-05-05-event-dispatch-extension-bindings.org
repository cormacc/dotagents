* Summary
Fixed a UX bug where leader-menu UI toggles (e.g. =SPC t t= for the tasks overlay) clobbered any text the user had already typed into the editor. Root cause: leader-menu's =command:= action implementation writes the slash command into the active editor and submits via =SubmitterEditor=, which calls =setEditorText()= and overwrites in-progress input. Fix: extension UI bindings dispatch events directly instead of routing through =command:=. Slash commands stay available for typed use; their handlers dispatch the same events used by the leader bindings so there is a single entry point. Applied to =tasks= and =git-diff=.

** Decisions
- Event-dispatch for keybindings :: leader-menu bindings use bare event names, not =command:=, when the action is an extension UI toggle.
- Slash commands as compatibility shims :: =/tasks=, =/tasks new=, =/tasks doctor=, and =/diff *= still work; their handlers emit the same events.
- Keep =command:= for actual slash-command shortcuts :: leader-menu local built-ins like =/compact= still intentionally submit commands.

- =pi/extensions/git-diff/index.ts=: leader registrations dispatch =git-diff:*= events; =/diff= subcommands validate arguments and emit those events.
- Both READMEs document the event-dispatch convention.

* Context

Activating in-repo extension UIs through leader-menu currently uses =command:= actions such as =command:/tasks= and =command:/diff toggle=. leader-menu implements =command:= by writing the slash command into the active editor and submitting it through =SubmitterEditor=. That is correct for slash-command shortcuts, but undesirable for UI toggles when the user has already typed text: the intermediate =setEditorText()= clobbers the input area.

The fix is to make extension leader bindings dispatch events directly. Slash commands remain available for typed use, but command handlers dispatch the same event path as the keybinding so the implementation has a single entry point.

Affected in-repo extensions for this bug: =tasks= and =git-diff=.

** Design decisions

- Event-dispatch for keybindings :: Leader-menu bindings should use bare event names, not =command:=, when the desired action is an extension UI action.
- Slash commands as compatibility shims :: =/tasks= and =/diff= remain, but their handlers emit the same events used by leader-menu bindings.
- Keep =command:= for actual slash-command shortcuts :: leader-menu's local built-ins like =/compact= still intentionally submit commands.
