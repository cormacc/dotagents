#+TITLE: Introduce =task:= and =archive:= org-link abbreviations for parent links
#+DATE: 2026-05-14 Thu
#+PARENT: [[archive:40f66a21-bdbc-4f8b-80d2-1ec806070f1d][org-memory Create 'task' and 'archive' link types rather than current file/anchor]]
#+SETUPFILE: ../../TASKS.setup.org
#+STATUS: Complete

* Summary
Replace =#+PARENT: [[file:../../TASKS.{org,archive.org}::#<uuid>][...]]= with
=#+PARENT: [[task:<uuid>][...]]= and =#+PARENT: [[archive:<uuid>][...]]= via
project-local =#+LINK:= abbreviations declared in =TASKS.setup.org=. =TASKS.org=
and =TASKS.archive.org= each carry a local =#+LINK:= override (placed *before*
their =#+SETUPFILE:= directive so the first-declared abbreviation wins) that
strips the =../../= prefix, so a single =task:= / =archive:= pair resolves
correctly whether followed from a plan file (in =design/log/=) or from the task
files themselves. One-shot content sweep across =~/dotfiles/agents=, =~/dotfiles=,
and =~/nmd/products/connect/portal=; no legacy tolerance window.

** Decisions
- Two link types (=task:=, =archive:=) :: matches the task body's "acceptable
  compromise". A single overloaded type would require live-vs-archive lookup at
  every follow; two types make the archive-rewrite a tight prefix swap on the
  link key.
- Local override beats =#+SETUPFILE:= defaults via declaration order :: empirical
  test (=/tmp/orgtest=, 2026-05-14) confirms org's =org-link-abbrev-alist-local=
  takes the *first* =#+LINK:= per key. Local override placed before
  =#+SETUPFILE:= directive in =TASKS.org= / =TASKS.archive.org= wins; setup file's
  =../../= default carries through to plan files unmodified.
- Setup-file abbreviations target the default plan dir :: =file:../../TASKS.org::#%s=
  assumes =design/log/= (one-level subdir of project root). Projects with a
  non-default =#+DEFAULT_PLAN_DIR= override =TASKS.setup.org= at bootstrap; the
  scaffolder already computes the relative prefix from =#+DEFAULT_PLAN_DIR=.
- No legacy tolerance window :: same posture as the 2026-05-08
  =:ID:= → =:CUSTOM_ID:= migration. Three local repos swept atomically; a
  tolerant reader stays cheap to bolt on if a fourth project surfaces.
- =:BLOCKED-BY: task:<uuid>= stays textual :: the protocol never promised
  =:BLOCKED-BY:= entries were clickable links. Switching =task:= to an org
  abbreviation makes them clickable *in plan files*; inside =TASKS.org= the
  local override resolves them to the same file, which is the desired
  behaviour. No code change needed beyond the existing
  =task:<uuid>= textual recogniser.

** Gotchas
- Local =#+LINK:= must precede =#+SETUPFILE:= in =TASKS.org= /
  =TASKS.archive.org=. Reversing the order silently re-establishes the
  =../../= prefix and breaks intra-file navigation. The order constraint is
  documented in =TASKS.setup.org= as an inline comment and asserted by the
  doctor.
- =~/dotfiles= (wrapper repo) has only *one* affected plan file in its own
  =design/log/= — easy to miss because the bulk of its plan content lives
  in the =agents/= submodule (counted under =~/dotfiles/agents=, not the
  wrapper). The migration script must scope =rg= to exclude the submodule
  so files aren't rewritten twice.
- =#+SETUPFILE:= caches: stale =org-link-abbrev-alist-local= can survive across
  buffer revisits within a single Emacs session. If a user edits
  =TASKS.setup.org= and follows a link in an already-open plan-file buffer,
  they may need =M-x org-mode= or a buffer reload to pick up the change. Not
  worth tooling around; document it.
- =:raw-link= as reported by =org-element-context= reflects parser state at the
  *position of the link in the buffer* (so a local =#+LINK:= above the link
  changes =:raw-link= even if the final alist disagrees). Tools that consume
  =:raw-link= directly to derive parent UUIDs should keep parsing the
  =[[task:UUID]]= /textual/ shape rather than expanding through org.
