* Summary
A single =self-improvement= skill (=skills/self-improvement/SKILL.md=) captures friction with agent / pi configuration at the moment it arises and routes it as actionable TODO work to the right tier. Project-local feedback (project =AGENTS.md=, project skills, project conventions) lands in the current project's =TASKS.org= under =* Agent feedback= via =tasks_insert_task=. Global feedback (dotfiles =AGENTS.md=, =~/.agents/skills=, =~/.pi/agent=) is sent via =pi-intercom= to a live dotfiles session (auto-spawned in tmux if none alive) which triages and inserts into =~/dotfiles/TASKS.org=. Spec-only skill artefact: no scripts. Unified triage routine handles classify→tag→dedupe→confirm→insert→ack at both tiers.

** Decisions
- Single skill, repo-agnostic :: keys behaviour off *what the feedback is about*, not which repo it's invoked in.
- Routing by target tier :: project-local vs dotfiles-global; ambiguous defaults to current project with a =:tier-unknown:= tag.
- Submit + triage as one flow :: no separate client/server; the routing session also runs triage when local.
- Cross-tier transport :: =pi-intercom=, fire-and-forget =send=, prefix tag =[self-improvement]=. Plain prose envelope, structured =Origin:= block; no JSON schema.
- Confirmation policy inverted from usual default :: human-sender confirms wording (dotfiles agent has reformulated their words); agent-sender auto-inserts (no human at submit-time).
- Persistence under =* Agent feedback= :: feedback becomes durable TODOs via =tasks_insert_task=; standard org-tasks lifecycle / archive applies. No parallel inbox.
- Auto-spawn dotfiles session :: cmux-preferred / tmux-fallback recipe with intercom-registration polling and retry budget.

** Shipped
- =skills/self-improvement/SKILL.md= covering when-to-use (user- and agent-invoked), routing, two flows (local insert / cross-tier intercom), spawn recipe, triage routine, =* Agent feedback= entry conventions, and a worked example.
- =skills/README.org= populated with intro + one-line entries for every existing skill so the new entry has context (modest scope creep — kept the file useful instead of a stub).

** Gotchas
- Acknowledgement uses =send= not =reply=: the original submit was fire-and-forget so there is no in-flight =ask= to =reply= to. The originating agent watches for inbound messages with the =[self-improvement]= prefix as the planning prompt.
- =mkOutOfStoreSymlink= for =agents/skills= picks up new directories automatically — no =hms= run needed when adding a skill.

- /Confirmation policy./ Inverted from the usual "trust humans more" default: human-sender → confirm wording (the dotfiles-side agent has reformulated their words); agent-sender → auto-insert (no human at submit-time).
- /No archiving of feedback entries here./ Standard =org-tasks= status discipline handles DONE/CANCELLED archiving.
