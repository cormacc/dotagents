* Intent
Give the agent a durable way to turn recurring friction with its own configuration into actionable work, so a lesson learned in one session is not lost when that session ends. The skill owns eligibility, ownership routing, and persistence; it never becomes a second task store.

* Summary
*Level:* production · *Tests:* none (spec-only artefact, no scripts) · *Docs:* full

** Scope
*** In scope
- =skills/self-improvement/SKILL.md= as the canonical contract for durable-friction eligibility, ownership routing, deduplication, and persistence.
- Routing across three tiers: project-local, dotagents, and dotfiles.
- Persistence as =* Agent feedback= TODO tasks through the =ot= CLI, with entry conventions for target tags and body shape.
- =skills/README.org= entry so the skill is discoverable alongside its siblings.
*** Out of scope
- Any executable artefact -- the skill is spec-only, no scripts.
- A parallel feedback inbox: entries are ordinary org tasks under standard =org-tasks= lifecycle and archiving.
- Promotion of a captured item into a change-record, which belongs to =org-plan=.
- Session-to-session messaging, removed by the transport pivot (see Decisions).

** Decisions
- Single repo-agnostic skill :: keys behaviour off *what the feedback is about*, not which repo it is invoked from.
- Routing by owning tier :: project-local vs dotagents vs dotfiles, classified after resolving symlinks; ambiguous ownership asks once, then defaults to the current project with a =tier_unknown= tag.
- TODO-first by default :: the slow loop files a task and stops; a narrow tight loop permits one tiny approved documentation edit, in the current repo or a clean home-config tier.
- Direct cross-repo writes rather than agent-to-agent transport :: supersedes the original =pi-intercom= hand-off, which discovered or tmux-spawned a live dotfiles session, sent it a prose envelope, and waited for it to triage, insert, and acknowledge. Cross-project routing is now a plain =ot --root <target> create=, which drops the live-session dependency, the spawn recipe, and the acknowledgement round-trip. Landed 2026-07-15 in =dd43f48=; see [[plan:2026-07-14-housekeeping.org][housekeeping record]].
- Confirmation policy inverted from the usual default :: a human sender confirms wording, because the agent has reformulated their words; an agent sender writes without asking, because no human is present at capture time.

* Implementation
The skill is a single spec document, so the plan tasks above map to sections of =SKILL.md= rather than to separate artefacts.

Its current shape -- trigger gate, two loops, routing table, entry conventions, verification -- postdates the transport pivot recorded under Decisions. The cross-tier submit, session-spawn, and inbound-triage machinery built by plan tasks =d0730273=, =92ada34d=, and =e71730f4= no longer exists; what survives from them is the classify/dedupe logic, now run by whichever session captures the friction instead of by a dotfiles-side triage session.
