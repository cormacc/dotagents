* Intent
Retain automatic quota recovery with concrete account selection on the installed Pi runtime. Warn during pending authentication and report the resulting selection after cancellation, accepting that native selection can still commit after cancellation or overwrite an intervening manual selection.

*Level:* production · *Tests:* thorough · *Docs:* README

** Acceptance
*** Core functionality
- [X] A visible warning precedes each automatic recovery call to the native model setter.
- [X] The warning identifies that a pending switch can change selection after abort.
- [X] The warning advises against manual selection while the switch is pending.
- [X] The pending-selection warning remains until the setter settles in the active session.
- [X] A cancelled attempt reports the actual selected account/model after its setter settles.
- [X] Normal recovery retains the original finite, tier-constrained continuation contract.
- [X] Operator documentation states that a pending recovery switch can overwrite a newer manual selection.
*** Edge cases
- [X] Abort suppresses automatic continuation from the invalidated recovery attempt.
- [X] An external model/account change reported by Pi invalidates the recovery chain even if the older native setter later commits.
- [X] Operator documentation states that pending or silent same-target native selections may not cancel recovery.
- [X] Installed-runtime tests cover silent same-target selection as an accepted continuation outcome, alongside explicit-abort controls.
- [X] New input invalidates the recovery chain without authorising a late automatic continuation.
- [X] A failed setter clears its pending warning and reports the failure without claiming a successful switch.
- [X] Session shutdown or replacement cannot let an old callback write UI state into the replacement session.
- [X] Installed-runtime tests distinguish the accepted stale-selection outcome from forbidden automatic continuation.
- [X] Delayed-selection tests have passing normal-selection controls.
*** Anti-criteria
- [X] Must not: disable native abort or model-selection controls.
- [X] Must not: restore an old selection automatically after cancellation.
- [X] Must not: treat a timeout of an extension wait as cancellation of the native setter.
- [X] Must not: log credentials or send warning text into model context.
- [X] Must not: require a modified Pi runtime or relax unrelated multi-subscription acceptance.

** Decisions
- Use an extension-only warning and explicit result report around native concrete selection. The user accepts the timing limitation as a corner case; its normal frequency and duration are not measured.
  Rejected:
  - Native fix/fork: maintenance cost is not justified for this accepted limitation.
  - Manual-only recovery: loses the requested automatic recovery benefit.
  - Virtual dispatch: changes the accepted concrete-account selection contract.
  - UI lock: removes useful escape controls and is not a native atomicity guarantee.
  - Startup auth gate: each setter still checks credentials; a later file change can still cause a locked reload.
- Manual invalidation begins at an externally reported model/account change, not an unobservable native selection request. The owner accepts that pending requests and silent same-target selections may not cancel recovery. Explicit abort and new input still invalidate automatic continuation. Do not replace this limit with transcript polling or a fixed waiting window.
- Suggested warning: "Checking recovery account authentication. Avoid changing models until this finishes. Abort stops recovery, but the account selection may still change."
- Suggested cancellation report: "Recovery cancelled. Selected account/model: <actual selection>. No automatic retry will run." This describes the invalidated recovery attempt, not a user-initiated request.
- Reuse documented Pi UI status/widget and notification facilities. Cancellation invalidates continuation but does not end the pending-setter warning. Clear only this controller's UI when the setter settles; retain session ownership checks for late callbacks.
- Do not queue another automatic selection while this controller's setter is unresolved. Do not attempt rollback. Add a ~known-limit:~ comment at the selection boundary naming stale native commits and revisit if Pi gains a cancellation-safe public setter or observed impact makes the limitation unacceptable.

** Risks
- Accepted: native auth-await completion can change selection after abort or overwrite a newer manual selection. Warnings reduce surprise but do not prevent this.
- Accepted: a stalled setter can leave the warning visible for an extended period. Abort remains available; do not hide an unresolved switch behind a success message or an extension-only timeout.
- Accepted: pending manual auth requests and equal/no-op commits can be invisible to extensions, so recovery may continue. Distinguish externally reported changes from recovery-generated events and test both observed-change invalidation and silent same-target continuation. Do not claim request-time cancellation.
- A warning may not render in every host mode. Test TUI and supported RPC presentation separately; do not claim visual coverage from SDK tests.
