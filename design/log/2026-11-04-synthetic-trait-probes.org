* Intent
Replace repository-dependent trait scenarios with synthetic subjects and record marginal effects honestly. Separate a fragment's write-boundary behaviour from restrictions imposed by the probe harness.


* Summary
*Level:* prototype · *Tests:* thorough · *Docs:* inline

Every packaged trait and ~%prune~ has a synthetic, self-contained gate under ~traits/<name>/gate.md~. ~scripts/run-trait-gate.bb~ runs a gate in the host harness, Pi, with the complete deployed resource context: home ~AGENTS.md~, every installed skill and extension, and MCP servers. In scaffold mode each arm's prompt is the gate's scaffold; with ~--persona NAME~ each arm gets the packaged persona that ~oh~ composes, as an appended system prompt, and the control removes only the trait fragment. An audit extension checks every actual provider request for the baseline, the persona and the fragment, with matcher controls, and a gate's ~## Fixture~ gives each arm a committed Git repository so that a write shows in ~git status~. ~grounded~ is deleted: three attempts showed no marginal effect over the ~reviewer~ body and the ~code-review~ skill.

** Scope
*** In scope
- Synthetic scenarios, pre-registered conditions and treated/control pairs for every trait.
- Directory-form fragments with gate records in the repository user layer.
- A reusable Pi runner with packaged-persona composition, payload audit and write fixtures.
*** Out of scope
- Weakening a recorded condition, claiming general equivalence from one pair, or treating a pass as an admission prerequisite.
- ~oh~'s launcher text (delegation and publication instructions) in the arm prompt: an arm has no ledger to publish to.

** Decisions
- Probe in the host harness with the complete deployed resource context :: that is where a trait must earn its place. Rejected: native Codex scaffolds, whose results now stand only as history; an isolated ~oh --context measurement~ subject, which loads only configured extensions.
- Control persona is the composed treated persona minus the one fragment occurrence :: ~oh~ has no way to remove an inherited trait, and the substituted fragment text is exact. The runner fails when the fragment does not occur exactly once.
- Delete ~grounded~ :: three attempts at two models showed no marginal effect; the ~reviewer~ body and the ~code-review~ skill already carry the range and clean-result rules.

** Gotchas
- Pi has no read-only sandbox. The runner reports writes; it does not prevent them.
- A search of the serialised JSON payload misses present multiline text. Match decoded strings; the audit's known-bad control guards this.
