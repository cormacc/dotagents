* Intent

Eliminate the duplication and boilerplate identified by two parallel architecture reviews (claude-fable-5, gpt-5.5) of the `ot` CLI, shrinking the codebase by roughly 400–550 LOC and removing drift hazards — without changing any org-tasks/v1 contract behaviour, CLI text output, or TUI interaction. The registry-driven dispatch, CLI/TUI separation, and round-trip-preserving parser core are keepers; this pass consolidates the copy-pasted idioms around them.

* Summary

*Level:* production · *Tests:* thorough · *Docs:* inline

** Scope

*** In scope
- Sync `scripts/ot` bash-wrapper fallback deps with `bb.edn` (already drifted: charm.clj artifact + nexus pin differ).
- Single shared import/link/path-resolution helper replacing the 5 copies (`loader`, `list_show`, `maintenance`, `archive_publish`, `insert` ×2) of the expand-link → base-dir → sandbox idiom.
- Unified tree walk (children + import-children) replacing the 7–8 reimplementations across `task`, `scan`, `doctor`, `commands/util`, `status`, `loader`, `insert`, `list_show`.
- `commands/util` positional-arg helper replacing ~15 copies of `(or (:id opts) (first (:args result)))` and the duplicated missing-arg error blocks (verify the `:args` fallback is dead under registry `:args->opts` first).
- Data-driven property commands in `links.clj` (handoff/blocker/issue triples); merge `publish`/`unpublish` into one parameterised mover.
- Registry cleanup: derive `dispatch-coerce` from the specs; `enum-opt` helper for the 6 hand-rolled enum validators; delete empty `section-spec`.
- Dead-option removal or implementation: no-op `--scope` on `ot list`; unused `--selected` (`registry.clj:102`).
- Publicise `loader/atomic-write`; replace the 3 inline tmp+move copies in `archive_publish`; decide whether `insert`/`record` writes become atomic.
- Consolidate small dupes: `closed-statuses` (×4 → `lifecycle`), `escape-regex` (×2), `random-uuid-str` (×2, bb has `random-uuid`), trailing-tag-strip regex (×3), `#+LINK:` preamble strings (×2), `requiring-resolve` where no cycle exists (`record`, `doctor`, `maintenance`), misleading `ot status` comment in `create.clj:12`.
- Split `commands_test.clj` (1,300+ lines) by command family with a shared `test_util`; update `docs/test-map.md`.
- Doctor: restructure `run-doctor`'s 200-line volatile body into a vector of pure `input -> [findings]` check fns; replace gratuitous `volatile!` walkers elsewhere (`task`, `loader`, `insert`, `status`) with reduces.
- Perf: memoize `parse-link-templates` by `:source-path` in `task->wire`; reuse the single-pass depth computation from `tui/tasks` in `list-cmd` (currently O(n²)).
- Update `README.md` project layout for any new/renamed namespaces; note that `bb test` runs from repo root.

** Acceptance

*** Core functionality
- `bb test` (from repo root) passes with assertion count ≥ baseline (185 tests / 648 assertions).
- `scripts/ot` fallback `-Sdeps` names the same artifacts and versions as `bb.edn`.
- Exactly one implementation of import/link target resolution exists; `loader`, `list_show`, `maintenance`, `archive_publish`, and `insert` all call it.
- Exactly one children+import-children walk/find/update implementation exists; `commands/util/task-children*`, `insert/find-task-by-id`, `scan/walk-tasks`, and `doctor/walk-tasks` are deleted.
- `dispatch-coerce` is derived from command specs, not hand-maintained.
- `--scope` on `ot list` either filters archived tasks or is no longer accepted; `--selected` is either read by production code or removed from the spec.
- All file writes that were tmp+move remain atomic through one shared public helper.
- `status.clj` `valid-statuses` derives from `lifecycle/status-cycle`; non-parser callers use `lifecycle/closed-statuses`. (Full single-definition consolidation moved to the parser follow-up task.)
- Each `commands/*` production namespace has a corresponding focused test namespace; `commands_test.clj` no longer exists as a monolith.
- `doctor` checks are pure fns; `run-doctor` composes them without a `volatile!` accumulator.
- Total `src/` LOC is reduced versus the pre-pass baseline (5,549). Outcome: −177 (5,372); the original ≥300 target assumed the parser split, which was descoped.

*** Edge cases
- Standalone-skill install path (wrapper fallback classpath, no repo `bb.edn`) still launches `ot` successfully.
- Round-trip fixtures (`test/fixtures/round-trip/`) remain byte-identical through parse→serialize.
- `ot doctor` finding order and wording are unchanged.
- TUI command bridge (`tui/tasks` `call-command`) behaviour is unchanged for both success and error envelopes.

*** Anti-criteria
- Must not: change any key, field, or value in org-tasks/v1 machine output (`--format json|edn`).
- Must not: change CLI human-text output except where an accepted-but-ignored option is removed.
- Must not: add new top-level dependencies or JVM-only libraries.
- Must not: modify `paths.clj` resolution/sandbox semantics.
- Must not: rewrite `parser/parse-tasks` internals beyond mechanical relocation.

** Decisions
- Chose incremental dedup within the existing architecture :: both reviews independently rated the registry/dispatch/TUI design as earning its keep; consolidation beats restructuring.
  Rejected:
  - Structural rewrite (merge command namespaces, replace registry): no payoff against ISC; both reviews explicitly said leave the architecture alone.
  - Cherry-picking only quick wins: leaves the two P1 duplication clusters (path resolution, tree walk) — the security-relevant and highest-divergence-risk items — unaddressed.
- Parser split is facade-preserving :: `org-tasks.parser` remains the public namespace re-exporting from internal splits, so no caller churn and no round-trip risk.
- `links.clj` command generators keep named fns :: registry entries and TUI `tui-command-fns` reference vars by name; the data-driven table produces named defs so the registry is untouched.

** Gotchas
- Mutation-command machine envelopes (`issue add/remove` etc.) had zero test coverage — a data-driven refactor silently changed `:tokens` from raw strings to wired maps and only an independent review caught it. Envelope regression tests now exist; keep them when touching `links.clj`.
- The `(first (:args result))` positional fallback is NOT dead: command fns are invoked directly by tests and the TUI bridge, bypassing registry `:args->opts`. Centralised in `commands.util/positional-arg`, not deleted.
- Moving parser-owned `closed-statuses` to `lifecycle` creates a `parser` → `lifecycle` → `parser` cycle; needs the parser split (or a constants extraction) first.
