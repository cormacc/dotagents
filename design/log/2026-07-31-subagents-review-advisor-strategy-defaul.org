** Decisions

- Evaluate before changing defaults :: the advisor-strategy record (2026-07-29) deliberately chose middle-default + caller-driven heavy escalation and kept `skilled-worker` as a stable comparison baseline; the open questions in task 899fe848 are exactly what the deferred paired comparison was designed to answer, so the experiment is absorbed here and gates the definition changes.
  Rejected:
  - Set advisor heavy directly now: raises the cost of every mandatory pre-publish consult and preempts the pending comparison with no new evidence.
  - Merge worker/skilled-worker now: destroys the comparison baseline; the persona body's unconditional consult step contradicts a `--spawns none` spawn until made conditional.
- Benchmark: mini org-outline parser with byte-identical round-trip :: objective hidden-test scoring, judgment-bearing edge cases (tags vs heading text, drawer boundaries, whitespace preservation), fits repo Babashka tooling.
  Rejected:
  - Sliding-window rate limiter: more memorized territory, less advisor-differentiating.
- Cell C tier selection via `--prompt-extra` :: no structured parent-side knob exists (`--model` on the worker spawn sets the worker's own model); using the free-text route doubles as live evidence for the override-mechanism gate question.
- Extend to a feather advisor-tier ladder rather than repeat saturated cells :: with A, B and D all at 35/35 the discriminating power has to come from a weaker executor, so E–G hold the executor at feather and vary only the advisor tier (light/middle/heavy). Rejected: repeat runs of A–D for statistical confidence, which would spend more to re-measure a ceiling.
- Round-2 benchmark: =cellform= spreadsheet formula engine :: deepest interacting-rules core of the candidates (dependency graph + cycle topology + error-precedence lattice + strictness), with deliberately counter-Excel semantics so pattern-matching to memorized spreadsheet behaviour loses points while rule-reading does not; scoring stays mechanical with the round-1 runner shape.
  Rejected:
  - Text buffer with grouped undo/redo: state discipline but a shallower algorithmic core; undo semantics are well-trodden training material.
  - Event-sourced payment ledger: rule volume risks checklist difficulty a diligent light model grinds through, rather than reasoning depth.
- Switch the round-3 difficulty axis to performance rather than more rules :: two benchmarks built from explicitly-stated but counter-intuitive rules both saturated at light tier (=cellform= pilot: sonnet 60/60, plus 32/32 on off-suite probes), because careful rule-reading is exactly what these models do well. Algorithm selection under a stated time budget is a different capability and is where a frontier advisor consult should plausibly add value. Rejected: toughening =cellform= along the same axis (no reason to expect a different outcome); running only the feather cells (answers a narrower question than the gate needs).
- Round-3 budget set generously at 60s for a 30k/30k workload :: babashka's constant factor is large and varies by approach — a legitimate lazy segment tree takes ~28s where two Fenwick trees take ~3s — so a tight budget would fail correct logarithmic solutions and would measure micro-optimisation instead of asymptotic judgement. At 60s any log-per-op approach passes while the quadratic rescan (~148s, hard-aborted at 100s) fails.
- Round-2 matrix: 9 cells = the round-1 configurations plus skilled-worker feather/light baselines :: H and I complete the no-advisor baseline at every executor tier (round 1 had it only at middle), and cell I run first is a difficulty gate at zero marginal cost.
  Rejected:
  - Heavy-executor cells: answer no gate question and are the most expensive per run.
  - =worker= middle + middle advisor: A vs D already isolates the advisor at middle tier; n=1 cannot use the extra resolution.
  - Benchmark-1 repeats: would re-measure a known ceiling.
- Round-2 report row order fixed at planning time :: increasing executor weight then advisor weight (feather < light < middle < heavy; no-advisor before any advisor tier) — exactly H, E, F, G, I, B, C, A, D — so the report task cannot drift from it.

** Gotchas

- *The ledger under-reports, it does not merely omit.* A worker that hand-rolls a consult with raw =herdr agent start= instead of =subagent run advisor= gets the default model (defeating any tier instruction), spends money that appears nowhere in the ledger, and orphans the pane. Round-3 cell E hid $1.6883 this way, understating its cost 2.3x. Treat consult counts and advisor costs as a floor.
- *=prompted-at= is not a safe duration baseline.* A spawned pane can hold its composed prompt unsubmitted; measured submit-delays ranged 5–47s against 0.8s before the regression. Measure from the child transcript's first user message instead — =acceptance/metrics= now does.
- *=collect= can capture a premature write.* A child that writes non-envelope content to its =RESULT= path mid-flight triggers an =invalid= capture while it is still working, and the parent then stops waiting for it. Round-1 cell E did exactly this, so a mid-flight score is not a final score.
- *babashka's constant factor swamps asymptotics at benchmark scale.* Two equally valid O(log n) solutions differed ~10x (lazy segment tree ~28s vs two Fenwick trees ~3s) on the same 30k/30k workload, so any timed budget must be generous enough to pass every correct approach or it silently grades micro-optimisation.
- *A reference implementation passing its own suite proves consistency, not correctness.* The round-1 reference scored 35/35 while mis-serialising a bare keyword with tags — a case the suite did not contain. Off-suite probing found it; the suite never would have.

** Risks

All the planning-time risks resolved; only these remain durable:

- Single run per cell. Never retired — every result here is n=1, so single-case score gaps and minute-scale duration gaps are inside noise. The convergence-time signal in the feather trio is the one finding that would most benefit from repeats.
- Conclusions are scoped to one problem genre. All three benchmarks were self-contained, precisely-specified, single-file problems with objective tests, and all three saturated. Nothing here establishes what happens on multi-file, ambiguous, or archaeological work — where an advisor may still pay.

* Implementation

** Benchmark design (task 5cc4e2a1)

Artifacts live under the record's same-stem folder. =skeleton/= (=ASSIGNMENT.md=, =bb.edn=, stubbed =src/orgmini.clj=, visible smoke tests) is the only material seeded into a cell; =acceptance/= holds the hidden suite (=orgmini_acceptance.clj=, 35 cases across 6 categories), the =score= wrapper, and a =metrics= extractor; =rubric.md= is the root-session reading guide.

The suite was validated before use rather than assumed correct: a reference implementation scores 35/35, the stubbed skeleton scores 0/35 all-errored without crashing the runner, and a deliberately sloppy implementation scores 24/35 (68.6%), losing points in =tags= (2/5), =drawer= (3/6) and =round-trip= (7/10). The benchmark therefore discriminates, retiring the "benchmark may not discriminate" risk. Both validation implementations were moved outside the worktree to =~/.cache/orgmini-validation/= so that no answer key sits beside the cell scratch dirs.

Hidden-case inputs deliberately differ from the illustrative examples in =ASSIGNMENT.md=. The recognition rules stay stated in full — hiding them would test mind-reading rather than diligence — but a cell must generalize those rules instead of special-casing the literals it was shown.

Two measurement facts were established against the live ledger schema, both correcting assumptions recorded above:
- Token cost is *exact* for pi-kind children, not best-effort: pi sessions record per-message =message.usage.totalTokens= plus a real =cost= map. A historical worker sample shows one middle-tier consult accounting for 37% of total spend ($1.14 of $3.04), so the advisor loop is not a rounding error.
- Wall time must be measured as mtime(=RESULT=) − =prompted-at=, not =captured-at=: under the non-blocking policy =captured-at= records when the parent got round to collecting and can lag publication arbitrarily.

Advisor consults are discoverable by matching each advisor ledger entry's =parent-session= against the cell's own =child-session.value= (nested consults share the single ledger directory rather than getting their own), and the resolved tier is readable from the nested label (=worker-3/advisor-1-middle=) and independently corroborated by the transcript =modelId=. That gives cells C and D a hard pass/fail on the =--prompt-extra= override mechanism.

Noted for the run task: =.agents/tmp/= already contains substantial prior advisor-strategy design material (previous worker/advisor assignments, reviews, reports), so each cell assignment must pin its executor to its own scratch dir.

** Run-phase findings (task 1a2fdaa6)

*** Spawned prompts are not reliably dispatched

Every spawn in this session left the composed prompt typed into the new pane but *unsubmitted*, requiring a manual focus and Enter; the user first noticed it against an extension-update notification, and it persisted after updating extensions. Confirmed mechanically: cell E read =idle= five seconds after =subagent start=, one =herdr agent send-keys <child> enter= moved it to =working=. Measured submit-delays were 25.6s (A), 40.4s (B), 37.3s (C), 46.6s (D) against 0.8s for a pre-notification historical run, so the regression is recent and its size varies per cell.

Two consequences: wall-clock duration must be measured from the transcript's first user message rather than =prompted-at= (already corrected in =acceptance/metrics=), and cells are now spawned through =.agents/tmp/advisor-eval/spawn-cell.sh=, which polls lifecycle state and sends Enter only on a definite =idle= — nudging on an unobservable =unknown= risks submitting stray empty input. The durable CLI-side fix is tracked separately as a repo task, not fixed inside this experiment.

*** Comparison report (task febc1e3c)

Report: [[proj:design/log/2026-07-31-subagents-review-advisor-strategy-defaul/comparison-report.md]]. Raw per-cell artifacts are the =cell-*-score.edn= and =cell-*-metrics.edn= files under =.agents/tmp/advisor-eval/=, with judgement calls in =compliance-notes.md= alongside them.

Headline: quality saturates above feather (A, B, D and G all 35/35), and cell A — =skilled-worker= with no advisor — won on every axis at once: joint-best score, cheapest perfect score ($3.2288) and fastest perfect score (389.8s). Both controlled comparisons argue against a heavy default: at equal light executor, middle advisor scored 35/35 for $5.3666 while heavy scored 34/35 for $7.1269; at equal middle executor, adding a heavy advisor cost $2.98 and 135s for no score gain over A. Heavy only earned its cost at feather (G 35/35 versus F 34/35 and E 32/35).

The =--prompt-extra= override is verified functional in all four attempts, corroborated at two independent levels — the nested ledger label and the model actually run in the consult transcript (heavy → =claude-fable-5= three times, middle → =claude-opus-5=, light → =claude-sonnet-5=). The remaining case for a structured flag is ergonomics, not reliability.

=requires: advisor= proved unenforced at feather tier: cell E spawned its mandatory consult and published three minutes later without awaiting or capturing it (leaving an orphan that ran ~30 minutes and had to be closed manually), and cell F skipped the consult altogether while still scoring 34/35 for $0.7324. The mandate is prompt semantics rather than a mechanical gate, so "the consult happened and was used" should be treated as unverified unless checked in the ledger.

*** Round-2 difficulty gate: FAILED — benchmark 2 also saturates at light tier (task d2b65b17)

Benchmark 2 (=cellform=) was built and validated exactly as planned: 60 cases across 7 categories, reference 60/60, stub 0/60 all-errored without crashing, and a deliberately sloppy implementation 47/60 (78.3%) failing precisely in the counter-intuitive categories (=errors= 2/8, =strictness= 6/11, =cycles= 8/10) while acing every mechanical one. The calibration therefore looked healthy.

The pilot then falsified the premise. Cell I (=skilled-worker --model light=, i.e. =claude-sonnet-5=, no advisor) scored **60/60** — including =strictness= 11/11, =errors= 8/8 and =cycles= 10/10, every deliberately counter-Excel rule — for $2.5152 in 672.6s, with zero consults. It also passes all 32 off-suite semantic probes, so the score is genuine robustness rather than overfitting to the suite.

The design assumption behind both benchmarks was wrong. Difficulty built from *more, stranger, but explicitly stated rules* does not challenge a light-tier model, because careful rule-reading is precisely what these models are good at. The 78.3% sloppy calibration models a *careless* implementer, which sonnet is not. Two independent benchmarks have now saturated at light tier and above.

Per this task's gate condition the remaining eight round-2 cells were **not** spawned. The pilot cost $2.5152 and averted roughly $25 of matrix spend on a saturated benchmark — the run-first pilot design paid for itself on its first use. Toughening along the same axis is not indicated; a genuinely discriminating round 2 needs a different *kind* of difficulty (algorithmic/performance constraints where a naive solution fails, long-horizon multi-file consistency, or debugging an existing subtly-broken system) and that is a design decision for the user, so the pilot task stays open pending it.

Incidental: the accumulating evidence across both rounds is consistent on the gate questions — at light tier and above, no-advisor executors match or beat advisor-bearing ones (round 1 cell A won on score, cost and speed simultaneously; the round-2 pilot reached a perfect score unaided).

*** Round-3 difficulty gate: FAILED — the performance axis also saturates at light tier (task d2b65b17)

Benchmark 3 (=segwin=) switched axis from rule-following to engineering judgement under a stated time budget, and calibrated cleanly: reference 34/34, stub 0/34 all-errored without crashing, and a *correct but quadratic* naive implementation 32/34 — passing every correctness category including three randomised brute-force cross-checks, and failing only =performance= 0/2 (hard-aborted at 100s against a ~148s projected runtime). The performance gate was therefore the sole discriminator by construction.

Cell I (=skilled-worker --model light=, sonnet, no advisor) scored **34/34 including performance 2/2**, in 378.5s for $1.5185 with zero consults. It chose a lazy-propagating segment tree over coordinate-compressed timestamps unprompted, measured itself with =bb bench= at ~27s against the 60s budget, and added its own randomised property tests cross-checked against a brute force across 40 seeds.

That is three benchmarks, three distinct difficulty axes, all aced unaided by light tier — and each one cheaper and faster than the last ($2.5152 → $1.5185):

| Round | Benchmark | Difficulty axis | Cell I / A result |
|-------|-----------|-----------------|-------------------|
| 1 | org-outline parser | precise rule-following | 35/35 (cell A, middle) |
| 2 | =cellform= | counter-intuitive stated rules | 60/60 (sonnet) |
| 3 | =segwin= | algorithmic judgement under a time budget | 34/34 incl. perf (sonnet) |

The limiting factor is the *problem genre*, not the difficulty axis. A self-contained, precisely-specified, single-file problem with objective tests is precisely the shape at which current frontier-adjacent models are strongest, so no amount of difficulty *within that genre* creates headroom for an advisor to fill. Making an advisor consult matter would likely require a different genre altogether — multi-file work with cross-cutting consistency, genuine requirement ambiguity needing pushback, or archaeology in a large unfamiliar codebase — none of which score objectively or cheaply.

The remaining eight round-3 cells were again **not** spawned, per the gate condition. Across both rounds the two pilots cost $4.0337 in total and averted roughly $50 of matrix spend on saturated benchmarks; the run-first pilot is the single most valuable design decision in this record.

* Open questions

** DECIDED Should the advisor default to heavy instead of middle? — No, it stays middle

The only equal-executor comparison of advisor tiers went against heavy: at light executor, a middle advisor scored 35/35 for $5.3666 while heavy scored 34/35 for $7.1269 — worse, for 33% more. Adding a heavy advisor to a middle executor (D) bought nothing over no advisor at all (A). Heavy consults cost $2.28–$4.18 against middle's $2.02. Heavy won only at feather, the tier being abandoned as a false economy.

=--model heavy= remains available per spawn for genuine extremis. Noted honestly: every measurement above concerns *routine* consults — no cell ever became stuck and escalated — so there is no evidence either way about escalation quality at any tier. The decision follows the evidence that exists rather than a plausible argument about a case never observed.

** DECIDED Should the parent-side advisor-tier override stay a `--prompt-extra` convention? — Yes, keep the convention and document it

Verified functional in all four attempts, corroborated at two independent levels (nested ledger label and the model actually running in the consult transcript). A structured flag would therefore be an ergonomics improvement, not a reliability fix. The caveat that must be documented alongside it: the convention is only as reliable as the executor's willingness to use the CLI — round-3 cell E bypassed =subagent run advisor= for a raw =herdr_agent start=, which silently defeated tier selection, hid $1.6883 of spend from the ledger, and orphaned the pane.

** DECIDED Should worker and skilled-worker merge? — Yes: retire =skilled-worker=

With the mandatory consult removed, =worker= becomes a light executor with an *optional* advisor and =skilled-worker= a middle executor with none; =worker --model middle= then covers =skilled-worker='s entire purpose, leaving an unused optional capability as the only difference. One executor persona with a =--model= tier and an opt-in advisor is simpler than two. Cell I (=skilled-worker= at light, no advisor) being the best cell of the study on every axis is an argument for that *configuration*, not for a second persona to express it.

** DECIDED Is the mandatory pre-publish advisor consult worth its cost? — No: eliminate it

Three comparisons, no measurable quality gain in any: B (light + middle advisor) 35/35 = A (middle, no advisor) 35/35; D (middle + heavy) 35/35 = A; F (feather + middle) 34/34 = H (feather, none) 34/34. The mandate cost $1.43–$2.98 per run. Its single genuine catch — cell B's advisor finding a real spec violation — only brought that cell to *parity* with a stronger executor that never made the mistake. It is also unenforceable in practice: five of six feather cells failed some part of the protocol, one bypassing the CLI entirely, so =requires:= expresses a guarantee the mechanism cannot deliver. Finally it duplicates existing practice, since a heavy review is already spawned from the orchestrator at feature closeout.

Counter-signal retained rather than dismissed: duration fell 3047.8s → 1973.9s → 854.7s as advisor involvement increased at feather, with identical quality — a possible convergence benefit at n=1 on the noisiest metric. Retaining the *optional* escalation path covers that case without paying for it on every assignment.

** DECIDED Which executor tier should be the default? — Light; feather is a false economy

Measured head to head on benchmark 3 against cell I (light, no advisor, $1.5185 / 378.5s): feather cost 1.1–2.4x more and ran 2.3–8.1x slower for an identical score, burning 2–2.5x the executor tokens, and accounted for every protocol failure in the study. Scope caveat worth carrying: all three benchmarks saturated, so this establishes light as the cheapest route to a score every tier achieves on well-specified, self-contained, objectively-testable work — not that light suffices on work that genuinely discriminates, which this study never managed to construct. Light-versus-middle at no advisor was also never run head to head on one benchmark.
