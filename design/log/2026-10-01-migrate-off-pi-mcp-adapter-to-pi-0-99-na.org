* Intent

Retire the =pi-mcp-adapter= package and run every configured MCP server (=atlassian=, =ms365=, =context-mode=, =context7=, =searxng=) on pi 0.99's built-in MCP support with =codemode= exposure, so that no Atlassian, ms365 or jira tool declaration enters the model context and each =/jira= flow sends the model only a one-line trigger and the filtered result of one jira extension tool.

* Summary

*Level:* production · *Tests:* thorough · *Docs:* README

** Scope

*** In scope
- Remove =npm:pi-mcp-adapter=; move =mcp.json= to =pi/mcp.json= in native syntax, linked at =~/.pi/agent/mcp.json= by the dotfiles =agents.nix=.
- =pi/extensions/jira=: deferred =jira_*= tools that call =mcp__atlassian__*= through =ctx.executeTool()=, hidden one-line triggers, no =jira_clone_apply=.

** Decisions
- Approach C: deferred jira extension tools, called from =codemode=, orchestrate =mcp__atlassian__*= via =ctx.executeTool()= :: the trigger is one line, the model re-emits no script, and filtering, rendering and the =SAND= guard are deterministic and unit-tested. This knowingly reverses the I/O-free extension decision in =design/log/2026-04-28-jira-integration.org=. A slash-command handler cannot call tools (=executeTool= exists only on =ExtensionToolContext=), so the model still makes one =codemode= call per flow. Rejected:
  - B (canned codemode script in each prompt; shipped first, then replaced): on =/jira get SAND-75= a 2,491-char user message plus a 1,192-char script re-emitted as =codemode= arguments, against a 302-char result. =display: false= only hides a message from the terminal; pi still sends it to the model.
  - A (agent-authored scripts): returned fields and context cost vary per run.
  - Direct-exposed jira tools: six more declarations on every request.
- Jira tools use =exposure: "deferred"= in a =jira= namespace :: callable from =codemode= whether or not active, never declared, and filtered out of the =codemode= description by =createCodemodeDescription=. Rejected: =exposure: "codemode"=, which lists every callable non-deferred tool in that description on every request (about 2,350 chars for the six tools).
- The =atlassian= server =description= points at the jira tools: "Jira and Confluence. For Jira issues, call the jira_* tools instead, e.g. tools.jira_get({keys})." :: it appears in the =mcp_servers= system-prompt section and in =describeNamespace("mcp__atlassian")=, the path an agent takes first. Rejected: relying on the =org-jira= skill (it did not load for prose requests) and the shorter "Prefer the deferred jira_* tools." (the agent never found =jira_get=); see =* Validation=.
- =jira_get= shows every field and =none= for an empty one :: an omitted line read as missing data and the agent re-fetched the raw issue. Rejected: omitting empty lines; one summary line of empty fields (36 chars saved on =SAND-75=, and a format of its own).
- =ot create= protects task bodies itself :: it is the writer for every caller, including the =org-jira= manual Clone step. A body line that would parse as an Org heading is indented by one space; callers pass =--body=<text>= and put the summary after =--=. Rejected: sanitising in =jira_clone= only, which leaves the manual protocol and other callers exposed.
- Exposure stays =codemode= (the default) for all five servers :: =direct= would declare the Atlassian tool set on every request and make the first prompt wait up to 10 s; =deferred= adds a =tool_search= round trip for no gain.
- =mcp.json= moves to =pi/mcp.json= and is linked only at =~/.pi/agent/mcp.json= :: it now carries pi-only keys (=oauth.callbackUrl=, =description=). Rejected: keeping both links; a generic plus a pi file for no second client.
- codemode activation relies on =autoEnableCodemode= (default =true=) :: nothing needs =codemode= without MCP, so no =defaultTools= pin.
- ms365 OAuth block is =oauth: {callbackUrl: "http://localhost/callback", clientName: "pi"}= :: pi appends a free port to a port-less loopback =callbackUrl=, which matches the Entra =http://localhost/callback= registration documented in =skills/ms365/README.org=.
- Re-login is a user-run step :: the adapter kept tokens in the OS keyring and native pi keeps them in =~/.pi/agent/mcp-auth.json=, so no migration path exists.

** Risks
- The model alters the one-line tool call in the trigger :: accepted; the tool validates its args and enforces the =SAND= guard itself.

- pi rewrites =pi/mcp.json= through the symlink on =/mcp= exposure or enable changes :: accepted; it writes only on explicit user action and adds no volatile keys.

* Implementation

- Native config: the adapter-era file fails =pi mcp list --json= with =server "atlassian": auth.provider must be a provider name= (same for =ms365=), and =validateOAuth= in =dist/core/mcp-servers.js= ignores the unknown =redirectUri=. Probe config changes against a copy with =PI_CODING_AGENT_DIR= pointing under =.tmp/=, keeping the old file as the negative control.
- =getJiraIssue= result under native MCP: the =CallToolResult= has =content=, =isError= and =statusCode= and no =structuredContent=; =content= is one text block holding JSON (=JSON.parse= gives =expand, id, self, key, fields=), and an error is =isError: true= with the Jira message in that text. The description is markdown, =null=, or an ADF document (see Gotchas); =normalizeIssue= reduces ADF to text. =getAccessibleAtlassianResources= lists the same site twice, so the cloudId lookup matches by =url=.
- Nested calls: a tool's =ctx.executeTool()= returns ={toolCall, result, isError}=. For MCP tools =result.content= may be truncated at 20 KB while =result.structuredContent= is the untruncated =CallToolResult= (=convertMcpResult= in =dist/extensions/mcp/tools.js=), so =callAtlassian= reads =structuredContent.content= first. A codemode script calls a tool as =tools.<name>(args)=; a namespace only groups listings.
- Tool behaviour: =jira_clone= fetches every issue before inserting any, and reports per-key =inserted=, =duplicate=, =section_not_found= or =error= instead of throwing. Calls outside the per-key loop (cloudId, user info, issue-type metadata, create) throw on =isError=; per-key calls in claim, comment and transition report the Jira message in that key's =error=, so one bad key does not hide keys already written. =jira_create= names the new key in its error when =ot issue add= fails after the issue exists.
