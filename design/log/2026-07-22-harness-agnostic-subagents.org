* Intent

Replace the pi-specific =edxeth/pi-subagents= extension used by Pi inside Herdr with a Herdr-based delegation convention — a pristine vendored =herdr= skill, a thin =herdr-subagents= companion skill, and portable subagent definitions under =subagents/= — preserving the current personas while reducing Pi-specific machinery and leaving artifacts reusable by other Herdr-hosted harnesses.

* Summary

*Level:* production · *Tests:* smoke (live spawn inside Herdr) · *Docs:* README + skill docs

** Scope

*** In scope

- Replace the Pi-specific =edxeth/pi-subagents= extension with a pristine vendored =herdr= skill and a thin =herdr-subagents= companion.
- Move the seven reusable personas to a harness-neutral =subagents/= roster with advisory =name=, =description=, =kind=, and =model= metadata.
- Keep persona definitions concise by referring to canonical skills for shared workflows while retaining role-specific constraints and output guidance.
- Expose the roster through =~/.agents/subagents/= and document project-over-global lookup.
- Define kind/model resolution, persona injection, pane geometry, lifecycle, and cleanup across Herdr-hosted harnesses.
- Support blocking and non-blocking assignments, one-child and wave-based fan-out, and ephemeral or opt-in resident children.
- Use a durable per-assignment result inbox as the only completion signal.
- Permit the planner to spawn one blocking ephemeral =scout= or =researcher= for a factual gap; those children cannot delegate further.
- Remove the legacy compatibility paths and Pi-specific package after live validation.
- Validate subagent metadata without the pi-subagents parser.

*** Out of scope

- Removing or replacing the retained =@ogulcancelik/pi-herdr= extension.
- Headless children, unrestricted hierarchical orchestration, autonomous pipelines, and enforced tool/model policies.
- A spawn helper or scheduler; the markdown workflow remains intentional until operational friction justifies code.
- Wiring every harness-specific global context file to the shared =AGENTS.md=.

** Decisions

- Use a markdown-only =herdr-subagents= companion over a spawn helper :: preserves portability and avoids rebuilding a smaller pi-subagents extension.
- Vendor upstream =skills/herdr/SKILL.md= unchanged and keep proactive delegation language in the companion :: makes upstream refreshes diff-free.
- Use =subagents/= with project-over-global lookup :: separates reusable personas from Pi prompt templates while allowing project overrides.
- Treat =kind= / =model= as paired advisory routing metadata :: model dialects are harness-specific; incompatible inherited values are dropped.
- Use read-then-act persona injection by default and native appended system prompts for long-lived Pi/Claude sessions :: keeps the baseline harness-neutral.
- Use a parent-addressed atomic result inbox as the sole completion channel :: avoids PTY injection and false completion from echoed prompts or terminal history.
- Keep waiting policy, cardinality, and lifecycle orthogonal :: supports blocking context calls, non-blocking work, bounded fan-out, and explicit residents without a scheduler.
- Bound normal fan-out to direct orchestrator children in waves of two :: keeps context and terminal geometry manageable.
- Permit one narrow planner exception for blocking =scout= / =researcher= fact-finding :: lets an interactive planner resolve evidence without enabling deeper delegation; those children remain leaves.
- Keep persona files role-specific and defer shared mechanics to canonical skills :: removes prompt drift and stale duplicated APIs.

** Gotchas

- =herdr agent read= contains submitted prompts as well as responses, and =agent prompt --wait= can settle at an intermediate idle. Only the validated result file proves completion.
- Terminal pane dimensions are columns × rows with non-square cells. A visually portrait =113×110= pane must split =down= under the portable 80-column and 2:1 rule.
- Bare Pi model patterns may resolve through an unintended provider; provider-qualified refs such as =openai-codex/gpt-5.6-sol= are deterministic.
- =herdr notification show= is best-effort and may return =reason: disabled=. The ledger, result file, and visible Herdr lifecycle remain authoritative.

** Risks

- Persona restrictions are cooperative rather than tool-enforced; keep assignments scoped and review artifacts before accepting them.
- Cross-harness model inheritance remains best-effort because model names are dialect-specific; omit the model when compatibility is unknown.
- Skill-triggered delegation depends on ambient context discovering the roster pointer; add harness-specific context wiring only where observed use justifies it.
- Resident sessions may accumulate stale context; residency remains explicit and is guarded by identity, capture, and release checks.
- Wave-based fan-out is intentionally bounded rather than scheduled; large batches trade throughput for simple, visible orchestration.
