* Intent
Restore confidence that the repository's documented installation model, custom agents, extensions, and skills match their real runtime behavior. Remove or consolidate stale surfaces, make failures observable, and provide one reproducible validation path so future drift is caught early.

Audit evidence: [[file:2026-07-14-housekeeping/audit.md][repository audit — 2026-07-14]].

* Summary
*Level:* production · *Tests:* comprehensive · *Docs:* full

The work converts the 2026-07-14 repository audit into a correctness-first cleanup: repair broken active behavior, simplify skill/plugin surfaces, then refresh the living documentation from the verified implementation.

** Scope
*** In scope
- Repair custom subagent definitions against the installed pi-subagents schema and available tools/skills.
- Correct extension error signaling, cross-provider schemas, and unbounded context injection.
- Make active extension tests portable and add a single root validation entry point.
- Replace unavailable task/improvement workflows with verified =ot= behavior and align related skills.
- Redesign GitLab guidance as an explicit parent router, consolidate trivial utility skills, and correct command claims/triggers.
- Resolve the bare =code-review= skill and make skill-creator validation reproducible.
- Remove stale active configuration and dead helpers; make extension dependency resolution reproducible.
- Update =README.md=, =AGENTS.md=, and the skill inventory to describe the source tree, packaging routes, dependencies, and update behavior accurately.
- Review all task-relevant specs listed above as part of implementation and closeout.
*** Out of scope
- New end-user features unrelated to the audit.
- Redesigning the =org-tasks= file protocol or task lifecycle.
- Replacing pi, the MCP adapter, or the current package/submodule installation architecture.
- Deleting the entire =pi/archive= tree; curated historical source remains unless a separately justified cleanup is created.
- Fixing defects in external tools or providers beyond adapting this repository to their verified interfaces.

** Decisions
- Use one phased change-record under the requested top-level task :: the findings share one repository-confidence outcome and can be validated together.
  Rejected:
  - One top-level task per finding: fragments the audit and duplicates closeout/documentation work.
  - A documentation-only pass: leaves confirmed runtime defects behind accurate prose.
- Repair active correctness before consolidation and documentation :: README claims should be regenerated from the resulting behavior, not today's broken state.
  Rejected:
  - Update docs first: guarantees another rewrite and risks documenting behavior that is about to change.
- Keep GitLab command groups behind an explicit thin router and merge trivial diagnostics into the parent :: preserves detailed guidance without injecting 39 conflicting descriptions globally.
  Rejected:
  - Full-depth discovery: broad trigger conflicts with org-tasks, org-jira, and code-review.
  - One monolithic SKILL.md: makes routine GitLab requests load thousands of irrelevant lines.
- Develop =code-review= into a real review protocol rather than remove the capability :: review is a distinct workflow, but the current four generic bullets do not justify a skill.
  Rejected:
  - Keep unchanged: retains prompt overhead without useful behavior.
  - Remove permanently: loses a useful home for severity, diff-selection, verification, and false-positive standards.
- Preserve =pi/archive= as an explicitly historical surface for this pass :: remove stale active references/configuration, not curated history.
  Rejected:
  - Delete all replaced archives: unnecessary scope and risks losing migration rationale not yet promoted elsewhere.
