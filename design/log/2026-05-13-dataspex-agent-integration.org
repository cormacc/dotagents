* Summary
pi-coding-agent has runtime visibility into a ClojureScript app's state — atoms, datascript DBs, taps, change/audit log, nexus action log — via Dataspex's in-process client. Reads route through ~dataspex.core/store~ over ~shadow.cljs.devtools.api/cljs-eval~ on the JVM nREPL. A pi extension wraps the path as token-disciplined tools; a portable skill documents the same workflow plus ~clojure_eval~ fallbacks for non-pi agents.

** Decisions
- Read path :: ~shadow/cljs-eval~ from the JVM nREPL, reading ~dataspex.core/store~ directly. ~browser_eval~ rejected (~store~ is not ~^:export~-tagged, breaks under ~:advanced~). Hiccup-via-render-host rejected (rendered, not raw).
- Scope :: CLJS browser runtime only; JVM-side ~dataspex.server~ (port 7117) parked.
- Shape :: extension + skill, shipped together. Action log and audit-history volume make a skill-only path a recurring token tax.
- Parallel-label convention :: agent-registered tracking uses ~<label>-audit~. Re-calling ~dataspex/inspect~ on an existing label is forbidden — it overwrites the app's panel state. Cleanup via ~dataspex_untrack~.
- Skill is fallback-first :: each capability pairs the ~dataspex_*~ tool call with a copy-pasteable ~clojure_eval~ form.

** Shipped
- Extension :: ~pi/extensions/dataspex/~ registers ~dataspex_labels~, ~dataspex_value~, ~dataspex_history~, ~dataspex_track~, ~dataspex_untrack~, ~dataspex_db_query~, ~dataspex_actions_tail~.
- Refusal semantics :: ~dataspex_track~ throws on ~:missing-label~ / ~:audit-label-exists~ / ~:not-watchable~ (~isError: true~). ~dataspex_untrack~ returns ~{:untracked label :was-present? bool}~.
- Skill :: ~skills/dataspex/SKILL.md~ + ~skills/dataspex/references/fallback.md~.
- Wiring :: ~../agents.nix~ installs local extension deps on Home Manager activation, alongside ~chromium~ and ~pi-clojure~.

** Gotchas
- *Read path must return a bounded string.* Shadow's remote writer enforces a 1 MB limit on the cljs return-value serialisation, *outside* any ~(binding [*print-length* ...])~ block in the form. ~dataspex_value~ against the whole ~state~ atom triggered this even with ~limit: 10, level: 2~. Fix: ~(with-out-str (binding [...] (pr <expr>)))~ so the cljs return value is itself a bounded string.
- *Do not rely on `:out` from `cljs-eval`.* Concurrent calls against the same build share the runtime's ~*out*~; each request's ~:out~ snapshot can include sibling-request bytes. Empirically: three concurrent ~(print "A-")~ / ~(print "B-")~ / ~(print "C-")~ requests returned ~:out~ of ~"A-B-"~ / ~"A-B-C-"~ / ~"A-B-C-"~. The harness is sequential and missed this; pi runs tools in parallel by default. Read ~:results[0]~ and ~clojure.edn/read-string~ it instead.
- *Implicit pi-clojure dependency at runtime.* dataspex imports ~evalExpr~ from ~../pi-clojure/nrepl-client~, which imports ~bencode~. dataspex's ~package.json~ declares no runtime deps — ~bencode~ resolves from ~pi-clojure/node_modules~ via Node's parent-walk. ~agents.nix~ activates both for this checkout; a future standalone pi package would need its own ~bencode~ dep.
- *TypeScript-template `\"` is not a CLJS quote escape.* In template literals, write ~\\"~ to produce ~\"~ in the embedded CLJS form. First iteration of the throw-based refusal messages used ~\"~, which TS reduced to ~"~, producing strings like ~(str "" label# "")~ that swallowed the binding's quotes.

** Follow-ups
- JVM-side ~dataspex.server~ + port 7117 parked unless a concrete JVM-inspection need emerges.
- If advanced-compiled browser access without nREPL is ever needed, consider an upstream PR exporting a safe ~dataspex.core/store~ accessor.

* Implementation

** Task 1: API surface map
Source read at ~no.cjohansen/dataspex~ HEAD ~1be4df8~ (cloned read-only into ~.agents/tmp/dataspex/~).

Headline: ~dataspex.core/store~ (defonce, ~src/dataspex/core.cljs:39~) is the single canonical read surface. Every inspected value, revision, and audit history lives in that one CLJS atom. No need to hook hiccup, the render channel, or the browser extension.

Store shape:
#+begin_src clojure
{"App state" {:rev 7
              :val {...}                    ; current value
              :ref <atom>                   ; original watchable
              :idx 0
              :history [{:created-at #inst "..."
                         :rev 7
                         :val {...}
                         :diff <editscript>
                         :dataspex.audit/summary <opt>  ; via IAuditable; sparse
                         :dataspex.audit/details <opt>}
                        ...]                ; bounded by :history-limit, default 25
              :dataspex/path []
              :dataspex/inspectee "App state"}
 :dataspex/host-str "..."                   ; internal bookkeeping mixed in
 :dataspex/remotes #{}
 :dataspex.render-host/channels [...]}
#+end_src

Access patterns: list user labels via ~(filter string? (keys @store))~; current value via ~(get-in @store [label :val])~; history (when tracked) via ~(get-in @store [label :history])~.

Public ~dataspex.core~ functions (all ~^:export~-tagged): ~inspect~, ~uninspect~, ~inspect-taps~, ~uninspect-taps~, ~connect-remote-inspector~, ~inspect-remote~, ~uninspect-remote~. ~store~ itself is *not* exported. Datascript extends ~dataspex.protocols/Watchable~; datomic/datalevin/datahike are JVM-only.

** Task 2: Spike against live ~connect/portal~
shadow build ~:app~ on nREPL port 9000, Chrome runtime attached. ~connect.app/spex~ registers five labels: ~"state"~ (app atom), ~"db"~ (datascript conn), ~"Taps"~, ~"Actions"~ (~nexus.inspector/LogInspector~), ~"hiccup"~ (UI vector).

Verdict: viable, no ~browser_eval~ fallback needed under dev compilation. Canonical idiom:

#+begin_src clojure
(require '[shadow.cljs.devtools.api :as shadow])
(shadow/cljs-eval :app "(get @dataspex.core/store \"state\")" {})
#+end_src

Surprises surfaced into Summary § Gotchas:
- App-registered labels lack ~:track-changes? true~, so ~:history~ stays empty. Agent must register a parallel ~<label>-audit~ to see diffs.
- ~Actions~ ~:val~ is a ~LogInspector~ deftype: not ISeqable; the log is only reachable via ~(aget log-inspector "log")~.
- ~IAuditable~ is sparse: datascript history entries carry only ~:diff~.

** Task 4: MVP extension + skill
Extension wraps the canonical idiom via ~pi-clojure~'s nREPL client.

Tool parameters: ~buildId?~ / ~port?~ / ~host?~ for target selection (port from project port files, build from ~shadow/active-builds~). ~dataspex_value~'s ~path~ is an EDN vector string; ~dataspex_db_query~'s ~q~ / ~args~ are EDN strings. ~dataspex_history~ prefers ~<label>-audit~ when present, so the normal flow is ~dataspex_track {label: "state"}~ → mutate → ~dataspex_history {label: "state"}~ → ~dataspex_untrack {label: "state"}~.

Read tools use ~(with-out-str (binding [*print-length* L *print-level* D] (pr <expr>)))~ so the cljs return value is itself bounded. JVM wrapper reads ~:results[0]~ (per-call, never accumulated) and ~clojure.edn/read-string~ unwraps shadow's outer pr-str. Side-effect tools (track, untrack) return their map literal directly; ~edn/read-string~ handles both paths uniformly.
