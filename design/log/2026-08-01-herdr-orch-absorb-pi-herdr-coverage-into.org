* Intent

Own the Herdr control surface first-party instead of depending on a floating upstream pi extension, and rename the skill and CLI so the name matches what they actually do: orchestrate terminal topology *and* delegation.

* Summary

*Level:* Standard · *Tests:* bb suite 419 tests / 2276 assertions, plus a fresh-pi-session tool verification · *Docs:* SKILL, contract, README, AGENTS · *Commits:* 0b21b89, 945638f, 361b1ea, 630eabd, 2ee159a

Herdr control is now first-party: =herdr.clj= covers all 27 operations the npm extension exposed, the =oh= CLI presents them object-namespaced alongside delegation, a thin proxy extension keeps pi tool discoverability without delegation leaking onto the tool surface, and the skill and binary are renamed to match the broadened charter.

** Scope

*** In scope

- Complete =herdr.clj= to the 27 operations pi-herdr exposes: 16 are missing (=workspace list/create/focus=, =tab list/focus=, =pane list/current/read/run/send-text/send-keys/wait-output=, =agent read/send-keys/focus/rename=). Note the current 11 are not a strict subset either way -- =pane rename= exists here and not in pi-herdr.
- Port the *behaviours*, not just the plumbing: the self-close guard (refuse to close the pane the caller runs in), output truncation on read/wait-output, human-readable pane/agent list summaries, herdr error-envelope mapping, and lifecycle =until= semantics on agent wait.
- Object-namespaced CLI verbs: =oh pane|tab|ws|agent <op>= for mechanics, =oh task <op>= for delegation, plus =oh spawn "<command>"= as sugar for the unambiguous infrastructure case (create tab, run, report the pane).
- A thin first-party pi extension exposing =herdr_layout=/=herdr_pane=/=herdr_agent= as passthroughs to =oh=, with all logic remaining in Babashka.
- Remove =npm:@ogulcancelik/pi-herdr= from =pi/settings.json=.
- Rename: skill directory =herdr-subagents= → =herdr-orch=, launcher =subagent= → =oh=, env prefix =HERDR_SUBAGENT_*= → =HERDR_ORCH_*=, ledger/result directory =.agents/tmp/herdr-subagents/= → =.agents/tmp/herdr-orch/=, and every reference across docs, tests, personas and =AGENTS.md=.

*** Out of scope

- Backward compatibility. This is dev-only infrastructure with no external consumers, so no shim, alias or deprecation window is provided -- in-flight children are drained instead (see =** Risks=).
- The rest of the herdr CLI beyond pi-herdr's surface: =worktree=, =session=, =notification=, =config=, =channel=, and =pane zoom|swap|move|resize|neighbor|edges|process-info=. Add on demand.
- =pi/extensions/herdr-agent-state.ts=. A different concern (reporting pi lifecycle *into* Herdr), regenerated by Herdr, and owned by task =a6be7668=.
- Renaming =.agents/subagents/= persona directories -- see the decision below.
- Delegation as a discoverable tool. Deliberately excluded; see the decision below.

** Decisions

- Absorb into the bb CLI rather than dropping to the raw herdr CLI or adding a third skill layer :: the raw CLI loses the enforced self-close guard, argument validation and tool discoverability, trading a three-line upstream defect for a permanent capability loss; a =herdr-wm= skill on top would add a fourth layer while being unable to fix a tool that throws. Absorbing is cheap because =herdr.clj= is already the harness-agnostic mechanical layer at 98 lines and already covers 11 of 27 operations.
- Object-namespaced verbs; do *not* unify delegation under =spawn= :: =spawn "bb nrepl-server"= succeeds when a process is running, while delegating succeeds only when a validated RESULT envelope exists with ledger entry, persona/model resolution, allow-list, depth bound and closure rules. Same verb, incompatible post-conditions. Worse, the single most damaging finding of the advisor evaluation was a worker hand-rolling =herdr agent start= instead of =subagent run advisor=, which defeated tier selection, hid $1.6883 from the ledger and orphaned a pane; a surface where =spawn --kind pi= and =spawn <persona>= differ by a flag turns that category error into a typo. Rejected: unifying under =spawn=; a mandatory disambiguating mode flag (a dispatcher with a required argument is worse than two verbs).
- =oh= as the binary, =herdr-orch= as the skill :: =herdr-wm= under-describes the load-bearing half -- skill loading is driven by the =description:= frontmatter, so \"window manager\" would mis-route discovery away from the part owning the envelope contract and the ledger. =oh= is free on PATH with no alias and matches the local two-character convention (=bb=, =pi=, =rg=, =fd=, =gh=, =jj=). Rejected: =ho= (derogatory English slang, and this repository is public); =hd= (taken by hexdump); =hwm= (pairs with the under-describing skill name). Residual: a niche Unix shell is also called =oh=, which would surface immediately if ever installed.
- Keep =.agents/subagents/= unrenamed :: those directories name their *contents* -- subagent personas -- not the owning skill, and a persona is still a subagent persona. =~/.agents/subagents/= is also deliberately unmanaged and user-owned, so renaming it would silently orphan user files. Verified safe: =core/persona-directories= builds the two override tiers as skill-independent literals, and the packaged tier derives script-relative from =skill-directory=, so the rename relocates packaged personas with zero code change.
- Delegation stays off the tool surface :: needing to load the skill to learn the contract is a useful gate. A discoverable =oh task run= tool would let an agent delegate without reading the envelope, ledger and closure rules -- the documented route to uncaptured children and orphaned panes.
- Supersede rather than wait on the upstream fix :: task =34683f68= reports the pi-herdr defect upstream. First-party coverage fixes it by construction (exit-code semantics in bb), so this work does not depend on upstream latency. The report is still worth sending as a courtesy; close =34683f68= as superseded-for-our-purposes once the proxy lands.

** Gotchas

- *CLI options are a multimap.* A flag arrives as a vector, so a =select-keys= slice passed to a wrapper yields a literal argv value like =["6"]=. This bit three separate call sites (=pane read=, =agent read=, =pane wait-output=); use =one= at every boundary.
- *Herdr does not always answer in JSON.* Argument errors come back as plain text and the read family returns raw terminal buffers, so neither stdout nor stderr may be decoded unconditionally. An unguarded decode replaces the actionable message with a Jackson token error, which is strictly worse than no parsing at all.
- *The test fixtures emit JSON for every subcommand*, so none of the above is reproducible in the suite. Operations that pass text through need live exercise, which is why the proxy verification ran as a fresh-session agent rather than a unit test.
- *=~/.pi/agent/{settings.json,extensions}= resolve through the nix store to the live repo.* Extension changes therefore need no Home Manager rebuild, but they take effect for *every new pi process* immediately -- including subagents spawned moments later.
- *Renaming the launcher strands children.* =$HERDR_ORCH_BIN= is embedded in composed prompt text and injected env, so a child in flight across a rename keeps a path that no longer exists and cannot publish. Any future rename is root-session work with nothing in flight, the executor included.

** Risks

- Taking first-party ownership means Herdr CLI changes become our breakage rather than upstream's. Accepted: =herdr.clj= already carried that exposure for 11 operations, so the increment is modest, and the alternative is a dependency that silently misreports success.
- A passthrough extension can drift from the CLI it wraps. Mitigated by keeping it literal -- schema, dispatch and error surfacing only -- so drift can only present as a missing action rather than divergent behaviour.

* Implementation

** Landed

Coverage, verbs, rename, proxy and verification landed as five commits. `herdr.clj` grew from 11 to the full 27 Herdr operations with the self-close guard, bounded reads, visible-source fallback and error mapping ported rather than re-plumbed. The CLI is object-namespaced (`oh pane|tab|ws|agent`, `oh task` for delegation, `oh spawn` for infrastructure), the skill and binary are renamed, and `pi/extensions/herdr-orch` replaces the npm extension.

** Defects found and fixed during execution

Three CLI-layer defects surfaced only under live use, because the test fixtures emit JSON for every subcommand and so could not reproduce them:

- `--lines` and `--timeout` reached Herdr as stringified arrays. The CLI stores options as a multimap, and passing a `select-keys` slice straight through produced literal argv values like `["6"]`. Fixed at all three call sites; no `select-keys opts` slices remain.
- Herdr reports argument errors as plain text rather than a JSON envelope, and the error path decoded stderr unconditionally, so a Jackson parse failure replaced the actionable message with a token error. `decode` is now tolerant.
- Success stdout was decoded unconditionally too, which fails on the raw terminal text the read family returns.

The `--timeout` instance was found by the verification agent *after* the `--lines` fix, which is the more useful lesson: the first fix addressed an instance rather than the class, and only exercising a second code path exposed the rest.

** Verification

`bb test` 419 tests / 2276 assertions green. A fresh pi session loading the new extension confirmed the three previously broken paths (`run`, `send_text`, `send_keys`) now report success *and* execute, the self-close guard refuses, and no delegation tool is reachable. Live delegation completes end to end under the renamed binary, and `oh spawn "bb nrepl-server"` surfaces `Address already in use` rather than hiding it -- the original symptom that motivated the whole change.
