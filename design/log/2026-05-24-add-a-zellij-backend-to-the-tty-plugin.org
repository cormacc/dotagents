* Summary

Extend `pi/extensions/tty` from tmux-only to a backend-selected tty layer. `/t`, `tty:*` events, `tty_list`, and `tty_capture` stay backend-neutral; runtime dispatch detects tmux vs zellij from the environment and routes to the matching backend.

** Decisions
- Keep tmux implementation first-class and simple: wrap the existing tmux code behind an adapter with minimal behavioural change, rather than forcing tmux through zellij-shaped abstractions.
- Implement the same `/t` behaviour for tmux and zellij where both have native primitives: `spawn`, `watch`, `kill`, `list`, `tail`, plus `tty_list` / `tty_capture`.
- `/t join`, `/t monitor`, `/t break` remain tmux-only and keep the existing tmux semantics. On zellij they return "Join implemented only for tmux backend" (and equivalent for monitor/break). No zellij feasibility spike.
- Detection order: tmux when `$TMUX` is set, otherwise zellij when `ZELLIJ` or `ZELLIJ_PANE_ID` is defined (presence, not value). Nested multiplexers are unsupported; selected backend is reported in `tty_list` and errors.
- Backend-specific command execution stays backend-specific: tmux keeps its known-working shell-string path; zellij uses `sh -lc <command>` after `zellij action ... --` to preserve `/t spawn <shell line>` quoting semantics.
- Zellij `/t spawn` = `zellij action new-tab` (tmux `new-window` analogue). Zellij `/t watch` = `zellij action new-pane --direction down --near-current-pane` with `--close-on-exit` so the second Ctrl-C closes the pane.
- Zellij `tty_capture` dumps full scrollback via `zellij action dump-screen` and truncates to `lines` in-process.
- Public ids stay backend-native in tool output (`%1`/`@1` for tmux, `terminal_1`/`plugin_2` for zellij); tool docs retain explicit tmux examples.

* Context

`pi/extensions/tty/index.ts` currently hardcodes tmux for context discovery, listing, target resolution, spawn, capture, join, monitor, break, and kill. Live zellij 0.44.3 exposes the primitives we need (`list-panes`/`list-tabs --json`, `new-pane`, `new-tab`, `dump-screen`, `close-pane`, `write`) but no CLI for moving a live pane between tabs, which is why join/monitor/break are scoped tmux-only rather than emulated.

Acceptance criteria:
- `getContext` reads `ZELLIJ_PANE_ID` from the env and `zellij action list-panes --json` to identify the current pane (session name is not a reliable env var; derive it from the panes listing if needed).
- `listPanes` parses `zellij action list-panes --all --json`; non-selectable plugin panes are excluded or clearly marked.
- `spawn` uses `zellij action new-tab --cwd … --name … -- sh -lc <cmd>`; zellij switches focus to the new tab by default (same as tmux `new-window`); records tab/pane identity to list and later kill spawned tabs. Consider `--close-on-exit` later if orphaned tabs accumulate.
- `watch` uses `zellij action new-pane --direction down --near-current-pane --cwd … --name … -- sh -lc <wrapper>` with the existing Node watch wrapper (no `--close-on-exit` — the wrapper stays alive via `setInterval` until the second Ctrl-C, then exits and the pane closes naturally); focus returns to pi after watch.
- `capture` uses `zellij action dump-screen --pane-id <id> --full` (with `-a` for `preserveEscapes`), then truncates to the requested line count in-process.
- `kill` sends two Ctrl-C bytes via `zellij action write --pane-id <id> 3`, then closes the recorded pane or tab (`close-pane` / `close-tab-by-id` as appropriate); missing-target errors are tolerated.
- No-arg zellij `/t kill` policy is explicit and does not affect tmux: target the latest watched pane if known, otherwise return a target-required message.
