* Summary

Shipped a backend-neutral TTY pi extension at `pi/extensions/tty/` with `/t` as the grouped slash command. The current backend is tmux; naming and user-facing docs leave room for a future zellij backend. The extension supports spawning sibling windows, watching long-running processes, visually joining/monitoring windows below the pi pane, breaking them back out, killing active monitors/target windows, listing windows, and capturing pane output through agent tools.

** Decisions
- User-facing command is `/t <subcommand>` rather than the original `/tmux`; long and short subcommands are both supported (`w|watch`, `s|spawn`, `j|join`, `m|monitor`, `k|kill`, `b|break`, `l|list`, `t|tail`).
- Agent tools are backend-neutral: `tty_list` and `tty_capture`.
- `/t watch` creates a tmux window, runs a Node-based watch wrapper, joins the window below pi, and keeps focus in the pi pane.
- `/t monitor` is join-with-focus-preserved for existing single-pane target windows.
- `/t kill` with no argument targets the currently joined/monitored pane; `/t kill <numeric>` treats numeric targets as window indices.
- Join/break state remains in-memory keyed by the pi pane id; explicit pane ids remain the recovery path after reload/restart.

** Shipped
- Extension: `pi/extensions/tty/{index.ts,helpers.ts,index.test.ts,test.sh,README.md}`.
- Skill: `pi/skills/pi-tty/SKILL.md`, registered via `resources_discover`.
- Slash command: `/t` dispatching through `tty:*` events.
- Tools: `tty_list`, `tty_capture`.
- Tests and docs updated for short aliases and the tmux-backed tty naming.

** Gotchas
- `tmux new-window` switches focus to the new window. Any follow-up join/monitor operation must carry the saved pi pane context from before spawning.
- Cleanup after Ctrl-C can race with pane/window disappearance; kill cleanup ignores tmux “can't find pane/window” errors while preserving real failures.
- The watch wrapper was implemented as a Node one-liner rather than the original shell-trap sketch because non-interactive shell traps closed panes too early in smoke testing.

* Implementation

- Renamed the originally planned tmux extension to backend-neutral `tty`: `pi/extensions/tty` and `pi/skills/pi-tty`.
- Registered `/t` with short and long subcommands; command parsing expands aliases before dispatch.
- Replaced `tmux:*` events with `tty:*` events while retaining tmux backend helpers internally.
- Renamed agent tools to `tty_list` and `tty_capture`.
- `spawnWindow` records `pane_id`, `window_id`, `window_index`, window name, command, kind, creation timestamp, and owner pi pane id.
- Watch wrapper uses Node to spawn the child command, forward the first SIGINT, print status, and exit on the second SIGINT.
- `joinPane` accepts an optional saved pi context so `/t watch` can safely create a tmux window (which shifts focus) and then join it under the original pi pane.
- `breakPane` also accepts an optional saved pi context so replacing an existing monitor uses the correct owner pane even after focus changes.
- `killPane` sends two Ctrl-C signals, then removes either the active monitor pane or an explicit target window; missing-pane/window cleanup errors are ignored as successful cleanup races.
