** Decisions
- Repair Pi -> oh -> Herdr :: Both adapter layers drop options. Keep one local CLI authority; reject a direct Pi-to-Herdr bypass.
- Prompt waiting :: Reject wait-only options when waiting is disabled; do not silently discard them or enable waiting. Omitted timeout means indefinite for =oh agent prompt --wait=, matching the Pi prompt schema and Herdr. Leave the separate =oh agent wait= default of 600000 ms unchanged; document the distinction.
- Herdr >=0.9.1 client and server :: Explicit user choice supersedes the initial 0.8.2 constraint. Read the existing =herdr status --json= envelope; reject an old or unknown endpoint rather than adding capability probes or legacy fallbacks.
- Upstream owns agent kinds :: Validate nonblank input locally; installed Herdr determines actual support. This does not make arbitrary unmanaged harnesses supported.
- Extend the existing =close --abandon= :: The new no-publication path accepts identity-checked =idle=/=done= observations or proof that the child process stopped. Refuse =blocked=, =working=, =unknown= or unusable observations. A blocked child requires the operator to dismiss its dialog or stop the child manually, then retry after a permitted state is proved; abandonment itself sends no input or signal. Preserve existing captured abandonment behaviour. Reject force-prune, fabricated invalid capture and poke-then-collect recovery.
- Lock retirement against publication :: Reuse the existing per-child lock; re-read ownership, newest round, closure state and stream contents before committing abandonment. If an item exists, require collection rather than discarding it. Ordinary close remains capture-gated.
- Separate retirement from process termination :: Retain TASK/ledger/artifact files, report the pane as operator-owned, and leave checkout removal explicit. A released agent name alone is not proof that the child process stopped; preserve identity/shell-PID checks and fail closed on unusable observations.
- Managed files stay upstream-owned :: Refresh =pi/extensions/herdr-agent-state.ts= verbatim from a recorded revision; use external tests, not local hooks in that file. Refresh the vendored skill using the repository's documented installer; record licence location in =skills/README.org= without modifying its upstream body.
- Native prompt events are follow-up work :: The reviewed upstream integration still uses =herdr:blocked=. Draft an upstream proposal for Herdr to adopt Pi's existing =ui_prompt_start=/=ui_prompt_end= events and clean up its listeners, without making local delivery depend on upstream acceptance.
- Preserve configured model choices :: Replace obsolete migration-era expectations, not the configuration. Keep independent expected values in tests; correct the claim that tests automatically verify the documentation table unless such coverage is actually added.

** Risks
- A Pi-only test can conceal dropped oh flags :: Check the final Herdr argv as well as the Pi proxy output.
- Ledger closure releases worktree liveness guards :: The new path refuses blocked/working/unknown children; regression checks cover checkout ownership before retirement and prohibit checkout removal as a retirement side effect.
- Publication can arrive during recovery :: Exercise both lock orderings; preserve the winning publication and refuse late publication after a committed retirement.
- Upstream refresh is not complete lifecycle repair :: Native prompt-event adoption and listener disposal remain separate; the managed refresh must not claim these gaps are fixed.
- The runtime may be below the new floor :: Verify client and server versions before controlled live smoke. Upgrade requires the runtime owner's action, not a planning-side install.
- Concurrent work touches nearby files :: Re-read before editing; preserve unrelated changes and historical records. In the README review footer, only date-qualify the old minimum-version sentence as specified by the version-floor task; preserve the review table and execution limits.

** Gotchas
- A pane lookup that fails proves nothing about the pane. Only Herdr's =pane_not_found= code is positive evidence of absence, so a =catch=-all around =herdr pane get= silently converts an unreachable server into "the pane is gone" -- fail-open in any path about to mutate the ledger. =pane-alive?='s two other callers still conflate the two; they were out of scope here.
- A =.test.ts= at the =pi/extensions/= root is auto-loaded as an extension, so a top-level extension's tests belong in =pi/extensions/test/= and are run from a sibling extension's =test.sh=.
