* Summary
Add =tasks_scan_summaries= to the tasks extension so an agent drafting
a plan can mechanically discover prior art \u2014 walk every task in
=TASKS.org= + =TASKS.archive.org= (and their =#+IMPORT:= chains),
return a flat list of =[{ task header, * Summary body | absent }]=
records, and let the agent relevance-filter before pulling any full
change-records into prompt context. The =org-plan= skill's
*Planning principles* recommends checking prior art before drafting;
today that's a manual =rg= + filename-scan + N =Read= dance. This
tool collapses it to one call atop the existing =loadTasks= +
=readSection= primitives.

** Decisions
- Use case is prior-art discovery, not resume :: the original
  =tasks_resume_brief= framing conflated "resume an in-progress task"
  (where you want the full plan + Implementation, just =Read= the
  change-record) with "scan many tasks looking for related prior art"
  (where you want =* Summary= only from each). The latter is the real
  consumer for a structured tool; the former needs no convenience
  layer. =tasks_resume_brief= cancelled accordingly \u2014 see the
  rewritten TASKS.org task heading.
- No duplication into =TASKS.archive.org= :: =* Summary= lives in
  change-records exclusively. Mirroring summaries into the archive at
  archive-time was considered and rejected: it introduces drift
  (closure-time refresh updates change-records, not the archive copy),
  bloats =TASKS.archive.org= without bound, and saves zero tokens for
  the agent (the scanner returns the same chars as a tool result
  regardless of which file the I/O happens against). Walking N small
  change-record files on demand is sub-second on a modern SSD.
- Surface :: pure helper =scanSummaries()= in
  =pi/extensions/tasks/scan.ts= wrapped by an MCP tool registered
  from =index.ts=. Same =insert.ts= / =section.ts= / =readSection=
  pattern: helper imported directly by cross-extension JS callers,
  tool registry is for LLM dispatch only. =readSection= is invoked
  in-process; no registry round-trip.
- Result shape :: flat array of =ScanRow= objects, one per scanned
  task:
  #+BEGIN_SRC ts
  type ScanRow = {
    id: string;
    summary: string;          // task heading text
    status: string;           // TODO / STARTED / DONE / CANCELLED / WAITING
    priority: string | null;  // 'A' | 'B' | 'C' | 'D' | null
    tags: string[];
    sourcePath: string;       // TASKS.org | TASKS.archive.org | imported file
    importPath: string | null;
    recordSummary:            // discriminated; mirrors org_read_section
      | { found: true; body: string }
      | { found: false }
      | null;                 // null = task has no #+IMPORT: at all
    hasContext: boolean;      // true when change-record has a `* Context`
                              // heading; agent fetches the body via
                              // org_read_section if relevance scoring
                              // says it's worth pulling in.
  };
  #+END_SRC
  Flat (not nested) because the consumer is a relevance-scoring
  loop, not a presentation-layer renderer; flat keys are easier to
  filter on. The =recordSummary= null case is distinct from the
  =found: false= case so the agent can choose whether to consider
  un-planned tasks at all.
- Scope and filters :: =scope?: "active" | "archived" | "all"= selects
  which top-level files contribute tasks; default =all=. =tags?:
  string[]= optional whitelist (a task is included if it carries any
  listed tag). No status filter \u2014 the agent applies that post-hoc
  from the structured rows; including =STARTED= tasks is valuable
  prior-art for "what's happening right now in this area".
- Subtasks are included :: the walker descends into =task.children=
  and =task.importChildren= so plan-task headings inside change-records
  are scannable too. Each row's =sourcePath= identifies whether it
  came from the top-level task index, an imported change-record's
  =* Plan=, or elsewhere.
- Token budget :: typical row size is ~1KB (heading + a short
  =* Summary= body, capped at the first ~500 chars when the actual
  Summary is longer). Even at 200 archived tasks that's ~200KB =
  ~50K tokens for the full scan \u2014 well within budget for a one-shot
  prior-art tool call whose result is discarded after filtering.
  A =maxBodyChars?: number= parameter (default 500) lets the caller
  bound this precisely.
- =* Context= not inlined :: =scanSummaries= does not include
  =* Context= body in the result. Surfaces a boolean =hasContext=
  flag instead; the agent fetches the body via =org_read_section=
  when relevance scoring says a row is worth pulling further into
  context. Rationale: =* Context= is promoted only when durable
  rationale exceeds what =* Summary= can carry, so when it exists
  it tends to be long; bulk-inlining defeats the prior-art scanner's
  whole point (cheap surface, agent decides what to deepen). The
  =* Open questions= section gets the same treatment by omission
  — if a follow-up reveals scan consumers want OPEN headings too,
  add =openCount: number= or =openHeadings: string[]= as a sibling
  signal then.
- Out-of-root and unreadable change-records :: silently surface as
  =recordSummary: { found: false }=. =org-tasks=' existing
  =loadLinkedPlans= already swallows these errors; replicating the
  same behaviour keeps the scanner robust against half-moved or
  pruned design-log files. Diagnostics live in =/tasks doctor=, not
  here.
- Ordering :: rows are returned in the order =loadTasks= already
  produces (file-position order across =TASKS.org=,
  =TASKS.archive.org=, and walked imports). Predictable; agents that
  want chronological or relevance ordering re-sort the rows
  themselves.

** Gotchas
- =* Context= body is intentionally absent from =ScanRow=. Agents
  evaluating a row's prior-art relevance use =recordSummary.body= +
  =hasContext: true= to decide whether to call
  =org_read_section({ section: "Context" })=. Bulk-inlining
  =* Context= would defeat the scanner's token-budget design.
- =loadArchivedTasks= is *separate* from =loadTasks= rather than
  bolted on. The UI overlay's =loadTasks= path intentionally does not
  include archived tasks (the overlay shows only live work); making
  it conditional would have leaked the scanner's concern into UI
  loading. The cost of two parser passes is negligible — tens of
  microseconds for typical archives.
- =prepareReadChangeRecord= caches by *resolved absolute path*, not
  by =Task= object identity — so two distinct tasks pointing at the
  same change-record file share one read. Per-task caching would
  have read duplicate files in the rare case of plan-task children
  whose parents share a record.
- Tasks emitted by the walker include both top-level workstream
  roots *and* plan-task children inside change-records. The agent
  filtering rows for prior art should typically prefer rows where
  =importPath !== null= (workstream roots) or filter by =status=,
  rather than including every nested =** TODO Step= as its own
  candidate. README documents the ordering and the recommended
  filter style; the helper does not pre-filter because callers may
  legitimately want nested rows (e.g. a doctor-like "find every
  STARTED plan task across the project" view).
- The =\u2026= truncation sentinel is one UTF-8 character (3 bytes,
  1 code point). Callers concerned about byte-level budgets should
  treat =maxBodyChars= as a code-point cap, not a byte cap.

* Implementation
- =scanSummaries= is a single-pass depth-first walker over
  =task.children= + =task.importChildren=. Tasks without =:CUSTOM_ID:=
  are skipped early; tag-filter check fires before the (potentially
  expensive) =readChangeRecord= call to avoid unneeded reads for
  filtered-out rows.
- Helper kept fs-free for testability: all I/O lives in =index.ts='s
  =prepareReadChangeRecord= which walks the same task trees once
  asynchronously, resolves each =importPath= via =resolveProjectPath=
  (sandboxed under =ctx.cwd=), reads each unique resolved file once,
  and returns a sync =readChangeRecord= closure for the helper.
- =hasContext= detection uses a second =readSection(content,
  "Context")= call rather than a regex. Slightly redundant compared
  to a single-pass parser, but the consistency win (=readSection='s
  case-insensitive + trailing-tag rules apply identically to both
  Summary and Context) outweighs the few microseconds. Future
  optimisation: a =readSections(content, names[])= primitive that
  returns multiple sections from one pass. Not worth doing until a
  real workload demands it.
- =loadArchivedTasks= mirrors =loadTasks='s structure but reads
  =TASKS.archive.org= and walks its imports. Missing-file is silent
  (returns =[]=) so the tool works on new projects with no archive
  yet.
- Two test-expectation off-by-one slips during the first test pass
  (trailing newlines on slices between =* = headings). Same pattern
  as the section-reader work; corrected the tests, not the helper.
- Manual smoke against the live project via =.agents/tmp/scan-smoke.ts=:
  68 total rows (11 active TASKS.org + 57 archive), 25 with a found
  =* Summary=, 8 with =hasContext=, 43 with no =#+IMPORT:=. The
  =hasContext= signal is rare in practice (8/25 ≈ 32% of records with
  Summary also have Context), confirming the org-plan skill's
  "promote only when needed" guidance is actually followed.
