* Summary

`ot` now persists mutations for tasks inside `#+IMPORT:`-linked plan/change-record files. The loader tags parsed top-level tasks with `:file-root?`, `save-source-roots` walks the full graph (`:children` and `:import-children`) and serializes each affected source file from its own file roots, and parent auto-promotion crosses import boundaries. ID mutators (`status`, `handoff`, `blocker`, `issue`, `ready`, `backfill`) work against imported plan subtasks and write to the owning plan file.

** Shipped

- `parser/parse-tasks` marks source-file roots with `:file-root?`.
- `loader/save-source-roots` groups reachable file roots by `:source-path`, including imported plans.
- `commands/find-path-to-id` and backfill/update walkers traverse `:import-children`.
- `doctor` warns with `import-child-not-saveable` if imported tasks are reachable but their source file has no saveable file root.
- Contract and skill docs now state that ID mutators support linked plan-file tasks.
- Integration coverage exercises linked-plan `status` STARTED/DONE/reopen, `handoff`, `blocker`, `issue`, `ready`, `backfill`, parent promotion, and fixture round-tripping.

** Gotchas

- Imported plan tasks are not top-level TASKS.org tasks; archive/publish/unpublish still intentionally target top-level task roots only.
- `:file-root?` is loader/parser metadata, not org syntax. If future graph transforms drop it from imported roots, `doctor` should catch the persistence regression.
