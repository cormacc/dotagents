* Summary

Qwen models served by Lemonade need Pi's ~qwen-chat-template~ OpenAI compat
path, not Pi's default reasoning wire format. The extension now detects Qwen by
id/name, forces ~reasoning: true~, sets
~compat.thinkingFormat: "qwen-chat-template"~ plus
~requiresReasoningContentOnAssistantMessages: true~, and exposes only the
thinking states Lemonade actually honors: off/high.

The task also fixed two issues found during live validation: model-load requests
now set Lemonade's runtime ~ctx_size~ from model metadata (with health metadata
as a fallback), and raw JSON error blobs wrapped in HTTP 200
~text/event-stream~ responses are surfaced as actionable errors instead of Pi's
opaque "Stream ended without finish_reason".

** Decisions

- Match Qwen by id/name, not Lemonade's ~labels: ["reasoning"]~; several Qwen
  models that need the workaround are not labeled as reasoning models.
- Use ~thinkingFormat: "qwen-chat-template"~. Pi's plain ~"qwen"~ path emits a
  top-level ~enable_thinking~ field that Lemonade ignores; the chat-template path
  emits ~chat_template_kwargs.enable_thinking~ and ~preserve_thinking: true~.
- Force ~reasoning: true~ for Qwen so Pi takes the qwen-chat-template branch.
- Keep the UX trade-off: non-thinking Qwen variants may show a thinking toggle,
  but Lemonade ignores unsupported ~chat_template_kwargs~ and still responds.
- Register ~/api/v1/models[].max_context_window~ as the provider context window
  and pass it as ~ctx_size~ on ~/api/v1/load~ for context-size recipes. If model
  metadata lacks a max window, fall back to loaded health ~ctx_size~ and then the
  conservative default.

** Gotchas

- ~requiresReasoningContentOnAssistantMessages~ is needed because localhost
  Lemonade URLs do not trigger Pi's URL-based Qwen compatibility defaults.
- A compatible Pi build must include ~"qwen-chat-template"~ in
  ~OpenAICompletionsCompat.thinkingFormat~; verified in pi-ai 0.75.5.
- Lemonade 10.6.0 can return context-overflow failures as HTTP 200
  ~text/event-stream~ with a raw JSON body. The extension normalizes those to a
  ~context_length_exceeded:~ error including ~n_prompt_tokens~ and ~n_ctx~.
- Live manual validation exercised the llama.cpp recipe only; ONNX-Runtime-GenAI
  / FLM recipes remain untested.

* Implementation

- Upstream Pi check:
  - ~qwen-chat-template~ emits
    ~chat_template_kwargs: { enable_thinking, preserve_thinking: true }~ gated
    on ~model.reasoning~.
  - plain ~qwen~ emits top-level ~enable_thinking~.
  - ~requiresReasoningContentOnAssistantMessages~ backfills
    ~reasoning_content: ""~ on assistant turns that lack it.
  - Per-model compat merges over URL-detected defaults.
- ~mapToProviderModel~ now:
  - identifies Qwen by case-insensitive id/name match;
  - forces ~reasoning: true~ for Qwen;
  - installs qwen-chat-template compat and collapses intermediate thinking
    levels;
  - reports context window from model max metadata, loaded health metadata, or
    the conservative fallback, in that order used by the shipped code.
- ~registerLemonadeProvider~ fetches ~/api/v1/models~ and ~/api/v1/health~ and
  builds the provider model list from both.
- ~ensureRequestModelLoadedWithMaxContext~ sends ~/api/v1/load~ with ~ctx_size~
  for recipes that support runtime context sizing.
- The Lemonade error wrapper is intentionally narrow: only tracked Lemonade
  ~/v1/chat/completions~ URLs are inspected, and normal SSE streams pass through
  unchanged.
- Scratch research was moved under ~lemonade-pi-plugin/.agents/tmp/~.
