* Intent
Identify useful task-board and Herdr integration patterns in tsk without replacing Org task memory or installing another task store.

* Summary
*Level:* prototype · *Tests:* smoke · *Docs:* inline

Read-only review complete at upstream revision ~8d714a201280318f92ed42d26d20bf233a1f5baf~. Keep Org as the task source of truth. The useful plugin precedent is a workspace-scoped, reusable task-board pane, not a demonstrated parent/child session-tree implementation. Adoption remains a separate product decision.

** Decisions
- Retain the existing Org model :: ~STARTED~ status and one local selected-task pointer are separate concepts in org-tasks; a second database is not needed to represent several in-progress tasks. Rejected:
  - Adopt tsk wholesale: its documented shared JSON store and distinct workflow states would introduce competing task ownership.
  - Copy dispatch: tsk couples task start to worktree/workspace creation and a pull-request workflow, whereas herdr-orch has its own explicit delegation and publication contract.
- Consider workspace-scoped pane reuse in the existing plugin task :: tsk's launcher lists panes only in the invoking workspace, uses a stable pane label, focuses the existing tab before the pane, and targets the invoking pane when creating a board. Those are useful interaction constraints, not a reason to lower herdr-orch's required Herdr version.
- Defer bulk actions and undo :: tsk documents marked-set status changes, assignment and undo. Org lifecycle writes and cross-file tasks need an explicit transaction/undo design before copying that interaction.

* Plan

* Implementation
- Upstream [[https://github.com/smarzban/tsk/blob/8d714a201280318f92ed42d26d20bf233a1f5baf/herdr-plugin.toml][plugin manifest]] declares a board pane and explicit board/capture actions. [[https://github.com/smarzban/tsk/blob/8d714a201280318f92ed42d26d20bf233a1f5baf/scripts/open-board.sh][Board launcher]] scopes discovery to one workspace and preserves the invoking pane as the split target. [[https://github.com/smarzban/tsk/blob/8d714a201280318f92ed42d26d20bf233a1f5baf/src/board_pane.rs][Pane matching]] uses the pane label rather than the terminal title.
- [[https://github.com/smarzban/tsk/blob/8d714a201280318f92ed42d26d20bf233a1f5baf/site/src/content/docs/docs/storage.md][Storage documentation]] specifies one shared ~tsk.json~ store, agent profiles and per-project dispatch settings. [[https://github.com/smarzban/tsk/blob/8d714a201280318f92ed42d26d20bf233a1f5baf/site/src/content/docs/docs/dispatch.md][Dispatch documentation]] describes review handoff, launch rollback and guarded cleanup. These are documented upstream behaviours, not runtime checks performed here.
- [[https://github.com/smarzban/tsk/blob/8d714a201280318f92ed42d26d20bf233a1f5baf/src/ui/selection.rs][Selection implementation]] preserves a task's stable ID across reordered views and chooses the nearest surviving prior neighbour when a row disappears. This is a useful test oracle if the local task browser changes its filtering or sorting.
