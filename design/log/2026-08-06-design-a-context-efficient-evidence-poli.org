* Intent

Define one evidence principle for factual and causal claims while giving parent-to-child premises and child-to-parent results mechanisms proportionate to their different costs. Preserve independent validation where consequences require it without making routine delegation duplicate the child's context in the parent.

* Summary

*Level:* production · *Tests:* smoke · *Docs:* full

Use explicit epistemic status when composing assignments, bounded evidence probes when consuming results, and independent review only at high-consequence trust boundaries. The initial 1--3 candidate probe-budget range is confirmed at 3 probes per load-bearing claim from a 5-session, 13-result parent-verification sample (see `* Implementation`).

** Decisions

- Use one principle with two directional mechanisms :: parent premises use measured/unverified labeling at assignment composition; child results use consequence-tiered probes at capture. Treating both directions as duplicate verification would impose cost where labeling is sufficient.
- Adopt three consequence classes :: Class A trusts a validated envelope, Class B uses an explicit small probe budget of up to 3 probes per load-bearing claim confirmed from the session sample (`* Implementation`), and Class C requires independent validation. Session-sample evidence confirmed, without revision, the three candidate examples: a scout account of subsystem behavior used only to choose an in-flight approach (Class A), a claim persisted to a task, record, spec, commit message, or user report (Class B), and a destructive action, feature closeout, or top-level lifecycle closure (Class C). Probe disagreement triggers escalation; persistence alone does not trigger full re-ingestion.
- Preserve identity checks outside the bounded claim policy :: the existing AGENTS.md CRITICAL requirement to verify symbols, functions, config options, module paths, variables, CLI flags, and API fields remains unconditional because an incorrect identifier makes the underlying probe or action invalid; attribution is not a substitute for checking those identities.
- Start with textual policy rather than protocol enforcement :: the current problem is broad and unbounded guidance, while no evidence yet shows that assignment labels need mechanical syntax or validation.
- Reject a persistent auditor :: the prior mandatory-advisor evaluation found no quality gain from routine review while adding cost and latency; an ephemeral reviewer already supplies independence when Class C warrants it.
  Rejected:
  - Self-verification only: cheap but not independent and insufficient when the parent adopts durable or high-consequence claims.
  - Routine ephemeral audit for Class B: moves context out of the parent but adds latency, cost, and another testimony layer without measured benefit.

* Implementation

** Evidence audit

The durable [[file:2026-08-06-design-a-context-efficient-evidence-poli/session-sample.md][5-session, 13-result sample]] found per-result verification ranging from 0--15 actions and 0--5 re-read files. One child claim was corrected and one pointer was refined; each disagreement required approximately 2-3 targeted claim probes depending on counting convention, with none exceeding 3. This supports an initial Class B budget of up to 3 probes per load-bearing claim without claiming a general future correction rate.

** Policy

The complete three-class result policy lives only in `skills/herdr-orch/SKILL.md` (247 body words; 251 with heading). `AGENTS.md` keeps identifier verification unconditional, while reviewer, worker, and retro guidance carry only their local premise or bounded-probe rules. The absorbed test-baseline and `ot doctor` incidents map to the reviewer baseline constraint and general factual/causal claim rule respectively.
