* Intent
Make `ot` and `oh` cheaper and more reliable for agents to read, by applying the AXI principles (https://axi.md) adapted to this repository's JSON contracts. Give skill authors one local reference for agent-facing CLI design.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* README

`ot` and `oh` return compact default listings with counts; full graph consumers explicitly request `--full`. `oh` has a bounded read-only home view, usage exit codes and selective hints. AXI is vendored unchanged as an on-demand reference behind local contract exceptions. Seven implementation tasks are complete. Routing defaults, fixtures and generated documentation are aligned in the separate routing commit; final integration remains open for Linux measurement checks.

** Scope
*** In scope
- `ot list --format json` default payload, count, and `--full` opt-in; the standalone TUI, pi `tasks` extension and Hermes dashboard backend opt in.
- Routine `oh task list` and `oh task status` (no UUID) default payload, status counts, and `--full` opt-in.
- `ot` text output: no ANSI styling when stdout is not a terminal.
- `oh` exit code 2 for argument errors, as `ot` already does.
- The unchanged upstream AXI skill vendored as on-demand reference material with its MIT licence and source revision; a short local exceptions guide in skill-creator links to it.
- A bounded, read-only, checkout- or caller-scoped `oh` home view.
- Selective contextual hints, separate from result data.
- Contract and skill docs named in `#+SPEC:`, updated in the same task as each behaviour change.
*** Out of scope
- TOON output (see Decisions and Open questions).
- `ot show`, `ot scan`, `ot selected`, `oh task collect`, and `oh task status <full-task-uuid>` payloads.
- Automatically triggering the upstream AXI skill for every CLI change; its absolute rules need local qualification.
- Moving `ot` error envelopes from stderr to stdout.
- Session hooks (AXI principle 7): the pi `tasks` and `herdr-orch` extensions already supply ambient context.

** Decisions
- Keep JSON as the machine format :: field selection gave the large byte reduction in the baseline; TOON token savings have not been measured here. The pi `tasks` extension, the Hermes backend, the `oh` envelopes, the tests, and the `jq` rule in `home/AGENTS.md` depend on JSON.
  Rejected:
  - TOON default: breaks the JSON contracts and has no parser in the toolchain; axi.md claims about 40% token saving over JSON, not measured here.
- Compact default with `--full` opt-in (AXI principles 2 and 3) :: an agent gets the small payload without knowing a flag; programs that need the full graph name it.
  Rejected:
  - Keep the full default and only change skill guidance: an agent that runs the bare command still reads the full payload.
  - A `--fields` selector: no consumer needs a partial set yet; add it when one does.
- Program consumers opt in within the same task as the default change :: the change is a contract break, and splitting it would leave a red suite between tasks.
- `oh task status <full-task-uuid>` stays full :: a direct lookup is the place where an agent wants detail.
- `ot` errors stay on stderr :: the pi harness captures both streams, and `pi/extensions/tasks/ot.ts` `runOtResult` already reads the stderr envelope. AXI principle 6 asks for stdout; the change has no measured benefit here.
- Vendor upstream AXI unchanged as on-demand reference material :: reviewed [[https://github.com/kunchenguid/axi/blob/a8a320cc426a5f136a797a5ad138b84cb88bd172/.agents/skills/axi/SKILL.md][upstream SKILL.md]] at `kunchenguid/axi` revision `a8a320cc426a5f136a797a5ad138b84cb88bd172`; the repository MIT licence permits redistribution with its copyright and notice. Keep provenance and licence beside the reference. The skill is one document, not bundled npm scaffolding.
- Keep a short local exceptions guide in skill-creator :: retain JSON contracts and existing error channels; do not generate workflow skills wholesale from a home view, require extra harness integrations, add transcript capture, or adopt a JavaScript SDK for these Babashka CLIs. Link the entry point from skill-creator and both CLI developer guides; load it for CLI design/review, not normal CLI use.
- Add a bounded read-only `oh` home view :: scope assignments to the current checkout or caller; show counts and concise discovery hints; missing context is explicit.
- Add selective contextual hints :: lists suggest detail lookups, truncation names the expansion command, argument errors include valid options or concise help, and pending delegation suggests collection. Omit hints for final results and self-contained confirmations. Hints do not prescribe extra workflow steps.
- Already conformant, no work :: `ot` exits 2 on unknown options; empty states are explicit (`ot issue list` prints `(no linked issues)`, `oh --format text` prints `none`); both CLIs have per-command `--help`; `oh` read verbs already omit the raw `text` blob unless `--raw` is given.

** Shipped

- MODIFIED :: `skills/herdr-orch/scripts/docs/contract.md` and `skills/herdr-orch/scripts/README.md`: compact/full listings, counts, usage errors, scoped home view and selective hints.

** Risks
- A script outside this repository parses `ot list --format json` and needs `tree` or `sources`: accepted; a missing key may fail silently in a permissive consumer. Inventory repository callers and update them together; document `--full` as the migration path.
- `System/console` under Babashka may not report a pipe as non-terminal on every JDK: the `ot` ANSI task verifies with a piped probe, not by reading the code.
- Repository graph consumers must request the detailed payload. The broad test run found the standalone TUI consumer in addition to pi and Hermes; it explicitly requests full output, and the entire org-tasks namespace set passes.

* Open questions
** DECIDED Should `oh` with no arguments show a routine task summary?
Yes: bounded, read-only and scoped to the current checkout or caller, with counts and concise discovery hints. Missing context is explicit.
** DECIDED Should commands append next-step hints?
Yes, selectively: use a separate structured field; omit hints for self-contained outputs and do not suggest collection after a final result.
** DECIDED Should we add `--format toon`?
Defer. First reduce fields, then compare actual token counts and task correctness for compact JSON, existing text output and TOON on identical data. The JSON-parsing rule is not a prohibition on TOON; AXI's overall benchmark does not isolate its contribution.
