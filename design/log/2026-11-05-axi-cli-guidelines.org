* Intent
Make `ot` and `oh` cheaper and more reliable for agents to read, by applying the AXI principles (https://axi.md) adapted to this repository's JSON contracts. Give skill authors one local reference for agent-facing CLI design.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* README

`ot` and `oh` return compact default listings with counts; full graph consumers explicitly request `--full`. `oh` has a bounded read-only home view, usage exit codes and selective hints. AXI is vendored unchanged as an on-demand reference behind local contract exceptions. The seven implementation tasks are complete and committed. Linux measurement validation is retained as a separate follow-up; closure does not claim a full Linux-suite pass.

** Scope
*** In scope
- `ot list --format json` default payload, count, and `--full` opt-in; the standalone TUI, pi `tasks` extension and Hermes dashboard backend opt in.
- Routine `oh task list` and `oh task status` (no UUID) default payload, status counts, and `--full` opt-in.
- `ot` text output: no ANSI styling when stdout is not a terminal.
- `oh` exit code 2 for argument errors, as `ot` already does.
- The unchanged upstream AXI skill vendored as on-demand reference material with its MIT licence and source revision; a short local exceptions guide in skill-creator links to it.
- A bounded, read-only, checkout- or caller-scoped `oh` home view.
- Selective contextual hints, separate from result data.
- Contract and skill docs named in `#+SPEC:`, updated in the same task as each behaviour change.
*** Out of scope
- TOON output (see Decisions and Open questions).
- `ot show`, `ot scan`, `ot selected`, `oh task collect`, and `oh task status <full-task-uuid>` payloads.
- Automatically triggering the upstream AXI skill for every CLI change; its absolute rules need local qualification.
- Moving `ot` error envelopes from stderr to stdout.
- Session hooks (AXI principle 7): the pi `tasks` and `herdr-orch` extensions already supply ambient context.

*** Anti-criteria
- [X] Must not: change `oh task status <full-task-uuid>` output; README worktree teardown reads the branch from it.
- [X] Must not: change the `ot list --format edn` and JSON parity rule: EDN gets the same compact default and `--full`.
- [X] Must not: add a dependency to `bb.edn`.

- [X] Must not: make the home view start agents, create panes, alter selection, or query unrelated workspaces.
- [X] Must not: suggest collection after a final `oh task run` result.

** Decisions
- Keep JSON machine contracts and reduce fields first. TOON remains an optional experiment requiring an actual token/correctness comparison; byte counts are not token evidence.
- Compact listings are the default; `--full` supplies the detailed graph. The standalone TUI, pi tasks and Hermes opt in explicitly. A compact opt-in alone would leave bare agent invocations returning the full payload.
- Preserve existing error channels, direct UUID detail lookups and workflow-skill ownership. Contextual hints are separate from result data and do not prescribe extra actions after a final result.
- Vendor the pinned AXI document unchanged with its MIT notice, behind an on-demand local exceptions guide rather than a broadly triggered standalone skill. Do not add hooks, transcript capture or JavaScript dependencies merely for upstream compliance.

** Gotchas
- Program consumers that require `tree` or `sources` must request `--full`; permissive consumers can otherwise fail silently. The in-process standalone TUI needs the same opt-in as external callers.

* Implementation
- Compact `ot` JSON/EDN listings and explicit full-graph consumers preserve detail workflows; automatic text styling requires an attached console and retains explicit TUI overrides.
- Compact `oh` listings use recorded fields without live probes. Its read-only home view limits output to ten records and 240-character summary previews; counts cover the selection before truncation. Usage errors exit 2, and domain failures exit 1.
- The pinned AXI document and licence are retained byte-for-byte. Local exceptions and developer-guide links keep the existing CLI contracts authoritative.
- [[file:2026-11-05-axi-cli-guidelines/catalog-review.md]] preserves the catalogue assessment. glab-axi and gh-axi remain proposed read-only pilots, not installed dependencies or approved routing replacements.
