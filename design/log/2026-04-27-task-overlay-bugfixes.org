* Summary
Three tasks-extension overlay bugs fixed: (1) compact widget not refreshing after selection toggle (race between async =save()= and the file watcher), (2) overlay cursor not landing on the selected task when it lived as a =planChild= under a DONE/CANCELLED parent (collapse logic incorrectly collapsed ancestors), (3) external file changes silently discarded by the live overlay because =refreshTaskUi= skipped it entirely. No new lifecycle hooks — module-level =isOverlayActive= flag, =activeOverlayInstance= ref, and a =TasksOverlay.refreshTasks()= method.

** Decisions
- No new lifecycle hooks :: reuse the same module-level pattern as =compactWidgetComponent=, =activeCtx=.
- In-memory-first widget sync :: after overlay close, sync from already-mutated task state; subsequent =refreshTaskUi= still reads disk to converge with external edits.
- Collapse-logic simplification :: removing the erroneous third condition makes the implementation match its own doc comment.

** Shipped
- =index.ts= :: =isOverlayActive= module flag suppresses =syncCompactWidget= during the overlay session; immediate in-memory widget sync after the overlay loop exits; =activeOverlayInstance= ref drives live-refresh.
- =overlay.ts= :: erroneous third condition removed from =applyDefaultCollapseView=; new =TUI= constructor param and =refreshTasks(newTasks)= public method that replaces task state, rebuilds rows, preserves cursor by task ID.

* Implementation

Commits: =4b04886= (original two fixes) and =2b7cffc= (live-update follow-up), both 2026-04-27.

Files:
- =pi/extensions/tasks/index.ts= — =isOverlayActive= flag, =activeOverlayInstance= ref, =refreshTaskUi= branching, immediate in-memory widget sync after the overlay loop exits.
- =pi/extensions/tasks/overlay.ts= — removed erroneous third condition from =applyDefaultCollapseView=; added =TUI= parameter and =refreshTasks()= method.

Bug 2 root cause: =applyDefaultCollapseView='s third condition collapsed tasks in =keepVisible= when they were DONE/CANCELLED and not themselves selected, contradicting the purpose of =keepVisible= (ancestors of the selected task must stay expanded). With the parent collapsed, the =planChild= never appeared in =rebuildRows()=, =focusSelectedTask()= returned =-1=, and cursor stayed at 0.

The =isOverlayActive= guard correctly suppresses =syncCompactWidget= in archive/create reopen flows (=archiveTopLevel= calls =refreshTaskUi= internally while the loop iterates with =isOverlayActive= still true). =activeOverlayInstance= is null in the gap between overlay sessions, so stray =refreshTasks= calls in that window are no-ops.
