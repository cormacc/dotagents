* Summary
Fixed two related archive defects: (1) the first archive attempt for a freshly-completed task spuriously failed with "Task is not a top-level entry; cannot archive" because the overlay's task tree had been replaced from disk (file-watcher re-load), so object-identity comparisons across the overlay/handler boundary broke; (2) archive writes were going to a newly-created =TASKS.ARCHIVE.org= rather than the existing canonical =TASKS.archive.org= already in the project root, splitting the archive across two files. Reconciled by introducing reload-and-resolve-by-=:ID:= for every mutating workflow and lowercasing =TASKS_ARCHIVE_FILE= to match the on-disk file. Two stray entries from the wrongly-named file were merged back in.

** Decisions
- Resolve task references by =:ID:= before each mutating workflow :: the overlay's tree can be replaced from disk; identity by =:ID:= is the only stable key across the overlay/handler boundary.
- Lowercase canonical archive filename :: the on-disk file is the source of truth.
- Soft-fail on stale parent for =create= :: missing parent =:ID:= degrades to a top-level append with a warning rather than discarding the user's collected title.

** Shipped
- =index.ts=: =TASKS_ARCHIVE_FILE= changed from =TASKS.ARCHIVE.org= to =TASKS.archive.org=. New helpers =resolveStale(stale)= and =reloadAndResolve(stale, verb)= in the =/tasks= command's workflow-dispatch block. Every mutating workflow (=archive=, =publish=, =unpublish=, =changeRecord=, =create=) reloads and resolves before invoking its helper; read-only workflows untouched.
- =README.md= and =skills/org-tasks/SKILL.md=: aligned to the lowercase filename.
- One-shot =.agents/tmp/merge-archives.mjs= merged the two stray entries (=6bee9f80…= local-tasks feature, =80ea589b…= org-memory protocol refinement) back into =TASKS.archive.org= sorted by =CLOSED:= / =:ARCHIVED:=. Pre/post sanity: 33 → 35 entries correctly interleaved by timestamp. Wrongly-named =TASKS.ARCHIVE.org= deleted (was never tracked in git).

** Gotchas
- Root cause is the overlay/handler boundary: the overlay's internal task tree can be replaced while open (file watcher fires after writes to =TASKS.local.org= or external Emacs saves and calls =activeOverlayInstance.refreshTasks(...)=). After that, any =request.task= the overlay sends back belongs to the fresh tree while the outer command handler in =index.ts= still holds the original =tasks= array. Object identity therefore can't be relied on across that boundary.

** Follow-ups
- Workflow-dispatch glue is currently untested. A small unit test exercising stale-reference resolution would catch regressions of this class.

* Implementation

- =index.ts=
  - =TASKS_ARCHIVE_FILE= constant: =TASKS.ARCHIVE.org= → =TASKS.archive.org=. Doc-comment on =archiveTopLevel= updated.
  - New helpers in the =/tasks= workflow-dispatch block:
    - =resolveStale(stale)= — looks up a fresh task by =:ID:= against the current outer =tasks= array.
    - =reloadAndResolve(stale, verb)= — reloads =tasks= from disk first, then resolves; emits a clear notification when the task no longer exists.
  - Every mutating workflow (=archive=, =publish=, =unpublish=, =changeRecord=, =create=) now reloads + resolves before invoking its helper. Read-only workflows (=edit=, =plan=) untouched.
- =README.md=: two =TASKS.ARCHIVE.org= references updated to match the constant.
- =TASKS.archive.org=: merged the two stray entries from the wrongly-named =TASKS.ARCHIVE.org= back in. One-shot script split entries on top-of-record headings, sorted by =CLOSED:= then =:ARCHIVED:=, and rewrote the file.
- =skills/org-tasks/SKILL.md= aligned to the lowercase filename so the skill doc and extension agree.
