* Intent
Let a root agent that runs in a herdr-app terminal delegate through `oh`, and stop `oh` and the pi Herdr extensions from acting on the wrong Herdr session when Herdr TUI environment variables leak into a herdr-app terminal. Choose between a second `oh` backend over `hc` and a thin layer over hc-native delegation from measured hc behaviour, not from its documentation.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* full

`oh` selects a runtime by caller ancestry and delegates through a shared protocol to Herdr TUI or local herdr-core. herdr-app terminals use `HC_TERMINAL_ID`; raw TUI controls refuse an hc caller, including when TUI variables leak into it. The hc runtime preserves the ledger and validated completion path, with the approved safe skip for unverifiable Pi parent notifications. Native Pi-root delegation, fan-in, close, tab/split placement and synthetic fork passed in herdr-app; representative root TUI parity also passed.

** Scope
*** In scope
- Caller-backend detection by process ancestry: the nearest ancestor that is a Herdr pane shell (`pane process-info` `shell_pid`) or an hc terminal (`hc get` `pid`) selects the backend.
- Refusal of every `oh` verb, and of the pi `herdr-orch` extension and its `herdr_*` tools, when the detected backend does not match the variables in use.
- An isolated hc capability spike before the approach decision; retained evidence is in [[*Validation]].
- The chosen approach (see `* Open questions`), with its contract, skill and README changes.
*** Out of scope
- Changes to herdr-app, herdr-core or Herdr TUI upstream. File upstream issues instead.
- Remote machines (`hc run --on`). The first delivery is local only.
- Measurement context (`--context measurement`) on the hc backend.
- The Herdr plugin wrapper ([[plan:2026-08-16-herdr-plugin-wrapper-for-herdr-orch.org]]). It stays TUI-only.
- Herdr-app layout mods that display the ledger.

- [X] In a Herdr TUI pane with no hc ancestor, existing `oh` behaviour is unchanged.
- [X] In a Herdr TUI pane inside a herdr-app terminal (reverse nesting), the TUI backend is selected.
- [X] The spike records whether `herdr-agent-state.ts` (Herdr-owned, not edited here) reports pi state to a leaked `HERDR_PANE_ID`. If it does, an upstream issue exists.
- [X] Under the chosen approach, `oh task run scout --task ...` from a pi root in herdr-app returns a validated `COMPLETE` envelope.
- [X] Under the chosen approach, `oh task collect --any --wait` returns the first of two published hc children.
- [X] Under the chosen approach, `oh task close <uuid>` ends the child terminal.
- [X] Under the chosen approach, the child appears in the parent's herdr-app space with the configured placement.
*** Edge cases
- [X] In both runtimes, a child whose parent terminal ends stays live until `close` or `orphans --close`.
- [X] A blocked hc child is never sent prompt text (hc exit 9 is surfaced, not forced).
- [X] `--context fork` from a pi root in herdr-app resolves the source session without `agent_session`.
*** Anti-criteria
- [X] Must not: call `herdr` when the detected backend is hc.
- [X] Must not: call `hc send --force`.
- [X] Must not: run `hc server stop`, `hc server restart` or `hc update`.
- [X] Must not: give a verb, flag or envelope field a behaviour that differs between the two runtimes, except where `contract.md` names the runtime fact that forces it.

Verification strength and native limits are recorded in [[*Validation]]; checked criteria do not imply every runtime combination was exercised natively.

** Decisions
- Backend detection by process ancestry :: Both variable sets can leak in either nesting direction, so variable presence cannot choose a backend. The nearest ancestor is the innermost host.
  Rejected:
  - Prefer `HC_TERMINAL_ID` when set: wrong for a Herdr TUI that runs inside a herdr-app terminal.
  - Prefer `HERDR_PANE_ID` when set: wrong for the measured case.
- Chose Option A, a second `oh` runtime over `hc` :: Keeps the ledger, validated envelope, worktrees, `continue`, `poke`, retro and trait composition, which Option B loses. The spike shows that `--outlive-parent`, `--no-notify` and an `env K=V` wrapper remove the hc conflicts.
  Rejected:
  - Option B, thin layer over hc templates, `hc send` and `hc wait --children`: no validated completion, and the TUI runtime would need a second, different design.
- Runtime parity over runtime fidelity :: One contract, one behaviour. Where hc and Herdr TUI differ, `oh` picks one behaviour and implements it in both, preferring the simpler one. The contract can be rewritten for this, provided its functionality stays equivalent.
- One `oh`-owned parent push, subject to verified session identity :: hc children launch with `--no-notify`. The push fires only on a validated terminal result when the parent's current session can be verified, with the same text in both runtimes. User-approved exception, 2026-11-05: skip advisory pushes to hc Pi parents whose current session cannot be observed; keep the existing safety guard and use `collect --wait` or `collect --any --wait` for results. No session reporter is in scope; inter-subagent communication will be revisited separately. Blocked and exited children show through `collect --wait` `child-status`.
  Rejected:
  - hc-style notes in Herdr TUI: needs a watcher process for each child, because Herdr does not push child events to a parent.
  - hc notes plus the `oh` push in herdr-app: duplicate messages in two formats.
- Children outlive their parents in both runtimes :: hc children launch with `--outlive-parent`, and `orphans` stays the cleanup path. Herdr TUI already behaves this way, and hc kills on parent-terminal exit, not on parent-agent exit, so hc's default would not give "ends with the parent" anyway.
  Rejected:
  - End children with their parent: needs a new Herdr TUI mechanism that a crash skips, and loses in-flight work that a resumed parent could collect.

** Shipped
- MODIFIED :: [[proj:skills/herdr-orch/SKILL.md]], [[proj:skills/herdr-orch/scripts/docs/contract.md]], [[proj:skills/herdr-orch/scripts/README.md]] and [[proj:skills/herdr-orch/README.org]] define both runtimes, shared delegation semantics and explicit runtime limits.
- MODIFIED :: [[proj:pi/extensions/herdr-agent-state.md]] records the state-reporter leak observation and its uncertainty; the Herdr-owned reporter remains unchanged.
- Backend gates, a shared runtime protocol and the local hc adapter preserve ledger-backed completion, ownership, continuation and fork semantics. Pi extension entry points refuse the wrong runtime.

** Gotchas
- An hc Pi parent has no freshly observable cross-terminal session. Skip advisory pushes rather than trust the ledger's original session; collect remains the completion path.
- Raw TUI controls and measurement remain TUI-only. hc has no native operator toast; the contract names that exception.

* Implementation
- Backend selection refuses unresolved competing hosts and uses the nearest proven shell/terminal ancestor. CLI and Pi extension entry paths share the gate; raw TUI controls refuse an hc caller.
- Delegation uses the runtime protocol for identity, placement, launch, prompt, wait, read, status, close and notification. Deferred allocation and launch-time prompt delivery preserve the ledger interface and prevent duplicate initial prompts.
- The local hc runtime injects the child environment, disables native parent notes, keeps children alive after parent termination and selects app placement through space/tab labels. Process witnesses detect replaced programs without claiming a fresh Pi session. Waiting prompts match requested state with start, identity and deadline guards; they do not wait for native turn completion first.
