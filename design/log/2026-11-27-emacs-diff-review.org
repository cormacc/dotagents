* Intent
Give pi a review loop in Emacs: walk the agent's diff in Magit, or any file such as a change-record, attach FIX or DISCUSS notes to lines, files or the whole change, and stage the resulting prompt in pi's editor without sending it. The idea comes from [[https://github.com/robzolkos/pi-slopchop][pi-slopchop]] (=7999ecc=), but its conventions are not binding. The review must work the same way when pi runs on a remote machine inside Herdr.

* Summary
*Level:* MVP · *Tests:* thorough · *Docs:* README

=/review [git-diff|last-commit|branch|<file>]= in pi opens the diff in Magit (or the file) and a notes buffer, in the Emacs server on the machine where pi runs, and waits. Outside Herdr the frame is a GUI frame; inside Herdr it is a terminal frame in an Emacs tab ([[archive:b9d2a8f2-4380-492f-a8bc-9644afcba9c3][precursor]]). The user annotates, then finishes (=C-c C-c=) or cancels (=C-c C-k=). Pi reads the notes file, builds a FIX / DISCUSS / mixed prompt and calls =ctx.ui.setEditorText=.

** Scope
*** In scope
- Diff scopes: uncommitted changes against =HEAD= (=git-diff=), =HEAD~1..HEAD= (=last-commit=), and merge-base of the default branch to the working tree (=branch=).
- File scope: any file, for example a change-record or a spec, with notes anchored to =path:N=.
- Line notes on added, deleted or file lines, with a region giving a multi-line range on one side.
- File notes and one whole-change note.
- FIX and DISCUSS intent on every note, switchable after creation.
- Markers in the reviewed buffer for annotated lines.
- Magit operations stay available during review (stage, discard, visit, blame).
- Two frame hosts: a GUI frame when pi is not in Herdr, and a Herdr Emacs tab when it is.
- Contract docs: =pi/extensions/emacsclient/README.md= (=/review=, notes format) and =emacs/README.org= (Emacs-side keys).
*** Out of scope
- The Emacs-tab mechanism itself, Plan and Magit tabs, and any herdr-app Changes-panel replacement: owned by [[archive:b9d2a8f2-4380-492f-a8bc-9644afcba9c3][the precursor task]].
- A local Emacs serving a remote pi over SSH.
- Starting a review from Emacs without pi.
- Template shortcuts, submodule drill-down, side-by-side view.

** Acceptance
*** Core functionality
- [ ] =/review git-diff= opens a Magit diff of uncommitted changes.
- [ ] =/review last-commit= shows =HEAD~1..HEAD=.
- [ ] =/review branch= shows the merge-base of the default branch against the working tree.
- [ ] =/review <file>= opens that file with the notes buffer.
- [ ] A line note on an added diff line records =path:N (added)= with the new-file line number.
- [ ] A line note on a removed diff line records =path:N (deleted)= with the old-file line number.
- [ ] A line note in a file buffer records =path:N=.
- [ ] A line note with an active region records an =N-M= range on one side.
- [ ] A file note records the path only.
- [ ] A whole-change note appears under =Review-wide:= in the prompt.
- [ ] Toggling intent on an existing note changes it between FIX and DISCUSS.
- [ ] An annotated line shows a marker that differs for FIX and DISCUSS.
- [ ] Finishing stages the prompt in pi's editor.
- [ ] Pi does not send the staged prompt.
- [ ] FIX-only, DISCUSS-only and mixed notes each produce their own preamble, with DISCUSS items marked as no-edit.
- [ ] Outside Herdr, the review opens in a GUI frame of the local Emacs server.
- [ ] Inside Herdr, the review opens in an Emacs tab on the machine where pi runs.
- [ ] The extension loads =pi-review.el= into the server when the feature is absent, so no Emacs configuration change is needed for the basic flow.
*** Edge cases
- [ ] Cancelling returns control to pi, leaves the editor unchanged, and shows a "review cancelled" notification.
- [ ] Finishing with no notes behaves as a cancel.
- [ ] Killing the notes buffer or its Herdr tab without finishing behaves as a cancel.
- [ ] Interrupting =/review= in pi ends the wait and leaves the editor unchanged.
- [ ] An empty diff scope is reported in pi without opening Emacs.
- [ ] No reachable Emacs server gives a pi error notification, not a hang.
- [ ] Point on a Magit header or context line rejects a line note with a message.
- [ ] A note body with several lines keeps its line breaks in the prompt.
*** Anti-criteria
- [ ] Must not: call =pi.sendUserMessage= or otherwise submit the prompt.
- [ ] Must not: put a timeout on the wait for the review to finish.
- [ ] Must not: break the existing =emacs_*= tools or their tests.

** Decisions
- Review diffs in Magit :: mature and already the user's tool; gives scope commands (=magit-diff-working-tree=, =magit-diff-range=), section navigation, staging and visiting during review, and a path to a Magit tab in Herdr.
  Rejected:
  - Plain =diff-mode= from =git diff=: stable public API, but no staging or Magit navigation, and a second diff UI to maintain.
- One location adapter, =pi-review--location-at-point= :: the only code that calls Magit internals (=magit-file-at-point=, =magit-diff-hunk-line=, =magit-diff-on-removed-line-p=, and private =magit-diff-visit--position= if needed). ERT tests pin its behaviour, so a Magit change fails a test, not a review.
- Ship =/review= in the =emacsclient= extension, with =pi-review.el= beside it :: reuses =ensureEmacsServer= and =emacsEval=; the extension loads the elisp from its own directory, so the package works without the dotagents Emacs config and the elisp is always on the same machine as pi.
  Rejected:
  - Separate =emacs-review= extension with elisp in =emacs/=: one more extension and a config dependency for no gain.
- Emacs runs where pi and the repository are :: in Herdr the frame is =emacsclient -t= in a tab on the space's machine, so local and remote sessions take the same path and Magit works on local files.
  Rejected:
  - Local Emacs serving a remote pi through an SSH-tunnelled TCP server and =emacsclient --tramp=: needs =server-use-tcp=, auth-file sync and a tunnel per session, and Magit over TRAMP is slow.
- Pi waits on a status keyword in the notes file :: the frame can be in another terminal (a Herdr tab), so pi cannot own a blocking =emacsclient=. Emacs writes =#+PI_REVIEW_STATUS: done= or =cancelled= on finish, cancel or buffer kill; pi watches the file and honours its abort signal.
  Rejected:
  - Blocking =emacsclient FILE= run by pi: works only for a GUI frame, not for a terminal frame in another tab.
- Notes file is the contract; pi builds the prompt :: the TypeScript builder is unit-testable, and the elisp only writes structured notes.
- Own prompt wording, informed by pi-slopchop :: keep its FIX / DISCUSS / mixed split and no-edit rule for DISCUSS; no byte-compatibility. Add =PROVENANCE.md= only if text is copied.

** Risks
- Magit internals can change: contained by the location adapter and its ERT tests.
- Evil normal state can shadow the minor-mode keymap in Magit buffers: bind annotation keys with =evil-define-key= in =config.org= as well as under a =C-c= prefix.
- Remote machines need Emacs, Magit and a server; the extension starts a daemon with =ensureEmacsServer=, but Magit must be installed there. Accepted: the user confirmed on 2026-11-27 that the remote hosts where pi runs get Emacs and Magit through the dotfiles Home Manager config.
- =ctx.ui.setEditorText= may be a no-op in some RPC front ends. Accepted: the terminal TUI is the target.
