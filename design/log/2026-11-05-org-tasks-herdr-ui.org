* Intent
Provide a harness-independent task interface in terminal Herdr and the Herdr desktop app, using the existing org-tasks TUI. Deliver terminal Herdr first; keep Pi agent access independent of its legacy visual UI.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* README

Terminal Herdr shows the selected task in a compact pane in every tab and opens the task browser in a popup; the Herdr desktop app shows the same view as a native widget and opens the browser in a dialog. `ot` owns every task decision: the compact view model (`ot compact`) feeds the TUI and the desktop widget. Pi's visual task UI is switched off in this repository's settings and remains available for Pi users without Herdr.

** Scope
*** In scope
- Shared `ot` TUI: compact view, embedding context contract, compact view model and `ot compact`.
- Pi separation: non-visual `tasks/agent.ts`, legacy visual entrypoints, and the cutover in `pi/settings.json`.
- Terminal host: `herdr-plugin/org-tasks/` and `scripts/test-herdr-org-tasks.bb`.
- Desktop host: `herdr-app/mods/org-tasks/`, the `org-tasks` block in `herdr-app/layouts/herdr-orch.json`, and the herdr-app tests.
- Installation: parent `agents.nix` leaves and `herdr/config.toml` bindings.
*** Out of scope
- Remote task operations, Windows and host-core changes.
- Workspace pinning, deferred by the user on 2026-11-06 to [[task:16358bea-c42f-4342-883b-6409d14c7281][Add workspace pinning to the Herdr org-tasks adapters]].
- A second Org parser, task database or task-mutation implementation; deleting the legacy Pi UI.

** Acceptance
Reversed on 2026-11-07 with the user: expand/collapse, the right-aligned memory path, the plan row and `(completed/total)` tokens gave way to popup selection, the title (`Tasks :: <folder> :: <plan>`) and one right-justified `done/total` token; the desktop terminal block gave way to a native widget, because herdr-app has no plugin pane host and the widget can draw `ot compact` data.
- [X] Bare interactive `ot` retains standalone task browsing; non-interactive `ot` retains its selected-task JSON.
- [X] Compact mode shows the selected task, its top-level parent, every STARTED descendant and the next pending one, with status-led rows and current-row emphasis.
- [X] Without a selection, compact mode shows status counts and host key hints; a stale selection is distinguished.
- [X] External changes to task memory and imported plans refresh the view without reopening.
- [X] The project follows the focused local agent; a shell pane, remote context or missing task memory has an explicit state.
- [X] An open mutation interaction stays bound to its original root; superseded refreshes cannot replace the current graph.
- [X] Terminal Herdr: the compact pane opens in every tab while display is on; selection opens in a popup and Esc restores focus.
- [X] Desktop: the widget renders `ot compact`, opens `ot tui` in a dialog that closes with Esc, and toggles with `layout.toggle`.
- [X] Pi prompt helpers and agent access to `ot` work without the visual entrypoint; the legacy UI can still load.
- [X] Native Linux validation of both hosts and the desktop restart check: passed 2026-11-12 on Linux and on macOS after darwin-rebuild; results are in the archived task [[archive:2b49d0fd-413d-47a3-a5da-61e655dea4a1]]. One fault found: restored Tasks panes ([[task:7b95f3fa-14b1-4d94-8143-88ee35469d33]]).
*** Anti-criteria
- [X] Must not: use a remote working directory as a local task root.
- [X] Must not: initialise missing task memory because host focus changes.
- [X] Must not: close, replace or send input into an unowned pane.
- [X] Must not: duplicate Org parsing, task selection or mutation policy in a host adapter.
- [X] Must not: overwrite the quota/system layout work, shipped app files or foreign installation paths.

** Decisions
- Shared logic in `ot` :: Hosts present; `ot` decides. The terminal host embeds the TUI; the desktop host draws the `ot compact` model natively.
- Selection in a popup or dialog :: A modal host surface that closes when `ot` exits returns focus without host focus handling, which removed the terminal plugin's expand/collapse handoff.
- Global display toggle :: One preference for every tab, saved in plugin state; startup and new-tab hooks are idempotent and read no event payload.
- Root policy :: Follow the focused eligible local agent; missing context is unavailable, never another project. A pane's folder is its foreground process's, so the desktop widget switches only after a new folder holds for two polls.

** Gotchas
- Herdr reflows the alternate screen on resize; JLine's diffing display then shows duplicated rows. The TUI uses a full-screen display and repaints on resize.
- bling's colour detection prints to stdout while loading when TERM and COLORTERM give no clue, as in a GUI app's subprocess. `ot` loads bling with stdout on stderr.
- A herdr-app mod folder linked into the app does not hot-reload source edits; re-create the link or restart the app.
