* Intent
Provide a harness-independent task interface in terminal Herdr and the Herdr desktop app, using the existing org-tasks TUI. Deliver terminal Herdr first; keep Pi agent access independent of its legacy visual UI.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* README

One shared TUI supplies compact selected-task context and expanded task browsing. Thin host adapters supply project context, placement, focus and sizing. This record describes agreed design, not shipped behaviour.

** Decisions
- Shared TUI with thin adapters :: Reuse ~ot~ rendering and in-process command dispatch. Rejected: separate native desktop task widget duplicates interaction behaviour; native widgets in both hosts require terminal-host changes outside scope.
- Terminal-first delivery :: Shared TUI and Pi separation precede the terminal adapter's delivery gate. Desktop implementation follows a validated terminal integration, rather than blocking it.
- Tab-local terminal pane :: Explicit, idempotent opening is sufficient; no persistent window-wide footer or automatic pane creation on focus changes. The bottom split follows native split geometry rather than restructuring user panes to span the window.
- Root policy :: Follow the current tab's last focused eligible local agent pane; ignore the task interface as a source. Supply its directory to the existing ~ot~ resolver. Missing context is unavailable, not a fallback to the plugin checkout or another tab. The user deferred workspace pinning in both hosts on 2026-11-06 to [[task:16358bea-c42f-4342-883b-6409d14c7281]]; no workspace-root configuration or substitute directory map is required in this delivery.
- Embedding boundary :: Add a documented TUI entrypoint accepting a private per-instance JSON context-file path. The host atomically supplies directory, requested compact/expanded mode, context identity and availability. Validate the input before replacing state; distinguish unavailable/remote context from a usable local directory. Add a bounded liveness mechanism so an orphaned snapshot is not indefinitely authoritative. Final field names and CLI syntax belong in ~contract.md~ with producer/consumer fixtures; they are new API, not existing identifiers.
- Lifecycle ownership :: Host adapters own pane/terminal identity, sizing, focus restoration and context production. The TUI owns graph refresh, rendering and interaction state. Context updates are data, never simulated keyboard commands. End instance-owned polling/watchers on exit; reopening must not reuse stale process identity.
- Safe switching :: Freeze the original root during a form, picker or removal confirmation; show a pending switch and apply it after completion/cancellation. A context failure blocks mutations. Use the existing optimistic-concurrency writer rather than adding a competing write path.
- Compact behaviour :: Preserve parent/plan/subtask context and completed-first truncation, adapted to actual terminal geometry. Remove the separate path header; right-align its home-shortened path on the selected-task row. Replace completed-count and more-count summary rows with ~(completed/total)~ tokens on the task and plan rows. Keep the selected task identifiable at narrow widths without adding a path row. Compact mode is passive; expand to browse or mutate.

- Pi coexistence :: Separate prompt construction and CLI access from visual registration. Keep legacy UI opt-in after Herdr becomes the default task surface. Retain existing in-overlay event semantics for the optional legacy UI; a new Herdr-to-Pi event bus is not part of this change.

** Risks
- Host APIs differ :: Validate placement, focus restoration, resize, tab changes, process exit and restart on each native host. A failed capability check returns to the owner, not an unapproved UI substitution.
- Rapid focus changes or asynchronous refresh can target the wrong project :: Test two disposable task roots, delayed results and a root switch during confirmation. Keep context identity separate from task UUID identity.
- Context files can outlive their producer :: Validate instance ownership and liveness; reject malformed, stale or missing context before mutations. Define the lease/poll bound in the embedding contract and test producer failure.
- Pi source/docs have drifted :: Inventory current exports and consumers before extraction. Test non-visual-only, legacy-only and combined loading; preserve event cleanup on reload.
- Native validation hosts may be unavailable :: Linux and macOS checks are delivery gates, not claims inferred from offline fixtures. Report an unavailable host as a remaining dependency.
