* Intent
Extend the owned LSP extension for C/C++, reliable language selection and definition lookup, and a preview-then-apply rename. Consolidate duplicated language metadata without adding user configuration or weakening existing language support.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* README

- Built-in language catalogue, shared root discovery and progress tracking; retain server-specific exceptions.

** Decisions
- Keep the shared LSP client; replace duplicated ordinary language glue with a built-in data catalogue. Preserve specialised hooks only where existing behaviour needs them. Delete replaced modules and unused internal exports only after checking their consumers.
  Rejected:
  - Continue copying per-language modules: repeats root discovery and progress tracking and permits extension-map drift.
  - User-configurable routing: adds trust, validation and migration work without solving the measured query-definition gap.
- Keep explicit =language= selection; validate against the catalogue rather than infer silently. Shared headers use the selected language.
- Use one clangd server identity per workspace, independent of the requested C/C++ document language. Use =clangd --background-index=; do not enable extra lint/fix behaviour by default.
- Return every distinct best-ranked definition location available to the selected lookup path. Preserve server-result order within a tier; do not claim whole-workspace completeness from the bounded fallback. Reuse implementation rendering and location deduplication.
- Retain the references consumer's single-target policy explicitly when changing shared lookup helpers; do not silently union references from unrelated symbols.
- Reject =@narumitw/pi-lsp= 0.49.12 as a replacement: its published tools provide diagnostics/source fixes, not navigation, references or semantic rename. Its documented per-call startup, default 20-second timeout, unbounded output and non-queued fix writes are poorer fits for this task. Sources: [[https://cdn.jsdelivr.net/npm/@narumitw/pi-lsp@0.49.12/README.md][published README]], [[https://cdn.jsdelivr.net/npm/@narumitw/pi-lsp@0.49.12/docs/settings.md][settings]], [[https://cdn.jsdelivr.net/npm/@narumitw/pi-lsp@0.49.12/src/pi-lsp.ts][tool source]]. This was a source/document review, not a benchmark.
- Adopt its extension-routing principle through the built-in catalogue. Source-fix preview and configurable diagnostic settling do not justify speculative tasks; revisit only if source fixes enter scope or stale/premature diagnostics are reproduced.
- Reject supi-code-intelligence 13.0.0 and Serena 2.1.1.dev0 as replacements (controlled evaluation 2026-11-17, artefacts in the gitignored =.tmp/alt-eval/=). supi: +5,429 fixed prompt tokens, no built-in Clojure route, and 0/2 Clojure renames (document-version mismatch) with a custom route. Serena: 0/2 C field renames (declaration only, build broken), 0-based line numbers reported as 1-based by the model, and an orphaned clangd after exit. Adopt supi's plan/apply rename design, which gave an exact semantic C field rename in 2/2 runs.
- Automatic formatting stays out of scope. Revisit after the MBT firmware and framework reformatting task (cd =TASKS.org=, =febdf388=) lands, because firmware non-conformance with =.clang-format= is the main reason for the rule.

** Risks
- Catalogue consolidation can change root and startup behaviour. Mitigation: characterise the five existing language families before replacing their modules; include marker precedence, missing-marker fallback and tracker lifecycle.
- The firmware host-GCC database may not represent a target build. Mitigation: preserve the evaluation's host-database scope and verify the named semantic-reference case; do not claim target-build validation.
- Shared clangd ownership can mix header IDs or duplicate processes. Mitigation: fixture tests for explicit header modes and mixed C/C++ reuse; keep language IDs document-specific.
- Workspace-symbol results and the bounded source scan are not guaranteed exhaustive. Accepted limit: identify lookup provenance and truncation; add a =known-limit:= comment at the bounded fallback, with workspace-wide completeness as the revisit trigger.
- Private validation projects or historical symbols may be unavailable. Treat this as blocked validation and return the decision to the owner; synthetic fixtures do not silently replace accepted live smokes.

- clangd routing (=fa53bc2c=): the catalogue adds =c= and =cpp= with a shared =serverId= (=clangd=); =getServer= keys servers by =serverId= and root. =LspClient= records the language ID of each open document; an explicit different ID reopens the document (=didClose=, =didOpen=). =execute= validates the language and the file extension, resolving relative and =@= paths against =ctx.cwd=, before any server starts. =/lsp-stop c= maps to the shared server.
- By-name lookup: =rankSymbolMatches= replaces =findBestSymbolMatch= (which returned the first exact match, or else the server's first result). Exact tier also accepts =container::name=, =container.name= and =container/name=; partial matching uses the bare name. =collectOpenDocumentSymbols= replaces =findSymbolInOpenFiles= and carries a =known-limit:= comment. =buildLspToolResult= appends a truncation notice and reserves 2 lines and 200 bytes for it.
- Additions found during implementation, both inside the accepted scope:
  - Query =references= started at =location.range.start=. clojure-lsp gives a workspace symbol the range of its whole form, so the request position was the opening parenthesis and the portal query found no references (the =ef33181= code has the same defect). =symbolNamePosition= moves the position to the matching document symbol's selection range; the portal query then found 17 references in 5 files.
  - clangd begins background indexing only after the first =didOpen=; the first firmware references request on a fresh server returned 1 reference, and the same request 5 seconds later returned 6. Probe (=.tmp/live-smoke/progress.out=): progress began 22 ms after =didOpen= and ended at 452 ms. The catalogue field =indexOnOpenGraceMs= (2000 ms, clangd only) makes a fresh server wait for indexing to begin, then up to 30 s for it to end (=LspClient.waitForIndexingAfterOpen=). Existing languages keep their indexing waits.
- =tsc --noEmit= after =fa53bc2c= reports three of the four pre-existing =index.ts= errors (bodyRange null, renderCall argument, buildLspToolResult action); the error in the replaced =findSymbolInOpenFiles= is gone. The new test files type-check.
- Tests: =dispatch.test.ts= (15 tests at =fa53bc2c=) uses an injected fake client (=LspExtensionOptions.createClient=) and the stdio fixture =fixtures/fake-lsp-server.mjs=; =test.sh= runs it after the two existing suites. Each new guard failed under a targeted mutation (validation disabled, server key by language, no reopen on ID change, no name-position lookup, no wait after open, wait on every open) and passed when restored.
- Rename plans (=1ac6d56d=): =previewRename= replaces =applyWorkspaceEdit=; it fingerprints each target with SHA-256, lists edit counts and 1-based ranges, and computes the diffs without writing. =applyRenamePlan= re-runs every check (resource operations, workspace root, fingerprint, overlap) inside =withFileMutationQueues= and writes only when all pass. The tool adds the action =apply_rename= and the parameter =plan_id=; the plan identifier is 4 random bytes in hex. Plans live in a per-extension =Map=, which =session_shutdown= clears.
  - Decision: the first =apply_rename= removes the plan even when it refuses, because every refusal reason needs a new preview (the files changed, or the edit cannot be applied).
  - The workspace root is the root of the server that answered the rename, so a rename whose edits reach a sibling project outside that root is refused.
  - =collectWorkspaceEditChanges= records resource operations for the refusal report instead of throwing. The client does not advertise =workspace.workspaceEdit.resourceOperations=, so clojure-lsp refuses a namespace rename itself (=LSP error -32602: Can't rename - client does not support file renames.=).
  - Tests: =lsp.test.ts= routes the five existing edit tests through preview then apply and adds five plan tests (preview writes nothing; stale fingerprint, overlap, outside root and resource operation each refuse with no write and no refresh). =dispatch.test.ts= adds the tool flow (preview, apply, second apply refused, missing =plan_id=, shutdown discards a plan) and the empty-rename case. Mutations that removed the fingerprint check, plan removal, shutdown clearing, root check or resource-operation check each failed one test.
