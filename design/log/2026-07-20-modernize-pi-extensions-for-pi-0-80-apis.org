* Intent
Adopt the extension-facing capabilities and lifecycle guarantees added from pi 0.69.0 through 0.80.10 where they remove local workarounds, prevent incorrect behavior, or reduce model context cost. Keep each extension's existing purpose and user-facing workflow while moving maintained code onto current public APIs and explicit TUI/RPC boundaries. Treat =pi-clojure= as locally owned code: preserve its import history and license attribution, but optimize and document it according to this repository's current contracts rather than an upstream-sync constraint.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* README

** Scope
*** In scope
- Make the question tool sequential and explicitly TUI-only while preserving cancellation and free-text behavior.
- Guard the tasks overlay with =ctx.mode= without disabling RPC-capable task creation and doctor commands.
- Replace stale event-bus registrations with subscriptions that are released during =session_shutdown=.
- Move display-only system-prompt output from model-visible messages to custom entries, with an explicit non-TUI behavior.
- Return standard pi diffs for LSP rename operations and invalidate cached file previews after mutations and session replacement.
- Extend the reviewed changelog window back to pi 0.69.0 (2026-04-22) so the TypeBox 1.x migration and other extension-facing changes immediately preceding May are explicitly covered.
- Resolve global extension files through =getAgentDir()= and migrate maintained imports from =@mariozechner/*= to =@earendil-works/*= and from the legacy-aliased =@sinclair/typebox= root to =typebox=.
- Harden and simplify the now locally owned =pi-clojure= extension: current public types, bounded/cancellable nREPL operations, deterministic transport cleanup, stronger tests, and ownership-accurate documentation.
- Replace the Herdr agent-state retry timing heuristic through the managed integration's source of truth, or capture an upstream follow-up when that source cannot be changed here.
- Update =pi/skills/ext-dev/SKILL.md=, =skills/clojure/SKILL.md=, the Clojure tool guide, and extension READMEs with the durable API, mode, and tool behavior rules exercised by the changes.

- Dynamic browser-tool loading without measured prompt-cache pressure.
- Jira issue-key autocomplete without a product request and cache/search design.
- Provider registration, =ModelRuntime=, compaction hooks, project-trust policy, or SDK embedding changes not used by these extensions.
- Replacing the intentional model-visible source injection in =ext-dev= with a display-only entry.
- Broad rewrites of extension UI or tool schemas unrelated to the reviewed pi changes.

** Decisions
- Chose targeted API adoption with regression tests per affected extension :: it captures the concrete pi 0.69.0–0.80.10 wins without coupling unrelated extensions into a framework rewrite.
  Rejected:
  - Rebase each extension wholesale on current upstream examples: local behavior and integrations would be overwritten or obscured.
  - Redesign the complete tool surface around dynamic loading: added indirection is not justified by the current tool counts or measured cache data.
- Preserve mode-appropriate behavior rather than treating =ctx.hasUI= as equivalent to TUI :: RPC supports dialogs and notifications but not custom component factories.
- Use custom entries only for human-facing data that should not enter model context :: =systemprompt= qualifies; =ext-dev-source= intentionally does not.
- Use =getAgentDir()= for global files and reserve =CONFIG_DIR_NAME= for project-local config paths :: this preserves configured agent-directory overrides.
- Treat the Herdr file header as authoritative :: change the integration generator/source when discoverable; otherwise create a concrete upstream follow-up rather than committing a change that reinstalling Herdr will erase.
- Include the pi 0.69.0 TypeBox migration despite its 2026-04-22 date :: it is the nearest preceding extension break, the local tree still depends on the compatibility alias, and the user explicitly expanded the review window beyond May.
- The pi 0.69.0–0.71.0 review found no current use for terminating tool results, stacked autocomplete, =message_end= replacement, custom-editor composition, thinking-level events, or working-row visibility :: retain them as reviewed/non-applicable rather than manufacturing features.
- Migrate old package scopes, including =@sinclair/typebox= → =typebox=, but keep =StringEnum= on the current pi-ai root :: none of the extensions use the legacy global model API that moved to =/compat=; pi bundles typebox 1.1.38 and no longer shims the =@sinclair/typebox/compiler= subpath.
- Maintained scope is every extension under =pi/extensions/= except the Herdr-managed =herdr-agent-state.ts= :: =pi-clojure= began as a copied upstream project but has been materially modified and is now owned here, so behavioral simplification, transport hardening, tests, and documentation are in scope while original license and authorship attribution remain intact.

** Gotchas

** Risks
- Entry renderers are interactive-only; the implementation must deliberately preserve or redefine =/systemprompt= behavior for RPC callers.
- =agent_settled= carries no message payload; Herdr must retain the last terminal error observed at =agent_end= until settlement.
- Standard LSP diffs may be substantially larger than the current range summary; rendering and model-visible content need independent truncation decisions.
- The Herdr source of truth may live outside this repository, turning that work unit into a separately tracked upstream dependency; creating and linking that follow-up satisfies this record's Herdr scope but does not claim the new runtime behavior shipped locally.
- TypeBox 1.x migration can expose assumptions hidden by the legacy declaration shim; package manifests, lockfiles, and typechecks must move together.
- nREPL cancellation and truncation touch transport/result boundaries; tests must preserve namespace routing, nested/chunked bencode handling, and useful failure diagnostics.
