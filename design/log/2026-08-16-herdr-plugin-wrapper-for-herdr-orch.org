* Intent

Package herdr-orch as a Herdr plugin so `herdr plugin install cormacc/dotagents/herdr-plugin` gives a new machine a working orchestration surface, while the skill under `skills/herdr-orch` stays the canonical implementation and the live dotagents development flow (out-of-store symlinks, `herdr plugin link`) continues unchanged. The plugin is an adapter and distribution surface only.

* Summary

*Level:* MVP · *Tests:* smoke · *Docs:* README

** Decisions

- Chose a `herdr-plugin/` subdir adapter with thin bash entrypoints :: separate native package surface per the parent task's constraint; doctor must run without `bb`, so bash is forced there and setup is only symlink management. Rejected:
  - Repo-root manifest: conflates the whole repository with the plugin surface.
  - `bb.edn` tasks with degraded bash shims: the degraded path reimplements half of doctor for no user-visible gain.
  - Single dispatcher script: separate scripts read better in the install preview users audit.
- Minimum Herdr version 0.8.2 everywhere (manifest and `oh` preflight) :: eliminates legacy-support and API-drift considerations; unlocks `popup` placement. User decision 2026-08-16 set this at 0.8.0; raised to 0.8.2 by the later user decision of 2026-08-26, when task cf561004 gated `oh` on 0.8.2 to delete the readiness workarounds. The floor is single-valued on purpose: a manifest that loads on a Herdr the bundled `oh` refuses is the incoherence this bullet exists to prevent.
- Link classification by realpath equality against the clone root :: one rule serves linked-dev and GitHub-install modes. Measured on this machine: both canonical paths realpath into the live checkout, so linked-dev classifies healthy and setup no-ops. States: healthy, foreign, foreign-parent, plugin-stale, absent.
- No `[[build]]` entries :: nothing needs building; the install-time no-global-mutation constraint is honoured structurally. Babashka is a documented prerequisite that doctor checks.
- Traits fallback keeps the live path's priority :: env override, then the canonical home path, then extension-file-relative, per the parent task constraint.

** Risks

- Whole-repository clone retention for subdir installs is measured behaviour on Herdr 0.8.0 (one probe against `ogulcancelik/herdr-plugin-examples`), not documented contract. Accepted: doctor's clone-layout check makes a future break immediately diagnosable.
- The managed clone directory embeds a hash suffix that matches neither commit nor an obvious ref, so its stability across reinstalls is unknown. Designed for: the `plugin-stale` repair path covers both outcomes.
- Popup interactive `read` is documented but unverified. Mitigation: manual linked-flow verification; fallback is `split` placement for setup.
