** Decisions
- Adapt upstream UI :: Preserve its native rendering, responsive behaviour, keyboard support and relevant preferences; replace collection, schema mapping and stale handling. Do not retain upstream-only provider integrations, remote quota logic or login-shell fallback. A fresh rendering implementation was rejected; refresh/reduction may be considered later.
- Direct JSON invocation :: Use ~exec(home() + "/.agents/skills/herdr-orch/scripts/oh", ["usage", "--format", "json"], {cwd: home()})~. Check exit code and the ~herdr-orch/v1~ success envelope before consuming ~result.providers~. Normal refresh respects collector cache/backoff; do not add ~--fresh~ by default. Text/status formats lose popup structure.
- One local quota snapshot :: The status instance owns polling; the popup shares a refresh coordinator and state, not another timer. Isolate shared keys/assets/overlay references under the new mod identity. Use ~localProvider~ for row identity and ~provider~ only for adapter presentation. Explicitly label quota as this computer; the system companion retains upstream selected-machine behaviour.
- 60-second polling, native 30-second command limit :: The user revised the original 75-second choice after inspection of ~herdr.d.ts~. No background collector or timeout wrapper is needed. The checked-in TUI config uses 75 seconds; its stanza generator uses 30 seconds. Neither TUI file changes here.
- Failure policy :: Retain a failed-command snapshot for at most five minutes, stale immediately, then show unavailable. Keep transport age separate from provider freshness. Provider failures from a valid new snapshot supersede old rows; never restore authentication-invalidated numbers. Use safe categories, not raw stderr, in UI state.
- Separate system companion :: Preserve upstream collection and attribution. Disable its Activity Monitor action unless running locally on macOS. Linux CPU/RAM plus NVIDIA-only GPU support is accepted.
- Managed leaf paths :: Install two mod-directory links and one personal-layout link through the parent's existing out-of-store mechanism; never manage the whole app directory. Refuse collisions. Base the personal layout on shipped ~main~, retain bundled mod references and record the source app version. Select it explicitly; installation does not switch layouts.

** Risks
- Symlink discovery, source watching and restart persistence are not promised by the app guide. Native lifecycle checks are delivery gates; a failed check returns to the owner rather than silently changing installation strategy.
- The native timeout bounds the invocation according to the app type contract. Validate timeout/recovery and process cleanup on the actual app; do not treat a UI timer as process cancellation.
- Schema mismatch can hide unavailable providers or fabricate window semantics. Fixtures cover aliases, empty windows, unknown durations, model scopes and stale/auth failures; retain only finite in-range percentages.
- The copied layout structure does not receive upstream structural updates. Accepted: record provenance and document manual refresh; bundled mod code remains app-owned.
- Linux is the primary platform. The owner deferred native Linux evidence to follow-up task ~a5cbd996-628f-4883-929a-e5d54338f9b8~; macOS and fixture results must not be described as Linux validation.
