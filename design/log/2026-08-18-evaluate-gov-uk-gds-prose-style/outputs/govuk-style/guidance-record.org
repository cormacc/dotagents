** Decisions
- Keep the 6 existing task UUIDs as separate work units :: Each correction has an independent observable outcome and a local validation scenario. The 3 `home/AGENTS.md` changes target distinct directives.
  Rejected:
  - Merge all guidance edits into one task. Evidence and failure diagnosis would become coupled.
  - Add ordering blockers. No correction needs another correction to land first.
- Use targeted edits and adversarial behaviour probes :: Inspecting the string or the prose confirms the wording. It does not confirm that an agent follows the directive.
  Rejected:
  - Run only structural validators. They cannot detect guidance that does not work.
  - Build a new repository-wide guidance test framework. That scope is too large for 6 focused probes.
- Keep `gitlab-cli-skills` vendored and carry the temporary workaround in `home/AGENTS.md` :: Upstream `main` still documents invalid `--all` guidance, while installed glab accepts `--instance` and rejects `--all`.
  Rejected:
  - Reclassify the complete skill because of one upstream defect. This creates unnecessary local maintenance.
  - Edit the vendored body locally. The next vendor refresh would overwrite the correction.
  - Wait for the upstream merge without a local workaround. Agents would keep receiving invalid guidance.
- Put the Herdr distinction in the shared `publication-guidance` and in its complete-string regression :: The initial, continuation and poke prompts all use this shared value.
  Rejected:
  - Add persona-specific wording. Duplicate guidance can drift.
  - Change the prompt text without a regression test. The measured failure could then return silently.
