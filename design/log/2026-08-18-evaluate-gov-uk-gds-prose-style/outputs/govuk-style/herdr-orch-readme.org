* Subagent lifecycle
The parent owns both ends of a round. It decides where the child works, and it owns everything the child produces.

- Target :: The parent resolves exactly one checkout before the child exists. That checkout is the caller's own checkout, an existing attached checkout in the same repository (=--worktree <path>=), or a managed checkout (=--worktree new=). With no flag, a read-only child or a first write-enabled child shares the caller's checkout, while an additional concurrent write-enabled child gets a managed one. The parent creates a managed checkout from the source HEAD on branch =orch/<task-prefix>=, before any pane exists.
- Spawn :: =oh task run= blocks for the result. =oh task start= returns immediately. The child's cwd is the resolved checkout, and that cwd is the only child state the target affects. =oh= never communicates topology through the persona, and the child carries no commit permission.
- Publish :: =oh task publish= appends immutable result items to the round's stream, including interim reports and monitor observations. A terminal status (=COMPLETE=, =BLOCKED=, =FAILED=) seals the round. Publication is also the commit gate. From a non-shared checkout, it mechanically stages and commits pending nonignored changes, and it records the resulting tip as =CHECKPOINT=. Recovery therefore never depends on anyone having told the child to commit. From the shared checkout, it never touches Git. It refuses a read-only child that holds dirt, rather than committing the changes.
- Collect and reconcile :: =oh task collect= captures published items. =collect --any= takes whichever in-flight child publishes first. For a child with its own checkout, =collect=, =status= and =oh worktree list= also report base, branch, tip and checkout state. They keep committed, dirty and ignored paths as 3 separate sets, because each set calls for a different parent action.
- Close, continue, or tear down :: Capture never closes a pane. =oh task close= closes a settled child's pane. =oh task continue= assigns the same child another round and carries its checkout identity forward without resolving topology again. =oh worktree remove= deletes only a managed checkout, and only when that checkout is owned, unreferenced and clean. The branch always survives.

Integration is the parent's work. =oh= never merges, rebases, pushes, deletes a branch, or commits in the shared checkout. Isolation keeps concurrent writers out of each other's index, but it does not prove that their edits compose. The parent still remeasures the combined tree. Retained =orch/*= branches build up until the parent integrates or deletes them.
