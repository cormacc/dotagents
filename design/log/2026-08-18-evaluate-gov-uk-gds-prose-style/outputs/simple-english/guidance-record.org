** Decisions
- The six existing task UUIDs remain separate work units :: Each correction has an independent observable outcome. Each correction also has a local validation scenario. The three `home/AGENTS.md` changes target distinct directives.
  Rejected:
  - One task for all guidance edits: with one task, the evidence and the diagnosis of failures become coupled.
  - Ordering blockers: no correction needs another correction to land first.
- Targeted edits plus adversarial behavior probes are the method :: An inspection of the string or the prose confirms the wording. Such an inspection does not confirm that an agent obeys the directive.
  Rejected:
  - Only structural validators: they cannot detect ineffective guidance.
  - A new repository-wide guidance test framework: six focused probes do not justify that scope.
- `gitlab-cli-skills` stays vendored, and `home/AGENTS.md` carries the temporary workaround :: Upstream `main` still documents the invalid `--all` guidance. Installed glab accepts `--instance` and rejects `--all`.
  Rejected:
  - Reclassification of the complete skill for one upstream defect: this option creates unnecessary local maintenance.
  - A local edit to the vendored body: the next vendor refresh overwrites such a correction.
  - The upstream merge with no local workaround: agents continue to receive the invalid guidance.
- The Herdr distinction goes in the shared `publication-guidance` value, together with its complete-string regression :: The initial prompt, the continuation prompt, and the poke prompt consume this shared value.
  Rejected:
  - Persona-specific wording: duplicate guidance can drift.
  - A change to the prompt text with no regression test: the measured error can return silently.
