* Subagent lifecycle
The parent owns both ends of a round. The parent decides where the child works, and the parent owns everything that the child produces.

- Target :: The parent resolves exactly one checkout before the child exists. That checkout is one of three: the checkout of the caller, an existing attached checkout in the same repository (=--worktree <path>=), or a managed checkout (=--worktree new=). With no flag, a read-only child shares the checkout of the caller. The first write-enabled child also shares it. An additional concurrent write-enabled child gets a managed checkout. A managed checkout is created from the source HEAD on branch =orch/<task-prefix>=, before any pane exists.
- Spawn :: =oh task run= blocks for the result. =oh task start= returns immediately. The cwd of the child is the resolved checkout. That cwd is the only child state that the target affects. The persona never communicates the topology. The child carries no permission to commit.
- Publish :: =oh task publish= appends immutable result items to the stream of the round. These items include interim reports and monitor observations. A terminal status (=COMPLETE=, =BLOCKED=, =FAILED=) seals the round. Publication is also the commit gate.

  From a non-shared checkout, =oh task publish= mechanically stages and commits the pending nonignored changes. It records the resulting tip as =CHECKPOINT=. Therefore recovery never depends on an instruction to the child to commit. From the shared checkout, =oh task publish= never touches Git. A read-only child that holds dirt is refused, and its changes are not committed.
- Collect and reconcile :: =oh task collect= captures published items. =collect --any= takes the first in-flight child that publishes. For a child with its own checkout, =collect=, =status=, and =oh worktree list= also report the base, the branch, the tip, and the checkout state. These commands keep committed, dirty, and ignored paths as three separate sets. Each set calls for a different parent action.
- Close, continue, or tear down :: Capture never closes a pane. =oh task close= closes the pane of a settled child. =oh task continue= assigns the same child another round. This command carries the checkout identity of the child forward, and it does not resolve the topology again. =oh worktree remove= removes only a managed checkout, and only when that checkout is owned, unreferenced, and clean. The branch always survives.

Integration is the work of the parent. =oh= never merges, rebases, pushes, removes a branch, or commits in the shared checkout. Isolation keeps concurrent writers out of the index of each other. Isolation does not show that their edits compose. Therefore the parent measures the combined tree again. Retained =orch/*= branches accumulate until the parent integrates them or removes them.

[[file:scripts/docs/contract.md][contract.md]] owns the mechanics. Its § Worktree reconciliation and teardown gives the shape of the reconciliation, the removal guards, and the recovery when =.tmp/= was cleared before a child published. Its § Close gives the closure guards.
