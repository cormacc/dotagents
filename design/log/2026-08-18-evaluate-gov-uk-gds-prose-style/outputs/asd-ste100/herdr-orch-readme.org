* Subagent lifecycle
The parent owns both ends of a round. The parent decides where the child works, and the parent owns everything that the child produces.

- Target :: The parent resolves exactly one checkout before the child exists. That checkout is the caller's own checkout, an existing attached checkout in the same repository (=--worktree <path>=), or a managed checkout (=--worktree new=). With no flag, a read-only child shares the caller's checkout, and so does the first write-enabled child. An additional concurrent write-enabled child receives a managed checkout. A managed checkout is created from the source HEAD on branch =orch/<task-prefix>=, before any pane exists.
- Spawn :: =oh task run= waits for the result. =oh task start= returns immediately. The child's cwd is the resolved checkout, and that cwd is the only child state that the target affects. The persona never communicates the topology, and the child has no commit permission.
- Publish :: =oh task publish= appends immutable result items to the round's stream, and those items include interim reports and monitor observations. A terminal status (=COMPLETE=, =BLOCKED=, =FAILED=) seals the round. Publication is also the commit gate. From a non-shared checkout, =oh task publish= mechanically stages and commits pending nonignored changes, and records the resulting tip as =CHECKPOINT=. Therefore recovery never depends on an instruction to the child to commit. From the shared checkout, =oh task publish= never touches Git. =oh task publish= refuses a read-only child that holds dirt, and does not commit that dirt.
- Collect and reconcile :: =oh task collect= captures published items. =collect --any= takes the first in-flight child that publishes. For a child with its own checkout, =collect=, =status=, and =oh worktree list= also report the base, the branch, the tip, and the checkout state. These commands keep committed, dirty, and ignored paths as three separate sets, because each set needs a different parent action.
- Close, continue, or remove :: Capture never closes a pane. =oh task close= closes the pane of a settled child. =oh task continue= assigns another round to the same child. It carries that child's checkout identity forward and does not resolve the topology again. =oh worktree remove= deletes only a managed checkout, and only when that checkout is owned, unreferenced, and clean. The branch always survives.

Integration is the parent's work. =oh= never merges, rebases, pushes, deletes a branch, or commits in the shared checkout. Isolation keeps concurrent writers out of each other's index, but it does not prove that their edits compose. Therefore the parent remeasures the combined tree. Retained =orch/*= branches accumulate until the parent integrates them or deletes them.
