** Decisions
- Preserve the six existing task UUIDs as separate work units :: Each correction has an independent observable outcome and a local validation scenario. The three `home/AGENTS.md` changes target distinct directives.
  Rejected:
  - Merge all guidance edits into one task. This would couple the evidence and the failure diagnosis.
  - Add ordering blockers. No correction requires another correction to land first.
- Use targeted edits and adversarial behaviour probes :: An inspection of the string or the prose confirms the wording. It does not confirm that an agent follows the directive.
  Rejected:
  - Run only structural validators. Structural validators cannot detect ineffective guidance.
  - Build a new repository-wide guidance test framework. Six focused probes do not justify that scope.
- Keep `gitlab-cli-skills` vendored and carry the temporary workaround in `home/AGENTS.md` :: Upstream `main` still documents invalid `--all` guidance. Installed glab accepts `--instance` and rejects `--all`.
  Rejected:
  - Reclassify the complete skill because of one upstream defect. This creates unnecessary local maintenance.
  - Edit the vendored body locally. The next vendor refresh would overwrite the correction.
  - Wait for the upstream merge without a local workaround. Agents would continue to receive invalid guidance.
- Put the Herdr distinction in shared `publication-guidance` and in its complete-string regression :: The initial prompt, the continuation prompt, and the poke prompt consume this shared value.
  Rejected:
  - Add persona-specific wording. Duplicate guidance can drift.
  - Change the prompt text without a regression test. The measured failure can return silently.
