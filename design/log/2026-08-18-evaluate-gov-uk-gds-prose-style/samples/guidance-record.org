** Decisions
- Preserve the six existing task UUIDs as separate work units :: Each correction has an independent observable outcome and a local validation scenario. The three `home/AGENTS.md` changes target distinct directives.
  Rejected:
  - Merge all guidance edits into one task: evidence and failure diagnosis would become coupled.
  - Add ordering blockers: no correction requires another correction to land first.
- Use targeted edits plus adversarial behaviour probes :: String or prose inspection confirms wording but does not confirm that an agent follows the directive.
  Rejected:
  - Run only structural validators: they cannot detect ineffective guidance.
  - Build a new repository-wide guidance test framework: six focused probes do not justify that scope.
- Keep `gitlab-cli-skills` vendored and carry the temporary workaround in `home/AGENTS.md` :: Upstream `main` still documents invalid `--all` guidance, while installed glab accepts `--instance` and rejects `--all`.
  Rejected:
  - Reclassify the complete skill for one upstream defect: this creates unnecessary local maintenance.
  - Edit the vendored body locally: the next vendor refresh would overwrite the correction.
  - Wait for the upstream merge without a local workaround: agents would continue to receive invalid guidance.
- Put the Herdr distinction in shared `publication-guidance` and its complete-string regression :: Initial, continuation, and poke prompts consume this shared value.
  Rejected:
  - Add persona-specific wording: duplicate guidance can drift.
  - Change prompt text without a regression test: the measured failure can return silently.
