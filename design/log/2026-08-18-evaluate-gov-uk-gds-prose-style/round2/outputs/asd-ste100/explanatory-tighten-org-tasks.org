* Intent
This change has two goals. First, answer one question with a single cheap
`ot` call instead of several raw file reads: which task is selected, and
what is its plan. Second, stop the agent-facing surface from carrying
context that the agent never uses. The agent-facing surface includes the
`ot show` output and the extension's registered tools.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* README + skill + contract

** Scope
*** In scope
- Remove `sourceContent` and `effectiveSourceContent` from the `ot show` and `ot selected` JSON output.
- Add the documented one-shot resume shape to `ot show`. The shape includes ancestors and a record metadata block.
- Change the `org-tasks` skill resume path to start with `ot show selected --format json`.
- Remove the three agent-facing pi tool registrations: `tasks_insert_task`, `org_read_section`, and `tasks_scan_summaries`. Keep the JS `insertTaskIntoFile` primitive.
- Match the `show`/`selected` schema in `scripts/docs/contract.md` to the shipped shape.
*** Out of scope
- Changing `ot list`. `ot list` is already content-deduped through `result.sources`.
- Changing the data path that feeds the extension's overlay and widget.
- Changing tracker-specific (`jira`) behavior, beyond confirming that its JS import still resolves.
- The tree-sitter org-extension extraction (`f361c429`) itself. Only its claim on `org_read_section` is touched here.
- Backfilling richer `ot show` data into the `ot status` and `ot create` payloads.

** Decisions
- Remove all embedded source content from `ot show`, instead of deduplicating it into a `sources` map ::
  `ot show` has no internal consumer. The extension uses `otList`. `jira` imports the JS
  function directly. Link templates and linked issues are already resolved into wire fields
  before this point. Therefore the raw content serves no purpose.
  Rejected: mirroring `ot list`'s `sources` map. This would add a field that no `show`
  caller needs.
- Put the raw-content escape hatch behind the opt-in flag `--include-content`, which is off by default ::
  This keeps a path open for a possible future consumer. It adds no cost to the common case.
- Decision 4: remove all three registered tools. Use `ot <cmd> --format json` through Bash
  instead. The skill already documents this approach ::
  This removes about 7KB of tool schema from the persistent context, which is the biggest
  context saving here. It adds almost no bloat to the skill, because the commands already
  appear in the quick reference. The CLI is the single source of truth.
  Rejected:
  - Consolidate into one `tasks` passthrough tool. This still ships a shell-shaped schema,
    plus an indirection layer that re-parses arguments the CLI already parses. The net
    effect is negative, compared with Bash and `ot` directly.
  - Keep the current tools unchanged. This keeps about 7KB of persistent tool schema for
    wrappers that the skill already covers.

** Shipped
- `ot show` and `ot selected` omit raw source strings by default. Use `--include-content` as the explicit escape hatch.
- `ot show` now returns `ancestors` and `record` metadata for resolvable change-record imports. The metadata includes `path`, top-level sections, `hasContext`, and `hasOpenQuestions`.
- The `org-tasks` resume guidance now starts from `ot show selected --format json`. It uses `ot section` for the linked record's summary and context.
- The tasks extension no longer registers `tasks_insert_task`, `org_read_section`, or `tasks_scan_summaries`. The README now points agents to `ot create`, `ot section`, and `ot scan`.

** Gotchas
- `linkedIssues` still resolves correctly, even without emitted raw content. `task->wire` computes `linkedIssues` from the internal `:effective-source-content` field, before it applies the `include-content?` output gate.
- `insertTaskIntoFile` remains the JS primitive for Jira and direct integrations. Only the agent-facing tool registration was removed.
- Selected work that already exists in an imported plan may not itself carry a `#+IMPORT:` marker. Record metadata is guaranteed only for tasks that have an import-bearing ancestor in the loaded graph. Top-level roots with imports are the canonical resume path.
