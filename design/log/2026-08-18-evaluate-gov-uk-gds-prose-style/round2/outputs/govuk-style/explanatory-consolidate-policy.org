* Intent
Remove the policy logic duplicated between the pi tasks overlay
(TypeScript) and the standalone TUI (Clojure), by making ~ot~ the sole
owner. Both UIs become thin clients: they send intent (a direction, or an
anchor and relation) and render the result.

* Summary
Level: production. Tests: thorough. Docs: boundary, README and ot-cli.

** Scope
*** In scope
- (1) Status cycle order: add ~ot status --cycle forward|back~, and remove
  the order constant from both UIs.
- (2) Create placement: add ~ot create --relative-to <id> --as
  sibling|child~. ~ot~ derives the parent, after-position, local and
  source from the anchor, so remove the placement maths from both UIs.
- (3) Linked-issue URL resolution: the overlay now uses ~ot list~'s
  resolved ~linkedIssues~ (rawToken, label, url), instead of re-resolving
  them through the TS ~getLinkedIssues~.

*** Out of scope
- New keybindings. The key map is unchanged.
- Consolidating the editor and Emacs launch. These use different runtimes,
  so this is left as is.
- Browser and URL opening. This is an OS launch, not domain logic.

** Acceptance
- [ ] ISC-1: ~ot status <id> --cycle forward|back~ returns the resolved
  transition. The order lives in ~lifecycle/status-cycle~.
- [ ] ISC-2: ~ot create --relative-to <id> --as sibling~ inserts after the
  anchor at its level. ~--as child~ nests it underneath. Both inherit the
  local and source settings.
- [ ] ISC-3: ~ot create --relative-to~ with no ~--as~ defaults to sibling.
- [ ] ISC-4: The TUI and pi overlay no longer encode the status cycle
  order or the create-placement maths.
- [ ] ISC-5: The pi overlay renders and opens linked issues from
  ~ot list~'s wire data, not the TS resolver.
- [ ] ISC-6: The boundary, README and ot-cli docs reflect the new
  ownership.
- [ ] ISC-A-1: This must not change the selected-task JSON schema, or add
  new keybindings.

** Decisions
- Chose to put the cycle order in ~lifecycle/status-cycle~, not
  ~commands~ :: this sits beside the rest of the lifecycle semantics, and
  ~ot status --cycle~ reuses it.
- Chose ~--relative-to~ and ~--as~ over passing a resolved parent and
  after-position from the UIs :: the anchor and relation are the real
  intent. ~ot~ already parses the anchor, so it can derive the placement,
  local setting and source routing in one place.
- Chose to pass only ~--after~ for siblings, not ~--parent~ and ~--after~
  together :: ~insert-task-into-file~ treats a set ~parent-id~ as "make it
  a child" (level = the parent's level plus one), so a sibling must derive
  its level from the anchor through ~--after~ alone. This also fixes a
  latent bug in the previous TUI ~create-opts~, which set both for nested
  siblings.
- Chose to delete the overlay's in-process status fallback
  (~applyStatusTransition~ with ~persistChange~ or ~save~) :: this
  duplicated the lifecycle and serialization that ~ot~ owns, and was dead
  code in the live pi path.
