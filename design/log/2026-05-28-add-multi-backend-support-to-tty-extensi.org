* Intent
Give the tty extension (currently tmux-only) a thin vendored backend layer
modelled on ~pi-interactive-subagents~' ~cmux.ts~, so ~/t spawn~, ~/t watch~,
~/t join~, ~/t monitor~, ~/t break~, and ~tty_capture~ can use the best
available cmux / tmux / zellij / wezterm primitives without taking on the full
pi-interactive-subagents package or its subagent-specific coordination
(subagent focus snapshots, cmux subagent tab reuse, zellij stacked-pane
prediction).

* Summary
*Level:* MVP · *Tests:* smoke (extend existing helpers tests; manual smoke per
backend) · *Docs:* inline + extension README + ~pi-tty~ skill backend note.

The tty extension's ~pi/extensions/tty/index.ts~ talks to tmux directly via a
local ~runTmux~ helper plus a tmux-only ~requireTmuxContext~. We replace the
narrow set of mux operations the extension actually needs with a vendored
module (~pi/extensions/tty/mux.ts~, target ≤ ~350 LOC) that exposes a
backend-neutral surface: ~getMuxBackend~, ~isMuxAvailable~, ~muxSetupHint~,
~createWindow(name, command, cwd)~, ~sendCommand(surface, command)~,
~readScreen(surface, lines)~, ~closeSurface(surface)~, plus
~attachSurface(surface, {focus})~ / ~detachSurface(surface)~ for
~/t monitor~, ~/t join~, and ~/t break~.

The vendored base module is derived from
~~/.pi/agent/git/github.com/HazAT/pi-interactive-subagents/pi-extension/subagents/cmux.ts~
(confirmed installed location; upstream npm package
~pi-interactive-subagents~ is *not* present in ~~/.pi/agent/npm/node_modules~
on this machine, contra the task body — use the git checkout). The
attach/detach operations are backend-specific additions validated by the
2026-05-28 parallel review; re-vendor the base primitives on material upstream
changes, but keep tty's attach/detach policy local.

** Scope
*** In scope
- New file ~pi/extensions/tty/mux.ts~ with the primitives above plus internal
  helpers (~hasCommand~, ~shellEscape~, ~tailLines~, ~requireMuxBackend~,
  backend-specific owner-pane/current-pane lookup).
- Refactor ~pi/extensions/tty/index.ts~ to drive ~/t spawn~, ~/t watch~,
  ~/t join~, ~/t monitor~, ~/t break~, ~/t kill~, ~/t tail~, and
  ~tty_capture~ through ~mux.ts~ where the current backend supports the
  requested operation.
- Implement join/monitor as one attach primitive with explicit focus policy:
  ~monitor~ attaches below the pi pane then restores/fixes focus to pi;
  ~join~ attaches below the pi pane then focuses the attached surface.
- Implement break as the inverse detach primitive where available, restoring
  focus to the pi pane after the operation. In zellij, detach means
  "undock back to floating" rather than "move to a separate tab".
- For zellij, ~/t spawn~ creates a floating pane in the pi tab; ~/t monitor~ /
  ~/t join~ dock that managed floating pane into the tiled layout with
  different focus outcomes; ~/t break~ floats it again.
- Backend-native ids in tool output (~%1~/~@1~ for tmux, ~terminal_1~ for
  zellij, ~surface:42~ for cmux, numeric for wezterm).
- Update ~pi/extensions/tty/README.md~ and ~pi/skills/pi-tty/SKILL.md~ with a
  backend capability table rather than a blanket tmux-only caveat.

*** Out of scope
- Event-bus coordination between tty and pi-interactive-subagents
  (~subagent:surface-created~ → ~tty_list~).
- Vendoring subagent-only primitives: ~createSurfaceSplit~,
  ~cmuxSubagentPane~ tab reuse, ~captureCmuxFocusSnapshot~ /
  ~restoreCmuxFocusSnapshot~, ~predictZellijSplitDirection~,
  ~selectZellijPlacement~, ~withZellijSurfaceLock~, ~sendLongCommand~,
  ~pollForExit~.
- Adopting arbitrary user-created zellij panes from other tabs. The extension
  only needs to manage processes spawned from the current pi session; zellij
  support is therefore built around tty-spawned floating panes in the pi tab.
- Fragile zellij keyboard automation (~switch-mode tab~ + ~send-keys b~) for
  true tab break. The supported zellij break operation is floating/undocking a
  managed pane.
- Replacing window-listing for every backend in v1. Use explicit
  backend-native ids for non-tmux attach/detach where discovery is not yet
  implemented; keep broader ~tty_list~ parity as follow-up work.

** Decisions
- *Vendor, do not depend on pi-interactive-subagents.* The package is not a
  runtime dep today and the upstream module is 1334 LOC of mostly
  subagent-specific concerns. Vendoring the shared primitives keeps the tty
  extension free-standing and makes upgrades a deliberate re-vendor.
  Rejected:
  - Add ~pi-interactive-subagents~ as a dependency — pulls in unrelated
    surface area, ties tty's release cadence to upstream.
  - Fork upstream and reuse the JS file directly — same coupling, plus
    distribution overhead.
  - Roll a zellij-only backend in the existing index.ts (previous
    approach, task 77d82282…) — concentrates effort in one backend and
    duplicates work already done upstream.
- *Do not keep join/monitor/break tmux-only.* The initial plan was too
  conservative: tmux, cmux, and wezterm all expose native move/adopt/detach
  operations. Model these as tty-owned attach/detach primitives with explicit
  focus policy, and let each backend pick the cheapest correct sequence.
- *Zellij uses a managed floating-pane model.* Because tty only needs to
  operate on processes spawned from the current pi session, zellij does not
  need arbitrary cross-tab adoption. Create spawned processes as floating
  panes in the pi tab; monitor/join embed them via
  ~toggle-pane-embed-or-floating~ (then focus pi or target respectively);
  break toggles them back to floating and restores focus to pi. Idempotency
  guards read live zellij state from ~list-panes --json --tab --state
  --geometry~ rather than trusting only tty's in-memory ledger.
- *Use ~PI_TTY_MUX~ rather than ~PI_SUBAGENT_MUX~.* The tty extension is not a
  subagent extension; keeping its override name local avoids coupling while
  still allowing users to set both env vars if they want cross-extension
  consistency.
- *Keep ANSI-preserving capture tmux-only for v1.* If ~tty_capture~ is called
  with ~preserveEscapes=true~, bypass generic ~mux.readScreen~ and use the
  existing tmux capture path; non-tmux backends ignore or reject the flag with
  documentation rather than inventing inconsistent ANSI capture semantics.
- *Single per-backend dispatch module, no per-backend subclasses.* Match
  upstream cmux.ts shape (~switch~ on ~MuxBackend~ inside each exported
  function). Premature abstraction otherwise.
- *Backend-native ids leak into tool output.* Matches how cmux.ts itself
  treats surface ids; lets users copy-paste ids into ~tmux~/~zellij~/~cmux~
  CLI without translation. Documented in ~tty_capture~ tool description.
- *~tty_list~ parity is follow-up work, not a blocker for attach/detach.*
  Tmux already has full discovery; wezterm/zellij/cmux have possible list
  commands, but v1 can accept explicit backend-native ids and document any
  discovery gaps.

** Risks
- *Upstream cmux.ts drifts.* Vendored copy becomes stale; mitigation is the
  ** Follow-ups note + a header comment in ~mux.ts~ citing the source
  commit/path.
- *Zellij toggle is not idempotent.* ~toggle-pane-embed-or-floating~ must be
  guarded by ~list-panes --json --tab --state --geometry~ (or tracked state)
  so monitor/join only embed floating panes and break only floats embedded
  panes. Mitigate with tests for repeated monitor/break calls.
- *Zellij placement is approximate.* Embedding a floating pane lets zellij pick
  its tiled layout position; add optional ~move-pane --pane-id <target> down~ /
  resize polish only if the default placement is awkward during smoke.
- *Wezterm same-tab move bug.* ~split-pane --move-pane-id~ has a known
  same-tab bug; guard against source/destination in the same tab or refuse
  that case. Cross-tab moves are the intended path.
- *Cmux split-off availability is uncertain.* ~move-surface~ is confirmed;
  ~split-off~ is documented in cmux's agent reference but absent from the
  public website docs. Probe at runtime and fall back to ~new-split~ +
  ~move-surface~ + ~close-surface~ if needed.
- *Wezterm/cmux not present on the workstation.* Cannot smoke-test those
  paths locally; verify command construction with tests and mark manual smoke
  pending for machines running those backends.
