* Intent

Give `oh` first-class checkout isolation for concurrent subagents without changing the initial shared-tree workflow. The parent resolves each child's checkout target and owns integration; non-shared publication mechanically checkpoints work on the child's branch so recovery and reconciliation do not depend on prompt compliance.

* Summary

*Level:* production · *Tests:* thorough · *Docs:* full

`oh task run|start` resolves one checkout target before allocation: the caller's checkout, an existing attached same-repository checkout named by `--worktree <path>`, or a new managed checkout named by `--worktree new` or selected automatically for an additional concurrent write-enabled child. Publication from a non-shared checkout mechanically commits pending nonignored changes and adds its authoritative tip as `CHECKPOINT`; shared-root publication never mutates Git, and a read-only child with dirt is refused. Ledger identity follows the child lineage, reconciliation distinguishes committed, dirty, and ignored paths, and teardown removes only guarded managed checkouts while retaining branches for parent-owned integration.

** Scope

*** In scope

- One target resolver for shared, existing, and new checkouts; canonical same-repository validation; managed creation before pane mutation; existing-target live-reference refusal.
- Value-taking `--worktree <path>|new`, with implicit managed isolation only for an additional concurrent write-enabled child; explicit paths remain legal for read-only children.
- Lineage-owned `:worktree` identity, `continue` carry-forward, mechanical publication checkpoints, optional `CHECKPOINT` envelope field, and retry-safe commit-before-append ordering.
- Reconciliation on collect/status/list and explicit `oh worktree list|remove` with ownership, liveness, dirt, ignored-path reporting, and canonical managed-root containment.
- Parent integration guidance and operator recovery when `.tmp/` or its ledger has been cleared.

*** Out of scope

- Merging, rebasing, pushing, deleting branches, or resolving edit conflicts on the parent's behalf.
- Treating checkout isolation as proof that overlapping edits compose or that parent-side remeasurement can be skipped.
- A third placement mode, a worktree passthrough group, a config key, or automatic file-overlap analysis.
- Removing an externally supplied checkout; only managed checkouts under the assignment root are teardown-owned.

** Decisions

- Separate target mechanics from child behaviour :: `--worktree` answers where; the child receives no topology or permission signal. The rejected marker-trait and `HERDR_ORCH_WORKTREE` designs coupled spawn mechanics to prompt composition, and one route demonstrably failed to deliver the directive.
- Checkpoint at publication, not in the persona :: `worker.md` retains its fail-safe no-commit default; an accepted worktree publication stages and commits mechanically before writing the envelope. Rejected: auto-applying a `no-commits` trait to the shared root, which makes a missing prohibition fail open.
- Resolve one target before allocation :: explicit `new`, explicit path, and the in-flight default converge before ledger construction and placement. Existing non-shared paths reuse the teardown liveness predicate; explicit shared-root selection remains the parent's override.
- Worktree identity belongs to the child lineage :: path, branch, base, and repository witness carry through continuation; round state does not re-resolve topology.
- Reconciliation keeps committed, dirty, and ignored sets distinct :: each requires a different parent action; a union would hide whether to integrate, rescue, or ignore.
- Teardown owns only managed checkout directories :: canonical containment, ownership, liveness, and tracked/untracked dirt are hard guards; ignored paths and tip ancestry are information. The branch always remains parent-owned.
- Keep packaged interactive trait expansion as a general capability :: the worktree marker fragments and gates were deleted, but the packaged interpolation layer remains useful independently.

** Gotchas

- `git status --porcelain` omits ignored files, while `git worktree remove` can delete a checkout containing only ignored data at exit 0; reconciliation/removal therefore query and report ignored paths separately.
- Checkout containment must compare canonical path components, not strings: a same-prefix sibling and a symlink under the managed root both reached external linked checkouts in adversarial probes.
- Commit-before-append can leave a successful checkpoint with no envelope when append fails; retry must report the current tip even when there is no new dirt and no new commit.
- A non-shared explicit target must retain the live-reference guard deleted with task-addressed reuse, or two children can race in one index and publication can sweep the other's changes.

** Risks

- Clearing `.tmp/` before a child publishes can still destroy uncheckpointed work; WAITING checkpoints reduce but cannot eliminate the interval. Git retains already-committed branch objects, and `git worktree prune` repairs stale registration after the directory is gone.
- Retained `orch/*` branches accumulate until the parent integrates or deletes them; this is deliberate because `oh` cannot know whether squash, cherry-pick, merge, or abandonment is correct.
- The initial write-enabled child still shares the caller's checkout by design; isolation protects additional concurrent writers, not the baseline workflow.

* Implementation

- Managed branches use `orch/<task-prefix>` and checkouts use `<assignment-root>/.tmp/herdr-orch/worktrees/<task>`; ledger identity is persisted before creation so partial failure remains discoverable.
- Existing targets record canonical checkout path, attached branch, assignment-time HEAD as base, and canonical common-Git-directory identity. The current target drives ledger identity, creation, and pane cwd; trigger provenance is intentionally absent.
- Publication runs all existing refusals before Git mutation, then validates the recorded checkout and branch, stages with `git add -A`, commits only a changed index using `herdr-orch checkpoint <task> <status>`, records HEAD as `CHECKPOINT`, appends, and notifies. Read-only dirt refuses before staging; shared entries never enter this path.
- Worktree removal validates ownership and canonical managed-root containment before liveness and dirt, reports ignored paths without refusing on them, removes only the checkout, and retains the branch regardless of ancestry.

* Validation

- A throwaway Git probe reproduced ignored-file loss: `status --porcelain` reported clean and `git worktree remove` deleted the checkout; the final test proves `!! ignored.cache` is reported separately while removal remains allowed.
- Adversarial ledger-path probes pointed removal at a textual-prefix sibling and through a managed-root symlink; both external checkouts survived after canonical containment was added.
- The explicit-path reuse test was first observed accepting a second live child and creating a ledger entry; the restored shared liveness predicate makes the same test refuse before allocation while allowing reuse after the prior round seals.
