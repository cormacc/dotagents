* Intent
Route a weight alias (`heavy`, `middle`, ...) to the highest-ranked candidate model whose subscription still has allowance, balancing equal-rank candidates by remaining allowance, so that a spawn does not land on an exhausted Anthropic or ChatGPT/Codex subscription. Expose the allowance query as `oh usage` so pi and Herdr integrations can display it.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* README

Feature delivery, approved live fixture capture and the four owner-approved behaviour-preserving simplifications are complete; acceptance and scope are unchanged. No authored commit or push was made. An alias value in `config.edn` may be a vector of `{:model :rank}` candidates. At spawn, `oh` filters candidates to the providers the resolved harness kind can run, fetches each provider's remaining allowance through its cached harness OAuth token (read-only, cached per provider), and picks by rank, then known-before-unknown allowance, then larger remaining fraction, then config order. String aliases and canonical IDs resolve exactly as before with no usage call. `oh usage` reports per-provider allowance; `/oh usage` and bare `/oh` render it. Endpoint facts: [[file:2026-11-04-subscription-routing/usage-endpoint-research.md]].

** Acceptance
*** Core functionality
- [X] A vector-valued alias resolves to the highest-ranked candidate whose provider has credit; equal rank breaks by larger remaining fraction, then config order.
- [X] A kind's `:providers` set excludes candidates before ranking; a kind without the key accepts every provider.
- [X] A string alias or canonical ID resolves exactly as today and makes no usage call.
- [X] A candidate's remaining fraction is `1 - max(used)` over the provider's account-wide windows plus any model-scoped window whose family token matches the candidate's canonical basename.
- [X] `oh usage` reports, per configured provider: credential source, each window (name, scope, used fraction, reset time), remaining fraction, status `ok`/`stale`/`unknown`, and the reason when not `ok`.
- [X] `oh usage --format json` returns a `herdr-orch/v1` envelope whose `result` is keyed by provider and documented in the contract.
- [X] `--print-prompt`, the `task start` envelope and the ledger entry carry `:model-route` with candidates, each allowance, and the chosen canonical ID.
- [X] `HERDR_ORCH_MODEL` injected into a routed child is the chosen canonical ID, so a same-kind grandchild inherits a concrete model and does not re-route.
- [X] The shipped `config.edn` uses the new shape; `heavy`, `middle`, `light`, `feather` each list an anthropic and an openai-codex candidate; `bb test` passes with the updated `shipped-config-invariants` and weight table.
- [X] `/oh usage` renders each configured provider's remaining fraction, or `unknown` with its reason; bare `/oh` includes the same block after the spawn defaults.
- [X] Contract 'Model resolution' and 'Usage' sections, `README.org` and the extension README describe routing, `:providers`, `oh usage` and the cache.
*** Edge cases
- [X] No candidate with known credit and no `unknown` candidate refuses the spawn, naming each candidate and its allowance, before any ledger or pane mutation.
- [X] A provider with status `unknown` is chosen only when no known-credit candidate of equal or higher rank exists, and the envelope records the reason.
- [X] A provider with status `stale` counts as known, with its last good allowance.
- [X] A provider without `:usage` (local) always has remaining fraction 1.0 and status `ok` with no fetch.
- [X] An expired cached token yields `unknown` with reason `expired`; nothing refreshes or writes a credential store.
- [X] A 401/403 yields `unknown` with reason `auth`/`scope`; a 429 or 5xx negative-caches for `max(Retry-After, ttl)` seconds and serves the last good payload as `stale`.
- [X] An HTTP call that exceeds 5 s yields `unknown` with reason `timeout`.
- [X] The cache is keyed by provider, honours that provider's `:cache-ttl-s`, is written by atomic rename, and `--fresh` bypasses it.
- [X] A fetch writes a 30 s claim marker first; a second caller inside the claim window reads the cached snapshot instead of fetching.
- [X] A stale snapshot older than 60 min is not served; status becomes `unknown` with reason `stale-expired`.
- [X] A `null` Codex `primary_window` or `secondary_window` is skipped; a single-window response routes normally.
- [X] Both Anthropic response shapes (flat `five_hour`/`seven_day`/`seven_day_<family>` buckets and `limits[]`) normalise to the same windows; a `null` bucket or a 0 % bucket with `null` reset is skipped.
- [X] A model-scoped window whose family matches no candidate is reported by `oh usage` and affects no route.
- [X] Config validation names the file for: a candidate `:model` that resolves to a vector alias, an unknown provider prefix, a missing or non-positive `:rank`, a `:harnesses :providers` member absent from `:providers`, an unknown `:usage` adapter, or a `:credentials` member outside `#{:pi :claude :codex}`.
- [X] Usage adapters are exercised by fixture responses through a fake HTTP function; no test contacts a provider. Verified for the final harness. An earlier verification run breached this requirement; see [[*Validation]].
*** Anti-criteria
- [X] Must not: print, log, cache, envelope or include in an exception a token or refresh token (a test asserts no fixture token prefix appears in any output or cache file).
- [X] Must not: refresh, rotate or write any credential store.
- [X] Must not: change harness kind during routing.
- [X] Must not: silently downgrade when every candidate is exhausted.
- [X] Must not: add in-session failover, retry or successor logic.
- [X] Must not: let the `/oh` usage entry enter model context (same session-entry mechanism as the roster).

** Decisions
- Keep fallback discrete :: task c3ae685d ([[file:2026-11-04-model-fallback.org]]) is in-session failure classification and successor authorisation; its open questions concern replay safety, not selection. Its implementation task is blocked on this task; its "allowed fallback targets" question is answered by the alias's ranked set. Rejected: absorbing it, which would force the replay-safety contract into a routing record.
- Config shape :: `:models` rows keep canonical keys (native spelling survives) and lose the cross-provider columns; `:aliases` values are a string (single hop, unchanged) or a candidate vector; a new `:providers` map carries `:usage`, `:credentials`, `:cache-ttl-s`, optional `:reserve`; `:harnesses` gains `:providers`. Merge semantics unchanged: `:aliases`/`:defaults` per key, `:models`/`:harnesses`/`:providers` rows wholesale. Rejected: the draft `config.new.edn` inversion (short name → canonical in `:models`), which drops per-kind spellings.
- Usage adapters inside `oh` (Babashka, `babashka.http-client`), reading harness credential files directly :: routing lives in `oh`, and claude/codex roots have no pi extension. Rejected:
  - Shell out to a harness usage command: none is non-interactive.
  - Fetch in the pi extension and pass to `oh`: blind outside pi.
  - External collector (agent-router, ccusage): agent-router calls neither endpoint; a Node dependency for a few HTTP calls.
- Allowance metric :: minimum remaining fraction across windows (account-wide plus matching model-scoped), 0.0--1.0; the config never names a window. Threshold is `> :reserve` (default 0).
- Unknown is eligible but unranked :: a provider whose allowance cannot be determined is used only when nothing known has credit at that rank or above; never a spawn failure on its own.
- Exhaustion refuses :: no silent downgrade; an explicit string model bypasses routing.
- Per-provider cache TTL :: shipped anthropic 300 s (third-party polling of `api/oauth/usage` draws persistent 429), openai-codex 60 s; negative cache on non-200 honouring `Retry-After`; a 30 s claim marker so concurrent spawns make one fetch; last good payload served as `stale` for at most 60 min. Rejected: reading another extension's cache file (for example `~/.pi/agent/pi-minimal-footer/`): a herdr-orch extension will own display of this data and must not depend on another pi extension's format.
- Request headers per provider :: Anthropic sends `anthropic-beta: oauth-2025-04-20` and a `User-Agent: claude-code/<version>` (the third-party reference attributes stricter rate limiting to other user agents; this causality was not tested); Codex sends `ChatGPT-Account-Id` when the store carries an account id, `Accept: application/json` and a `User-Agent`. Header values are config-free constants in the adapter.
- Model-scoped windows gate their family only :: a scoped window (Anthropic `seven_day_<family>` / `limits[] weekly_scoped`, Codex `additional_rate_limits`) applies when its lower-case tokens form a contiguous run in the candidate's canonical basename. Hyphens, underscores and spaces split tokens; dots do not. Generic or numeric scope tokens can match several families; revisit if providers use non-family scope identifiers.
- Scope of `HERDR_ORCH_MODEL` :: the chosen canonical ID, not the alias, so inheritance is concrete and routing happens once per spawn.

- Both endpoints are unofficial. Shape failures become `unknown`; provider error-body variants remain incompletely observed.
- Anthropic usage-endpoint rate limiting is anecdotal; tokens without `user:profile` can return 403. Provider caches and negative backoff limit polling.

* Implementation
- Shipped :: ranked alias configuration and provider filters, pure routing, read-only usage adapters/cache, `oh usage`, routed spawn provenance and concrete inheritance, and Pi `/oh usage` plus the bare `/oh` usage block. The declared contract and both READMEs describe the delivered interfaces.
- Simplified ownership :: `canonical-model` owns candidate alias resolution; stable sorting preserves configuration-order ties; `partition` matches contiguous scope tokens; one cache-answer rule serves both sides of claim acquisition. Timeout exception handling and explicit route-record conversion remain unchanged.
- Failure policy :: authentication, scope, malformed response and timeout failures remain `unknown` on immediate and cached reads. HTTP 429/5xx and network failures can serve the last good snapshot within 60 min. The full HTTP exchange is bounded; unwritable caches permit uncached queries.
- Live fixtures :: [[file:2026-11-04-subscription-routing/live-fixtures.md]] records the approved capture and redaction limits. Captured bodies supplement synthetic edge-case fixtures and replay offline through the adapters.
