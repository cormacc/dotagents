** Acceptance
Proposed criteria; not yet approved.
*** Core functionality
- [ ] Two concurrent workers each discover only their own candidate.
- [ ] Single-worker behaviour remains unchanged.
- [ ] A failing worker removes its own candidate without removing a sibling's candidate.
*** Edge cases

- [ ] Required project context is retained in the selected isolation design.
*** Anti-criteria

** Decisions
- Document serial execution immediately :: both runners expose `--num-workers`; one worker avoids overlap inside one process. Also require one trigger-eval process per project root. This does not solve leftover or unrelated candidate files.
- Prefer an upstream isolation fix :: `skills/README.org` classifies the runner as vendored. Rejected:
  - Unique filenames alone: they prevent file collisions, not discovery contamination.
  - Unreviewed scratch-project substitution: changing the working directory can remove project context and change what the eval measures.

** Shipped

* Implementation

- `run_eval` dispatches queries through `ProcessPoolExecutor(max_workers=num_workers)`; `run_loop` passes its worker count through to it.
- The stored task records an earlier multi-worker recall failure. This session has not rerun that model experiment.

Failure and timeout controls each observed a candidate before confirming cleanup. No model was invoked. ** Upstream report draft
Title: Concurrent Claude trigger queries share candidate discovery.

`_run_single_query_claude` writes each query's unique command file into the same project `.claude/commands/` directory before starting the CLI from that project root. A fake CLI that records visible command filenames observes one candidate for a single call, but both concurrent calls observe the same two candidates. Unique filenames avoid overwrites but do not isolate discovery. The stored model observation is reduced recall when a worker selects its sibling's candidate; the fake-CLI reproduction demonstrates visibility, not model choice. A fix needs isolated discovery per query while retaining the project context that the eval intends to measure. Serial workaround: `--num-workers 1` and one trigger-eval process per project root. Failure and timeout cleanup already remove the worker's own file. This report is a local draft; it has not been submitted.
