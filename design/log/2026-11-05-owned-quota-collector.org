* Intent
Replace quota-axi with direct Babashka subscription collection for Anthropic and OpenAI. Use credentials belonging to the consuming harness, leave refresh with that harness, and remove quota-specific npm installation and process supervision.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* README

One read-only Babashka collector owns HTTP, provider normalisation and a bounded cache; quota-axi and its setup/deployment path are removed. The consuming harness selects the credential context; routing consumes fresh validated subscription evidence. Kimi, Qwen and Z.AI are deferred.

** Scope
*** In scope
- Anthropic subscription usage and OpenAI Codex subscription usage; existing local-provider behaviour.
- Pi-aligned credential detection, explicit native harness contexts, credential expiry, model scopes, window duration, cache/backoff and concurrent callers.
- CLI JSON/text/markdown/status reporting, Pi user-only usage entries, Herdr quota pane and tab-bar consumers.
- Living contracts listed above: update credential ownership, evidence shape, provider configuration, setup removal and reporting prerequisites.
- Dotfiles integration: remove quota-driven root dependency installation from =/home/cormacc/dotfiles/agents.nix=; review =/home/cormacc/dotfiles/README.org= and =/home/cormacc/dotfiles/AGENTS.md= for corresponding instructions.
*** Out of scope
- New providers or routing candidates; multi-account discovery, profile switching or a credential-management service.
- Owned OAuth exchanges, refresh-token writes, login flows or vendor CLI refresh delegates.
- Changes to rank/reserve policy, explicit-model bypass, harness restrictions or terminal ownership rules.
- Removal of Node, development tooling or npm installation needed by unrelated Pi extensions.

** Decisions
- Chose direct Babashka adapters :: two required providers do not justify an npm collector, installer and process supervisor. Reuse reviewed parts of =usage.clj= at =b8e5e99^= rather than restore that revision wholesale.
  Rejected:
  - Retain quota-axi and simplify discovery: retains the external schema, process and credential-selection boundaries.
  - Exact historical revert: restores provider-keyed output, implicit store fallback and normalisation rules that do not match the chosen contract.
- Harness-owned credentials and refresh :: the collector reads the active harness store but never refreshes it. Missing, expired or unreadable credentials return fixed unknown/authentication reasons. A later read can use credentials refreshed through normal harness operation; no quota read launches a harness merely to refresh.
- Source selection :: Pi reporting defaults to the active Pi credential context, respecting its supported location overrides. Routed launches select the destination harness context. Standalone native reporting requires an explicit context; neither missing credentials nor an expired token permits silent fallback to another harness. Background status defaults to Pi unless explicitly configured otherwise.
- Small credential boundary :: verified file-store rules match the installed consumers within the documented limits. Detected native OS stores return unknown without prompting or falling back. Public evidence has no account identifiers or credential paths. SDK in-memory and per-request overrides are outside this process's visibility.
- Owned evidence :: retain the =herdr-orch/v1= envelope and providers-array structure. Keep fresh/unknown state, safe windows, exact effective scopes and fixed reasons; remove the claim that an owned report is quota-axi schema 5/6. Update consumers and migration documentation in the same change. Do not maintain a second legacy output shape.
- Subscription semantics :: account bounds apply to each applicable model scope; explicit model bounds add constraints. Keep duration separate from scope. A Codex base window of 2,592,000 seconds remains an account bound rather than losing numeric credit because its duration is unfamiliar. A present Anthropic limits array is authoritative; malformed or unresolved entries cannot silently fall back to more generous flat buckets. Unrecognised scope relationships remain unknown; monetary credits and code-review-only budgets do not grant ordinary model-routing credit.
- Cache :: keep TTL reuse, negative caching, =Retry-After= and cross-process request coalescing. Associate snapshots with the selected credential context; detect credential changes before reuse. Expired credentials invalidate numeric credit. Stale evidence is diagnostic only. =--fresh= bypasses normal reuse without bypassing in-flight coordination or provider-directed rate-limit backoff.
- Deployment :: remove quota-axi discovery, setup, guardian and npm dependency. Remove =/oh setup= and its automatic readiness checks; ordinary usage reports explain authentication failures instead. Do not delete an existing user-local install or modify harness credentials during migration.

- Cache complexity can erase the simplification :: keep one snapshot/backoff/coalescing mechanism; do not retain quota-axi or add a service as a second backend.
- Dotagents and dotfiles are separate Git repositories :: verify the parent activation change independently; sequence the submodule update only after the collector no longer needs quota-axi.

* Implementation
- =herdr-orch.quota-credentials/credentials= is a private, read-only boundary. Its ready result is never serialised; its credential-generation digest selects the cache and OS file lock. One lock mechanism coalesces callers, including independent fresh requests. Failure snapshots retain labelled diagnostic windows for at most one hour, never effective routing credit.
- Verified Pi 1.5.0 =getAgentDir=, =ReadOnlyAuthStorage= and =normalizePath= from installed source, and Claude Code 2.1.317 file/override rules from embedded installed source. Codex 0.166.0 binary identifiers and current OpenAI =codex-rs/login/src/auth/storage.rs= establish the file/config boundary; the installed-version source URL was unavailable, so exact source equivalence is not claimed.
- Offline consumers use a test-only file-backed HTTP transport. Production code has no fixture environment hooks. Loopback tests exercise whole-response deadlines, body bounds, socket closure, redirects and two independent Babashka callers; credential and process guards have passing and known-bad controls.
