* Intent
Make existing task subtrees movable from either task browser. Support explicit sibling ordering without manual Org edits.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* full

** Scope
*** In scope
- CLI sibling-relative placement through ~--before~ or ~--after~.
- A move destination picker in the standalone TUI and pi overlay.
- CLI contract, UI boundary, skill and reference documentation listed above.
*** Out of scope
- Cross-file moves, archive relocation, automatic section creation and general task editing.

** Acceptance
*** Core functionality
- [X] ~ot move <id> --before <anchor>~ inserts the subtree as the anchor's preceding sibling.
- [X] ~ot move <id> --after <anchor>~ inserts the subtree after the anchor's whole subtree.
- [X] Existing ~--parent~ placement appends as the last child.
- [X] Existing ~--section~ placement appends within the named existing section.
- [X] The standalone TUI offers a move destination picker.
- [X] The pi overlay offers a move destination picker.
- [X] Both UIs dispatch moves through ~ot move~.
- [X] Documentation states that destination sections must already exist.
*** Edge cases
- [X] Moves reject self and descendant destinations without writes.
- [X] Moves reject cross-file destinations without writes.
- [X] Conflicting destination options fail before writes.
- [X] Cancelling either picker leaves task files unchanged.
- [X] Source-before-destination and source-after-destination moves use the correct post-cut position.
*** Anti-criteria
- [X] Must not: change task UUIDs, properties, body text or descendant order.
- [X] Must not: introduce a second writable node for imported tasks.
- [X] Must not: write on ~--dry-run~.

** Decisions
- Use four mutually exclusive destination modes: parent, section, before, after. Relative modes infer the anchor's parent and depth; no separate parent is needed.
  Rejected:
  - Ordering modifiers combined with parent/section: redundant destination information introduces mismatch handling.
- Retain the line-splice implementation to preserve source text; both UIs delegate durable validation and writes to the CLI.
  Rejected:
  - UI-owned move logic: duplicates the file and graph safety rules.
- Require pre-existing sections. A section-creation flag is unnecessary for the selected ordering and UI scope.
- Use ~m~ for move within each browser; choose relation then destination. Sections use a name input; task destinations use a same-file picker.

* Implementation
- Relative placement resolves the anchor again after cutting the source. Its in-file parent determines the result, independently of imported display-tree ancestry.
- The standalone browser uses a modal picker; pi closes its overlay before native dialogs. Both refresh after mutation and retain the cursor task where possible.

* Validation
- Inspected renderer snapshots for the relation picker, task picker, section input and a scrolled long list at 70 columns, plus the pi overlay at 160 columns. These are renderer snapshots, not a live terminal-input smoke test.
