* Summary
Added a first-class condensed memory layer to change-records so future agents can rebuild context from a small, stable surface before reading the full execution ledger. =* Summary= becomes a top-level section required on every change-record (any size, any status past Draft), superseding the legacy =** Outcome= / =** Shipped= heading under =* Implementation=. =* Context= is demoted from required to optional and is promoted only when durable rationale exceeds what =* Summary= can carry. =org-tasks= teaches a layered resume read order that loads =* Summary= first, then =* Context= (when present), =:HANDOFF:=, blockers, open questions, and actionable plan items, deferring full =* Implementation= and completed plan bodies. A closure-time prompt in the tasks extension nudges the agent to generate =* Summary= when a top-level task transitions to =DONE= and its linked change-record either lacks the section or has not been touched since =:STARTED:=. Convention applied retrospectively to nine high-value records across this repository, =~/dotfiles=, and =~/nmd/products/connect/portal=.

** Decisions
- Layered memory, not less detail :: Granular plans and implementation notes preserved for auditability; =* Summary= is the default agent-ingestion surface.
- Section name :: =* Summary= (over =* Memory=) — matches existing =** Outcome= / =** Shipped= language; "memory" is the section's purpose, not its name.
- =* Summary= supersedes =** Outcome= / =** Shipped= :: One canonical condensed surface, not two. Retrospective summaries absorb prior outcome text and remove legacy headings.
- =* Summary= always-on; =* Context= optional :: Inverts the original threshold model. =* Summary= is required on every change-record regardless of size; =* Context= is included only when durable rationale exceeds the synopsis. The size of a record is no longer a criterion for *whether* to summarize — only for whether to split or archive completed history.
- Closure discipline lives in skill *and* tasks extension :: Skill is the durable contract; extension prompts on =DONE= when =* Summary= is missing or stale (file mtime predates =:STARTED:= with a 60s grace).
- Comprehensive retrospective backfill :: All existing change-records across the three known org-memory repositories adopt =* Summary= in this same change to match the always-on rule. The earlier "existing records are not bulk-rewritten" carve-out was a v1 artefact and has been retired.

* Context
The org-memory skill set is working well as task-tracking and planning infrastructure, but the change-records are also serving as durable agent memory. Recent records show the useful tension: detailed =* Plan= and =* Implementation= sections are valuable while executing and auditing work, but they can be expensive and noisy when a later agent only needs to regain context for future planning.

The desired direction is to keep the detailed record rather than flattening it, while adding a compact memory surface. Agents should ingest =* Summary= plus =* Context=, =:HANDOFF:=, blockers, open questions, and actionable plan items first; completed task details, LOGBOOK entries, and lengthy implementation notes should be read only when needed.

This plan continues the agent-memory work captured in =design/log/2026-05-01-org-memory-agent-memory-review.org=, which added the =Agent memory= section to =org-tasks/SKILL.md=, lifecycle LOGBOOK semantics, and import-path sandboxing. That review built the resume checklist and identified per-record cost as the next pressure point; this plan adds the condensed summary layer the resume checklist needs.

This plan intentionally applies the proposed convention to itself: it leads with =* Summary=, keeps detailed rationale in =* Context=, tracks executable work in =* Plan=, and leaves =* Implementation= as the future audit trail.

** Design decisions
- =* Summary= is required on non-trivial change-records :: Top-level placement before =* Context= so agents and humans see the compact final state before the detailed rationale and ledger.
- =* Summary= supersedes =** Outcome= / =** Shipped= :: One canonical condensed surface, not two. Retrospective summaries on existing records absorb the prior =** Outcome= text and remove the legacy heading.
- Summary subsections are conventional, not mandatory for tiny records :: =** Decisions=, =** Shipped=, =** Gotchas=, =** Validation=, and =** Follow-ups= provide a repeatable shape. Small records may use a single paragraph plus only the relevant subsections.
- Closure discipline lives in skill *and* tasks extension :: The skill is the durable contract; the extension prompt is a cheap reinforcement that keeps the convention from rotting under deadline pressure.
- =* Summary= always-on; =* Context= optional :: After the v1 implementation pass, the size threshold for triggering =* Summary= was identified as redundant (closure-time tooling already enforced always-on) and as conflating two concerns. Refined: =* Summary= is unconditional, =* Context= is promoted only when durable rationale exceeds the synopsis. Size is now a *splitting* signal for completed history, not a summarize-or-not signal.
- Tooling should scaffold the convention :: The tasks extension's change-record scaffolder emits =* Summary= up front so new records start in the right shape.
