* Intent

Mechanize the herdr-subagents delegation contract as an in-skill CLI (`subagent`: tiny Bash launcher + Babashka implementation, mirroring `ot`) so a parent spawns/collects a subagent in 1–2 tool calls instead of ~10–15, the child publishes its result with one command instead of hand-transcribing an envelope, and SKILL.md shrinks to decision guidance plus safety semantics.

* Summary

*Level:* MVP · *Tests:* thorough · *Docs:* inline + scripts README

** Scope
*** In scope
- New `skills/herdr-subagents/scripts/` tree: `subagent` Bash launcher, `src/herdr_subagents/`, `test/`, wired into root `bb.edn` / `deps.edn` (contract doc impact: [[proj:skills/herdr-subagents/SKILL.md]], see =#+SPEC:=).
- Parent commands: blocking `run`, non-blocking `start` + `collect`, `status`/`list` assignment inspection.
- Child command: `publish` — atomic, no-overwrite, exactly-once result publication reading identity from injected env.
- Automation inside those commands: pre-mutation Herdr capability checks, roster discovery, kind/model resolution, caller-rect split geometry, index/label allocation, ledger entry, `pane split --env` assignment/policy injection, rename+verify, `agent start`/`prompt`/wait loop, envelope validation, non-blocking success notification, and eligible-pane cleanup.
- Tests: pure-logic units, fake-`herdr` integration (PATH shim), root + nested live smoke.
- SKILL.md rewrite delegating mechanics to the CLI while keeping safety semantics normative.
*** Out of scope
- Resident lifecycle commands and `many` fan-out waves (ledger schema leaves room; commands deferred to follow-ups).
- General pane management wrapping (`subagent` is not a `herdr pane` porcelain; parents keep using `herdr` directly for non-delegation work).
- Changes to Herdr, the vendored `skills/herdr/SKILL.md` (byte-identical to upstream by contract), or `@ogulcancelik/pi-herdr`.
- Harness-specific integration (pi extension/tool); the CLI must work from any harness with shell access.
- Publishing a second `bbin` entry point; in-tree launcher path only for MVP.

** Decisions
- Command name = `subagent` :: explicit and readable in prompts and shell commands; no existing PATH collision at planning time.
- Chose Babashka implementation behind a tiny Bash launcher (the `ot` pattern) :: proven in-repo layout (`bb.edn` paths, `src`/`test`, launcher resolving repo root with `-Sdeps` fallback); safe ProcessBuilder-style argv via `babashka.process`; pure functions are unit-testable; JSON in/out via bundled cheshire.
  Rejected:
  - Pure Bash scripts: ledger/JSON/atomic-publish logic in Bash is fragile, untestable, and reintroduces string-splicing injection risk for prompt text.
  - pi extension / pi-herdr change: harness-specific, and pi-herdr is upstream-owned npm (established in [[proj:design/log/2026-07-23-add-hierarchical-pane-labels-to-herdr-su.org]]); the skill must stay harness-agnostic.
  - Folding commands into `ot`: wrong domain — `ot` is the org-tasks protocol engine; coupling delegation mechanics to task memory helps neither.
- Assignment injection via `herdr pane split --env` :: verified live on herdr 0.7.5 — repeated `--env KEY=VALUE` flags propagate into the child pane shell and are inherited by `agent start`. Child `subagent publish` reads `HERDR_SUBAGENT_CHILD`/`_TASK`/`_RESULT`, `_BIN` with the launcher's absolute path, and `_WAITING_POLICY=blocking|non-blocking`; prompts shrink, transcription errors disappear, and successful non-blocking publication can emit the required operator notification. Prompt text still states task + persona path; the result contract collapses to "run `$HERDR_SUBAGENT_BIN publish ...`".
- Atomic no-overwrite publish via hard-link-then-unlink :: POSIX `rename(2)` silently overwrites, so `Files/move` + `ATOMIC_MOVE` cannot guarantee no-overwrite. `publish` writes the sibling temp, then `Files/createLink(result, temp)` (fails `FileAlreadyExistsException` when `RESULT` exists), then unlinks the temp. Same-directory link keeps it one filesystem.
- File-based ledger under `<assignment-root>/.agents/tmp/herdr-subagents/ledger/` :: one JSON file per assignment keyed by `TASK`; per-(parent-agent-session, type) index allocated by atomically creating marker files (`O_CREAT|O_EXCL` loop) — lock-free, concurrency-safe, and honours the existing gitignored tmp convention. Parent identity comes from `herdr agent get "$HERDR_PANE_ID"` session metadata so a moved pane preserves its counter while a restarted parent begins a new session; the pane ID remains recorded as topology context.
- MVP is one ephemeral child :: `run`/`start`/`collect` cover blocking and non-blocking single delegation; residents and wave fan-out stay documentation-only until demand exists (ledger fields don't preclude them).
- CLI-composed invariant prompt with opaque assignment input :: `--task`, `--task-file`, or stdin supplies the parent-owned task body unchanged; the CLI adds persona, leaf/delegation, identity, publication, and lifecycle instructions. `--prompt-extra` handles exceptional constraints and `--print-prompt` makes composition inspectable; a raw-prompt mode is excluded from the MVP because it would reintroduce protocol omission and transcription risk.
- Ten-minute total default budget for blocking waits :: `run --timeout` overrides it; timeout is non-final and retains the pane. `collect` is an immediate poll unless `--wait` is supplied with a bounded timeout. The result file is checked immediately before and after every bounded lifecycle wait regardless of outcome, with each wait bounded by the remaining total budget.
- Caller geometry comes only from its matching layout pane rect :: select `.result.layout.panes[*]` where `pane_id == $HERDR_PANE_ID` and apply the geometry rule to that entry's `rect.width`/`rect.height`; tab `area` and focus are unrelated when the caller is an unfocused split.
- Preflight capabilities before mutation :: require `HERDR_ENV=1`, parse a supported minimum Herdr version, and non-mutatingly inspect help for every required command/flag (`pane layout/split --env/rename/get/close`, `agent start/prompt/wait/get`, `notification show`) before ledger allocation or pane creation. Missing shapes return an actionable JSON error.
- Guarded live-smoke task :: `bb smoke-subagent` requires Herdr, explicit `SUBAGENT_LIVE_SMOKE=1`, and an explicit model because it launches billable agents; it exercises root and nested flows but never joins `bb test` or CI.
- `subagent` emits concise structured JSON (`{ok, schema, result|error}`, schema `herdr-subagents/v1`) :: mirrors the `ot` machine contract so agents parse uniformly; human-readable text only via `--format text` if trivially cheap, else JSON-only for MVP.
- Single test-discovery path with fail-loud empty set :: delete the dedicated `herdr-subagents.test-runner` (its regex literals `#"_test\\.clj$"` match nothing, its file walk is cwd-relative, and its `bb.edn` invocation is unreachable behind `org-tasks.test-runner/run`'s unconditional `System/exit`); the org-tasks runner's classpath-wide `**/*_test.clj` glob is already generic and proven to execute the herdr suite. Harden it to exit nonzero on zero discovered namespaces so silent discovery breakage cannot recur.
  Rejected:
  - Fixing the dedicated runner's regexes: keeps two runners plus permanently dead code after `System/exit`.
  - Reordering the `bb.edn` invocations: the same namespaces would run twice with divergent exit semantics.
- Fixed-interval budget-capped poll for settled-without-result :: sleep `SUBAGENT_POLL_INTERVAL_MS` (default 1000 ms), capped by the remaining total budget, between wait iterations when the child is settled without a valid result. The injectable interval keeps fake-Herdr tests fast and lets them assert an interval-derived call-count bound deterministically.
  Rejected:
  - Exponential backoff: extra state for no material win — 1 Hz polling is ≤ ~600 subprocesses over the worst-case 10-minute budget versus 100+/s today.
  - `herdr agent wait --until` with narrower states: changes live wait semantics validated in the guarded smoke; the defect is only the missing sleep.
- `--help` stays human-readable text; JSON is the machine contract for everything else :: nothing consumes `subagent --help` programmatically — SKILL.md never references it, README.md cites it as a human command, and `herdr.clj`'s `command-help` parses *Herdr's* help, not the CLI's. So contract.md's "exactly one JSON object" sentence is narrowed to non-help commands rather than wrapping usage text in an envelope, and `run --help` is fixed to print usage instead of an error envelope. No `--help --format json` / `--info` discovery variant until a machine consumer actually exists (YAGNI).
- One `SUBAGENT_ASSIGNMENT_ROOT` knob covers ledger *and* roster, and tests point it at the repo's own tracked personas :: `roster` (`cli.clj:40`) already derives its project root from `ledger/assignment-root`, so overriding that single function relocates ledger, index markers, result paths, and project-roster lookup together — coherent, because all four are per-project notions. `cli_test.clj` therefore symlinks `<test-root>/.agents/subagents` to the repo's tracked `subagents/` instead of inventing fixture personas: the suite stops depending on a deployed home, tests run against the personas that actually ship (no fixture drift), and the project-roster-wins branch gains its first end-to-end coverage.
  Rejected:
  - A separate `SUBAGENT_ROSTER_DIR`: a second knob for the same "which project" question (YAGNI).
  - Hand-written fixture personas under the temp root: extra surface that silently drifts from the real roster and never exercises real frontmatter.
  - Relying on the `~/.agents/subagents` → repo symlink as-is: it works on this host, but makes `bb test` fail on a bare checkout or CI runner with no Home Manager activation.
- Launcher fallback uses `--deps-root "$script_dir" -Sdeps '{:paths ["src"]}'` :: an absolute `:paths` value throws `IllegalArgumentException: ... is not a relative path` whenever the caller's cwd contains a `bb.edn`, which is exactly the state created by dropping the fallback `cd`. Verified: absolute `:paths` succeeds from a cwd with no `bb.edn` or with only a `deps.edn`, and fails from any cwd with a `bb.edn`; the `--deps-root` form succeeds in all cases while preserving `user.dir`.
  Rejected:
  - Absolute `-Sdeps :paths` (the 2026-07-27 implementation review's sketch): silently correct only until the fallback is exercised from a Babashka project — the likeliest real caller.
  - `bb --classpath "$script_dir/src"`: works, but abandons the `-Sdeps` shape the record already contracts for.
- SKILL.md keeps safety semantics normative and moves mechanics to the CLI :: the skill remains the constitution (completion-signal rule, pane lifecycle, planner exception, invocation dimensions, resident/fan-out contracts); step-by-step command mechanics, label math, geometry arithmetic, and envelope assembly live in `subagent` + `scripts/docs/contract.md`. A compressed manual-envelope fallback stays in the skill for environments without the scripts.

** Gotchas
Launcher, roster, and caller-identity traps that outlived this change are maintained in [[proj:skills/herdr-subagents/README.org]] (deployment symlinks and `cd -P`, the `-Sdeps`/`bb.edn` coupling, `parent-identity` failure modes, roster location). Record-specific surprises:
- `herdr pane layout --current` followed the UI-focused pane rather than the inherited caller in live validation; delegation passes explicit `--pane "$HERDR_PANE_ID"` for layout and split.
- Planner prompts must retain the sole planner→scout/researcher exception; applying the generic leaf instruction to planners prevents nested delegation.
- Pi accepts the persona file path for `--append-system-prompt`; Claude requires the persona body text.
- `*file*` under `babashka.classpath/add-classpath` is absolute, but the walk to the repo root needs five `..` segments from the test file's parent, not the four a naive count suggests — verify empirically.
- `(or 0 default)` returns `0` in Clojure because zero is truthy, so an env-var knob parsed with `parse-long` needs an explicit `pos?` guard or its "disabled" value silently becomes a busy-wait.
- `clj`/`deps.edn` tooling can generate an untracked `.clojure/` directory that `.gitignore` does not cover; remove it if it appears mid-session.

** Risks

- Live smoke exercises billable agents and cannot run in CI, so launcher/argv changes rely on an operator remembering to run it. Mitigated by the deployed-path smoke procedure recorded in `* Validation` and the README.
