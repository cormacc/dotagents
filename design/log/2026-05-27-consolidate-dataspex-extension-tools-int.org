* Summary
Collapse the seven active ~dataspex_*~ tools into one canonical ~dataspex~ tool with an ~op~ discriminator. Preserve the existing nREPL/shadow bridge, per-op CLJS forms, bounded-output protections, audit-label semantics, and result shapes; change only the registration surface, parameter schema, docs, and JS-side dispatch/validation. The intent is to reduce tool-list and provider-schema context while keeping Dataspex runtime inspection equally reliable.

** Decisions
- Register one active tool named ~dataspex~; do not keep active ~dataspex_*~ compatibility wrappers because they preserve the context cost being removed.
- Use ~op~ as the discriminator with values ~labels~, ~value~, ~history~, ~track~, ~untrack~, ~db_query~, and ~actions_tail~. Underscores mirror the old tool-name suffixes and make migration mechanical. Hyphenated form is rejected; do not relitigate.
- Implement the ~op~ enum with ~@sinclair/typebox~'s ~Type.Union(values.map(Type.Literal))~. ~StringEnum~ from ~@earendil-works/pi-ai~ / ~@mariozechner/pi-ai~ is not resolvable from this extension directory; typebox is the only available primitive.
- Prefer a flat schema with optional op-specific fields plus TypeScript runtime narrowing over a seven-branch discriminated union. The union is stricter but likely pushes more JSON Schema into provider requests.
- Validate op-specific required fields and numeric bounds in TypeScript before templating CLJS forms.
- Do not add a TypeScript-side EDN-vector validator for ~value.path~ or ~db_query.args~; keep that error inside the CLJS form so existing reader/vector-check parity is preserved.
- Copy the existing CLJS bodies and output projections verbatim where practical; do not combine this refactor with semantic changes to Dataspex reads.
- Update README and skill prose to the new op surface; keep fallback CLJS forms functionally unchanged.

** Gotchas
- ~value~ defaults ~path~ to ~"[]"~; ~actions_tail~ defaults ~label~ to ~"Actions"~ only for that op; ~value~ and ~db_query~ use different ~limit~ defaults. Dispatcher code must apply per-op defaults, not global defaults.
- Read ops return bounded strings from CLJS; ~track~ and ~untrack~ return Clojure data. Do not add an extra ~pr-str~ layer or otherwise change the ~unwrapClojureString~ path.
- ~evalCljs~'s ~:results[0]~ + ~edn/read-string~ unwrap and explicit avoidance of ~:out~ are load-bearing for parallel tool execution.
- The single tool name is less self-descriptive than ~dataspex_value~ etc.; the description and one-line ~promptSnippet~ must enumerate the op set without reintroducing verbose per-op prose.
- Numeric params currently flow through ~Number(...)~ and are interpolated into CLJS. ~NaN~, non-finite, or negative values should become tool errors, not malformed CLJS.
- ~buildLiteral~ remains the chokepoint for user-supplied shadow build ids.
- Interactive sessions need ~/reload~ before the new tool surface is visible.
- A standalone measurement harness for context savings must load ~index.ts~ via jiti or precompile it to ~.js~; plain ~node --import~ will fail on TS syntax. The May 2026 spike's ~.agents/tmp/dataspex-build/~ precompile approach is the precedent.
- ~package.json~ and ~node_modules/~ of the dataspex extension are untouched by this refactor. ~bencode~ continues to resolve from ~pi-clojure/node_modules~ via Node's parent-walk; no ~agents.nix~ re-activation should be required.
- ~actions_tail~ against a missing label currently throws inside CLJS via ~(aget nil "log")~. Parity tests must confirm the same error shape is preserved through the new dispatcher.
- Resumed sessions may try retired ~dataspex_*~ names once before the skill update steers the model to the new spelling. Acceptable; surface in the README migration note.
