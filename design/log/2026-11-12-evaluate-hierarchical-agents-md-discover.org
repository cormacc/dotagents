* Intent
Decide how a Pi session gets the rules of a nested AGENTS.md when it works below that file: an on-touch extension, manual pointers, or nothing. Do not install rpiv-pi.

* Summary
*Level:* MVP · *Tests:* thorough · *Docs:* README

Research is complete (2026-11-12, installed Pi 1.5.2). Pi core declines this feature and leaves it to extensions. At least five published Pi packages implement it. rpiv-pi's implementation has defects that this repository must not copy. Shipped 2026-11-19: a local Pi extension, `pi/extensions/nested-context/`, for Pi sessions only. It delivers tracked nested context files in ~read~ results and as the block reason of the first ~edit~ or ~write~. No other harness and no manual pointers.

** Scope
*** In scope
- On-touch loading of nested context files for the built-in ~read~, ~edit~ and ~write~ tools in Pi.
- Context files that Git tracks in the working directory's repository or in one of its submodules.
- Removal of the manual ot pointer from the root ~AGENTS.md~, which the extension makes redundant.
*** Out of scope
- Claude Code, Codex and other harnesses: no ~CLAUDE.md~ stubs, no pointers.
- ~bash~, ~ffgrep~, ~fffind~, ~lsp~, the ~emacs_*~ tools and codemode. Path extraction from a command is guesswork.
- Context files above the working directory, which Pi already loads.
- A system-prompt injection, which invalidates the prompt cache.

*** Core functionality
- [X] A ~read~ of a file below a directory with a nested context file returns the file content followed by that context file, on the first touch in a session. → test:I `a new session keeps its own delivery record`
- [X] The first ~edit~ or ~write~ to such a file is blocked, and the block reason contains the context file. → test:I `the first write is blocked`
- [X] A repeated ~edit~ or ~write~ to that file runs. → test:I `the first write is blocked`
- [X] A second touch under the same directory in the same session adds nothing. → test:I `a later read in the same session adds nothing`
- [X] After ~session_compact~, the next touch delivers the context file again. → test:I `after compaction`
- [X] In each directory, the extension picks one file by Pi's order: ~AGENTS.override.md~, ~AGENTS.md~, ~AGENTS.MD~, ~CLAUDE.md~, ~CLAUDE.MD~. → test:D `files at several depths`, `AGENTS.MD is picked before CLAUDE.md`
- [X] Nested files at several depths between the working directory and the touched file are all delivered, outermost first. → test:D `files at several depths`; test:I `the first write is blocked`
*** Edge cases
- [X] A context file that Git does not track, or that Git ignores, is not delivered. → test:D `an untracked context file`, `an ignored context file`; test:I `an untracked context file`
- [X] A context file tracked by a repository that is not the working directory's repository or one of its submodules is not delivered (for example a clone under ~.tmp/~). → test:D `a nested clone`
- [X] A context file tracked in a submodule of the working directory's repository is delivered. → test:D `a submodule`
- [X] A touched path outside the working directory delivers nothing. → test:D `a path outside the working directory`
- [X] An ~edit~ and a ~read~ of the same directory in one parallel batch deliver the context file once. → test:I `a read and an edit in one parallel batch`
- [X] Two sessions in one Pi process keep separate delivery records. → test:I `a new session keeps its own delivery record`
- [X] A failing ~git~ call delivers nothing and does not fail the tool call. → test:D `a failing git call returns nothing`

- [X] Must not: install rpiv-pi or a third-party nested-context package. (No package or settings change.)
- [X] Must not: change the system prompt. (The extension registers no ~before_agent_start~ or ~context~ handler.)
- [X] Must not: block ~read~. → test:I `a read and an edit in one parallel batch`

** Decisions
- Chose a local extension for Pi only :: it can block a write until the rules are seen, it keeps the prompt cache, and its scope rule is ours. Only Pi sessions work in this repository.
  Rejected:
  - Trial ~pi-agents-autoload~ 0.1.3: unreviewed, one author, one week old; an extension runs with full user permissions. Read its source as a reference only.
  - Manual pointers and ~CLAUDE.md~ stubs: cover only this repository and only the named files; no other harness is in use here.
  - rpiv-pi's design: it steers after the tool batch, so a write runs before the rules arrive.
- Deliver rules in the ~read~ result, and as the block reason of the first ~edit~ or ~write~ :: both keep the prompt cache. The block guarantees that the rules arrive before the write.
- Scope by Git tracking, not by project trust :: a tracked nested file has the same source as the root ~AGENTS.md~, which Pi loads without trust. Untracked and cloned content is the real risk, and the tracking rule excludes it.
- The delivery record is one set per extension instance, not a map keyed by session ID :: Pi creates a new extension instance for each session (new, resume, fork, reload), so the closure already separates sessions. The defect to avoid is a module-wide set, as in rpiv-pi; the new-session test fails when the set is moved to module scope.
- A file counts as delivered when the extension returns it in a result or a block reason :: in parallel mode, ~tool_call~ preflight runs before sibling results exist, so delivery cannot be inferred from a sibling ~read~ in the same batch.

** Findings
- Pi 1.5.2 loads one context file per directory, from the agent directory and from the working directory up to the filesystem root. Per-directory precedence is ~AGENTS.override.md~, ~AGENTS.md~, ~AGENTS.MD~, ~CLAUDE.md~, ~CLAUDE.MD~ (~dist/core/resource-loader.js~, ~loadContextFileFromDir~ and ~loadProjectContextFiles~). Context-file discovery does not require project trust (~docs/configuration.md~ section 'Context files').
- In a linked worktree nested inside its main checkout, Pi skips the main checkout's root context file, because the worktree's own copy shadows it (~findShadowedContextFile~). herdr-orch managed worktrees are at ~<assignment-root>/.tmp/herdr-orch/worktrees/<task>~ (~managed-worktree-root~ in ~skills/herdr-orch/scripts/src/herdr_orch/cli.clj~), so a child gets the worktree's root AGENTS.md once. Context files above the main checkout, such as ~~/dotfiles/AGENTS.md~, still load.
- Upstream position: badlogic closed [[https://github.com/earendil-works/pi/issues/4834][pi#4834]] on 2026-05-21. He said that on-touch loading is "likely not what you want as default behaviour" and is "easy enough to do as an extension". He also said that additions to the system prompt invalidate the provider prompt cache, and that injection as a user message keeps the cache but gives lower adherence.
- Other harnesses: Claude Code loads a subdirectory CLAUDE.md on demand when it reads files in that subdirectory ([[https://code.claude.com/docs/en/claude-md][Claude Code docs]]). It does not do this for AGENTS.md. Codex concatenates the files from the project root to the working directory at start-up only ([[https://github.com/openai/codex/blob/main/codex-rs/core/src/agents_md.rs][codex-rs agents_md.rs]]).
- This repository has two nested files: ~skills/herdr-orch/scripts/AGENTS.md~ (84 lines) and ~skills/org-tasks/scripts/AGENTS.md~ (28 lines). Neither directory has a CLAUDE.md, so Claude Code children do not load them on demand either. The root ~AGENTS.md~ points to the org-tasks file only. The herdr-orch file is reachable only through the ~skills/herdr-orch/README.org~ file table and task records.
- rpiv-pi (~rpiv-mono@46dbdfd~, ~packages/rpiv-pi/extensions/rpiv-core/guidance.ts~) has these defects:
  - It reacts on ~tool_call~ and sends the guidance with ~pi.sendMessage~, using the default steer delivery. The guidance therefore arrives after the tool batch, so an ~edit~ or ~write~ runs before the agent sees the nested rules.
  - Its deduplication set is module-global. In a process with more than one session, an injection in one session suppresses the same file in another. The set is cleared only through the exported ~clearInjectionState~; its callers were not inspected.
  - It handles ~read~, ~edit~ and ~write~ only. Its precedence ladder omits ~AGENTS.override.md~ and the upper-case variants that Pi accepts.
- Published alternatives (from the package pages, not inspected or run):
  - ~pi-agents-autoload~ 0.1.3 (sk-ilya, published 2026-11-11, "Tested with Pi 1.5.2"). It uses Pi's precedence ladder and blocks an ~edit~ or ~write~ until the agent has seen new or changed instructions. It delivers the instructions as a mid-conversation system message on supported models, else in the tool result. It keeps frequently used files through compaction, within a 50 KiB limit. It manages only files inside the working directory, and only for the built-in ~read~, ~edit~ and ~write~ tools.
  - ~pi-subdir-context~ 1.1.7 (akuzmenko, about 2,100 downloads a week). It appends the files to the ~read~ tool result only, once per session.
  - Other packages: ~@zeldrisho/pi-nested-agent-md~, ~@vanillagreen/pi-nested-agents-md~, ~@howaboua/pi-subdir-agents~ and ~pi-auto-context-files~.
- Pi extension surface for a local implementation (~docs/extensions.md~): ~tool_result~ can append text to a result before the model sees it. ~tool_call~ can block a call. ~before_agent_start~ can add a message. ~session_compact~ marks the point where deduplication must reset.

** Risks
- Trust: Pi loads context files without trust. On-touch injection extends the same posture to nested files. Accepted with the Git-tracking scope rule (see Decisions).
- Adherence: rules in a tool result can be followed less strictly than rules in the system prompt. Accepted to keep the prompt cache.
- Bypass: an agent that edits through ~bash~ or another tool is not guarded. Accepted; the README states the limit.
- Cost: the first write under a governed directory takes one extra tool call. Accepted.
- Size: a large nested file is delivered whole. Accepted; the two files here are 84 and 28 lines.
