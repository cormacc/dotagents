* Summary
The org-tasks protocol now leans on native org-mode features — =#+TODO:= bang/at markers, =#+STARTUP: logdone logdrawer=, =#+ARCHIVE:=, =#+SETUPFILE:=, and =#+LINK:= abbreviations — so org-mode edits and the pi tasks extension produce byte-identical =CLOSED:= / =:LOGBOOK:= / archive / link artefacts. Repositories declare shared lifecycle and link config in a root =TASKS.setup.org= referenced by =TASKS.org=, =TASKS.archive.org=, and change-records via =#+SETUPFILE:=. A small Emacs companion (=emacs/tasks-org/=) provides locate, capture, plan-toggle, and selection-toggle commands; pi remains the canonical headless lifecycle implementation.

** Decisions
- Two-runtime split :: Pi owns lifecycle automation (status transitions, =CLOSED:= / =:LOGBOOK:= writes, archive mechanics, ID backfill, badge rendering) and must remain fully usable without Emacs. =emacs/tasks-org/= is a thin editor surface — four commands (locate, capture, toggle task↔plan, toggle selection) — with no minor mode, no hooks, no parallel parsers.
- =:CUSTOM_ID:= is the UUID slot :: The protocol uses =:CUSTOM_ID:= (not =:ID:=) because org natively resolves =[[#uuid]]= against it, and that is the slot =#+PARENT:= links target. Emacs capture and pi both write this property; the prior =tasks-org.el= use of =:ID:= via =org-id= was incompatible and is gone.
- Native org-mode shapes are the contract :: =#+TODO: TODO(t) STARTED(s!) WAITING(w@/!) | DONE(d!) CANCELLED(c!)= plus =#+STARTUP: logdone logdrawer= and =#+ARCHIVE: TASKS.archive.org::* From %s= ensure org-mode (=org-todo=, =org-archive-subtree=) and pi emit byte-identical artefacts. =:STARTED:= is a fast cache; the first =STARTED= entry in =:LOGBOOK:= is source of truth.
- Root =TASKS.setup.org= owns shared metadata :: Shared =#+TODO:=, =#+STARTUP:=, and =#+LINK:= abbreviations live in =TASKS.setup.org=. =TASKS.org= / =TASKS.archive.org= / change-records reference it via =#+SETUPFILE:= instead of repeating preambles inline. The pi parser and =emacs/tasks-org= both walk one level of =#+SETUPFILE:= so link templates resolve from any of those files. =#+ARCHIVE:= stays local to =TASKS.org= because it is task-index-specific.
- Typed org links replace bespoke keywords :: =:LINKED_ISSUES:= carries =[[jira:KEY]]= resolved via =#+LINK: jira https://.../%s=; =#+IMPORT:= for change-records carries =[[plan:foo.org]]= resolved via =#+LINK: plan file:design/log/%s=. Legacy =#+ISSUE_URL_BASE:= and =#+DEFAULT_PLAN_DIR:= are removed outright; bare =PROJ-NNN= keys are no longer recognised. Companion extensions (e.g. jira) own their prefix's URL template; the tasks extension owns only the syntax.
- Capture stays separate from scaffold :: The =org-capture= template (key =t= with =%^G= tag prompt; =T= for no-tag capture) inserts protocol-conformant TODO headings under a configurable section. Change-record scaffolding stays in pi's =p= keybinding so the skeleton has one source of truth.
- Packaging boundary :: =emacs/tasks-org/= is consumed by the dotfiles =org-user= Spacemacs layer via the existing =agents-src= submodule and is intentionally **not** bundled into =agent-org-memory.nix=. Mixing runtimes for no reuse benefit; a future flake output =packages.<system>.tasks-org-el= can be added if external consumers appear.

** Shipped
- Protocol preamble symmetry :: root =TASKS.setup.org= carries =#+TODO: TODO(t) STARTED(s!) WAITING(w@/!) | DONE(d!) CANCELLED(c!)=, =#+STARTUP: logdone logdrawer=, =#+LINK: jira .../%s=, and =#+LINK: plan file:design/log/%s=; task files and change-records reference it via =#+SETUPFILE:=.
- Linked issues :: =#+ISSUE_URL_BASE:= removed in favour of =#+LINK: jira= + canonical =[[jira:KEY]]= tokens; pi parser/overlay resolve typed links via parsed =#+LINK:= declarations.
- Change-record imports :: canonical form is =#+IMPORT: [[plan:<file.org>]]=; pi loader and =emacs/tasks-org-toggle-task-and-plan= follow the same =#+LINK: plan= chain so =C-c C-o= and =, g a= open the same file.
- Pi tasks parity :: new-file writes seed canonical preambles, plan scaffolds emit =#+SETUPFILE:=, archive writes preserve preambles, selection clear removes only the =#+SELECTED:= line.
- Emacs companion :: =emacs/tasks-org/tasks-org.el= provides =tasks-org-find-tasks-file=, =tasks-org-register-capture-template=, =tasks-org-toggle-task-and-plan= (+ =-other-window=), and =tasks-org-toggle-selected= with ERT coverage. Capture registers both =t= (tag prompt) and =T= (no-tag) templates.
- Dotfiles wiring :: parent =org-user= Spacemacs layer loads the live =agents-src/emacs/tasks-org= package and binds =SPC m g a= / =SPC m g A= / =SPC m SPC=.
- Cross-repo migration :: one-time sweep applied the protocol changes to the three adopting repos (this repo, =/Users/cormacc/dotfiles=, =/Users/cormacc/dev/blog=).

** Gotchas
- Emacs regexp syntax :: literal =+= in =#+KEYWORD= regexes uses =[+]=; =\\+= means repetition in Emacs regexps and silently broke selection-clear.
- Capture tags :: =%^G= prompts for tags and may inherit/default unwanted tags from the current org context (e.g. =TOC_2_gh=). The =T= template omits =%^G= for empty-tag capture.
- =TASKS.local.org= shape :: selection-only files are allowed to remain preamble-free; writers must preserve draft tasks/imports and remove only the =#+SELECTED:= line on clear.
- Emacs =#+LINK= regex needs the literal colon :: =tasks-org--link-template-in-current-buffer= requires =#+LINK:= (not =#+LINK =); without the colon the lookup silently returns =nil= and =[[plan:...]]= toggles fail.
- =%s= substitution distinguishes =file:= vs URL templates :: =expandOrgLinkTarget= URL-encodes keys for URL templates (so =jira:PROJ 1= → =.../browse/PROJ%201=) but keeps them literal for =file:= templates (so =plan:subdir/foo.org= stays =subdir/foo.org=). Org's own =org-link-expand-abbrev= is always literal; pi diverges for URL templates because consumers expect ready-to-open URLs.
- =#+LINK: plan= templates must be =file:=-prefixed for scaffold suggestions :: =planDirFromTemplate= falls back to =./design/log= for non-=file:= =plan= templates rather than emit URL-shaped scaffold paths.

** Follow-ups
- If a non-dotfiles consumer appears, package =emacs/tasks-org= as a flake output or standalone elisp package.
- Consolidate =readEffectiveOrgContent= into a shared helper :: =parser.ts= now owns =expandOrgLinkTarget=, but =readEffectiveOrgContent= is duplicated between =index.ts= (uses =resolveProjectPath= sandbox) and =insert.ts= (uses =sandboxPath=). A shared helper parameterised by the path-resolution callback would prevent drift.
