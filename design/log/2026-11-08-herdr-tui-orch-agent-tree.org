* Intent
Show the herdr-orch agent tree in terminal Herdr's native Agents sidebar: under each space, every live `oh` child appears once, in tree order after its parent, named by its `oh` label, so that an orchestrator sees who spawned whom and which child needs attention without leaving the TUI.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* README

The herdr-app `orch-spaces` mod (`herdr-app/mods/orch-spaces/`) draws spaces, git tails, machines and the agent tree itself, because herdr-core carries a native parent link and `oh.label`. Herdr TUI 0.9.5 has none of that in its API (`herdr api schema --json` has no parent field), but its native sidebar already draws machine groups, space rows with `branch` and `git_status`, and agent rows grouped by space. Plugin v1 cannot add rows to that sidebar; it can decorate agent rows with `pane.report_metadata` (`display_agent`, `$name` tokens) and order them with `agent.view.set`. This change therefore ports only the tree model: the `cormacc.herdr-orch` plugin reads the herdr-orch ledgers, joins them to `agent list` by session, and reports, as each agent's display name, the tree mark plus the label for an oh child and `local:<workspace>:<agent>` for every other agent, and an `order` token for each agent in an oh tree, from a one-shot reconcile that startup and pane lifecycle hooks run.

** Decisions
- Decorate the native sidebar (approach A) :: Plugin v1 offers `pane.report_metadata` tokens, `display_agent`, and `agent.view.set`; the native sidebar already draws machines, spaces and git tails. Smallest change, no duplicated git or machine code, native next/prev navigation.
  Rejected:
  - Own plugin pane re-implementing the sidebar as a Babashka TUI (org-tasks pattern): full fidelity including tab rows, but duplicates the native sidebar and costs layout space in every tab.
  - Patching Herdr's Rust sidebar: outside this repository.
- Hierarchy from the ledger, liveness from `agent list` :: The TUI API has no parent link. The ledger's `parent-session`/`child-session.value` pair is the only join (review 1 finding 1: Herdr reuses pane ids, so a `pane-id` fallback let stale entries decorate unrelated agents; `oh` records the child session at launch); `closed-at` is unreliable (many open entries have none), so a parent is live only when a listed agent carries its session.
- A tree root is the live agent that a ledger `parent-session` names :: The orchestrator that starts the first `oh` children has no ledger entry of its own, but every child's entry names its session. The model treats that agent as a root node, and the plugin gives it an `order` token only (no display name, no `$tree` mark), so that its children sort directly after it. No `oh` or ledger change is needed. Decided with the user during execution of 3c0c5572.
- Ledger discovery by agent cwd :: For each distinct agent `cwd`, `git rev-parse --show-toplevel` names a candidate assignment root; its `.tmp/herdr-orch/ledger/*.json` entries are joined across roots so a worktree child finds its parent. No configuration map.
- Display name is the label's last segment :: Nested labels compose (`planner-2/scout-1-light`); the tree mark shows the parent, so the row carries `scout-1-light`. Non-oh agents are untouched.
- One-shot reconcile from hooks, no daemon :: Herdr documents startup hooks as one-shot and requires plugins to stop background processes before a hook exits. A file lock plus a dirty marker coalesces concurrent hooks into one trailing reconcile; a state file avoids redundant `report-metadata` calls.
- Global display toggle, persisted :: The tree shares the plugin with the quota pane, so disabling the plugin is too coarse to turn off only the tree. The toggle mirrors the org-tasks overlay toggle: one global flag file under `HERDR_PLUGIN_STATE_DIR`, not per session. While the flag is off, a reconcile clears whatever its session recorded and exits, so every session converges without a cross-session call. Turning it on re-syncs, so no separate `tree-reset` action is exposed. Decided with the user during execution; supersedes the re-sync-only decision in * Open questions.
- Display toggles use `prefix+ctrl+<letter>` :: Herdr 0.9.5 has one prefix layer and no second-key table, so the grouping is a convention. The 0.9.5 default keymap binds no `prefix+ctrl+` key (`clear_pane = "prefix+ctrl+k"` is only an unbound example), `prefix+shift+` holds ten defaults including `rename_tab = "prefix+shift+t"`, and the defaults note that ctrl+letter is among the most reliable bindings, unlike Alt on macOS. Avoid `prefix+ctrl+b` while the prefix is `ctrl+b`. Chosen by the user.
- Mark and workspace prefix in the agent name :: Herdr draws a `·` separator between row tokens, so a separate `$tree` token rendered as `└ · scout-1-light`. The mark is part of each child's display name (`└ scout-1-light`), and every other local agent is named `local:<workspace label>:<agent>` from `herdr workspace list`, so one `agent` token per row carries both the tree and the space; the rows stanza drops the machine, workspace and tab tokens. This reverses the earlier rule that non-oh agents keep Herdr's name and carry no metadata. A `workspace.renamed` hook re-runs the reconcile, because a root's name contains its workspace label; that event is documented as a subscription event but was not covered by the spike. Owner's change, 2026-11-09.
- No separate reset command :: Nothing called `tree.bb reset` (no manifest action), and toggling off and on gives the same re-sync. The simplification review removed the command, `reset-all!` and its runner case on 2026-11-09, with the owner's approval; `reset-once!` stays as the off path.
- Home is the existing `cormacc.herdr-orch` plugin :: Same owner and checkout resolution (`lib.sh`); the reconcile is Babashka like `herdr/plugins/org-tasks/adapter.bb`.

** Gotchas
From spike 5632e75a on Herdr 0.9.5:
- Plugin event hooks fire for `pane.created`, `pane.closed`, `pane.agent_detected`, `pane.agent_status_changed`, `tab.closed` and `workspace.closed`; `HERDR_PLUGIN_EVENT_JSON` is `{"event":"<snake_case>","data":{...}}`.
- `pane.closed` fires only for an explicit pane close. Closing a tab or workspace emits only `tab.closed` or `workspace.closed`, with no per-pane event, so the reconcile must also run on those two events.
- A manifest without top-level `platforms` gets the link warning `manifest does not declare platforms; platform support unknown`; declare `platforms = ["linux", "macos"]`.
- `herdr pane report-metadata <pane> --source <id> --display-agent X --token tree=Y` replaces the `agent` row text with `X` and renders `$tree` as `Y` (shown `Y · X`); `--source` is required, and an unreported `$tree` renders nothing.
- `report-metadata` re-emits `pane.agent_status_changed` with the same status and `display_agent` in the payload, so each report starts one more hook run; the state-file comparison must make that run a no-op.
- `[ui.sidebar.agents]` rows come from the client's local config: `herdr server reload-config` does not apply them to an open client. Use the UI menu `reload config` or restart the client. `display_agent` reaches an open client without a reload.
- The org-tasks `ensure` hook adds a Tasks pane to every tab, so `pane.created` arrives in bursts that include panes without an agent.
- `HERDR_PLUGIN_STATE_DIR` (`~/.local/state/herdr/plugins/<id>`) is shared by every session, and plugins run for every session: key the state and lock files by session (`HERDR_SESSION`, absent for the default session, or `HERDR_SOCKET_PATH`).
- Hooks get the `HERDR_SOCKET_PATH` of the server that fired them; `HERDR_PANE_ID` is absent for `workspace.closed`. Hook processes inherit the server's environment, including unrelated `HERDR_ORCH_*` variables: do not read those in hooks.
- `pane.agent_detected` arrives about 5 s after `agent start` and names the kind (`pi`), not the `oh` label.
- Startup hooks run after session restore or live handoff, not when a client attaches, config reloads or a plugin is linked (`plugins.mdx` 'Startup hooks'; 65277f97 observed no hook run in about 75 s after link and reload). The first live reconcile after a link is therefore the next pane or agent event.
- On this host, `herdr agent list --json` printed only a usage line; the plain `herdr agent list` prints the JSON envelope. The reconcile uses the plain form (65277f97, 6969ed5b reports).

From live check 076c6a03 (macOS, Herdr 0.9.5; evidence files named in ** Acceptance are in the same-stem folder `2026-11-08-herdr-tui-orch-agent-tree/`):
- With a separate `$tree` token a row renders as `└ · scout-1-light` (the reason the mark moved into the display name); a depth-2 mark `⠀ └` renders as indentation, because Herdr keeps U+2800.
- A scratch client for live checks needs `env -i` plus `HERDR_CONFIG_PATH`, so that no `HERDR_*` or `HC_*` variable leaks; `HERDR_SOCKET_PATH=~/.config/herdr/sessions/<name>/herdr.sock` addresses its CLI.
- An `oh` child started from a herdr-app pane runs in herdr-app. To get TUI children, prompt a pi agent in a TUI pane to run `oh`.
- `next_agent` and `previous_agent` have no default binding, and the tracked config binds neither; the live check used a temporary `prefix+j`/`prefix+k`.
- After `herdr session stop` and a fresh `herdr --session <name>`, pi agents resume with the same session path, so the ledger join holds and the `startup` hook (first plugin log entry) restores the marks.
- `display.json` is global to the machine: a toggle in any session reaches every session.
- Clearing a closed pane gets `pane_not_found` from Herdr; the reconcile treats that answer as success and logs nothing.

** Risks
- Hook storms: each status change starts a `bb` process (about 0.3 s). Accepted with the lock-and-coalesce design; the sidebar may lag one event.
- `agent.view.set` replaces `ui.agent_panel_sort` for the whole session while active. The sort begins with `workspace_order`, so grouping by space is preserved. Toggling the tree off clears the view; disabling the plugin also removes it.
- Untested paths: the contended-branch dirty re-check (needs a race), a view re-send caused only by a stale-pane clear, and the retry of a failed `agent.view.clear` by the next off reconcile.

* Implementation
- Tree model: liveness is a session match only; the newest round on a pane describes it; parent cycles degrade to roots; marks have no trailing space, and a finished branch continues with U+2800.
- Reconcile: the `tree` token is always cleared (the mark lives in the display name); an agent outside an oh tree gets no `order` token; the view is set once a row exists and re-sent in any pass that reports; the state records the server socket identity, so a new server discards it and the startup hook re-reports everything; a failed report keeps the old state entry for retry; a clear answered `pane_not_found` is dropped silently; a `git` launch failure warns once.
- Toggle: `tree.bb toggle` flips `display.json` under the global `display.lock`, then runs the normal reconcile, which reads the flag inside the session lock (off: reset what the session recorded; on: rebuild). A toggle that finds the session lock held leaves the dirty marker, so the holder applies the latest flag and no toggle is lost. A failed off reset run by the toggle itself exits 1.
- Reviews: two code reviews before live activation and three closeout correctness validations found and fixed a stale-entry adoption through the pane-id fallback, whitespace-trimmed marks, a lost dirty marker on the contended path, toggle exit codes and toggle races.
