* Intent
Evaluate a lower memory layer without adding a second task authority or enabling automatic session capture before its privacy and retention policy is agreed.

* Summary
*Level:* prototype · *Tests:* thorough · *Docs:* inline

Primary-source comparison is complete. The candidates solve different problems: in-session consolidation, cross-session service-backed recall, or a provider proxy. This research did not install a candidate or approve a trial; compatibility with the installed Pi 1.4.0 runtime remains unverified.

** Scope
*** In scope
- Candidate mechanisms, automatic capture/retrieval, data destinations, service requirements and deletion boundaries.
- A synthetic-only compatibility and recall trial after selecting the memory problem and permitted data flow.
- Existing ownership: org-tasks owns task lifecycle; self-improvement owns durable process feedback.
*** Out of scope
- Importing real session history, enabling background retention, deploying services or changing provider routing during research.
- Treating compaction as proven cross-session memory or a wildcard peer dependency as runtime compatibility evidence.

** Acceptance
Proposed trial criteria; data-flow and adoption choices remain OPEN.
*** Core functionality
- [X] Comparison distinguishes the candidates' mechanisms and operational surfaces.
- [ ] A selected candidate loads in the intended Pi runtime with synthetic data only.
- [ ] A fixed cross-session question is answered from permitted retained data, with its source identified.
*** Edge cases
- [ ] A conflicting memory cannot override task state or repository instructions.
- [ ] A deletion test identifies what disappears from active recall and what remains in backing history, queues or backups.
- [ ] Provider/model requests and retained content match the agreed data-flow policy.
*** Anti-criteria
- [ ] Must not: ingest existing sessions or run automatic capture before explicit approval.
- [ ] Must not: silently change model/provider selection or make memory a new task authority.

** Decisions
- Separate problem selection from package selection :: an in-session ledger, cross-session recall service and traffic proxy are not interchangeable. Rejected:
  - Install all candidates for a live comparison: increases data exposure and changes several mechanisms at once.
  - Treat publicity or a minimum Pi version as adoption evidence: neither establishes compatibility, usefulness or deletion semantics.
- Recommend one isolated synthetic trial only after policy selection :: measure successful and misleading recall plus deletion before considering real sessions. This is a proposal, not approval to install or send data.

** Risks
- Automatic lifecycle capture can transmit more session content than an explicit recall tool call suggests.
- Self-hosting a memory service does not by itself keep its extraction-model requests local.
- Removing an active observation can leave its original ledger history intact.

The researcher describes proxy capture/injection plus a service stack, not a drop-in local memory file.
