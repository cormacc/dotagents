* Intent
Use multiple subscriptions per provider in primary Pi sessions and usage-aware subagent launches. Start with Anthropic, retain explicit account selection, and recover primary sessions from quota exhaustion without leaving the selected weight alias tier.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* README

** Scope
*** In scope
- Named Anthropic subscription accounts in Pi; independent primary-session account selection; account-specific quota reporting and launch routing.
- Explicit primary-session weight selection using the existing merged alias configuration; bounded quota-triggered failover and continuation.
- Account identity propagation through fresh, forked and measurement launches, previews, ledger entries and inherited concrete selections.
- Existing CLI, Pi help and Herdr quota consumers; their fixtures and tests; the four declared operator contracts.
- Provider-neutral account identity and routing, with Anthropic-specific authentication and quota adaptation. Existing OpenAI and local alias candidates remain usable.
*** Out of scope
- Native Claude account switching or credential synchronisation. Shared tokens are optional only if later evidence establishes a low-cost, safe path; they are not a delivery gate.
- Additional multi-account provider adapters, a proxy service, overnight quota polling, account reservations or a new model taxonomy.
- Automatic in-flight child failover. Children retain their launch selection; primary-session recovery must be inactive in delegated children.
- Paid API-key fallback without explicit consent, automatic model upgrades, or changes to global Pi startup defaults.

- [X] Quota-triggered primary failover prefers another eligible account serving the current model.
- [X] Cross-model primary failover selects only candidates from the explicitly selected alias.
- [X] Cross-provider fallback is permitted within that alias.
- [X] Direct model selection permits only same-model account fallback.
- [X] A resumed primary session retains its explicitly selected tier.

- [X] A successful failover automatically continues the interrupted turn.

** Decisions
- Chose a focused repository-owned integration in the existing Pi Herdr extension, reusing native Pi authentication/provider APIs and the Babashka routing policy.
  - Rejected adapting ~pi-multi-account~ wholesale: its quality-band heuristics differ from configured weight aliases; its wider recovery/proxy surface is outside this change.
  - Rejected extending ~pi-multi-claude~ as the account foundation: its shared ~anthropic~ credential replacement cannot provide independent concurrent selections.
- Each account has a stable non-secret identity, separate from its base provider and quota adapter. Preserve the existing base-provider credential as the default account. Register additional accounts as distinct Pi providers so the selected model identifies the credential without global credential swapping.
- The owner selected ~<provider>-<N>~ for alternate account keys and display names, with positive integers without leading zeros: ~anthropic-1~, ~anthropic-2~. The base ~anthropic~ key remains the default. Bare ~/oh account add~ registers the lowest unused positive number; an explicit number is also supported. Only adapted base providers are recognised; adding another provider requires its authentication/quota adaptation, not a new naming scheme. No separate account database or display-alias layer is required. The authorised one-off credential-key migration preserves the existing OAuth credential without reauthentication.
- Keep canonical models and weight aliases account-independent. Expand candidates to model/account pairs at routing time; retain exact quota scopes, reserve thresholds, harness filters and deterministic order. Preserve the base account first for otherwise equal ties.
- Extend the existing collector with explicit account lookup and account-isolated cache keys. Its output retains ~providers~ rows with unique ~localProvider~ identities, plus explicit base-provider/account identity. Native non-Pi harnesses retain their existing single-account credential contexts.
- One pure Babashka selection policy serves launch routing and primary recovery. Add a bounded machine-readable routing operation usable without Herdr; it accepts the selected tier or direct model, current route, eligible registered model/account inventory and attempted-route exclusions. Validate request shape; return only non-secret routing evidence. This operation grants no terminal control and does not weaken existing launch gates.
- Pi owns account login, refresh and removal through supported credential transactions. Account providers retain native Anthropic OAuth/request shaping and model metadata; subscription aliases must not inherit ambient API-key authentication. The first implementation task proves this with the installed Pi runtime before downstream integration.
- Launches persist and forward the concrete account/model. Fork and measurement loaders must register the same account providers before model resolution. Same-kind inherited concrete selections do not reroute. Native Claude token sharing is not assumed safe.
- Primary tier intent is session metadata, restored on resume and cleared by direct selection. Recovery-generated model changes do not clear it. A child with copied session history must remain in pinned-child mode.
- Recovery first tries same-model accounts, then the selected alias's ranked candidates, including other providers. Direct selections have no cross-model fallback. Filter candidates by registered availability and ability to preserve the requested reasoning level.
- Attribute quota failures to the request's captured account/model. Stage the replacement at ~agent_end~ so that Pi's own retry uses it; when Pi does not retry, continue at ~agent_before_settle~. Attempt each candidate pair once in a finite chain; use Pi continuation rather than reconstructing tool calls. Cancellation, new input and externally reported model/account changes invalidate automatic continuation. The owner accepts that pending native selection requests and silent same-target selections may not invalidate recovery; the public API reports neither reliably. Explicit abort remains the reliable cancellation action. An already-pending native setter may still commit: retain a visible warning until it settles and report the actual selection after cancellation, per [[file:2026-pi-recovery-selection-limits.org]]. Do not lock controls, roll back selection or add startup auth checks. Report switches and terminal exhaustion. No timer waits for quota reset.

** Shipped
- Named Anthropic accounts ~anthropic-<N>~ are distinct Pi providers that reuse native Anthropic OAuth; the base ~anthropic~ credential stays the default account. ~/oh account add [N]~ registers an identity, and native ~/login~, ~/model~ and ~/logout~ act on it. Alternate-account browser login opens a private (incognito) window so that the primary SSO session stays signed in.
- Each primary session selects its own account through ~/model~, inside or outside Herdr. No shared credential is rewritten.
- The read-only quota collector reports one row per account, with account-isolated caches. CLI output, Pi help and the Herdr quota UI show each account.
- One Babashka policy (~herdr-orch.routing~, ~oh route~) expands model candidates to model/account pairs for subagent launches and primary recovery. Fresh, forked and measurement launches carry the concrete account; previews and the ledger name it without credentials.
- ~/oh tier <alias>~ keeps a weight-alias intent in the session. After a quota refusal, recovery tries same-model sibling accounts, then other candidates of the kept alias; a direct model selection permits only same-model fallback.
- MODIFIED [[proj:skills/herdr-orch/scripts/docs/contract.md]], [[proj:skills/herdr-orch/README.org]], [[proj:pi/extensions/herdr-orch/README.md]] and [[proj:herdr-app/README.md]]: account identity, the routing operation, ~/oh account~ and ~/oh tier~, and recovery limits.

** Gotchas
- Pi classes a 429 as transient and retries it before ~agent_before_settle~. Recovery therefore routes at ~agent_end~, which Pi awaits before its retry, so the retried request uses the new account. Only when Pi does not retry does ~agent_before_settle~ commit the stage to a continuation.
- Pi's ~auth_url~ consumer always opens the default browser. Private-window login therefore sends the URL as an info link and starts the browser itself.
- A pending native model setter can commit after abort or overwrite a newer manual selection. Accepted limit: recovery shows a warning until the setter settles and reports the actual selection; see [[file:2026-pi-recovery-selection-limits.org]].
- A credential stored under the earlier ~anthropic-account-<name>~ key needs a one-off ~auth.json~ key rename or a fresh login.

** Risks
- Simultaneous launches can choose the same account. Accepted: no reservation layer; revisit if measured contention justifies it.
- The controller does not replay completed tools, but cannot stop a model from requesting the same action again.

- Prior art reviewed and not adopted: [[https://cdn.jsdelivr.net/npm/pi-multi-account@1.28.1/index.ts][pi-multi-account 1.28.1]] (name-derived quality bands) and [[https://cdn.jsdelivr.net/npm/@ravshansbox/pi-multi-claude@2.0.5/index.ts][pi-multi-claude 2.0.5]] (rewrites the shared ~anthropic~ credential to switch).
