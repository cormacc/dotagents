* Intent

Give every `oh`-spawned child an explicit, inspectable thinking/effort level, resolved like the model (spawn flag > persona frontmatter > same-kind parent inheritance > shipped default `medium`) and rendered through a per-harness `:effort-flag` in `config.edn`, so a child no longer silently inherits whatever level its harness's own settings file happens to hold.

* Summary

*Level:* production · *Tests:* thorough · *Docs:* full

** Scope

*** In scope
- `core.clj`: `default-effort`, `effort-value!`, `resolve-effort`, `effort-args`; `validate-config-shape!` checks a present `:effort-flag`.
- `cli.clj`: `parent-effort`, `effort-policy`, `--effort` on `task run|start`, `HERDR_ORCH_EFFORT` injection, argv order `model-args ++ effort-args ++ extra-args ++ persona-args`, ledger/preview/`continue` fields.
- Packaged `skills/herdr-orch/subagents/config.edn` and home `subagents/config.edn`.
- `contract.md` § Model resolution and env-var table; `README.org` frontmatter, merge-rule, and `--print-prompt` sections.
- `core_test.clj`, `cli_test.clj` (`shipped-config-invariants` and new cases).

*** Out of scope
- A global default via the config chain or any new `:defaults` key (superseded by parent inheritance, 2026-09-24).
- Per-kind level vocabularies or translation tables; `oh` passes the level through.
- The pi `provider/id:<thinking>` model suffix: documented as unsupported, not rejected.
- Pinning `effort:` in any packaged persona.
- Cross-kind inheritance (a pi parent's `off` never reaches a claude child).

- [ ] Home `subagents/config.edn` restates `:effort-flag` for `:claude` and `:codex`.
- [ ] `oh task run|start` accepts `--effort <level>`.
- [ ] Persona frontmatter accepts `effort: <level>`.
- [ ] Precedence is `--effort` > frontmatter `effort:` > parent level (same kind only) > `medium`.
- [ ] Parent level reads `HERDR_ORCH_EFFORT`; at root, `PI_REASONING_LEVEL` only when the parent kind is pi.
- [ ] Every spawned child receives `HERDR_ORCH_EFFORT=<resolved level>` in its env.
- [ ] Child argv is `model-args ++ effort-args ++ harness-extra-args ++ persona-args`.
- [ ] A template containing `{}` splits on whitespace and substitutes the level into each token; a template without `{}` appends the level as the next arg.
- [ ] `--print-prompt` reports `:effort`, `:effort-source`, `:effort-args`.
- [ ] The ledger entry records `:effort` and `:effort-source`; `continue` carries both forward.
- [ ] `shipped-config-invariants` asserts the three shipped `:effort-flag` values.

- [ ] A blank or whitespace-containing `--effort` / `effort:` value fails at spawn before ledger allocation, naming the source. Narrowed by the owner on 2026-09-25: other control characters are left to Herdr's `agent start` check.
- [ ] A kind with no `:harnesses` entry yields empty `effort-args`.
- [ ] A pi parent spawning a claude child with no `--effort`/`effort:` resolves `medium`, source `default`.

- [ ] Must not: validate the level against a per-kind vocabulary.
- [ ] Must not: change `resolve-model`, `model-args`, or the `:models`/`:aliases` tables.
- [ ] Must not: add `effort:` to any packaged persona.

- [ ] `README.org` persona-frontmatter and merge-rule sections name `effort:` / `:effort-flag`; the `--print-prompt` field list names the three effort fields.

** Decisions
- Parent inheritance replaces a config-chain default :: mirrors `resolve-model`'s tier and mechanism (`HERDR_ORCH_EFFORT` injected per spawn; pi-only root fallback). Rejected: a `:defaults :effort` key -- a second global dial with its own merge semantics, when the operator's own level already expresses the default they want.
- Inheritance is same-kind only :: exactly `resolve-model`'s guard; prevents pi-only `off`/`minimal` reaching claude or codex without a vocabulary table. Rejected: cross-kind pass-through.
- `:effort-flag` is a string template with an optional `{}` placeholder :: one key, one type, expresses both `--flag <level>` and codex's `-c key=<level>`. Rejected: a vector template (same substitution work, more shape to validate); omitting codex (requirement says every entry gains the member; codex would silently ignore the level).
- Level vocabulary is pass-through :: consistent with the open model-ID set. Rejected: per-kind allow-lists (three tools, three vocabularies, codex's unverified).
- `:effort-flag` is optional :: revised by the owner on 2026-09-25, replacing "required, like `:model-flag`". A kind without one receives no effort args, which was the behaviour before this change. This removes the required check, the need for every override to restate the key, and the breakage of existing overrides. Accepted cost: an override that restates a harness entry and omits `:effort-flag` runs that kind at the harness default.
- pi `provider/id:<thinking>` suffix is documented as unsupported :: no packaged persona, alias, or `:models` column produces one; a rejection would be code for a case nobody has hit.
- Packaged personas declare no `effort:` :: the operator's level flows down; a persona that needs a fixed level can add it later without a contract change.
- One resolver per dimension :: `resolve-effort` beside `resolve-timeout`, not folded into `resolve-model`.

** Risks
- codex `model_reasoning_effort` accepted values are unverified (codex-cli 0.156.1: the key occurs in the real CLI binary `bin/.codex-wrapped` in the nix store, but no source states its value set). If `medium` is rejected, every codex child fails at `agent start` -- loud, not silent. Accepted; see `* Open questions`.
- `PI_REASONING_LEVEL` is set by pi 0.87.1's bash tool (`dist/core/tools/bash.js`, `= ctx.thinkingLevel`). A future pi that drops it degrades a pi root to `medium` silently. Accepted; `contract.md` names the version, as it does for `PI_MODEL`.
- pi's precedence between `--thinking` and a `:<thinking>` model suffix is unknown; out of scope by decision.
