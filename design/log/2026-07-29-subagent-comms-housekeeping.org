* Intent

Make the delegation loop's completion, progress, and handoff path observable and recoverable: a parent running several children should learn of the *first* completion, inspect bounded progress, retain portable artifact links after child-pane closure, and explicitly retire a stale assignment. Child publication mistakes should stay fixable in-session; persona, model, retro, and spawn-gating semantics remain untouched.

* Summary

*Level:* production · *Tests:* thorough · *Docs:* full

** Scope
*** In scope
- New fan-in primitive `subagent collect --any [--wait --timeout MS]`: capture the first published in-flight child of the caller's `:parent-session`.
- Multi-child support in the `fake-herdr` test fixture (per-child env/status/publish), a prerequisite of any `--any` coverage.
- Reframe root fan-out policy from "waves of at most two" to "at most N (default 2) children in flight", spawning a replacement as soon as one is captured.
- Advisory settle-gated parent push at publish time under the `non-blocking` waiting policy, plus the `:parent-pane` ledger field it needs.
- Bounded retry of `agent start` on the transient herdr error code `agent_pane_busy`.
- Publish-time rejection of relative `ARTIFACTS` entries, keeping the collect-side check as backstop.
- Contract/skill/README updates for all of the above: [[proj:skills/herdr-subagents/scripts/docs/contract.md]], [[proj:skills/herdr-subagents/SKILL.md]], [[proj:skills/herdr-subagents/README.org]], [[proj:skills/herdr-subagents/scripts/README.md]].
- Latest-only, throttled progress snapshots for long-running non-blocking children, visible through `status` / `list` without entering the result envelope or parent transcript.
- Explicit, ownership-scoped pruning of one stale assignment by full UUID; no automatic ledger sweep or fan-in candidacy heuristic.
- Documentation that assignment commands require the complete emitted UUID and never resolve `ot`-style prefixes.
- Portable Markdown artifact links (`[absolute path](file:///...) — purpose`) in the non-blocking publication advisory and in validated collect output; parent policy surfaces collected links to the user after pane closure.
- Bounded settle-close for `collect --any` captures: one budgeted `agent wait` on the captured child before the existing one-shot pane close, so a child observed mid-turn no longer permanently retains its pane; give-up retains the pane without touching the result.

*** Out of scope
- Multi-child *spawn* orchestration in the CLI: `run`/`start` stay one child per invocation; scheduling remains parent policy, now supported by a fan-in read.
- Any relaxation of the one-nesting-level depth bound or of below-root "one blocking child at a time".
- Resident (non-ephemeral) lifecycle changes.
- Making any signal other than the validated `RESULT` file authoritative for completion.
- Retrying `agent prompt`, `pane split`, `pane rename`, or `publish` itself.
- Cross-parent-session pane closure, and any change to single-task `collect` ownership semantics (including its foreign-session capture-with-`pane-retained` behaviour).
- Progress history, draft findings, parent prompts, or operator notifications: progress is one bounded ledger snapshot, not a second transcript/result channel.
- Automatic age/liveness sweeps or widening the `collect --any` candidacy predicate; stale retirement is an explicit command for one assignment.
- Prefix resolution for assignment commands; this change documents exact full-UUID semantics rather than adding aliases.
- Raw OSC 8 escape sequences or a guarantee that every harness/terminal makes links clickable; the contract guarantees portable Markdown plus a standard encoded `file://` URI.

- [x] Both gates (status and `agent_session` identity) are re-checked on the `AgentInfo` observed after that wait, before the single push.
- [x] A `blocked` parent receives no push at all (text must never land in an approval UI).

- [x] `collect --any` where every in-flight child is `blocked` reports `blocked` with the affected task ids instead of consuming the whole timeout budget.
- [x] `collect --any` where every candidate's child agent has vanished (`agent get` fails) reports `pending` / `no-live-children` instead of waiting out the budget.
- [x] `collect --any` honours `SUBAGENT_POLL_INTERVAL_MS` and does not overshoot the total timeout by a full interval.
- [x] `collect --any` with an unresolvable caller identity reports `pending` / `unknown-caller`, distinctly from `no-candidates`.
- [x] An `agent_pane_busy` budget exhaustion still runs the existing `:failure-phase "start"` cleanup (single ledger entry, child pane closed).
- [x] `publish --from-file` artifact lists are validated identically to repeated `--artifact` flags.
- [x] A rejected `publish` leaves no `RESULT` file behind.
- [x] A rejected `publish` leaves no `.tmp` sibling behind.
- [x] Progress updates inside the configured minimum interval (default 60 s; `SUBAGENT_PROGRESS_INTERVAL_MS` override) are reported as throttled and do not rewrite the snapshot.
- [x] Progress is rejected after `RESULT` exists, after capture, or on a terminal `failed`/`invalid` entry; it never changes completion status.
- [x] `prune` refuses a foreign-session assignment, a live child, an existing `RESULT`, or a captured/terminal entry without changing ledger state or closing a pane.

- [x] Empty artifact lists add neither an advisory artifact section nor collected `artifact-links`; an invalid/missing artifact never becomes a validated link.
- [x] Settle-budget expiry or a failed `agent wait` still makes the one close attempt and reports the envelope's own status with the pane retained.
- [x] The captured `--any` result's fields (including `remaining`) are identical whether the close succeeded or gave up.
- [x] A child that settles to `blocked` ends the settle wait early and keeps its pane.
- [x] A captured `BLOCKED` envelope skips the settle wait entirely.

*** Anti-criteria
- Must not: treat the advisory push, an operator toast, or terminal output as a completion signal — the validated `RESULT` file remains the only one.
- Must not: push to the parent under the `blocking` waiting policy.
- Must not: use `agent prompt --wait` for the push (that path can return `agent_prompt_stalled`).
- Must not: capture, validate, or close entries belonging to another `:parent-session` via `--any`.
- Must not: treat a terminal spawn-failure entry (`:status "failed"`) as an `--any` candidate.
- Must not: push to a parent pane whose current agent session differs from the ledger's `:parent-session` — panes outlive sessions, and a replacement agent must never be prompted.
- Must not: change single-task `collect` behaviour, including its foreign-session `pane-retained` outcome.
- Must not: absolutize, rewrite, or otherwise reinterpret child-supplied artifact paths.
- Must not: add an artifact *existence* check at publish time (artifacts may still be written up to collection).
- Must not: retry any herdr mutation other than `agent start`, or retry on error codes other than `agent_pane_busy`.
- Must not: grant a below-root child concurrent children.
- Must not: treat progress as completion, append progress history, put draft findings in progress, or push a progress prompt/notification to the parent.
- Must not: prune automatically from `collect --any`, close the stale entry's pane, or prune an entry owned by another parent session.
- Must not: resolve short assignment-ID prefixes.
- Must not: emit raw terminal-control hyperlinks or claim clickability independent of harness/terminal support.
- Must not: make publish-time artifact links evidence that the artifact exists; only `collect` produces validated links.
- Must not: wait for settlement before capturing, or apply the settle wait to any child other than the one captured.
- Must not: report anything other than the captured envelope's own status when the settle-close gives up.

** Decisions
- Chose a fan-in read (`collect --any`) over a CLI-side scheduler :: the parent already owns spawn decisions and task dependencies; it only lacked "tell me which child finished first". Rejected:
  - A `subagent fanout` command taking N assignments: duplicates the parent's dependency knowledge and would need its own queue/state machine in the ledger.
  - Pure polling loops in the skill text (`status` in a shell loop): every parent reinvents backoff, ownership scoping, and blocked detection.
- `--any` polls `RESULT` files rather than blocking in `agent wait` :: `agent wait` takes a single target, so N children cannot be awaited in one call. Consequence: lifecycle-based blocked detection degrades to one `agent list`/`agent get` scan per poll iteration, which is what keeps the all-blocked case from burning the budget.
- `--any` candidate set is same `:parent-session` + no `:captured-at` + `:status` not `failed` :: makes a repo-wide shared ledger safe to fan in over and keeps the ownership anti-criterion mechanically enforced. The `failed` exclusion is load-bearing rather than tidiness: `safe-cleanup!` (`cli.clj:228`) writes `:status "failed"` *without* `:captured-at`, so a session-scoped "uncaptured" predicate alone would keep dead spawn-failure entries as candidates forever, making both the `no-candidates` and all-blocked outcomes unreachable. `invalid` entries need no exclusion — `capture!` sets `:captured-at` on that branch too.
- Advisory push is gated on parent session identity *and* status :: a submitted prompt is the only channel that actually causes the parent to run `collect`, but a pane outlives the agent that occupied it, so status alone would let a delayed child prompt an unrelated replacement agent in a reused pane — the same ownership boundary `maybe-close!` already enforces for pane closure. Gating on `idle`/`done` (with a bounded wait for `working`) avoids hijacking an active turn, and refusing to push to a `blocked` parent avoids answering an approval dialog. Rejected:
  - `pane send-text`: never consumes a parent turn, but the parent may not look at its input box for a long time, and it needs a new preflight capability (`pane send-text` is absent from `required-capabilities`).
  - Operator toast only: the motivating failure was precisely a parent that learned of publication from the human operator.
- Relative artifact paths are rejected, not absolutized :: publication is immutable, so the cheap fix is to fail *before* the immutable write and let the child retry; silently resolving against the assignment root would reinterpret intent (child cwd vs root) and could name a file the child never meant.
- Retry is keyed on the herdr error `code`, not on message text :: `herdr` returns `{"error":{"code":"agent_pane_busy","message":"..."}}`, already decoded into `:response` by `herdr/invoke`. The code survives `value!` too (it re-throws the whole error map as `ex-data`), so retrying over `invoke` inside `herdr/start!` is a placement preference — no catch/re-throw of an `ex-info` — not a data-availability constraint.
- Progress is a latest-only ledger snapshot, not a push :: add child-only `progress --summary`, overwrite at phase boundaries no more than once per configured interval, and expose the snapshot through existing `status` / `list`. Rejected: progress `agent prompt` (interrupts/consumes parent turns), operator toast (human-only noise), and progress history (unbounded second transcript).
- Stale cleanup is explicit and single-assignment :: `prune <full-task-uuid>` reuses parent-session ownership and `agent list` liveness, then marks only a proven stale entry `failed` with `:pruned-at` / `:prune-reason`; it never closes the recorded pane because that pane may have been reused. Rejected: implicit collection-time pruning and age-based candidacy changes.
- Artifact context uses portable Markdown over raw OSC 8 :: render `[escaped absolute path](Path.toUri) — purpose`; Pi user messages turn Markdown links into OSC 8 when supported, while other renderers retain readable Markdown/URL fallback. Publish links are advisory; `collect` links are existence-validated. Rejected: raw control sequences in model-visible prompts and basename-only labels that lose path context.
- Assignment IDs remain exact ledger keys :: document complete UUIDs in help/examples instead of introducing a second prefix-resolution contract parallel to `ot`.
- Settle-close budget is additional to `--timeout`, never deducted from it :: `--timeout` bounds only the polling for a publication; folding the settle wait into that same budget would make a late capture's close chance depend on when it happened to land within the poll window, rather than being a fixed, predictable bound.
- `--any`'s settle-close is one bounded `herdr/wait!` on the captured child, not a re-check sleep loop :: `agent wait` polls natively in one subprocess and (without `--until`) returns on *any* settled state, so a blocked child ends the wait early instead of burning the budget. The budget must outlast publish's parent push: a non-blocking child that publishes while its parent sits in `collect --any` reads `working` for the full 30 s notify wait (the parent, mid-collect, never settles idle/done), which is exactly the reproduced retention — hence a 45 s default (named var, `SUBAGENT_SETTLE_CLOSE_MS` override) rather than a poll-interval-scale bound. Rejected:
  - Bounded re-check after a short sleep: reimplements `agent wait`'s polling at one `agent get` subprocess per probe, and any budget short enough to feel like a re-check loses the guaranteed ≥30 s notify stall, missing the motivating reproduction.
  - Deferred close on a later `collect --any` tick: the last captured child never sees another tick — the reproduced case leaked exactly the final two captures.
  - Trimming publish's notify wait when the parent is `working`: relitigates the shipped push gate from the wrong side of the race.

** Gotchas
- `herdr agent wait` without `--until` matches idle, done **and blocked** — stated only in the `--help` epilogue prose, not in the flag list. The settle wait must pass `--until idle --until done` explicitly; reusing `herdr/wait!` would have let a blocked parent satisfy the wait and receive prompt text in its approval UI. Read herdr's epilogue prose whenever an omitted flag's default is load-bearing.
- A fixture verb can carry side effects for its original role: `fake-herdr`'s `agent wait` publishes the *target child's* result, so reusing it for the parent-side settle wait would have published a result as a side effect of the notification path. Branch on the target before the existing role's case when a verb gains a second role.
- `herdr agent list` entries carry `name` only for *named* agents; a manually started agent appears nameless (verified live: all four current panes have `name: null`). Liveness must therefore be keyed on `name` with no `pane_id` fallback — a fallback would keep an exited child "live" forever and make `no-live-children` unreachable.
- `herdr <cmd> --help` documents flags only, never the JSON response shape. Learn a response shape from one live read-only invocation or from `contract.md`, never from a fixture stub (which may encode no shape at all).
- An absence/anti-criterion assertion can pass vacuously from test *ordering*, not just from prefix matching: the fan-in foreign-session assertion initially sat after the owning capture and passed on `:captured-at` alone. Verify each must-not by mutating the guard it protects and confirming the test fails.
- The fixture's preflight probes are in the same call log as real mutations, so a naive two-token prefix match (`["pane" "close"]`) matches the unconditional `pane close --help` probe and silently passes an absence assertion. Always exclude `--help` explicitly, as `mutating?` (`cli_test.clj:22`) already does.
- `--artifact none` is now rejected. The `- none` sentinel is a *rendering* artefact of an empty list (`core/section-lines` maps `["none"]` back to `[]`), never something a child should pass; before this change an improvised `--artifact none` published a silently empty artifact list, and now it fails loudly with "artifact path must be absolute". No persona or doc instructs that form, so this is a deliberate tightening rather than a regression.
- `collect --any`'s fast-path capture (`capture-first` finding a published `RESULT` before any liveness scan) used to call `maybe-close!` immediately with no settle-wait, checking the child's `agent_status` exactly once — a child observed mid-turn (`working`) then permanently retained its otherwise-`COMPLETE` pane. Discovered live this session (two workers' panes stayed open after capture); fixed by task `e8ea2227`'s bounded settle-close, above.
- A concurrent Edit-tool write from a sibling worker can silently clobber an in-progress worker's own uncommitted append to the same shared file (observed on `cli_test.clj` during the parallel progress/artifact-links wave); both workers self-detected via a failing `bb test` and re-verified before publishing, but nothing in the CLI or worker persona guards against this class of race. See `** Follow-ups`.
- `fake-herdr`'s `agent wait` used to record `--until` in its call log without honouring it, so a behavioural claim about that flag ("blocked ends the wait early") was pinned only by an argv-shape check — a real regression would still have passed. Fixed: the fixture now honours `--until`, timing out when the requested state is excluded. When a fixture verb gains a new flag-dependent behavioural claim, make the fixture actually implement the flag's effect, not just log it.

** Risks
- The push can still arrive as a duplicate stimulus when the parent is simultaneously blocked in `collect --any --wait`; accepted — the prompt is idempotent advice and `collect` on an already-captured entry returns the same outcome.
- Bounded `agent wait` inside `publish` keeps the child process alive after the result is committed. Accepted: the parent may close the child pane mid-wait, which kills only the notification, never the published result.
- `--any` fairness is poll-order dependent when two children publish inside the same interval; accepted (one is returned, the other stays capturable).
- A parent that never fans in leaves in-flight entries with panes open; unchanged from today's `start` behaviour, and `status`/`list` still show them.
- Progress is cooperative: a child that ignores the injected phase-boundary instruction still has no heartbeat. Accepted — progress remains advisory and cannot replace Herdr lifecycle state.
- Explicit prune requires the parent to identify the stale full UUID; accepted to keep destructive ledger mutation deliberate and ownership-checkable.
- Publish advisory links can point at an artifact that later fails collection; accepted because the advisory says validation is pending and only collected `artifact-links` are trusted.
- Markdown `file://` links are clickable only when the harness renderer and terminal support hyperlinks; absolute visible labels and URI fallback preserve useful context otherwise.
- `core/artifact-link` is not pure: `Path.toUri` stats the filesystem, so an existing-directory artifact's URI gains a trailing slash its label omits, and a pre-collection advisory link can differ from the post-collection validated link for the same declared line. Accepted and pinned by test.
- `progress`'s `ledger/update!` has no compare-and-swap: a concurrent parent `capture!`/`record-session!` write can race a child's `progress` write and lose one side. Bounded and recoverable (worst case, a dropped `:captured-at` briefly re-enters `collect --any` candidacy for a harmless re-parse of the already-published `RESULT`); not worth ledger locking.
- The settle-close budget is additive to `--timeout`, so a capture landing just before `--timeout` would have elapsed can return up to `SUBAGENT_SETTLE_CLOSE_MS` later than `--timeout` alone suggests. Accepted: `--timeout` bounds only publication polling, and the settle wait is a separate, predictable, post-capture bound.

** Settle-close for `collect --any` (task e8ea2227)
The wait lives inside `collect-any!`'s `captured` helper, applied only to a `capture-first` hit and gated on `(#{"COMPLETE" "FAILED"} (:status parsed))` — a captured `BLOCKED` envelope never closes a pane, so it skips the wait entirely. `herdr/wait!` (no `--until`) is used deliberately over `wait-settled!` (which excludes `blocked`): the bare form returns on *any* settled state, so a child that settles `blocked` ends the wait immediately instead of burning the whole budget, and `maybe-close!`'s own unmodified idle/done check still refuses to close its pane. Whatever the wait's outcome — settled, timed out, or a herdr error — the call is wrapped in a `try`/`catch` that discards it, and the unmodified `maybe-close!` makes the same single close attempt regardless; `remaining` is computed from the candidate set observed at capture, before the wait, which is what keeps the result's fields identical whether the close succeeded or gave up.

An advisor consult caught a vacuous test: the fixture recorded `--until` in its call log but did not honour it, so the "blocked ends the wait early" assertion was pinned only by an argv-shape check, not by actual behaviour — a `herdr/wait!` → `wait-settled!` regression would still have passed. Teaching `fake-herdr`'s `agent wait` to honour `--until` (timing out when the settled state is excluded from the requested set) converted it into a real behavioural guard; the same regression now also fails on elapsed time. The worker independently applied this same non-vacuous-test discipline (already filed as task `fd8e0daf`) without being told to.

The fixture also needed a new per-child `settle-to` marker, branched before the pre-existing `FAKE_WAIT` dispatch: the settle-close wait targets a child that has *already* published and is merely still `working`, so reusing the original `agent wait` verb unmodified would have re-triggered its publish side effect. `settle-to` settles the target without publishing, writing the settled status through to the child's `status` file so a following `agent get` agrees.

The budget (`default-settle-close-ms`, 45 000 ms / `SUBAGENT_SETTLE_CLOSE_MS`) is deliberately larger than `default-notify-timeout-ms` (30 000): the reproduced retention is exactly a non-blocking child publishing while its own parent sits inside `collect --any`, which keeps that parent `working` (never idle/done) for the entire 30 s notify-push wait — a budget at or below that would miss the very case that motivated the fix. This settle budget is additive to `--timeout`, not deducted from it, so a capture landing near the end of the poll budget can return up to the settle budget later than `--timeout` alone suggests; documented in `contract.md` rather than treated as a bug.

Coverage: 6 tests, including an elapsed-time bound (not just an argv check) proving the blocked-early-exit and a full field-equality comparison (modulo per-fixture identity fields) proving the give-up-vs-success result shape is identical. `bb test`: 404 / 2164 green (baseline 398 / 2117).

** Portable Markdown artifact links (task 41a5c747)
`core/artifact-link` reuses `core/artifact-path`'s absoluteness check (via a shared `artifact-parts` splitter) rather than trusting a pre-validated caller, builds the `file://` URI with `java.nio.file.Paths/get … .toUri` (not `File.toURI`, which omits the empty authority and yields `file:/…`), and backslash-escapes Markdown-significant characters in both the label and the purpose — including `&`/`<`/`>`/`~`, since an unescaped entity reference would make a CommonMark renderer display a *different* path in the one field that must stay trustworthy. `(` and `)` are legal URI sub-delimiters `toUri` leaves alone but are percent-encoded afterward because an unbalanced parenthesis would truncate a Markdown link destination.

An advisor consult (REVISE) caught real defects before publish: the plan's named API (`File.toUri`) does not exist (`File.toURI` is the real method and is *not* what should be used — `Paths/get … .toUri` is correct and canonical); `Path.toUri` performs I/O (stats the path, appending a trailing slash for an existing directory), so the renderer is not pure and a directory artifact's advisory link can differ from its collected link for the same declared line — pinned by `artifact-link-uri-reflects-directory-state-on-disk` rather than hidden; and a NUL byte passes `core/artifact-path` but fails both `Paths/get` and the `agent prompt` argv boundary, so an unrenderable declared artifact is dropped from the advisory and counted (`- (N … not renderable …)`) rather than raw-texted or allowed to crash the whole push.

`capture!` builds `artifact-links` only after every artifact clears the existing `fs/exists?` loop, stores it on the ledger entry via `cond->` (an empty/absent list adds no key at all — absence is not the same claim as validated-empty), and the `invalid` branch actively `dissoc`s any `:artifact-links` a prior successful capture had stored, since a re-collect after the artifact vanishes must never keep advertising a stale validated link. `collect --any`'s result shape is unaffected beyond the existing `remaining` field, since it flows through the same `capture!`/`maybe-close!` path.

** Advisory parent push (task 6a4101d1)
`notify-parent!` runs only under `non-blocking`, only after the committed link, and only when `push-decision` clears both gates — session identity is checked *first*, so a mismatched parent is reported as `session-mismatch` regardless of its status. A parent whose session cannot be observed fails the gate by construction (`nil` never equals the recorded identity), which is the safe direction since a ledger `:parent-session` is never nil.

** Fan-in primitive `collect --any` (task 157a2c3d)
Each tick is: poll every candidate's `RESULT`, one `agent list` to classify liveness, then **poll again** before any terminal outcome. That re-scan is not defensive padding — an advisor consult caught that a child can publish and exit inside the `agent list` subprocess window, so without it both `blocked` and `no-live-children` could discard a valid `COMPLETE` envelope on disk and leak its pane. The same consult caught `(into {} … nil)` yielding a truthy `{}`, which would have classified every child as vanished on any exit-0 payload lacking an `agents` key; `when-let` on the raw listing keeps "liveness unknown" (keep polling) distinct from "known zero live" (short-circuit).

`maybe-close!` is called with `owned? true` because candidacy is same-session by construction. Without `--wait` the budget is zero, so a single poll that finds nothing reports `pending` / `timeout` — the same reason string as an elapsed budget, since a zero budget *is* elapsed.

Known limitation, documented in `contract.md` rather than fixed: a `run`/`start` killed between `ledger/write!` and its cleanup leaves a same-session, uncaptured, non-`failed` entry that stays a candidate indefinitely, inflating `remaining` and making `no-candidates` unreachable for that session. Widening the candidacy predicate to cover it would weaken the pre-decided contract; clearing the stale ledger file is the remedy.
