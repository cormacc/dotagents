* Intent
Let task memory be tracked from outside a third-party repo (e.g. OSS PRs) by
resolving =TASKS.org= from any ancestor directory. The =ot= CLI already does
this when spawned from the workspace cwd; the pi tasks extension currently
forces =--root=cwd= and spawns =ot= without a workspace =cwd=. Bring the
extension in line with the CLI by spawning =ot= from =ctx.cwd=, consuming the
resolved =ot list= paths, and surfacing the resolved =TASKS.org= path in the UI.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* inline + SKILL/reference update

The original task framing ("traverse above git root") is largely already
satisfied in the CLI: =org_tasks/root.clj= walks =cwd= → ancestors to the
nearest =TASKS.org=, with no git dependency, falling back to =cwd=. The real
gaps are in the pi tasks extension: it uses =ctx.cwd= directly via
=join(cwd, TASKS_FILE)=, forces =--root=cwd= on =ot= calls, and =runOt= spawns
without =cwd= so CLI traversal would otherwise start from the pi process
directory rather than the workspace.

=ot list= JSON already emits =files= (absolute =tasks=/=local=/=archive= paths
from =resolve-protocol-files=); we add explicit =root= and make extension code
consume =root= / =files= instead of re-deriving paths from =cwd= or =root=.
=ot root= is added as a convenience command, but the extension's hot path uses
=ot list= so root + files are obtained in the existing round-trip.

** Scope
*** In scope
- =ot list= JSON includes an explicit resolved =root= alongside existing
  =files=.
- Extension =RunOtOptions= gains =cwd=; =runOt= passes it to =spawn(..., {cwd})=.
- Extension traversal-mode calls use =otList({cwd: ctx.cwd})= / related
  ={cwd: ctx.cwd}= calls rather than ={root: ctx.cwd}=.
- Extension threads =result.files= through direct file operations:
  =readSelectedId= reads =files.local=; watchers include =files.tasks= and
  =files.local=; UI prefers =files.tasks= for display.
- =/tasks= overlay (=overlay.ts=) and compact status header (=index.ts=) show
  the resolved =TASKS.org= path.
- Standalone =ot root= command prints the resolved project root
  (convenience/scripting); only =--root= overrides that root.
- SKILL.md + =references/ot-cli.md= document shared resolution, the =ot list=
  =root= field, =ot root=, and filesystem-root nearest-ancestor behaviour.
- Tests: =ot list= =root= field; =runOt= =cwd= pass-through; extension nested-cwd
  traversal; =ot root=.

*** Out of scope
- No traversal boundary (=$HOME= vs filesystem root): traversal continues to
  filesystem root by operator decision.
- No change to =ot init= resolution behaviour.
- No git dependency in root resolution.
- No TypeScript reimplementation of the ancestor walk.

** Decisions
- Chose Approach A (fold resolution into =ot list= output) :: the extension
  calls =otList= every refresh and the result already carries absolute =files=.
  Adding explicit =root= makes the list result self-contained; passing
  ={cwd: ctx.cwd}= to =runOt= makes CLI traversal start from the workspace.
  Rejected:
  - Extension resolving via =ot root= per refresh: an extra spawn for data
    =ot list= can carry inline.
  - Re-implement walk-up in TypeScript: duplicates =root.clj=, risks drift.
  - Drop =--root= without setting spawn cwd: traversal starts from the pi
    process directory, not the workspace.
- Add =ot root= as convenience only :: useful for humans/scripts; not used by
  the extension hot path.
- No traversal boundary :: filesystem-root traversal retained; a present
  ancestor =TASKS.org= is intentional. Nearest ancestor wins even outside =$HOME=;
  use a closer =TASKS.org= or explicit =--root= to override.

** Risks
- Wrong traversal start dir :: highest-risk implementation point. =runOt= must
  accept =cwd= and pass it to =spawn=; extension calls must use ={cwd: ctx.cwd}=
  instead of ={root: ctx.cwd}= for traversal-mode operations.
- Watch breakage :: =collectWatchPaths= must watch =files.tasks= and
  =files.local=, else live-reload dies when working from a nested dir.
- Surprising ancestor capture :: nearest =TASKS.org= wins even outside =$HOME=.
  This is accepted; docs should call out closer =TASKS.org= / explicit =--root=
  as the override.
