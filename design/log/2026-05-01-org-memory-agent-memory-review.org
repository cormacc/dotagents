* Summary
First pass at treating the org-memory protocol explicitly as agent memory rather than only a human task list. Identified protocol gaps that made cross-session resume ambiguous (duplicate IDs from subtask-mirroring, mutable =CLOSED:=, unspecified import trust boundary, unclear retrospective scoping when =:STARTED:= absent, and informal =:CREATED:= shape) and shipped the protocol decisions plus the tasks-extension changes that lock them in.

** Decisions
- Subtask migration is the identity model :: one canonical node per UUID; the parent retains a plain-text bullet summary, not duplicate task nodes. Replaces the earlier UUID-mirroring guidance.
- LOGBOOK is the durable history :: heading status and =CLOSED:= are mutable current-state caches; =:LOGBOOK:= is append-only.
- Reopen semantics are explicit :: leaving a closed state clears current =CLOSED:= but preserves the old close in LOGBOOK; re-close writes a fresh =CLOSED:= and appends another LOGBOOK entry.
- Direct =TODO → DONE= retrospective scoping :: use =:STARTED:= when present, otherwise the LOGBOOK created event / =:CREATED:= as the lower bound.
- Imports are sandboxed :: =#+IMPORT:= paths and scaffolded plan paths must resolve under the project root after symlink resolution. Absolute paths and parent-traversal escapes rejected by default.
- Linked-issue URLs are trusted :: =#+ISSUE_URL_BASE:= / =:LINKED_ISSUES:= are project-local trusted configuration. Non-HTTPS schemes intentionally permitted; opener uses argv-based =open= / =xdg-open= invocation (no shell interpolation).

- =org-jira/SKILL.md= + jira README: trust-boundary wording, planning/resume context, Jira-derived task identity, LOGBOOK vs live status-change events.

- Retrospective prompt scoping uses =:STARTED:= or the =:CREATED:= fallback.

** Gotchas

Pre-existing files with out-of-tree imports load with empty =importChildren= and an =importError= rather than silently following the link. This dotfiles repo has no such imports.
