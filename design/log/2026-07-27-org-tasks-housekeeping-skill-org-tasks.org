* Intent

Remove five recurring sources of manual repair and misleading `ot` output without broadening the org-task protocol: preserve identifier strings at the CLI boundary, recognise legacy bare-UUID blockers, make spec traversal safe over real repositories, add a guarded archive inverse, and show task bodies in human-readable output. Keep machine output, round-trip fidelity, lifecycle semantics, and existing on-disk blocker values compatible.

* Summary

*Level:* production · *Tests:* thorough · *Docs:* full

Five independent fixes stay within the existing parser, command-family, registry, loader, and documentation boundaries. The only new command is `ot unarchive`; the other four changes repair existing semantics or human-readable output without changing existing machine payloads. Unarchive preflights all baselines, writes the active subtree, then any linked-record reversal, and removes the archive copy last so a post-preflight failure leaves a recoverable copy.

** Scope
*** In scope
- String coercion for every task-ID positional argument and every task-ID-valued create option in the shared command registry.
- Bare full-UUID blocker classification, writer preservation, readiness resolution, and missing-reference diagnostics.
- Spec-discovery filtering for generated/dependency trees and NUL-bearing binary files.
- Non-fatal diagnostics for malformed transitive spec-link targets in `ot spec list` and `ot doctor`.
- Core-layer (`org-tasks.spec`) malformed-target guarding in `resolve-link-target`, effective independently of fs-adapter path guards, with direct regression coverage.
- `ot unarchive`, archive-origin section metadata, active/archive file mutation, and change-record parent-link reversal.
- Restricting `:ARCHIVE_OLPATH:` stamping to roots archived from shared `TASKS.org`, with focused archive/unarchive coverage for roots living in file-level `#+IMPORT:` records.
- Default task-body rendering in text-mode `ot show` / `ot selected`.
- Contract, protocol, CLI, architecture, and skill documentation touched by these behaviours.
*** Out of scope
- The parser-facade split and unrelated org-tasks backlog items.
- Rewriting existing bare-UUID blockers or changing their on-disk spelling.
- MIME detection, arbitrary binary-format classification, or a configurable spec-ignore language.
- Restoring legacy archived tasks to a guessed section when neither `:ARCHIVE_OLPATH:` nor `--section` supplies one.
- Reopening status as part of unarchive; callers continue to use `ot status`.
- Archived-task browsing or unarchive actions in the TUI / pi overlay.
- Changes to imported-root archive restoration; `ot unarchive` restores into shared `TASKS.org` only.
- Restoration or replacement of the intentionally deleted `TASKS.org` task `04602946` (bb-tasks extension improvements); the deletion is deliberate, not remediation scope.

** Decisions
- Keep the five fixes as independent command/core changes under the existing namespace boundaries :: each migrated task is independently implementable and verifiable; only shared documentation and the full suite couple them.
  Rejected:
  - Fold them into the deferred parser-facade refactor: unrelated risk and no acceptance payoff.
  - Add command-local stringification shims: easy to miss future ID-bearing handlers and too late to preserve the original token reliably.
- Coerce IDs in registry-derived dispatch at the CLI parse boundary :: create's `:id`, `:parent`, `:after`, and `:relative-to` specs use `:coerce :string`; the existing aggregate `dispatch-coerce` then applies `:id` string coercion to every positional command without advertising a synthetic `--id` option in each command's help. A structural test prevents partial coverage.
  Rejected:
  - Add an `:id` option spec to every positional command: fixes coercion but pollutes command help with an option that is documented as positional.
  - Stringify only in `resolve-id-arg`: fixes `show` but leaves status, links, archive, record, and create placement inconsistent.
  - Stringify numerics after coercion: scientific notation has already destroyed the original hexadecimal spelling.
- Recognise only bare full UUIDs as implicit task blockers :: preserve their raw spelling while projecting `kind=task`; explicit `task:` remains the documented preferred writer form.
  Rejected:
  - Treat every bare token as a task ID: turns human blockers into dangling references.
  - Rewrite old values to `task:`: unnecessary migration churn and violates round-trip expectations.
- Filter spec inputs before traversal and degrade malformed targets to diagnostics :: path-segment exclusions cover conventional generated/dependency trees; NUL is the deterministic binary heuristic; malformed-target details flow to `warnings` for `spec list` and an ordered doctor finding.
  Rejected:
  - Extension allow-list: drops extensionless and uncommon but valid living specs.
  - Catch only `InvalidPathException`: avoids the crash but still slurps dependency binaries and silently hides the source.
  - Full MIME detection: dependency and portability cost is disproportionate.
- Preserve archive destination context with Org-standard `:ARCHIVE_OLPATH:` :: new archives restore without guesswork; `--section` is an explicit override and the required compatibility path for legacy entries without context.
  Rejected:
  - Always restore under `Improvements`: silent semantic corruption for tasks archived from other sections.
  - Recover placement from git history: unavailable outside git, sensitive to rewrites, and unnecessary once archive metadata exists.
  - Invent a project-specific archive property: duplicates an established Org context field.
- Unarchive preserves lifecycle state :: it reverses file placement and parent-link kind only; `ot status <id> TODO` remains the single lifecycle writer that clears `CLOSED:` and logs the transition.
- Fix the malformed-target second defence in the pure core and prove it adapter-independently :: review 2026-07-28 found the `resolve-link-target` guard inert (`:as` written inside the `:keys` vector binds `link` to nil, so `invalid-link-target?` never fires); correct the destructuring and add regression tests that call `org-tasks.spec` directly through a permissive fs stub so no adapter guard can mask a regression.
  Rejected:
  - Rely solely on the fs-adapter `safe-relative-path?`/NUL guards: leaves the documented second defence layer dead code and reintroduces the original crash for any adapter without those guards.
- Stamp `:ARCHIVE_OLPATH:` only for roots archived from shared `TASKS.org` :: record-internal level-1 headings (`* Plan`, `* Implementation`, …) are never valid restore destinations, so stamping them is misleading at archive time and breaks default unarchive; leaving the property absent routes imported-record roots to the existing actionable `--section` legacy path.
  Rejected:
  - Map a record-internal heading back to the parent task's `TASKS.org` section: cross-file inference for marginal benefit while imported-root restoration stays out of scope.
- Deletion of `TASKS.org` task `04602946` (bb-tasks extension improvements) is intentional :: review flagged it as unexplained task-memory loss; confirmed deliberate, with no restoration, archive-lifecycle, or replacement work planned.
- Render the body by default in text `show` :: explicit `show` is the human inspection command; machine callers keep consuming the unchanged `description` field.
  Rejected:
  - Add `--body`: perpetuates the surprising omission and requires callers to know a second inspection mode.

** Shipped
- MODIFIED CLI dispatch :: preserve task-ID tokens as strings for positional commands and create placement options, including scientific-notation-shaped UUID prefixes.
- MODIFIED blocker semantics :: resolve bare full UUIDs as task dependencies without rewriting stored values; retain human handling for other bare text and diagnose missing task references.
- MODIFIED spec discovery :: exclude generated/dependency trees and NUL-bearing files, reject malformed control-data targets in both core and filesystem layers, and surface non-fatal diagnostics through `ot spec list` and `ot doctor`.
- ADDED `ot unarchive` :: guarded archive-only restoration with source-section metadata, explicit legacy/imported-root section selection, dry-run, parent-link reversal, lifecycle preservation, and active → linked-record → archive-removal write ordering that prefers a recoverable duplicate to task loss.
- MODIFIED text-mode `ot show` / `ot selected` :: render non-empty task bodies while preserving existing JSON/EDN payloads.
- MODIFIED `skills/org-tasks/SKILL.md`, `skills/org-plan/SKILL.md`, `references/protocol.md`, `references/ot-cli.md`, `scripts/docs/contract.md`, and architecture/readme material :: align durable workflow and command contracts with the shipped behavior.

** Risks
- The directory exclusion set can hide a deliberately-authored spec under a conventionally generated folder. Accepted and documented; explicit repository organisation should keep living contracts outside generated/dependency trees.
- NUL detection does not identify every binary encoding. Accepted; it prevents the reproduced crash without inventing MIME policy.
- `ot archive` and `ot unarchive` remain sequential multi-file writes rather than a filesystem transaction. For unarchive, loading and preflighting every baseline precede an active-subtree write, then linked-record rewrite, then archive removal last; atomic per-file replacement plus that order prefers a recoverable duplicate over task loss after a write failure. A failure can therefore leave duplicate active/archive copies or a temporarily stale record link, requiring recovery rather than automatic rollback.
- Legacy archive entries need an explicit `--section`; this is intentional rather than silently guessing from current repository layout.
- Plain `ot show` output becomes longer for large bodies. Intended; JSON/EDN and `ot list` remain the bounded automation surfaces.
- Roots archived from imported records carry no `:ARCHIVE_OLPATH:` and always require an explicit `--section` on unarchive. Accepted; explicit intent beats a wrong record-internal heading.

* Implementation

- Registry-derived `:id` string coercion preserves positional tokens without adding synthetic positional options to help; create's ID-valued placement options are explicitly string-coerced.
- Bare full UUID blockers are task-kind compatibility tokens only; writers preserve them while other bare input stays `human:`.
- Discovery filters excluded path segments and NUL-bearing candidates before filesystem reads; malformed control-data targets become `spec-link-invalid` diagnostics for `spec list` and doctor; obsolete migration-only `old-discover` code was removed.
- `resolve-link-target` destructures `{:keys [kind target] :as link}`, so its malformed-target guard actually fires and `linked-paths-from` drops control-data targets independently of any fs adapter; spec-test regression coverage runs through an `:eligible?`-free stub.
- Archive writes source-section metadata only when the root's `:source-path` is shared `TASKS.org`, so imported-record roots archive without a misleading record-internal `:ARCHIVE_OLPATH:` and restore via explicit `--section`; unarchive preflights active/archive/record baselines, restores only into an existing shared section, writes active then linked-record reversal then archive removal, and leaves status/CLOSED/LOGBOOK intact.
- Text show/selected append only non-empty descriptions; machine Task payloads are untouched.
