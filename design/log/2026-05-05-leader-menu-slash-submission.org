* Summary
Made leader-menu's =command:= leader actions submit slash commands in a single keystroke, regardless of whether vim-mode is loaded. Previously leader-menu populated the editor via =setEditorText()= and asked the user to press Enter; only vim-mode's =CustomEditor= subclass had a programmatic =submitCommand=. Introduced a thin =SubmitterEditor= base (=extensions/lib/editor.ts=) that adds one method (=setEditorText(text); super.handleInput("\r")=) and a module-scope active-instance registry. leader-menu installs =SubmitterEditor= unconditionally at =session_start=; vim-mode (when re-enabled) extends =SubmitterEditor= rather than =CustomEditor= so single-step submission survives editor swaps. Trivially stateless: no fields beyond the base, no overrides beyond =submitCommand=.

** Decisions
- Single ownership :: submission is leader-menu's responsibility end-to-end; vim-mode no longer carries its own =submitCommand= duplicate.
- Unconditional install :: leader-menu installs =SubmitterEditor= at every =session_start= regardless of =getEditorComponent()=. Trade-off: any extension calling =setEditorComponent()= without extending =SubmitterEditor= clobbers single-step submission. Documented as the contract.
- Shared base in =extensions/lib/= :: =SubmitterEditor= ships in =lib/editor.ts=, imported via the existing =../lib/= convention. Avoids the cross-extension-import prohibition (=VIM_NORMAL_RESERVED_KEYS= used to be duplicated for the same reason).
- Structural inheritance, not runtime delegation :: =VimEditor extends SubmitterEditor=. No second hidden editor instance with parallel text/render state — satisfies the prior plan's "no invisible composition" rule.
- Trivially stateless base :: must add no fields and override no methods other than =submitCommand=. Drift toward statefulness re-introduces the rejected state-skew hazard.
- Active-instance registry :: module-state shared across extensions via jiti's resolved-path dedupe; populated by the constructor, cleared on destruction. leader-menu reads the live submitter from the registry, not its own factory closure, so =VimEditor= replacing the factory at later session_start is transparent.
- Lifecycle :: at =session_shutdown=, leader-menu calls =setEditorComponent(undefined)= to restore pi's default editor.
- Relaxation of the 2026-05-01 "leader menu first, editor replacement second" default :: leader-menu now installs an editor by default. Justified by the trivially-stateless property the prior plan didn't have to consider.
- Invert leader-menu → vim-mode coupling :: leader-menu owns *no* vim knowledge. The dependency edge points the other way: vim-mode imports =SubmitterEditor=, subscribes to =leader-menu:keys-resolved= (now carrying =userConfigured= flags), and owns its own grammar-clash detection.

** Shipped
- =extensions/lib/editor.ts= :: =SubmitterEditor= base + active-instance registry.
- =extensions/leader-menu/= :: installs =SubmitterEditor= unconditionally; =command:= action handler captures the live instance from the registry and calls =submitCommand=. Dropped =VIM_NORMAL_RESERVED_KEYS= and =warnClashingLeaderKeys=. =leader-menu:keys-resolved= payload extended with =userConfigured: { globalLeader: boolean, localLeader: boolean }=.
- =extensions/disabled/vim-mode/= :: =VimEditor extends SubmitterEditor=; duplicate =submitCommand= removed. Vim-mode now subscribes to =leader-menu:keys-resolved= and emits its own clash warning gated on =userConfigured[slot]=.
- Documentation: leader-menu README + AGENTS.md "Slash command submission" section (vim-agnostic); vim-mode README + AGENTS.md note submission lives in the shared base and now own the =localLeader = ","= / repeat-find trade-off discussion; cross-reference to the 2026-05-01 change-record.

** Gotchas
- macOS gotcha: the default OS =⌃Space= shortcut for Input Sources steals =ctrl+space=; users must disable it for the leader chord. Documented in =leader-menu/README.md= Terminal compatibility section.
- Single-keystroke =command:= dispatch only works in terminals that speak the Kitty keyboard protocol or modifyOtherKeys (kitty, ghostty, foot, wezterm, recent xterm). =tmux send-keys= cannot drive the smoke test reliably because tmux strips Kitty-protocol bytes by default.

** Follow-ups
- vim-mode re-enable verification (TASKS.org task =fe6b1c6d=): load order so =VimEditor= is the registered active submitter; =getActiveSubmitter()= resolves to the live =VimEditor=; existing =,= repeat-find / default-local-leader conflicts unaffected.
