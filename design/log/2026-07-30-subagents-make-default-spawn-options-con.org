* Intent

Rename the subagent CLI's model-table file =roster.edn= to =config.edn= and extend it with an optional =:defaults {:placement …}= block so the spawn placement default (=:split=, =:tab=, or depth-aware =:tab-split=) is user-configurable through the existing packaged ← home ← project override chain. Shipped behaviour is unchanged; placement inheritance stays forbidden.

* Summary

*Level:* production · *Tests:* thorough · *Docs:* full

*** In scope
- =git mv= of =skills/herdr-subagents/subagents/roster.edn= → =config.edn=; loader, launcher-relative default path, and all live doc/spec surfaces follow. Hard rename, no dual-read or legacy detection (the roster file shipped yesterday; no external use).
- Optional =:defaults= config block with a single =:placement= key (=:split= | =:tab= | =:tab-split=), closed schema (unknown =:defaults= keys rejected), validated per-file before merge with the offending path in the error.

** Decisions
- Hard rename, no legacy detection :: roster.edn shipped yesterday with no use outside this repo; a transition window buys nothing.
  Rejected:
  - Dual-read =config.edn= → =roster.edn= fallback: lingering ambiguity about which file won.
  - Fail-fast on detected legacy files: guards against a population of zero.
- =:tab-split= is a configurable default, not the shipped one :: shipped default stays =:split=, so unconfigured behaviour is byte-identical; users opt into depth-aware tabs via =:defaults=.
  Rejected:
  - Shipping =:tab-split= as default (original task-body proposal): silent behaviour change for every existing spawn site.
- =:defaults= lives in the renamed =config.edn= alongside the model table :: one override chain, one merge, one validation pass; the rename exists precisely because the file is no longer just a roster.
- Full-config merge is =(apply merge-with merge configs)= :: generalises the documented row-level semantics — top-level collisions merge per-key at level 2, level-2 values replace wholesale — and =:defaults= merging falls out for free. Per-file validation before merge is load-bearing: it converts a would-be =ClassCastException= on a non-map collision into a path-named schema error.
- Closed =:defaults= schema :: unknown keys inside =:defaults= are rejected so typos fail loud, unlike the deliberately open kind set in =:harnesses=.
- Depth discriminator reuses =HERDR_SUBAGENT_PERSONA= :: same signal spawn gating uses, so =:tab-split='s root/below-root split can never diverge from the existing depth model. An agent with the var set outside =subagent= counts as below-root, consistently.
- =:kind= defaults parked (YAGNI) :: =:inherit= restates =resolve-kind='s existing parent-kind fallback; a configured harness id awaits a real use case.
- Terminology: only the model-table file is renamed :: SKILL.md's "roster" for the persona list (§ Roster and routing) is a distinct concept and keeps its name.

* Implementation

All three plan tasks were delegated to =worker= subagents on =gpt-5.6-terra= (kind resolved to pi by parent inheritance, translated to =openai-codex/gpt-5.6-terra=; a model ID never selects a harness). The docs and tests tasks ran concurrently against disjoint file sets. The orchestrator re-derived every load-bearing claim against source rather than trusting a child's report — see § Verification.

- Symbol renames: =default-roster-path= → =default-config-path=, =roster-file= → =config-file=, =roster-config= → =config=, =parse-roster= → =parse-config=, =validate-roster-shape!= → =validate-config-shape!=, =merge-roster= → =merge-config=.
- =merge-config= (=core.clj:167=) is exactly =(apply merge-with merge configs)=. The generic primitive gives =:defaults= per-key merging for free while preserving wholesale =:models= row replacement.
- =core/resolve-placement= (=core.clj:169=) is pure over ={:flag :configured :below-root?}=, so the whole precedence + depth contract is unit-testable without touching herdr; =below-root?= is =(some? (System/getenv "HERDR_SUBAGENT_PERSONA"))=.
- Per-file validation before merge is what converts a would-be =ClassCastException= on a non-map collision into a path-named schema error — the ordering is load-bearing, not stylistic.
- =herdr.clj= was never touched, which is what makes the unchanged-tab-behaviour and focus anti-criteria provable by absence rather than by assertion.
- Cross-repo close-out: =dotfiles/AGENTS.md= (parent repo, outside this submodule) named =roster.edn= in its =agents.nix= bridge section. Updated to =config.edn= and, since the file's role broadened, corrected to state that it "replaces complete model-ID rows and merges =:defaults= per key" — a bare rename would have left the row-replacement claim covering =:defaults=, which merges instead. That file hard-wraps at ~76 columns (the no-hard-wrap rule governs =TASKS*.org= and change-records, not repo Markdown), so the wrap was preserved. =agents.nix= needed no change: it symlinks whole directories, never individual filenames.
