* Intent
Simplify the `org-tasks` parser and correct its block handling without replacing the protocol-specific model. Preserve Babashka operation, machine contracts, and byte-identical treatment of unrelated Org content.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* full

The protocol parser now delegates scanning, rendering, and readiness through a stable facade. Shared block state shields literal block content, and in-place mutations patch only changed fields while retaining supported source variants. The linked [[file:2026-08-17-org-tasks-parser-improvements/org-parser-review.md][org-parser adoption review]] records the rejected dependency and the evidence behind this design.

** Scope
*** In scope
- Introduce shared block-aware line classification for task parsing, section extraction, and block-aware doctor checks.
- Split task scanning, task rendering, and readiness evaluation into focused namespaces behind the stable `org-tasks.parser` facade.
- Derive accepted task statuses from `org-tasks.lifecycle/status-cycle`.
- Add regression coverage for task-shaped lines inside Org blocks and for mutation locality.
- Use targeted source patches for in-place mutations only where a regression test proves that whole-root serialisation changes unrelated bytes.
- Update parser architecture, test-map, and operator documentation where behaviour or ownership changes.
*** Out of scope
- Add `org-parser`, Instaparse, a parser pod, or a JVM parser subprocess.
- Parse the complete Org grammar or expose a general Org AST.
- Change the `org-tasks/v1` envelope, task-file protocol, lifecycle states, CLI syntax, or TUI behaviour.
- Replace canonical serializers used to create, archive, restore, publish, or migrate complete task subtrees unless a concrete fidelity defect requires it.

** Acceptance
*** Core functionality
- [X] A task-shaped heading inside a matched `#+BEGIN_<kind>` and `#+END_<kind>` block remains body content and never becomes a task.
- [X] Task parsing, level-1 section extraction, and block-aware doctor scans use one shared block-boundary implementation.
- [X] The parser accepts exactly the lifecycle states in `org-tasks.lifecycle/status-cycle`.
- [X] `org-tasks.parser` retains every pre-extraction public identifier with baseline `:doc` and `:arglists` metadata after scanner, renderer, and readiness extraction.
- [X] A newly inserted canonical `CLOSED:` line follows its heading and precedes body text, existing drawers, and `#+IMPORT:`.
- [X] In-place property and STARTED mutations retain existing properties and LOGBOOK delimiter bytes, including supported case and whitespace variants.
- [X] In-place status, priority, property, and linked-issue mutations preserve every unrelated target-task byte.
- [X] Existing machine envelopes and command results remain unchanged.
*** Edge cases
- [X] Block matching is case-insensitive and a mismatched end marker does not terminate shielding for another block kind.
- [X] An unterminated Org block shields task-shaped body lines through end of file without hiding a pre-existing unterminated drawer error.
- [X] Existing round-trip fixtures remain byte-identical.
- [X] Namespace loading and the complete test suite succeed under Babashka.
*** Anti-criteria
- [X] Must not: add `org-parser`, Instaparse, ClojureScript, or another parser runtime dependency.
- [X] Must not: normalise unknown keywords, drawers, bodies, or block content as a side effect of an unrelated mutation.
- [X] Must not: weaken optimistic-concurrency checks or sandboxed path resolution.

** Decisions
- Keep a protocol-specific, lossless line scanner behind the stable parser facade :: `ot` needs task graph semantics, source ownership, and controlled mutation rather than a general Org AST.
  Rejected:
  - Adopt `org-parser`: its model, writer, Babashka support, packaging, performance, and AGPL-3.0 licence do not fit the runtime requirements; see the linked review.
  - Invoke a JVM parser process: this adds a process boundary and retains the model and writer mismatch.
- Share lexical block state instead of sharing a complete parsed document :: this removes the confirmed block-handling inconsistency while keeping body content opaque.
- Keep canonical whole-subtree serializers for creation and transfer flows :: use source patches only for in-place mutation defects proven by fixtures.

** Shipped
- ADDED shared block-boundary state for parser, section, and doctor scans.
- MODIFIED `org-tasks.parser` as a stable facade over scanner, renderer, and readiness namespaces.
- ADDED locality field patches for in-place status, priority, and property writes. A new `CLOSED:` line follows the heading. Existing properties and LOGBOOK drawer delimiters retain their source bytes while their bodies update.
- RESTORED and mechanically checked baseline public `:doc` and `:arglists` metadata for every pre-extraction parser facade var.
- MODIFIED `skills/org-tasks/scripts/docs/DESIGN.org` and `skills/org-tasks/scripts/docs/test-map.md`.
- REVIEWED `skills/org-tasks/SKILL.md` and `skills/org-tasks/scripts/AGENTS.md`; no change was required because the public workflow and development invariants remain unchanged.

** Gotchas
- Existing drawer patches must retain their original opening and closing lines. A new `CLOSED:` line must use the heading index rather than the next field index.
- `lifecycle.clj` depends on focused property and timestamp helpers, so extraction keeps dependency arrows acyclic.

* Implementation
- `parser.lines` owns shared block state and boundary classification.
- `parser.renderer` retains canonical structural output and applies field-level locality edits for in-place commands.
- The pre-implementation evidence and rejected-library rationale remain in the [[file:2026-08-17-org-tasks-parser-improvements/org-parser-review.md][org-parser adoption review]].

* Validation
- Regression tests failed against the prior implementation for block shielding, target-task locality, drawer delimiters, canonical `CLOSED:` placement, doctor boundary scans, and facade metadata.
- `bb test` ran 637 Clojure tests and 4,148 assertions with no failures or errors. Repository script tests passed with 43 and 14 assertions.
- A base/current comparison found all 40 baseline public facade vars with unchanged `:doc` and `:arglists` metadata.
- `ot doctor --format json` returned zero errors and seven advisory spec warnings.
- Two fresh independent Class C reviewers approved the final implementation with no findings.
