* Intent

Make the pi tasks extension test entrypoint deterministic and diagnostic: repository tests use the repository's declared dependency closure, and RPC mode-boundary failures surface the child-process cause immediately instead of consuming repeated 30-second timeouts.

* Summary

*Level:* production · *Tests:* thorough · *Docs:* README

** Scope

*** In scope
- Run every tasks-extension TypeScript test through the root lockfile's local =tsx= and fail fast when the declared development dependencies are not installed.
- Replace the unnecessary dummy-provider RPC setup with a model-free =pi --mode rpc --no-session= harness for extension commands.
- Parse RPC stdout with LF-only JSONL framing, capture child stderr/exit, and race expected events against process failure.
- Sanitize inherited Node loader/module-path variables before spawning pi while preserving the isolated HOME and agent directory.
- Update the tasks extension README and repository extension-check path to state and exercise the deterministic test contract.

*** Out of scope
- Changes to task-extension runtime behavior, command semantics, or UI mode boundaries.
- Real provider/model calls, authentication, or network-backed integration tests.
- Refactoring other extension test runners or introducing a shared test framework before a second consumer needs it.
- Hardcoding the active Nix store path or coupling tests to a globally installed =tsx=.

** Acceptance

*** Core functionality
- [X] =pi/extensions/tasks/test.sh= invokes the root-local =node_modules/.bin/tsx= for every TypeScript test and exits immediately with an actionable =npm ci= instruction when the locked dependencies are absent.
- [X] Import-dependent tests resolve =@earendil-works/pi-coding-agent= from the root dependency closure without =NODE_PATH= or a global =tsx= fallback.
- [X] The RPC harness starts the installed pi binary without a dummy provider, =--provider=, or =--model= and still verifies =/tasks new=, =/tasks doctor=, and bare =/tasks= mode behavior.
- [X] RPC output uses an LF-only JSONL decoder rather than Node =readline=, matching the documented protocol framing.
- [X] Extension-load errors, early child exit, and malformed RPC output fail the current test promptly with captured stderr instead of degrading into the outer timeout.
- [X] =scripts/check-extensions.sh= reaches a green tasks-extension runner after =npm ci= from a clean checkout.

*** Edge cases
- [X] Parent =NODE_PATH=, =NODE_OPTIONS=, and tsx loader state do not leak into the spawned pi process.
- [X] Child cleanup closes stdin, terminates only the process created by the test, awaits exit, and removes temporary HOME/agent state on success and failure.
- [X] Response/event correlation cannot let a notification from an earlier command satisfy a later assertion.
- [X] The runtime-load check continues exercising the installed pi binary rather than only importing extension modules directly under tsx.

*** Anti-criteria
- [X] Must not: make a real LLM request or require provider credentials.
- [X] Must not: hide stderr, ignore an =extension_error= event, or retain timeout-only failure messages when the child already exited.
- [X] Must not: weaken the existing RPC/TUI boundary assertions or treat =ctx.hasUI= as proof that the custom overlay is supported.
- [X] Must not: vendor pi packages, mutate the user's npm installation, or derive module paths from a Nix store layout.

** Shipped
- MODIFIED =pi/extensions/tasks/test.sh=: every TypeScript test uses the root lockfile's local =tsx=; incomplete direct development dependencies fail preflight with the repository-root =npm ci= recovery command and no ambient/global fallback.
- MODIFIED =pi/extensions/tasks/pi-integration.test.ts=: the installed =pi= binary runs model-free RPC mode-boundary scenarios with strict LF-only JSONL framing, isolated loader state, exact response-id correlation, prompt process diagnostics, and bounded child cleanup.
- MODIFIED =pi/extensions/tasks/README.md= (declared =#+SPEC:=): documents the locked-dependency entrypoint and model-free RPC harness contract.

** Decisions
- Use the root npm lockfile as the direct-test dependency boundary :: =test.sh= consumes the declared closure or fails before tests begin.
  Rejected:
  - Global =tsx= or =npx --yes= fallback: compilation could succeed while runtime imports still depended on ambient installation state.
- Exercise extension commands through the installed binary in model-free RPC mode :: command dispatch precedes model prompting, while the subprocess preserves extension discovery and protocol coverage.
  Rejected:
  - Dummy provider extension: adds a package-resolution boundary the commands do not use.
  - Direct =AgentSession= tests: bypass installed-binary discovery and RPC framing.
- Treat protocol and process failures as harness state :: command responses use echoed request ids; UI events use event-buffer cursors; malformed output, extension errors, process/stdin errors, and early exit beat generic timeouts.
  Rejected:
  - Type-plus-command response matching or per-wait process listeners: both leave race windows that can misattribute responses or lose the real child failure.

** Gotchas
- The nix-packaged =pi= launcher prepends its bundled =node_modules= to inherited =NODE_PATH=; the harness must remove the parent's loader path before spawn so jiti cannot resolve against the wrong package surface.
- Pi's strict JSONL reader emits empty records and does not split on U+2028/U+2029; blank-record, Unicode-separator, split-UTF-8, multi-record, CRLF, and unterminated-final-record fixtures preserve that behavior.
- Node process/stdin =error= listeners must span the harness lifetime, and every losing =Promise.race= timeout must be cleared; otherwise failures can crash between waits or successful scenarios can keep the suite alive.

** Risks
- The root development package can lag the installed =pi= binary; direct tests validate the locked package surface while RPC tests remain the compatibility check against the installed executable.

* Implementation

- =test.sh= validates the root-local =tsx= executable and the installed direct development closure with =npm ls --prefix "$root" --depth=0 --include=dev= before preserving aggregate reporting across the test list.
- The RPC harness spawns installed =pi --mode rpc --no-session= with isolated =HOME=/agent state, strips inherited Node loader state, decodes strict JSONL, correlates command responses by id, and retains child diagnostics until bounded cleanup completes.

* Validation

- A partial install fixture with =tsx= present and =@earendil-works/pi-coding-agent= absent failed before the first test with the repository-root =npm ci= instruction; the complete locked installation passed unchanged.
- The model-free RPC suite passed all 15 framing, mode-boundary, correlation, loader-isolation, and process-failure scenarios; clearing completed race timers reduced its wall time from 35.62 seconds to approximately 6 seconds.
- =scripts/check-extensions.sh= completed through the tasks runner, and the installed =pi= binary loaded =pi/extensions/tasks/index.ts= without =extension_error= output.
