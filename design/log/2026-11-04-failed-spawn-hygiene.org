* Intent
Reduce noise and resource residue from failed launches without deleting audit history or adding a readiness workaround that the current contract forbids.

* Summary
*Level:* MVP · *Tests:* thorough · *Docs:* README

The current source marks launch failures terminal and retains ledger entries. Listing noise can be addressed separately from the upstream readiness report. Managed checkout cleanup needs ownership and preservation checks; it must not be inferred from a failed status alone.

** Scope
*** In scope
- Failed-round visibility in routine ~task status~ and ~task list~ output.
- A bounded upstream readiness reproduction and safe failed-launch checkout policy.
- Existing branch-retirement guidance.
*** Out of scope
- Deleting ledger entries or immutable result files.
- Reintroducing a local start retry, reducing the Herdr version floor, or deleting branches automatically.
- Removing a checkout because its launch status is failed without checking its contents and ownership.

** Acceptance
Proposed criteria; readiness and automatic cleanup policy are not approved.
*** Core functionality
- [X] Routine listings omit lower-case launch status ~failed~ while ~--include-failed~ retains audit access.
- [X] Lookup by full task UUID can still inspect a failed round.
- [X] JSON and text output agree on which rounds are visible.
*** Edge cases
- [X] Publication status ~FAILED~, invalid captures and closed successful rounds are not confused with lower-case launch status ~failed~.
- [X] Listing never changes ledger bytes or resource state.
- [ ] A readiness reproduction records client/server versions and the exact upstream refusal.
*** Anti-criteria
- [ ] Must not: delete a ledger entry to hide it.
- [ ] Must not: retry ~agent start~ under the existing contract.
- [ ] Must not: remove dirty, ignored-content-bearing or foreign checkouts.

** Decisions
- Prefer a read-only listing filter with explicit opt-in audit visibility :: the stored task permits filtering and the retention contract preserves history. Rejected:
  - A retire/delete verb: conflicts with retained audit history and adds mutation authority to a display problem.
  - Automatic checkout removal inside every failure handler: a failed status does not prove an unused, clean checkout.
- Keep readiness owned upstream :: [[file:../../skills/herdr-orch/scripts/docs/contract.md]] section 'Start and prompt outcomes' explicitly forbids local polling/retry. A field report is not permission to reverse that decision. An upstream reproduction or explicit policy change must precede a workaround.

** Shipped
- MODIFIED :: [[file:../../skills/herdr-orch/scripts/docs/contract.md]] section 'JSON output' defines default failed-launch filtering and explicit audit visibility.
- MODIFIED :: [[file:../../skills/herdr-orch/scripts/README.md]] section 'Retire an integrated branch' supplies operator guidance; the CLI retains its no-branch-deletion boundary.

** Risks
- Hiding failed entries by default can surprise scripts that use listings as an audit export; the explicit option and unchanged full-UUID lookup must be documented and tested together.
- A launch may fail after creating valuable files. Checkout removal needs a separate ownership and preservation boundary, not only a status predicate.
