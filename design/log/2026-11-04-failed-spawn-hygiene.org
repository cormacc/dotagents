* Intent
Reduce noise and resource residue from failed launches without deleting audit history or adding a readiness workaround that the current contract forbids.

* Summary
*Level:* MVP · *Tests:* thorough · *Docs:* README

A failed launch is terminal and its ledger entry is retained but hidden from routine listings. The retry policy is fail-fast with a clean rollback: a failed interactive launch closes its pane and removes the pristine managed checkout it created, the error names the round and the checkout outcome, and the caller decides whether to spawn again. `oh` never retries `agent start`. Checkout removal needs ownership and preservation checks; it is never inferred from a failed status alone.

** Scope
*** In scope
- Failed-round visibility in routine ~task status~ and ~task list~ output.
- A bounded upstream readiness reproduction and safe failed-launch checkout policy.
- Existing branch-retirement guidance.
*** Out of scope
- Deleting ledger entries or immutable result files.
- Reintroducing a local start retry, reducing the Herdr version floor, or deleting branches automatically.
- Removing a checkout because its launch status is failed without checking its contents and ownership.

** Acceptance
Automatic removal of a pristine failed-launch checkout and fail-fast with no local retry were accepted by the user on 2026-11-04.
*** Core functionality
- [X] Routine listings omit lower-case launch status ~failed~ while ~--include-failed~ retains audit access.
- [X] Lookup by full task UUID can still inspect a failed round.
- [X] JSON and text output agree on which rounds are visible.
- [X] A launch that fails with ~:failure-phase~ ~worktree~, ~split~ or ~start~ removes the pristine managed checkout that the round created, retains its branch, and records ~:checkout-cleanup~ on the entry.
- [X] The spawn error carries the failed round's ~task~ and its ~checkout-cleanup~ outcome, and a second spawn after the failure succeeds.
*** Edge cases
- [X] Publication status ~FAILED~, invalid captures and closed successful rounds are not confused with lower-case launch status ~failed~.
- [X] Listing never changes ledger bytes or resource state.
- [X] Bounded readiness investigations recorded client/server versions and outcomes on macOS and Linux. The original exact-refusal criterion was not met: neither host reproduced the race. On 2026-11-04 the Linux occupied-pane control returned ~agent_pane_busy~ with exit 1; no upstream race report is warranted by these trials.
- [X] A checkout that was never cut reports ~missing~; a measurement ~launch~-phase failure is excluded from cleanup.
- [X] A retained checkout stays removable with ~oh worktree remove~.
*** Anti-criteria
- [X] Must not: delete a ledger entry to hide it.
- [X] Must not: retry ~agent start~ under the existing contract.
- [X] Must not: remove dirty, ignored-content-bearing or foreign checkouts.

** Decisions
- Prefer a read-only listing filter with explicit opt-in audit visibility :: the stored task permits filtering and the retention contract preserves history. Rejected:
  - A retire/delete verb: conflicts with retained audit history and adds mutation authority to a display problem.
- Remove a pristine failed-launch checkout automatically (user decision, 2026-11-04) :: a child that never took its assignment left nothing to integrate, so the rollback is part of the failure. The predicate is pristine and owned: the path and branch that ~--worktree new~ derives from the task, inside the managed root, attached to that branch at the recorded base, no dirty or ignored paths, no live reference. Rejected:
  - Removal by failed status alone: a failed status does not prove an unused, clean checkout.
  - ~git worktree remove --force~, or treating ignored content as disposable as manual ~worktree remove~ does: the parent has not decided to discard it.
  - Deleting the ~orch/*~ branch: the contract keeps branch deletion parent-owned, and an empty branch costs nothing.
  - Cleanup of a measurement ~launch~-phase failure: its supervisor can outlive the failure.
- Fail-fast with a clean rollback; no local retry (user decision, 2026-11-04) :: readiness stays owned by Herdr, as [[file:../../skills/herdr-orch/scripts/docs/contract.md]] section 'Start and prompt outcomes' requires. With the rollback, a failure leaves no residue, so the caller can run the spawn again; the error carries the round and cleanup outcome for that choice. Rejected:
  - A local ~agent start~ retry or shell-readiness poll: it duplicates Herdr's readiness model, needs timing settings and fixtures, and hides upstream regressions. It was deleted at ~4741d59~. Reconsider only a narrow, single retry on ~agent_pane_busy~ if the race is reproduced and frequent, with the upstream issue named for its removal.

** Gotchas
- Failed launches are hidden from routine listings, not deleted; audit callers need ~--include-failed~.
- An interrupted cleanup can leave a checkout without ~:checkout-cleanup~; inspect it through ~oh worktree list|remove~.
- Bounded negative trials do not rule out an intermittent readiness race. Reopen the investigation if a fresh field report supplies a reproducible trigger.

Decision [2026-11-04 Wed 08:43]: yes, for a pristine checkout that the round created. Dirty and ignored content are retained, the branch is retained, a never-cut checkout reports ~missing~, and an interrupted cleanup falls back to ~oh worktree list|remove~.

Decision [2026-11-04 Wed 08:43]: fail-fast with a clean rollback and no local retry. The caller runs the spawn again.
