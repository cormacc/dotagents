* Summary
Make =ot= ergonomic on the command line. Four interlocking improvements
shipped as one change-record because they share the id and text-output
surfaces:

1. *Short-id resolution.* Id-accepting subcommands accept a full
   =:CUSTOM_ID:=, a compact =prefix…suffix= short-id (the form printed
   by =ot list= and =ot scan=; both unicode `…` and ASCII `...` are
   accepted), or any unique ≥ 4-char leading prefix. Ambiguous values
   fail with a structured =ambiguous-id= envelope listing every match.
2. *Robust compact-id display.* =org-tasks.task/build-short-ids= picks
   the smallest symmetric edge size (≥ 4) that disambiguates every id
   in the loaded graph, so hand-numbered sibling tasks no longer collide
   on display. The wire envelope of =ot list= exposes the resulting
   `shortIds` map for JSON callers.
3. *Tooling-owned UUID generation.* =ot uuid [--count N]= generates
   UUIDv4 values for hand-authored plan / change-record task blocks.
   =org-tasks/SKILL.md= and =org-plan/SKILL.md= tell agents to call
   the command instead of inventing IDs.
4. *Bling-styled text output.* =--format text= renderers colourise
   status, priority, tags, linked issues, local-draft markers, selected
   marker, and the new compact short-id via
   =io.github.paintparty/bling 0.10.0=. The styling lives in
   =org-tasks.styling=, keyed only by verified bling palette keywords.
   =--no-color= and =NO_COLOR= both suppress styling without mutating
   the process environment. JSON/EDN output remains ANSI-free.

=ot doctor= gains two warnings to protect the new invariants:
=:non-uuid-v4-id= flags hand-authored ids; =:patterned-sibling-ids=
flags sibling tasks whose first 24 chars match (catching the
`…-3a6b2c4d0001` / `…0002` style that triggered this work). Both are
warnings so legacy records keep loading.

** Decisions
- Resolver lives in =org-tasks.task= :: New =find-by-id-or-prefix= +
  =find-top-level-by-id-or-prefix= return ={:match task}=, ={:ambiguous
  [task ...]}=, or ={:none}=. Command modules call a shared
  =resolve-required-id= helper that emits =unknown-task= or
  =ambiguous-id= envelopes uniformly. No regex / interactive prompting —
  the agent surface stays deterministic.
- Minimum prefix length :: 4 chars. Anything shorter falls through to
  =unknown-task= so =ot show a= can't accidentally collapse a
  many-thousand-task graph onto whichever task happens to sort first.
  Full 36-char UUIDs always exact-match without going through the
  prefix branch.
- Compact short-id shape :: `prefix…suffix`, edges expand symmetrically
  from 4 chars up to 16 chars until every id in the loaded graph yields
  a unique alias. The unicode `…` is what =ot list= prints; the resolver
  also accepts ASCII `...` so shells that struggle with unicode can
  paste compact ids back. Legacy bare prefixes still resolve when
  unique.
- UUIDs come from tooling :: =ot uuid= (single) and =ot uuid --count N=
  (bulk) replace agent-authored example IDs in prose. =ot doctor= warns
  on hand-authored or patterned siblings to keep the rule enforced in
  practice without breaking legacy task graphs.
- Styling library :: =io.github.paintparty/bling 0.10.0=. Babashka
  compatible, hiccup-like markup, native =NO_COLOR= support. Added once
  to the repo-root =deps.edn= / =bb.edn= so =bb run ot= and bbin
  installs both pick it up.
- Styling lives in a new =org-tasks.styling= namespace :: One canonical
  bling-keyword palette map plus thin helpers (=status=, =priority=,
  =tag-cluster=, =linked-issue-cluster=, =local-marker=, =short-id=).
  Commands never reach into bling directly, so swapping styling later
  is a one-file change.
- Palette mapping :: Status TODO :yellow, STARTED :blue, WAITING
  :orange, DONE :green, CANCELLED :gray (closed-and-inert reads
  better than red here; red is reserved for genuine errors via bling's
  =:negative= / =:error= aliases). Priority A :red, B :orange,
  C :yellow, D :blue (traffic-light gradient from urgent to deferred —
  chosen for bling-native clarity rather than mirroring the pi
  extension's A=orange/B=yellow/C=green/D=blue mapping). Tags
  :magenta with =:italic=. Linked-issue cluster :purple with the
  existing ⤴ glyph. Local-draft marker :magenta. Short-id :gray
  (subtle — present but never the focal point of the row). Do not use
  undocumented colours such as =:cyan= or =:pink= unless the installed
  bling version proves they are first-class palette keywords. The pi
  extension's =status-colors.ts= is left alone; the two surfaces agree
  semantically while differing in exact hue.
- =--no-color= wiring :: Styling helpers take an explicit
  ={:color? boolean}= / opts argument. =org-tasks.output= computes that
  flag from command opts plus the ambient =NO_COLOR= environment and
  passes it down; when false, helpers return plain strings without
  calling bling. Do not attempt to mutate process environment or rely
  on =System/setProperty= to fake =NO_COLOR=.
- Short-id everywhere or nowhere :: All id-accepting commands route
  through the same resolver, including =record path/create=, =issue
  add/remove/urls=, =blocker add/remove=, =handoff set/clear=,
  =ready=, =publish/unpublish/archive=, =select=, =status=, =show=.
  Don't ship a half-cohort.
- Pi extension is unaffected :: The =ot.ts= wrapper still passes full
  UUIDs everywhere — the extension never displays the truncated id back
  to itself. The new behaviour is purely a CLI-side affordance.

* Implementation
- Added prefix-aware resolution in =org-tasks.task=: exact UUIDs win first, prefixes shorter than four chars return ={:none true}=, and unique / ambiguous prefixes return explicit resolver maps. Top-level-only operations use a separate resolver over root tasks only.
- Routed id-taking CLI commands through shared command helpers. =show=, =select=, =status=, =publish=, =unpublish=, =archive=, =record path/create=, =issue=, =blocker=, =ready=, and =handoff= now accept full UUIDs or unique prefixes while persisting / returning canonical full UUIDs.
- Added =ambiguous-id= to the machine contract with =details.matches= entries carrying =id=, =summary=, and =file=.
- Added =io.github.paintparty/bling 0.10.0= to =bb.edn= and =deps.edn=, plus =org-tasks.styling= as the only namespace touching =bling.core=. Styling helpers accept explicit colour opts and honour =--no-color= / ambient =NO_COLOR= through =org-tasks.output/color-enabled?=.
- Updated the standalone skill shim fallback to launch Babashka with =-Sdeps= and a local =src= path from =scripts/= so Home Manager / skill-only installs can still load bling without a repo-root =bb.edn=.
- Styled high-traffic renderers for status, priority, short-id, tags, selected marker, and local marker in =list=, =show=, =status=, and =scan=. Commands without those metadata tokens remain plain.
- Documented short-id usage in =skills/org-tasks/SKILL.md=, =contract.md=, and the tasks extension README. The pi extension continues to pass full UUIDs.
- Replaced the first-N-prefix short-id with a `prefix…suffix` compact form via =org-tasks.task/build-short-ids=. Edges expand symmetrically (4 → 16) until every alias in the loaded graph is unique. The resolver now accepts `prefix…suffix` (and ASCII `prefix...suffix`) input alongside the legacy unique-prefix form. =list= / =scan= / =show= render the compact form; =list='s wire envelope adds a `shortIds` map.
- Added =ot uuid [--count N]= so plan / change-record authoring no longer requires hand-written `:CUSTOM_ID:` values. =org-tasks/SKILL.md= and =org-plan/SKILL.md= now point at the command instead of inviting agents to invent UUIDs.
- Added two doctor checks: =:non-uuid-v4-id= warns on any `:CUSTOM_ID:` that isn't UUIDv4; =:patterned-sibling-ids= groups direct siblings (`:children` + `:import-children`) by their leading 24 chars and warns when ≥ 2 share that prefix. Both are warnings so legacy records load.
