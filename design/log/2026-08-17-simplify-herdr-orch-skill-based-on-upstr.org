* Intent

Reduce the herdr-orch skill to the decisions and recovery actions an orchestrator must know. Remove mechanical guard detail that the `oh` CLI and its contract already own, without changing delegation behaviour.

* Summary

*Level:* production · *Tests:* thorough · *Docs:* full

** Scope

*** In scope

- Prune `skills/herdr-orch/SKILL.md`, especially `## Invocation policy` and `## Completion and pane safety`.
- Keep user decisions, non-mechanical policy, completion evidence, and short recovery commands in the skill.
- Keep guard preconditions, reason codes, race analysis, and implementation detail in `skills/herdr-orch/scripts/docs/contract.md`.
- Validate that fresh agents still choose the correct normal, timeout, missing-publication, and invalid-publication actions.
- Round two (Herdr 0.8.2): raise the `oh` preflight gate to Herdr >= 0.8.2 in `skills/herdr-orch/scripts/src/herdr_orch/herdr.clj`.
- Round two: delete the `agent_pane_busy` start-retry loop and the post-prompt dispatch verifier, with their contract, README, skill, test, and fixture surface.

*** Out of scope

- Changing personas, traits, raw Herdr verb groups, the Pi extension, or ledger parsing of existing entries. Round two only ceases writing `:dispatch` and `:dispatched-at`; old entries still parse.
- Adding a capability probe, compatibility layer, option, dependency, or new reference file.

Round one additionally excluded removing the start retry and dispatch verifier and updating the dotfiles Herdr flake input; the first exclusion is superseded by round two (see Decisions), and the flake bump landed independently in dotfiles commit `7f3a219`.

** Decisions

- Chose a prose-only simplification now (superseded [2026-08-26 Wed]) :: Superseded: Herdr 0.8.2 is released and its reported version distinguishes the readiness fixes from stable v0.8.0, falsifying the premise below; see the round-two decisions. Original rationale, preserved: `/Users/cormacc/dotfiles/flake.lock` pins Herdr at `51b7064`, and the installed Nix source matches that revision. That revision contains upstream readiness and blocked-prompt fixes. However, its binary still reports `0.8.0`, which is indistinguishable from the stable v0.8.0 release that predates those fixes. Rejected:
  - Remove compatibility code now: would silently weaken the published `Herdr >= 0.7.5` contract for stable v0.8.0 users.
  - Add a capability probe: adds a new mechanism only to retire temporary compatibility code.
  - Treat the flake URL as automatically current: `flake.lock` pins one revision until an explicit input update.
- Keep operational choices in `skills/herdr-orch/SKILL.md` and mechanical proofs in `skills/herdr-orch/scripts/docs/contract.md` :: the skill is loaded for every matched delegation, while the contract is loaded only for debugging or maintenance.
- Use deletion and short links rather than a new summary reference :: a new file would add another contract surface and navigation decision.
- Round two: gate `oh` on Herdr >= 0.8.2 :: `herdr --version` reports 0.8.2 and the dotfiles flake pins `d79fd74`, a descendant of tag `v0.8.2`. GitHub compare confirms readiness fixes `7ae4b05` (agent prompt readiness, #2537) and `37644ca` (pane shell readiness, #2774) are absent from tag `v0.8.0` and present in the 0.8.1 release commit `09b2554d` and tag `v0.8.2`. Raising the gate breaks portable users on stable 0.8.0; accepted. Rejected:
  - Gate `[0 8 1]` (earliest capable release): user chose the released version actually in use; there is no `v0.8.1` git tag to verify against.
  - Keep `[0 7 5]`: deleting the workarounds under the old gate would silently break stable-0.8.0 users.
- Round two: delete both workarounds outright, including `verify-dispatch!`'s session backfill :: `:child-session` is contractually best-effort; it is still recorded at spawn from `start!`'s return, from every `agent wait` outcome in `wait-and-capture!`, and unconditionally on every owned capture in `finish-capture!` (the actual fix for the ecb85350 stale-session defect). Every measured consumer (smoke tests, resume-after-collect) collects before reading the session. Rejected:
  - Replace the verifier with a single post-prompt probe: insurance with no consumer; the loss window is crash-before-first-collect on a best-effort field.
  - Retain the dispatch verifier wholesale: the upstream fix covers the failure mode it guarded.
- Round two: remove the `dispatch-unconfirmed` recovery path entirely :: contract.md already treats an absent `:dispatch` as dispatched, and ledgers are transient `.tmp` state; old `unconfirmed` entries degrade to that same rule. Rejected: keep `poke`'s guard as a degraded reader for old entries -- dead code guarding transient state.
- Round two: extend this record rather than open a new one :: the Intent is unchanged, the Follow-ups section held exactly this resume condition, and the round-one work is not separable from the deferred deletion it explicitly parked. Rejected: new change-record -- would split one intent across two records.
- Round two: no further 0.8.x features leveraged :: the 0.8.2 release notes were reviewed; beyond the two readiness fixes, `agent prompt`'s `agent_blocked` rejection (#2788) needs no local handling (existing anti-criterion retained) and the calling-pane resolution fixes (#2297, #2298) need no local change rather than being irrelevant: the layout, split, process-info, and `agent start` calls all pass an explicit `--pane`, while `current-pane!` deliberately does not -- it invokes `pane current --current` for `close!`'s self-close guard and consumes the upstream resolution directly.

** Gotchas

- The dotfiles flake pin can contain post-release Herdr fixes while the binary still reports the earlier stable version. Between 2026-08-17 and the 0.8.2 release this made the version string unusable as a capability boundary; since Herdr 0.8.2 (>= 0.8.1 at the earliest) the reported version does distinguish the readiness fixes, and round two gates on it. The general lesson stands: a flake pin can outrun the reported version.
- `test/fixtures/fake-herdr` reports a default version of 0.7.5; any `minimum-version` bump must move that default in the same change or every test fails preflight.
- Deleting the readiness workarounds breaks tests that are not named after them. Measured [2026-08-26 Wed] by simulated deletion against a green `bb test` baseline: bumping only the gate fails `preflight-fails-before-ledger-or-mutation` on its literal `0.7.5` assertion, and removing only the two `verify-dispatch!` calls fails `child-session-is-recorded-by-every-hook` (its post-prompt, `status`, and capture subcases) and `continue-allocates-a-fresh-round-inheriting-the-childs-identity` (missing `:dispatch`). Grep the symbol names, not the feature names.

** Follow-ups

- Discharged [2026-08-26 Wed]: Herdr 0.8.2 is released and contains readiness commits `7ae4b05` and `37644ca`; the reassessment became the round-two plan tasks below.
- The single Herdr floor is now `[0 8 2]` in `herdr.clj` and 0.8.2 in the plugin plan's manifest target. A future gate change must move both, or the plugin loads on a Herdr its own bundled `oh` refuses.

** Risks

- Over-pruning can remove a recovery cue that the CLI cannot initiate for the parent. Mitigated: old-skill and candidate-skill fresh agents produced the same required recovery decisions.
- The upstream fixes are present on this machine but remain unreleased under a distinct semantic version. Resolved by the 0.8.2 release; round two enforces the baseline through preflight.
- Deleting the verifier removes the only post-prompt, pre-collect `:child-session` refresh. Accepted: the field is best-effort and every measured consumer collects before reading it.
- Prose that describes `task start` as returning "after dispatch" drifts once the verifier is gone. Mitigated: doc-alignment criteria in the round-two plan tasks.
