* Intent
Make Emacs a first-class Herdr tab: one command opens, or focuses, a named tab that runs an =emacsclient -t= frame on the machine that owns the current space, in herdr TUI and herdr-app, locally and remotely. Use it for a Magit tab, a Plan tab on the selected task's change-record, and as the frame host for the [[task:66fea944-8ac8-422b-9417-d8ddbf99f3de][Emacs diff review]].

* Summary
*Level:* MVP · *Tests:* smoke · *Docs:* README

=emacs/herdr-tabs/emacs-tab <name> [--runtime tui|hc] [--cwd DIR] [--format json] [-- <elisp>]= focuses the tab called =<name>= in the caller's space, or creates it with =emacsclient -t -a '' --eval <elisp>= in DIR, on the machine where it runs. =magit= and =plan= have default elisp that calls =herdr-tabs-magit= and =herdr-tabs-plan= in =emacs/herdr-tabs/herdr-tabs.el=. herdr TUI binds =prefix+m= and =prefix+i=; herdr-app binds =ctrl-shift-m= / =ctrl-shift-i= (Linux) and =cmd-shift-m= / =cmd-shift-i= (macOS) to the =emacs-magit= and =emacs-plan= overlay mods. Both front ends call =emacs-tab= by absolute path. Remote hosts and herdr-app spaces on other machines are not verified.

** Scope
*** In scope
- =emacs-tab= CLI with focus-or-create by name, for herdr TUI and herdr-app.
- Remote spaces: herdr TUI running on a remote host over SSH, and herdr-app spaces on another machine.
- Emacs entry points: =herdr-tabs-magit= (=magit-status= on DIR) and =herdr-tabs-plan= (the selected task's change-record, else =TASKS.org=).
- Key bindings: herdr TUI =keys.command= entries in =herdr/config.toml=; herdr-app bindings in =herdr-app/keys.linux.json= and =keys.darwin.json=.
- A machine-readable result (tab and pane or terminal id) so that the review can host its frame and detect its end.
- Docs: =emacs/README.org=, =herdr-app/README.md=, and the install-surfaces reference.
*** Out of scope
- An Emacs view embedded in a herdr-app side panel: a mod view cannot hold a terminal.
- GUI Emacs frames; outside Herdr the review keeps its own GUI host.
- Starting an Emacs daemon with a non-default socket name.
- Removing the herdr-app Changes panel from the layout: ordinary herdr-app configuration that the user does by hand once the Emacs tabs are proven.
- The review itself: owned by [[task:66fea944-8ac8-422b-9417-d8ddbf99f3de][the review task]].

** Decisions
- A Herdr tab, not a herdr-app panel :: a tab works in both front ends and on remote machines; a herdr-app mod view cannot embed a terminal, and a layout terminal block needs a fixed terminal id.
  Rejected:
  - Replace the herdr-app Changes panel with an Emacs panel: not possible without a terminal-capable mod view.
- One CLI, =emacs-tab=, in Babashka under =emacs/herdr-tabs/= :: keys in both front ends and the pi review extension call the same command, so focus-or-create and remote behaviour have one implementation. Runtime: =--runtime tui|hc= when given, else =HC_TERMINAL_ID= selects hc and =HERDR_ENV=1= selects TUI; both or neither is a usage error.
  Rejected:
  - The =oh= ancestry gate for runtime selection: a key binding runs outside any pane, so there is no caller ancestry to inspect; the binding names its front end instead.
  - Separate herdr TUI plugin and herdr-app mod with their own logic: two implementations of focus-or-create.
  - A new =oh= verb: =oh= is the delegation CLI; an editor tab is not delegation.
- On herdr-app, create the tab through label adoption on the caller's machine core :: =hc run --no-parent --label herdr.space=<id> --label herdr.tab=<new id>= starts the terminal on the machine where the caller runs, which is how =oh= places hc children; =herdr-app do= reaches only the local window, so naming and focus are best effort. Verified locally; unverified for a space on another machine.
- Emacs entry points in =emacs/herdr-tabs/herdr-tabs.el=, loaded by =config.org= :: the same pattern as =emacs/tasks-org/=; the user confirmed that remote hosts get this Emacs config through Home Manager.
- Focus-or-create by tab name in the caller's space :: one Magit tab and one Plan tab for each space; re-pressing a key returns to the existing tab.

** Gotchas
- Herdr custom key commands get =HERDR_BIN_PATH=, =HERDR_ACTIVE_WORKSPACE_ID= and =HERDR_ACTIVE_PANE_CWD= but not =HERDR_ENV= (Herdr 0.9.5), so the bindings pass =--runtime tui=, =--workspace= and =--cwd=.
- Custom key commands belong to the Herdr server: =herdr server reload-config= applies them, a client restart does not.
- The user's =display-buffer-alist= sends Magit buffers to a side window. =herdr-tabs--fill-frame= deletes side windows and uses =set-window-buffer=, because =switch-to-buffer= obeys the rule and =delete-other-windows= fails from a side window.
- =herdr-app check= refuses a module outside the mod's folder, symlinks included, so =emacs-plan= holds copies of =emacs-magit/state.js= and =opener.js=; =herdr-app/tests/emacs-tabs.test.mjs= keeps them identical.
- A herdr-app key can name only an app command, and =mod.open= takes only a mod name, so each view is its own overlay mod.

** Risks
- herdr TUI has no focus-or-create primitive: two quick presses can create two tabs. Accepted.
- On a herdr-app space on another machine, =herdr-app do= reaches only the local window, so naming and focus can fail; =emacs-tab= reports them as =warnings= and still returns the terminal.

* Implementation
- herdr-app probe (local machine, 2026-11-27): a terminal from =hc run --bg --no-notify --label herdr.space=<caller's space> --label herdr.tab=<new uuid>= appears as a new tab in that space within 3 s, without focus. =herdr-app do pane.focus= and =tab.rename= work on it, custom labels survive (=hc get --json=), and =hc kill= closes the tab.
- =emacs-tab= on hc: lookup is =hc ls --label emacs-tab=<name> --label herdr.space=<space>=, live terminals only. =--no-parent= makes the terminal a tab, not a sub-agent of the caller. =tab.rename= and =pane.focus= are best effort and become =warnings=.
- =emacs-tab= on herdr TUI: lookup is by tab label; a new tab's root pane runs =exec emacsclient ...=, so deleting the frame closes the tab. A reused tab reports its first pane from =herdr pane list=.
- herdr-app keys: =p= was preferred for Plan, but =ctrl-shift-p= / =cmd-shift-p= open the palette, =ctrl-alt-p= is =org-tasks.pin=, and the free three-modifier chords were rejected (user's decision). =i= matches the TUI key.
- Each herdr-app mod runs =emacs-tab --runtime hc= through =sh= with =exec= (=on= the space's machine), waits up to 3 s for the window to adopt the terminal, focuses it with =pane.focus= and closes its overlay. =state.js= copies the org-tasks =project= rule; the test compares the two.
- One live =mod.open emacs-magit=, seconds after the mod folder was linked, did nothing, probably because the app had not loaded the mod yet. Not reproduced.
