* Intent
Make Emacs a first-class Herdr tab: one command opens, or focuses, a named tab that runs an =emacsclient -t= frame on the machine that owns the current space, in herdr TUI and herdr-app, locally and remotely. Use it for a Magit tab, a Plan tab on the selected task's change-record, and as the frame host for the [[task:66fea944-8ac8-422b-9417-d8ddbf99f3de][Emacs diff review]].

* Summary
*Level:* MVP · *Tests:* smoke · *Docs:* README

=emacs-tab <name> [--cwd DIR] -- <elisp>= finds the tab called =<name>= in the caller's space and focuses it, or creates it with =emacsclient -t -a '' --eval <elisp>= in DIR. Keys in both Herdr front ends open =magit= and =plan= tabs. The Emacs server is the one on the space's machine, the same server that the pi =emacs_*= tools use.

** Scope
*** In scope
- =emacs-tab= CLI with focus-or-create by name, for herdr TUI and herdr-app.
- Remote spaces: herdr TUI running on a remote host over SSH, and herdr-app spaces on another machine.
- Emacs entry points: =herdr-tabs-magit= (=magit-status= on DIR) and =herdr-tabs-plan= (the selected task's change-record, else =TASKS.org=).
- Key bindings: herdr TUI =keys.command= entries in =herdr/config.toml=; herdr-app bindings in =herdr-app/keys.linux.json= and =keys.darwin.json=.
- A machine-readable result (tab and pane or terminal id) so that the review can host its frame and detect its end.
- Docs: =emacs/README.org=, =herdr-app/README.md=, and the install-surfaces reference.
*** Out of scope
- An Emacs view embedded in a herdr-app side panel: a mod view cannot hold a terminal.
- GUI Emacs frames; outside Herdr the review keeps its own GUI host.
- Starting an Emacs daemon with a non-default socket name.
- Removing the herdr-app Changes panel from the layout: ordinary herdr-app configuration that the user does by hand once the Emacs tabs are proven.
- The review itself: owned by [[task:66fea944-8ac8-422b-9417-d8ddbf99f3de][the review task]].

** Acceptance
*** Core functionality
- [ ] =emacs-tab magit= in herdr TUI creates a tab called =magit= running an Emacs frame with =magit-status= on the caller's folder.
- [ ] A second =emacs-tab magit= in the same workspace focuses that tab and creates no new one.
- [ ] The same two behaviours hold in herdr-app for the caller's space.
- [ ] In herdr TUI on a remote host, the Emacs frame belongs to that host's Emacs server.
- [ ] In a herdr-app space on another machine, the Emacs frame belongs to that machine's Emacs server.
- [ ] =emacs-tab plan= opens the selected task's change-record from =ot show selected --format json= (=.result.record.path=).
- [ ] With no selected task, or a task without a record, =emacs-tab plan= opens =TASKS.org=.
- [ ] =emacs-tab --format json= prints the tab id and the pane or terminal id.
- [ ] Deleting the Emacs frame (=C-x 5 0=) closes the tab.
- [ ] A herdr TUI key opens the Magit tab.
- [ ] A herdr TUI key opens the Plan tab.
- [ ] A herdr-app key opens the Magit tab.
- [ ] A herdr-app key opens the Plan tab.
*** Edge cases
- [ ] With no Emacs server running, =emacsclient -a ''= starts one and the tab opens.
- [ ] Outside Herdr, =emacs-tab= exits nonzero with a message and creates nothing.
- [ ] A user-renamed tab with the same name is reused, not duplicated.
*** Anti-criteria
- [ ] Must not: change the =oh= delegation verbs or their ledger.
- [ ] Must not: modify the herdr-app shipped mods or layouts in =~/.config/herdr-app/mods/= or the shipped =main= layout.
- [ ] Must not: take a key that the existing bindings in =herdr/config.toml= or =herdr-app/keys.*.json= already use.

** Decisions
- A Herdr tab, not a herdr-app panel :: a tab works in both front ends and on remote machines; a herdr-app mod view cannot embed a terminal, and a layout terminal block needs a fixed terminal id.
  Rejected:
  - Replace the herdr-app Changes panel with an Emacs panel: not possible without a terminal-capable mod view.
- One CLI, =emacs-tab=, in Babashka under =emacs/herdr-tabs/= :: keys in both front ends and the pi review extension call the same command, so focus-or-create and remote behaviour have one implementation. Runtime: =--runtime tui|hc= when given, else =HC_TERMINAL_ID= selects hc and =HERDR_ENV=1= selects TUI; both or neither is a usage error.
  Rejected:
  - The =oh= ancestry gate for runtime selection: a key binding runs outside any pane, so there is no caller ancestry to inspect; the binding names its front end instead.
  - Separate herdr TUI plugin and herdr-app mod with their own logic: two implementations of focus-or-create.
  - A new =oh= verb: =oh= is the delegation CLI; an editor tab is not delegation.
- On herdr-app, create the tab through label adoption on the caller's machine core :: =hc run --no-parent --label herdr.space=<id> --label herdr.tab=<new id>= starts the terminal on the machine where the caller runs, which is how =oh= places hc children; =herdr-app do= reaches only the local window, so naming and focus are best effort. Verified locally; unverified for a space on another machine.
- Emacs entry points in =emacs/herdr-tabs/herdr-tabs.el=, loaded by =config.org= :: the same pattern as =emacs/tasks-org/=; the user confirmed that remote hosts get this Emacs config through Home Manager.
- Focus-or-create by tab name in the caller's space :: one Magit tab and one Plan tab for each space; re-pressing a key returns to the existing tab.

** Risks
- A terminal adopted into a remote herdr-app space may not take focus: accept a visible new tab without focus if the app gives no remote focus path, and record it in Gotchas.
- herdr TUI has no "focus-or-create" primitive: =emacs-tab= lists tabs and matches the label; two quick presses can create two tabs. Accepted.
- Emacs keys inside a terminal frame compete with Herdr's prefix and the app's =ctrl-alt-= and =alt-= bindings: the existing tables already avoid Emacs-relevant chords; the new keys must too.

* Implementation
- herdr-app probe (local machine, 2026-11-27, =.tmp/probe-hc-tab2.clj=): =hc run --bg --no-notify --label herdr.space=<caller's space> --label herdr.tab=<new uuid> --label emacs-tab=probe -- sleep 120= appeared as a new tab in the caller's space within 3 s, without taking focus. =herdr-app do pane.focus '{"terminal":"<addr>"}'= made it the active tab; =herdr-app do tab.rename= succeeded; custom labels survive on the terminal (=hc get --json=); =hc kill= closed the tab. Not probed: a space on another machine (no machines configured), where =herdr-app= may not reach the window.
- =emacs/herdr-tabs/emacs-tab= finds an existing tab by terminal labels on hc (=hc ls --label emacs-tab=<name> --label herdr.space=<space>=, live only) and by tab label on TUI. On hc the terminal is started with =--no-parent=, so herdr-app shows it as a tab, not as a sub-agent of the caller. Window calls (=tab.rename=, =pane.focus=) are best effort and become =warnings= in the result, so a remote caller still gets its tab. On TUI the root pane runs =exec emacsclient ...=, so deleting the frame closes the tab.
- Live smoke on herdr-app (local): create, reuse (=created: false=, same terminal), tab named =smoke=, and =delete-frame= finished the terminal and removed the tab. The TUI path is covered by =emacs/herdr-tabs/test-emacs-tab.bb= against a fake runtime only; the live TUI check is in the documentation task.
- =herdr-tabs--fill-frame= deletes side windows before =delete-other-windows= and sets the buffer with =set-window-buffer=. The first live Magit tab exited with =Cannot make side window the only window=, and a later one showed Magit in a right side window: the user's =display-buffer-alist= sends Magit buffers to a side window, and =switch-to-buffer= obeyed it. ERT regressions cover both.
- Live smoke on herdr-app (local): =emacs-tab magit= showed =magit: agents= alone; =emacs-tab plan= with no selected task showed =TASKS.org= alone. Selection-to-record is covered by ERT with a stub =ot=.
