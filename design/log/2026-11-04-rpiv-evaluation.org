* Intent
Absorb the rpiv-pi review, verification and scope-control mechanics that strengthen herdr-orch delegation, into their existing local owners. Do not adopt rpiv-pi, its workflow runner or its artefact store.

* Summary
*Level:* MVP · *Tests:* smoke · *Docs:* inline

Source review of rpiv-mono at revision ~46dbdfd78ab631bbf3ce41c2618bb173a5ec2725~ (package ~2.15.0~). rpiv-pi does not replace org-plan, org-execute or herdr-orch. Its value for us is a set of evidence mechanisms: verbatim-quote finding verification, a declared-scope floor on implementation, goal-derived executable acceptance, prior-finding adjudication on re-review, extra review lenses and disagreement-aware validator panels. Each mechanism landed in one existing owner; no rpiv package is installed and no persona, engine or store was added.

** Scope
*** In scope
- Finding verification: verbatim-quote citations in ~code-review~ findings and a grounding check before the root accepts them.
- A declared-scope floor that reports undeclared writes in ~oh~ worktree reconciliation.
- Optional runnable evidence on org-plan acceptance criteria, executed at org-execute closeout.
- Prior-finding adjudication on re-review.
- Peer-comparison, cross-component and precedent checks in ~code-review~.
- Distinct-lens Class C validators with disagreement escalation.
*** Out of scope
- Installing rpiv-pi, rpiv-workflow or their sibling packages; any interactive trial of the rpiv workflow.
- A workflow runner, typed stage DSL, run trail, lane dock or ~.rpiv/artifacts/~ store.
- New personas. Each candidate extends an existing persona, skill or CLI verb.
- Hierarchical ~AGENTS.md~ discovery: tracked separately in [[task:2ed2d031-aa15-4701-9608-2cf565ddc75e][Evaluate hierarchical AGENTS.md discovery for Pi]].
- Standalone ~rpiv-btw~: tracked separately in [[task:86be0a2b-0097-4b18-9070-506bf85b2bfe][Decide whether to trial standalone rpiv-btw]].

** Decisions
- Absorb mechanisms, not the workflow :: rpiv's ~/wf~ runner, detached lanes, per-skill model overrides, bundled agent sync and artefact buckets duplicate org-plan, org-tasks, the ~oh~ ledger, Herdr panes and model tiers. Rejected:
  - Install the umbrella and reconcile later: several competing owners and setup side effects before a missing capability is chosen.
  - Copy the 30-skill pipeline: duplicates planning and review contracts.
- Verify findings by quoted line :: rpiv's ~claim-verifier~ tags each finding Verified, Weakened or Falsified against a verbatim quote, with exactly one row per input finding; ~code-review~ Step 6 drops Falsified findings and demotes Weakened ones one severity tier. Our root performs this check under Class B probe budgets with no quote to ground it. Adopt the quote requirement first; a mechanical check or a light-tier verifier assignment follows only if root probing proves costly. Such a check must stay advisory: path resolution misses bare basenames and package-relative paths, which is why rpiv's ~citations.ts~ never blocks on it.
- Report scope excess mechanically :: rpiv's ~implement-scope-check~ compares ~git status~ with the plan's declared ~files:~. The org-execute brief already declares allowed files and reconciliation already reports ~:committed~ and ~:dirty~, so the comparison belongs in the CLI under herdr-orch's "mechanics belong in a CLI" rationale ([[file:../../skills/herdr-orch/design.org::*Why mechanics belong in a CLI]]).
- Acceptance from the goal alone :: rpiv's ~acceptance~ skill freezes items before planning and keeps research from narrowing them. Each evidence command measures the outcome, not a record of it, and must be satisfiable without a human. Adapt as an optional token beside org-plan's existing ~test:~ citation, not as a new artefact.
- The herdr-orch "no workflow engine" statement is a conditional scope limit, not an architectural principle :: it entered ~SKILL.md~ with commit ~3fc1823~ from the child-context-modes record, whose anti-criterion reads "Must not: add dependencies or a workflow engine without a separate demonstrated need" ([[file:2026-10-21-child-context-modes.org]]). The 2026-07-22 record deferred a scheduler "until operational friction justifies code" ([[file:2026-07-22-harness-agnostic-subagents.org]]). Two adjacent decisions are principled and stand independently: the parent owns dependency knowledge, so a CLI-side fan-out scheduler was rejected ([[file:2026-07-29-subagent-comms-housekeeping.org]]); and org-plan/org-tasks are the single plan and task store ([[file:../../skills/org-execute/SKILL.md]]). The "launch authority" half of the same sentence is a safety boundary, not a scope limit. None of this cycle's candidates needs an engine. ~SKILL.md~ and ~workflow-recipes.md~ state the condition; the recipes keep "no persona, scheduler, or runner".
- Defer the child command watchdog :: rpiv's ~RPIV_BASH_TIMEOUT_MS~ turns a wedged command in a detached session into a halt reason. Herdr children remain interactive and ~poke~/recovery covers a stalled child; revisit only on observed stalls.

Sources, pinned at ~46dbdfd~ (base URL ~https://github.com/juicesharp/rpiv-mono/blob/46dbdfd78ab631bbf3ce41c2618bb173a5ec2725/packages/~):
- Finding verification :: ~rpiv-pi/agents/claim-verifier.md~; ~rpiv-pi/skills/code-review/SKILL.md~ sections "Step 5: Reconcile Findings" and "Step 6: Verify Findings".
- Review lenses :: ~rpiv-pi/agents/peer-comparator.md~ (Mirrored / Missing / Diverged / Intentionally-absent, the last requiring a citation that proves intent); ~rpiv-pi/agents/precedent-locator.md~ (similar commits and their follow-up fixes within 30 days); ~code-review~ "Step 4b: Interaction Sweep" (stranded state, false-promise predicate, co-tenant filter gap) and the cascade triples in Step 5. Step 5 also checks a claimed resolving commit with ~git merge-base --is-ancestor~.
- Scope floor :: ~rpiv-pi/extensions/rpiv-core/built-ins/scope-checks.ts~ and ~citations.ts~ (~verifyPhaseFilesCoverage~ is the only blocking structure check; citation resolution is advisory).
- Acceptance :: ~rpiv-pi/skills/acceptance/SKILL.md~.
- Prior adjudication :: ~rpiv-pi/skills/grade/SKILL.md~ ~--prior~ mode.
- Panels :: ~rpiv-workflow/docs/workflow-authoring.md~ section "Adversarial verification (panel)": distinct lenses over N copies; ~PANEL_VERDICT~ carries ~agreement~ and ~tie~ for escalation.
- Local owners compared :: [[file:../../skills/code-review/SKILL.md]], [[file:../../skills/herdr-orch/SKILL.md]] section "Trusting a result", [[file:../../skills/herdr-orch/references/workflow-recipes.md]] section "Bounded decision review", [[file:../../skills/herdr-orch/scripts/docs/contract.md]] section "Worktree reconciliation and teardown", [[file:../../skills/org-execute/SKILL.md]] and [[file:../../skills/org-plan/SKILL.md]] section "Spec/test citation on acceptance criteria".
