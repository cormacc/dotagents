* Intent
One canonical statement per shared behavioural directive, stored as neutral trait fragments that compose into subagent personas at spawn and into interactively typed prompts, so a retro improvement to a directive propagates to every consumer in one edit. Verdict of the evaluation this task required: worth building, narrowly -- fragments plus two thin consumers, no templating engine; part of the measured duplication is resolved by deletion and wrapper absorption rather than by the mechanism.

* Summary

*Level:* production · *Tests:* thorough · *Docs:* inline + contract

** Scope
*** In scope
- Trait store at repo-top-level =traits/=, canonical; the packaged skill layer is a relative symlink into it. Fragments are flat =<name>.md= or a directory =<name>/prompt.md=; the directory form carries siblings (=gate.md=) that resolution ignores.
- Resolution chains: =oh= uses project =<git-root>/.agents/traits/= > home =~/.agents/traits/= > packaged =<skillroot>/traits/=. Interactive expansion uses trusted project =<ctx.cwd>/.agents/traits/= > home, with no packaged layer. Both are first-match-wins and check =<name>.md= before =<name>/prompt.md= within a layer.
- Four shipped fragments: =read-only=, =focused=, =no-bullshit=, =prune=.
- Consumer 1, =oh=: inline =%<name>= tokens in persona bodies, substituted at spawn into a composed persona file under =.tmp/herdr-orch/composed/=, recorded as the ledger =:persona-path=.
- Consumer 2, interactive: =pi/extensions/traits/= expands typed =%<name>= tokens before skill and template expansion, over a =traits= entry point in root =bb.edn=.
- One interpolation implementation, =herdr-orch.traits=, consumed in-process by =oh= and as a CLI by the extension. Failure policy stays with the caller.
- Optional fragment metadata: =adapted-from:= / =adapted-from-sha256:= provenance, and =incompatible-with:=, enforced at spawn.
- Trait store ownership, the admission bar, and the probing protocol documented as second-level reference material under =herdr-orch= (=skills/herdr-orch/references/traits.md=), not as a separate skill.
*** Out of scope
- Placeholders, parameters, or include directives inside fragments: fragments are inert text, substitution is single-pass, and text inserted from a fragment is never rescanned.
- Trait taxonomy (modes / behaviors / composites): the persona occupies the mode slot, so every fragment is stackable. =incompatible-with:= handles the exclusion case that taxonomy would have modelled.
- A per-assignment trait dial: traits are persona-definition properties, like =kind:=. Only =--model= is chosen per assignment.
- Vendoring ai-behaviors as a resolution layer -- decided NO-GO. Upstream content is adapted selectively instead.
- Persona role-core rewrites ("lean persona = mode composite") -- parked, see Open questions.
- Any change to harness kind resolution, delegation depth, or persona delivery on =continue=.

** Decisions
- Traits are a herdr-orch-independent contract -- directory layout, fragment format, token syntax -- with two consumers. :: Rejected: a generalised templating system before a second consumer existed; a zero-code "also read <path>" convention, which breaks layer resolution; wrapper-only consolidation, which correctly owns universal lifecycle prose and got it, but cannot carry a directive only some personas need.
- Token syntax is =%<name>=, substituted inline where the directive belongs rather than appended. :: Instruction position carries meaning, and an appendix reads as boilerplate. Reconsidered against =printf= collision and upheld; see Open questions.
- Not all measured duplication becomes a trait. :: No-delegation prose was deleted outright rather than promoted, because =spawns:= enforces it mechanically before any ledger or pane mutation. Prose restating a mechanical guarantee is belt-and-braces, not a trait.
- Flat namespace, no taxonomy; a composed file materialized at spawn rather than inlined into the prompt. :: The composed file is inspectable after the fact, survives =continue= via =:persona-path=, and keeps the prompt free of fragment bulk.
- Trait documentation lives under =herdr-orch= as second-level reference material, not as its own skill. :: Shipped first as a separate =traits= skill owning the store and admission rules but no code, then merged on 2026-08-11: a skill that owns no mechanism, whose only mechanism lives in a sibling, is a separation that complicates sharing =herdr-orch= with partial consumers of this repository and buys nothing back. The reasoning that justified separating it still holds for *ownership* -- ownership is expressed by where the rules live. Moving the implementation would have required a subprocess boundary, an availability probe, and a degraded mode for a deployment that cannot occur, since =agents.nix= symlinks the whole =skills/= tree as one unit.
- Admission requires a named consumer and a recorded probe attempt, not a passing one. :: Passing probes against synthetic scenarios are satisfiable; requiring them now was declined on cost on 2026-08-11, with the stricter bar tracked as =d669edf5=.
- Interactive expansion honours pi project trust. :: The project trait layer is read only when =ctx.isProjectTrusted()= is true, defaulting to untrusted, because the project layer shadows home and an untrusted repository could otherwise hijack a token the user believes is trusted. =oh= is unaffected: it resolves personas from the assignment root, not from a browsed working directory.
- Interactive interpolation failure warns and passes the input through rather than blocking the message. :: Unknown-token pass-through is deliberate and unchanged; an *error* now surfaces a visible warning instead of failing silently. Blocking a human's typed message on a tooling fault is worse than sending it unexpanded, which is the opposite of the spawn-side choice, where a missing directive silently removes a persona's boundary.
- Full substitution semantics, grammar, failure policy, and composed-file lifecycle live in =skills/herdr-orch/scripts/docs/contract.md= section Trait composition, which is the single normative source. Not restated here.

** Gotchas
- Fragment frontmatter is parsed line-wise as =key: value=. Nested YAML does not fail -- it flattens children into sibling top-level keys -- so metadata values must be single-line scalars.
- Trait tokens are =printf= format specifiers. =printf "$text"= silently corrupts =%focused= and =%no-bullshit= at exit 0, as it does any prose containing a percentage. See =AGENTS.md= section File operations.
- A probe scenario that takes this repository as its subject decays: the repository documents the answer, and a durable probe record becomes an answer key for the next control arm. Synthetic subjects are the only stable design.
- =AGENTS.md= loads in every pi session. Its overlap with =%challenge= was measured; the conclusion that the fragment was redundant was inferred from that overlap and was never established by a discriminating probe.
- Consolidating drifted wording changes what children read: a behavioural change, not a refactor, and no CLI test can detect a prompt-quality regression. Composed-file diffs and probes are the only checks.
- Markdown-context exclusion is pragmatic (same-line backtick pairing, fences, indent), not full CommonMark; exotic markdown can misclassify a boundary either way.

** Risks
- Per-child context grows +102 lines across the seven personas. Accepted: the admission bar exists to bound it, and removal is a normal outcome.
- =incompatible-with:= is enforced and tested but has no live declaration since =challenge= was deleted. Undecided deliberately: a guard awaiting its next conflicting pair, or dead weight.
- No fragment holds a probe result valid for the current repository state. Acknowledged by the admission bar rather than hidden; re-probing with synthetic scenarios is filed as =d669edf5=.

** DECIDED Trait-token syntax =%<name>=
:PROPERTIES:
:DECIDED: [2026-08-10 Mon 10:07]
:END:
=%<name>=, for persona files and interactive input alike (user, 2026-08-10). Markdown-inert, rare in prose, and short candidates are resolution-gated so =%s= and =%20= stay literal.

Reconsidered 2026-08-10 and upheld, after finding that our tokens are consumed as =printf= format specifiers: =%focused= silently becomes =0.000000ocused= at exit 0. Every alternative is worse in a commoner operation -- =^= expands to directory contents under zsh =extended_glob= and makes =rg '^focused'= match the wrong lines; =##= glob-matches nothing in zsh and makes bash swallow the line; =!= is owned by pi; =$= empty-expands in the idiomatic quoted form. Mitigated by an =AGENTS.md= rule instead, since prose containing a percentage breaks identically. The candidate table, the verified pi input conventions, and the generalisable lesson (check both directions -- what triggers our matcher *and* what consumes our tokens) are in =skills/herdr-orch/references/traits.md= section Why the token prefix is =%=.

:PROPERTIES:
:DECIDED: [2026-08-11 Tue 11:40]
