* Intent
One canonical statement per shared behavioural directive, stored as neutral trait fragments that compose into subagent personas at spawn and into interactively typed prompts, so a retro improvement to a directive propagates to every consumer in one edit. Verdict of the evaluation this task required: worth building, narrowly -- fragments plus two thin consumers, no templating engine; part of the measured duplication is resolved by deletion and wrapper absorption rather than by the mechanism.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* inline + contract

** Acceptance
*** Core functionality
- [ ] A trait name resolves =<layer>/<name>.md= first, then =<layer>/<name>/prompt.md=, per layer project > home > packaged; first match wins.
- [ ] A persona body containing =%read-only= spawns with a composed persona file in which the token is replaced in place by the fragment text; fragments appear where their tokens sit, never as a trailing =## Shared directives= appendix.
- [ ] Token grammar: =%= preceded by start-of-line or whitespace, name =[a-z][a-z0-9-]*=, ending at the first character outside that grammar -- =%focused,= expands; =page%focused=, =%20=, =%PATH%= never match.
- [ ] A 1-2 character candidate is inert unless it resolves in the chain: =%s= and =%h= pass through untouched, while a resolving short name (a vendored =%ct=) expands.
- [ ] Backtick code spans, fenced code blocks, and indented code blocks (4+ spaces or tab) are excluded from token scanning.
- [ ] YAML frontmatter is preserved byte-for-byte and excluded from scanning; only the markdown body is interpolated.
- [ ] A fragment opening with YAML frontmatter has it stripped at substitution, with =name:= validated against the file or directory name; a fragment without frontmatter (vendored ai-behaviors prose) is substituted whole; insertion is verbatim and single-pass: substituted output is never rescanned.
- [ ] One shared bb implementation (a herdr-orch namespace) performs scan/resolve/substitute and reports unknowns and repeats; failure policy stays with the caller; the standalone CLI bin ships with phase 2 if built, never with phase 1.
- [ ] The composed file path (not the source persona path) appears in the child prompt's =Read= line and in =persona-args= for =pi=/=claude= kinds.
- [ ] The composed file is written to =.tmp/herdr-orch/composed/<task>-<persona>.md=, recorded as the ledger entry's =:persona-path= (inherited by continued rounds with the rest of the entry), and never deleted by =oh=; continued rounds retain context and are not re-sent a persona path.
- [ ] =--print-prompt= reports resolved trait names in body-occurrence order and per-trait source layer, previews the prompt with a =<composed-persona-path>= placeholder, and writes no file.
- [ ] A persona whose body contains no candidate token gets no composed file: the composer passes the source persona path through unchanged. Identity is scoped to the trait composer; the separately accepted wrapper clauses and persona-body edits are exempt.
- [ ] =prompt-text= states the artifact/report publication convention for every spawn; the five persona restatements are gone.
- [ ] Typing a =%<name>= trait token in interactive pi input expands to the fragment text before agent processing (phase 2, only if its go/no-go decides build).
- [ ] =self-improvement= names the trait store as a routing destination with the >= 2-consumers rule.
*** Edge cases
- [ ] An unknown 3+ character candidate token (a grammar match resolving in no layer, e.g. a typo'd =%focsu= or an unquoted =%llu=) fails at spawn with the name, the searched layers, and the quoting escape; nothing is created (no ledger entry, no pane).
- [ ] A token repeated in one persona body fails at spawn like an unknown one.
- [ ] A project-layer trait shadows a home/packaged trait of the same name; =--print-prompt= source layer shows which won.
- [ ] Interactive expansion of an unknown token leaves the prompt untouched rather than erroring the message (phase 2, if built).
*** Anti-criteria
- Must not: materialize a composed file or alter the persona path for a persona whose body contains no candidate token (the separately accepted wrapper clauses are exempt from prompt-byte identity).
- Must not: parameterise fragments; inline tokens are the only trait declaration mechanism.
- Must not: introduce a spawn-time =--traits= flag.
- Must not: add a trait with fewer than 2 real consumers (personas or interactive use).
- Must not: alter the CLI output envelope schema.

** Decisions
- Traits are a neutral, herdr-orch-independent contract (directory layout + fragment format + token syntax), consumed by two consumers. :: The scanner is non-trivial (grammar, quoting exclusion, frontmatter strip), so one shared bb implementation -- a herdr-orch namespace, consumed in-process by =oh= -- serves both call sites; duplicating it in two languages would be exactly the drift this project exists to eliminate. Fragments carry no parameterisation. The standalone CLI bin belongs to the gated phase-2 task, its only concrete consumer: shipping a CLI contract ahead of that gate would be speculative surface. Extracting the whole thing as its own skill is parked in Follow-ups. Rejected:
  - Generalised templating system first: only one consumer class is demonstrated (spawn composition); interactive use is a user-requested capability with no demonstrated workflow yet, hence gated. Engine cost without engine need.
  - Zero-code convention ("Also read <path>" lines in personas): breaks layer resolution, costs a file read per trait, trusts the child.
  - Wrapper-only consolidation: correctly owns universal lifecycle prose, and got it (the publication convention); but it cannot own persona-selective directives -- =read-only= applies to 5 of 7 personas, =focused= to 4, =no-bullshit= to 2, and wrapper text is unconditional for every child. Phase 1 is justified on persona drift alone, not on the interactive consumer.
- Adopt ai-behaviors-compatible dual-shape resolution; vendor nothing yet (Option 2, vendoring staged as droppable phase 3). :: Flat =<name>.md= for hand-authored friendliness; =<name>/prompt.md= accepted so the ai-behaviors library can drop in as a base layer unchanged. Rejected: vendoring first (submodule maintenance and pi-extension composite/mode logic paid before their one real consumer exists); own incompatible format (free compatibility discarded).
- Not all measured duplication becomes traits: no-delegation prose is deleted (mechanically enforced by =spawns:=; leaf sentence already injected -- the =cli.clj:168-179= precedent), the publication convention is absorbed into =prompt-text= (context-aware wrapper states it unconditionally where a trait must hedge), verify-claims is demoted to AGENTS.md which already states it.
- Flat trait namespace, no taxonomy. :: None of the shipped traits is mode-like; the persona occupies the mode slot, so modes are banned from =traits:=. Mutual exclusion has mechanical consequence only in the interactive consumer and only once ai-behaviors modes exist there (phase 3's problem, solved upstream as last-wins).
- Composed file materialized at spawn rather than inlining fragments into the prompt; lifecycle decided once. :: Works for every harness kind (for most, the =Read <path>= line is the only persona delivery). Written at spawn to =.tmp/herdr-orch/composed/<task>-<persona>.md= (the ledger is flat -- there is no per-round directory); recorded as the entry's =:persona-path=, which =continue!= already inherits, so continued rounds keep a consistent inspectable role text while retaining context rather than re-reading; never cleaned by =oh=, matching the result-file policy. =--print-prompt= previews with a placeholder path and writes nothing; "inspect the resolved file" means the source persona and trait fragments before spawn, the composed file after.
- Trait-token syntax is =%<name>= (user decision, 2026-08-10), for persona files and interactive input alike. :: The 2026-08-09 deferral to the phase-2 go/no-go expired on new evidence: the earlier ranking assumed tokens appear only in human-typed interactive input, but inline substitution embeds them in persona =.md= files, so markdown behaviour became a criterion. That demoted the previous leader =##<name>= -- CommonMark 0.31.2 § 4.2 requires a space after the hashes, but the spec itself notes many implementations do not enforce it, so non-conforming editors and previews may render =##read-only= as a heading in exactly the files that embed it. =%<name>= is inert in markdown; in prose its safety is structural, not universal (corrected 2026-08-10 repair -- the original "inert" claim predated the fatal-unknown policy and contradicted it): =%20= (digit-first), =%PATH%= (uppercase), and every 1-2 character lowercase specifier (=%s=, =%h=, =%an=) is inert unless it actually resolves (resolution-gated, third repair 2026-08-10), while a 3+ character lowercase specifier such as =%llu= is a candidate and fatal at spawn unless written as code. The ai-behaviors kinship cost is real but was already established as non-discriminating: the extension matches uniformly across the whole chain. Knock-on: fragments carry optional YAML frontmatter (=name:=, =description:=) rather than a heading -- decided at the third repair, see the semantics decision. Candidate history preserved in Open questions (DECIDED).
- Tokens are substituted inline rather than appended. :: A persona body carries =%read-only= where the directive belongs; composition substitutes the fragment text in place. Rationale: instruction sequencing -- appended fragments arrive as an appendix divorced from context (advisor kept one bullet under =## Constraints= while three more constraints appeared under a trailing heading its own prose never mentions); one mechanism, two consumers -- the interactive extension and =oh= become two call sites of the same substitution rather than a frontmatter feature mirrored by a different token feature (the parent task's original goal); and it removes the declare-here/appear-there duality -- the shipped composer (=core.clj/compose-persona-text=) passes the body through with its =traits:= frontmatter line intact while the prototype's hand-built outputs stripped it, a mismatch class inline substitution makes unrepresentable. Preserved unchanged from the shipped design: fail-fast naming the trait and searched layers with nothing created; project > home > packaged with dual shape =<name>.md= then =<name>/prompt.md=; no composed file and unchanged source path for a token-free persona; =--print-prompt= reporting without writing; composed file never cleaned; =continue!= inheriting =:persona-path=. Rejected: keeping the shipped append design (the sequencing and duality defects are structural, not wording).
- Substitution semantics (decided 2026-08-10). :: Matching is inline-within-a-line: a candidate is =%= preceded by start-of-line or whitespace followed by =[a-z][a-z0-9-]*=, the name ending at the first character outside that grammar -- =%focused,= expands while =page%focused=, =%20=, =%PATH%=, =%%= are structurally inert. The unknown-candidate policy is length-gated (third repair 2026-08-10, replacing the second repair's minimum-length grammar): a 1-2 character candidate is inert unless it resolves, so printf =%s=/=%d=/=%ld=, git =%h=/=%an=, and strftime specifiers pass through untouched while a vendored 2-character behaviour stays reachable (parent-verified upstream: ai-behaviors ships =ct=, =fp=, =io= among its 70); a 3+ character unknown candidate is fatal. Trade accepted with eyes open: a typo'd 1-2 character name is silently inert rather than fatal -- no 1-2 character trait ships today, and the unexpanded token stays visible as literal text in the composed file. Backtick code spans, fenced code blocks, and indented code blocks (lines indented 4+ spaces or a tab, CommonMark § 4.4 -- added in the repair for CLI examples) are excluded from scanning (pragmatic, not full CommonMark). A remaining unquoted unknown candidate (a 3+ character specifier such as =%llu=, or a typo'd trait name) is a spawn error whose message names the escape: write it as code or fix the name. Convention: place trait tokens at less than 4 spaces of indentation, since the indent rule cannot distinguish deep list continuations from code; a known token skipped that way stays visibly literal in the composed file. YAML frontmatter is split off and preserved byte-for-byte; only the body is scanned. A repeated token is a spawn error: personas are curated files, and a repeat is a copy-paste mistake that silently doubles context. Substitution is single-pass; output is never rescanned. Fragments carry optional YAML frontmatter (=name:= validated against the file or directory name, =description:= as the axis; unknown keys ignored, the =parse-frontmatter= precedent), stripped at substitution; a fragment without frontmatter -- every vendored ai-behaviors =prompt.md= -- is substituted whole. Adopted over the earlier leading-H1 strip on user question (third repair 2026-08-10): the =---= delimiters are structural where the H1 rule was a text heuristic that would mis-strip a vendored file whose first line is a genuine content heading; the store family keeps one metadata convention; it extends later (=axis:=, =conflicts:=) with no new syntax. Honest caveat: =core.clj/parse-frontmatter= throws on absent frontmatter, so the fragment path needs a tolerant variant either way -- optionality is required for vendored prose regardless. Deliberate asymmetry, recorded: persona frontmatter is byte-preserved and excluded from scanning because the persona is the host document and its frontmatter is operative metadata (=kind:=, =model:=, =spawns:=); fragment frontmatter is stripped because a fragment is inlined guest text whose metadata describes the fragment, not the host. The store file still self-describes standalone while the composed prompt integrates cleanly -- the point of inline placement; the strip rule is written once in the shared implementation. =--print-prompt= reports =traits= in body-occurrence order and keeps =trait-sources= as ={trait, source, path}=. Rejected: line-scoped-only matching (diverges from the interactive consumer's token-in-text use, breaking one-mechanism); repeat-expands-twice (silent duplication); verbatim H1 (a top-level heading mid-section, in exactly the placement the inline decision argues for); bold-label fragments (label noise ships to every child); a =%%= literal escape (parameterisation creep, and =%%= is already structurally inert without yielding a literal =%name=); an allow-list making unknown candidates inert (loses typo-catching entirely -- a misspelled trait ships silently unexpanded); required quoting alone (leaves the commonest 1-2 character specifier class fatal in bare prose); a global minimum name length of 3 (second repair, withdrawn at the third: it made real upstream 2-character behaviours unreachable, narrowing the dual-shape vendoring goal to fix an unrelated problem); per-name aliases for short vendored behaviours (a mapping table built now for three names whose consumer, droppable phase 3, may never exist); accepting the 3-of-70 exclusion as documented limitation (quietly falsifies the recorded drop-in-unchanged compatibility rationale); keeping the H1 heading with strip (mis-strips vendored genuine first headings).
- Traits are canonical at repo-top-level =traits/=; the packaged layer inside the skill is a relative symlink into it. :: Single source in this repo while the skill remains self-resolving; a standalone copy of the skill alone loses shipped traits and fails fast at spawn, which is acceptable and documented.

** Risks
- Consolidating drifted wording changes what children actually read: a behavioural change, not a refactor, and CLI tests cannot detect prompt-quality regressions. Mitigated: composed-file diff review per persona; per-trait adversarial checks that probe the changed directives directly (mutation bait for =read-only=, layered bait for =focused=, clean-change review for =no-bullshit= -- see the persona-rewrite task); persona rewrites staged as an independently revertable task. Envelope/artifact-shape checks cover only the wrapper and stay with the wrapper task.
- Per-child context grows, measured across all 7 personas (2026-08-09, revised after visual-tester gained =read-only=): composed files total 613 lines vs 511 source (+102); every trait-bearing child reads 17-27 lines (~150-270 tokens) more, and the wrapper absorption adds ~2-3 lines to every spawn prompt on top. Accepted explicitly: the value case is drift elimination and retro routing, never context savings -- an earlier draft of this entry claimed the composed persona shrinks, which the measurement contradicts. The decision stands; the claim does not.
- Trait-name collisions with a future vendored layer. Accepted: our layers shadow the vendored base by chain order; =--print-prompt= source layer makes the winner visible.
- Upstream ai-behaviors is small (34 stars) and quiet since 2026-04-30; phase 3 may vendor a dead project. Mitigated: phase 3 is droppable by construction and decided when its consumer (phase 2) is live.
- Retro-driven trait bloat inverts the win (every child pays context for every rule). Mitigated: >= 2-consumers anti-criterion enforced in =self-improvement= routing guidance.
- Markdown-context exclusion is pragmatic (same-line backtick pairing, fences, 4-space/tab indent), not full CommonMark: exotic markdown could misclassify a boundary in either direction -- a quoted specifier scanning as a candidate, or a real token hidden (notably, a token in a list continuation indented 4+ spaces is skipped as code). Accepted: personas are curated files, tokens sit at less than 4 spaces by convention, and both failure directions surface immediately -- spawn fail-fast, or a visibly unexpanded token in the composed file and =--print-prompt=.
