* Intent
The Herdr TUI org-tasks plugin runs one compact pane, one supervisor and one embedded =ot tui= in every tab, and each supervisor polls Herdr every 500 ms. Replace this with one compact pane per session that moves to the focused tab and reacts to Herdr events, because the display is informational for the user and is only useful where the user looks.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* README

One compact pane per session. Its supervisor subscribes to Herdr events on =HERDR_SOCKET_PATH=, moves its own pane into the focused tab with =herdr pane move=, and samples the focused tab's source pane on focus and title events, with a slow fallback poll for folder changes. Startup and =tab.focused= hooks open the pane when no live instance exists. Tabs that the user never focuses, such as subagent tabs, get no pane.

** Scope
*** In scope
- =herdr/plugins/org-tasks/src/org_tasks_host.clj=: session-level instance record, lease and lock; event client; follow-focus supervisor; =ensure=, =toggle= and =select= on the single instance.
- =herdr/plugins/org-tasks/herdr-plugin.toml=: =startup= and =tab.focused= hooks; no =tab.created= hook.
- =scripts/test-herdr-org-tasks.bb=: fake event stream and single-instance cases; existing per-tab cases replaced.
- Relevant contract: =herdr/plugins/org-tasks/README.md= describes the pane lifecycle and must change.
- Relevant contract: =skills/org-tasks/scripts/docs/contract.md= section 'Embedded TUI context contract' binds the producer; this change must keep it.
*** Out of scope
- The herdr-app org-tasks mod (=herdr-app/mods/org-tasks=).
- Graph reload cost inside =ot tui= (=org-tasks.tui.embedding= reloads each 500 ms); with one instance it is one reload stream, not one per tab.
- A one-line =[ui] tab_bar_right= status as a replacement for the pane.
- More than one client: the pane follows the server's focus only.

** Acceptance
*** Core functionality
- [ ] With display on and three or more tabs, the session has exactly one compact pane.
- [ ] The session has exactly one supervisor process.
- [ ] Focusing another tab moves the compact pane into that tab within 1 s.
- [ ] The moved pane keeps its =terminal_id=, so =ot tui= is not restarted.
- [ ] Focusing a tab in another workspace moves the compact pane into that tab within 1 s.
- [ ] After a focus change, the pane shows the newly focused pane's project within 1 s.
- [ ] After a =cd= in the focused source pane, without a title change, the pane shows the new project within 7 s. (Amended from 5 s during implementation: the 5 s fallback sample finds the folder, and the 1 s folder hold publishes it.)
- [ ] While no event arrives, the supervisor makes at most two Herdr requests per 5 s. (Amended from one during implementation: a fallback sample needs the snapshot and the source pane's =process-info=, which detects an =ssh= that starts without a folder or title change.)
- [ ] After a move, the compact pane has the configured =:compact-rows=, unless Herdr's minimum pane size clamps it.
- [ ] When every other pane in the pane's tab closes, that tab closes.
- [ ] After such a tab closes, the compact pane opens in the tab that Herdr focuses next.
- [ ] =toggle= off closes the single pane.
- [ ] =toggle= on opens the single pane in the focused tab.
- [ ] After the supervisor dies, the next tab focus opens a new compact pane.
*** Edge cases
- [ ] Focusing the tab that already holds the pane does not move it.
- [ ] Ten tab switches within 2 s leave one pane, in the last focused tab.
- [ ] When the event connection closes, the supervisor exits.
- [ ] Focusing the compact pane or another plugin pane keeps the previous source.
- [ ] A remote (ssh) or unavailable source shows the existing remote or unavailable state.
*** Anti-criteria
- [ ] Must not: take focus when the pane opens or moves.
- [ ] Must not: open a compact pane in a tab that has not had focus.
- [ ] Must not: poll Herdr at 500 ms.
- [ ] Must not: change the embedded context contract. → spec:[[proj:skills/org-tasks/scripts/docs/contract.md]]

** Decisions
- Chose one pane per session that moves with focus :: removes the per-tab processes, the per-tab polling and the per-tab stuck-tab risk at once. On this computer, 28 supervisors used about 2.0 GiB RSS and 27 embedded =ot tui= processes about 2.5 GiB (summed RSS, which counts shared pages more than once).
  Rejected:
  - Keep per-tab panes, poll slowly in hidden tabs: still one supervisor and one =ot tui= per tab.
  - Open a new pane on focus and close it on blur: a =bb= and =ot= cold start (about 0.4 s or more) and an empty pane on each switch.
  - Per-tab event subscribers: removes polling but not the per-tab processes.
  - =[ui] tab_bar_right= status line: one line only, interval refresh, and the user must paste config.
- Move the pane with =herdr pane move=, not close and reopen :: the process, its =terminal_id= and the loaded graph survive the move.
- A subscription for live changes, hooks for recovery :: the supervisor subscribes with =events.subscribe= on =HERDR_SOCKET_PATH=; the =startup= and =tab.focused= hooks run the idempotent =ensure=, so a dead supervisor comes back at the next tab switch. A workspace switch also emits =tab_focused=, so no =workspace.focused= hook is needed.
- Slow fallback poll of the own tab only :: a =cd= without a title change emits no event (see Gotchas), so the supervisor also samples every 5 s.
- The same-pane folder hold is 1 s of time, not a sample count :: with event-driven sampling, three samples could take 15 s. A pending folder schedules one more sample at the end of its hold.

** Gotchas
- =pane_updated= fires on a terminal-title change only. A =cd=, a foreground command and =pane rename= emitted none in the spike; the title event carried the current =foreground_cwd=.
- Subscriptions take no filter: the supervisor receives every subscribed event in the session and must drop events for other tabs. Busy agents can change titles often.
- =pane move --split down --ratio R= gives the existing target pane the share R. A compact pane needs R near =1 - rows/height=, or =resize!= after the move.
- A move to another workspace gives the pane a new ID (=w1:p3= → =w2:p2=). The process keeps its old =HERDR_PANE_ID=; =herdr pane current --current= inside it returns the new ID, and =plugin pane close= works on the new ID.
- Hooks receive =HERDR_PLUGIN_EVENT_JSON= (the event, with =tab_id=) and =HERDR_PLUGIN_CONTEXT_JSON= (the focused pane and its folder).
- =source= merges a pane with its entry in the snapshot's =:agents= list, so a test fixture that changes an agent pane's folder must change both lists.

** Risks
- Each tab switch reflows panes in two tabs, and each resized pane redraws once: accepted by the user after a check in a real client (see Open questions).
- The event protocol is undocumented outside =herdr api schema=: pin =min_herdr_version=, and end the supervisor on an unknown envelope so that the hook reopens it.
- Several clients on one server: only the server's focused tab gets the pane; accepted.

* Implementation
- Event client :: =subscribe!= and =events!= in =herdr/plugins/org-tasks/src/org_tasks_host.clj=. =subscribe!= returns only after =subscription_started= and throws ex-info with =:subscription= =:closed=, =:error=, =:unparsable=, =:unexpected= or =:timeout= (=*subscribe-timeout-ms*=, default 2000 ms). =events!= blocks, returns ={:end :closed}=, ={:end :error ...}= or ={:end :unparsable ...}=, and always closes the connection. Against an isolated Herdr 0.9.5 server it delivered both =tab_focused= events in order, and =server stop= ended it with ={:end :closed}=.
- Single instance :: a per-session =instance.json= index and =instance.lock= replace the per-tab =<tab>.json= and =<tab>.lock=. =open-session!= opens the pane below the focused pane of the focused tab; =close-legacy!= closes live panes of the per-tab version and removes their index files. After a move, the supervisor rewrites =owner.json= and the index, under the lock, with its new pane and tab.
- Supervisor loop :: events go to a queue, and the loop takes every queued event at once, so a burst becomes one sample. A sample is due on =sample-reason=, at the end of a folder hold, or after =*fallback-ms*= (5 s); =*min-sample-ms*= (250 ms) spaces samples. One sample moves the pane (=follow!=, ratio from =move-ratio=, then =resize!=), closes it when alone, or publishes. The heartbeat rewrites the context and owner files every 500 ms without a Herdr request.
- Not covered by the fake-Herdr tests :: the compact height after a move (the fake has no split geometry) and every timing criterion; plan task "Validate the follow-focus pane in an isolated Herdr server" covers them.
