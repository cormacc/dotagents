* Intent
Make engineering simplicity a default constraint in foreman-led delegation, without weakening accepted scope or verification. Give context management and engineering simplicity equal weight through explicit, harness-independent persona composition rather than incidental inheritance of an interactive Ponytail mode.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* full

Agreed direction: one-level persona inheritance, additive metadata/per-spawn traits appended after the persona body, a read-only base analyst, and a compact simplicity default. Migrate only trailing trait blocks; preserve embedded placement. Incrementally replace Ponytail with the hybrid persona/trait/skill system, retaining upstream material for reference/comparison where useful. Keep the existing CLI authoritative; defer a Pi task interface.

Delivered across four plan tasks (`b95b430..dfa3100`, five commits), after the prerequisite [[task:561270b1-e372-47a7-9173-bd966c4204ae][herdr-orch improvements 260917]] landed.

** Scope
*** In scope
- Composition: one-level =extends=, =traits: [name, ...]=, explicit per-spawn trait selection, deterministic preview, retained launch provenance, and pre-mutation validation. Metadata/per-spawn fragments follow the complete persona body.

- Activation: replace automatic Ponytail policy incrementally as the hybrid guidance/workflows become usable. Retain upstream skills as reference/comparison material where useful, without duplicate automatic activation. Permanent full-mode opt-in is not a delivery requirement.
- Contracts: update the relevant spec files above together with their implementation; document the distinction between interactive token expansion and child composition.
*** Out of scope
- A Pi task UI, dashboard, automatic scheduling, or a second state store/model resolver.
- Reimplementing the prerequisite's raw-adapter repairs, version gate, abandonment recovery, model-contract repair or managed/vendored refresh. Native prompt-event/listener work remains its separate upstream follow-up, not a Ponytail dependency.
- A new generic write-enabled base, mandatory advisor consultation, or combining complexity review with correctness review.
- Parsing natural-language spawn requests inside the CLI; arbitrary YAML configuration; automatic detection of semantic contradictions in prose.
- Hot replacement of a child's recorded launch persona. User intervention and supplementary prompts remain available.
- Benchmark/gain/help injection, mandatory ponytail debt comments, or a new debt-scanning mechanism.

*** Composition
- One-level inheritance, clarified on 2026-09-17: resolve one named base through the existing project > home > packaged lookup, then concatenate base body before derived body. Reject a missing base or a base that itself declares extends; that also rejects self-reference without graph traversal or a cycle detector. The earlier recursive choice sought to avoid elaborate depth safeguards, not to require arbitrary-depth inheritance.
- Inherit scalar runtime settings; the nearest derived declaration wins before existing spawn flags apply. Keep name/description local to the selected persona. Inherit an omitted spawns declaration; preserve the existing meaning of an explicit empty declaration. Traits never set runtime settings or capability.
- Append metadata traits after the complete base-plus-derived body, separated by blank lines: base metadata first, derived metadata second, explicit spawn traits last. Deduplicate these selections by name. They cannot remove inherited traits. Different policy requires a different base, not a subtraction switch.
- Retain legacy inline substitution in place. Repeated resolving inline tokens remain errors. If a metadata selection already has an inline occurrence, use that occurrence rather than emit a second body. Resolve the effective trait set before read-only checkout/publication policy is selected.
- Proposed CLI surface: repeatable =--trait NAME= on task run/start and their preview path. Validate explicit names regardless of token-length rules; do not parse assignment prose for traits. Compose through the existing interpolator, not a copied implementation.
- Support the requested one-line list syntax explicitly; reject unsupported list shapes rather than silently flatten them. Preserve existing scalar parsing behaviour for legacy definitions. No new general-purpose configuration language is required.
- Keep selected/base persona and trait-source provenance beside the existing persona path in the ledger. Preview must expose the same effective text/settings that spawn consumes, without creating a pane or ledger entry.
- Migrate only a suffix of standalone trait tokens after the persona's last substantive prose, preserving token order. Keep embedded tokens in place, including earlier tokens in a persona with an eligible suffix. Do not move prose to manufacture eligibility or force a common authoring style. This limits existing-token migration, not the addition of newly admitted metadata traits. Do not force unrelated roles into an inheritance hierarchy.
- Continue retains the launch composition. Normally spawn a fresh child to change persona or traits. Supplementary prompts, already-expanded inline guidance and direct user intervention remain valid; these do not rewrite launch metadata or promise removal of prior instructions.

Scope-changing simplifications return to the owner for approval. Preserve security, accessibility, data safety, repository conventions and required validation.

* Implementation
** Composition mechanism (`b4c63339`, `7487f88`)
One-level `extends:` resolution and additive `traits:`/`--trait` composition landed in `core.clj`/`cli.clj`/`traits.clj`. `resolve-base` rejects a missing base or a base that itself declares `extends` (also rejecting self-reference through the identical check); composition merges scalar frontmatter (derived declaration wins; `name`/`description` excluded), computes the ordered/deduplicated base-then-derived-then-`--trait` name union, validates every name in that union regardless of length (closing the inline short-candidate leniency gap for explicit/metadata selections), and appends only the names without an existing inline occurrence before one `traits/interpolate` call. `preview!`/`spawn!` read the effective (post-merge) frontmatter; the ledger records `:persona` and, when present, `:base-persona`, `:traits`, `:trait-sources`; `preview!` additionally reports the exact effective `:persona-text` with no pane or ledger entry created.
