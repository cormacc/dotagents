* Summary
Renamed the two skills that form the org-memory protocol so they share a symmetric =org-= prefix: =org-memory → org-tasks= (file/persistence protocol) and =plan → org-plan= (planning methodology / change-record sections). The =tasks= pi extension is *not* renamed — extension naming optimises for user-facing concision (=/tasks=, =SPC t t=, the "Tasks" widget label) where skill naming optimises for symmetry and namespace clarity in the agent registry. "org-memory" survives as an informal umbrella term in prose. =git mv= preserves history; no backwards-compatibility shim.

** Decisions
- Skill rename, not extension rename :: skills serve LLMs (verbose names cheap); extensions serve humans (short names matter). Skill rename has low blast radius.
- =org-memory= survives as prose :: "the org-memory system, implemented by =org-tasks= and =org-plan=" is encouraged.
- =git mv= for directory renames :: =git log --follow= keeps tracing through history.
- Description fields unchanged :: behaviour didn't change, only names.
- No backwards-compatibility shim :: pre-release; clean rename is fine.
