* Intent
Make ot reject surplus input before mutation and preserve text values instead of coercing them as data. Make repeated blocker/issue additions safe to retry, restore local task creation, and let delegated workers change their tasks without promoting ancestors.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* full

The registry defines accepted inputs; dispatch validates them before handlers. Babashka's parser, protocol-path representation, doctor semantics, and UI implementations remain unchanged.

** Decisions
- Keep babashka.cli and validate at the shared dispatch boundary before a command handler runs. Reject surplus positionals with =argument-error= and exit 2, not command-specific checks. Validate options against the selected command's effective spec; mapped positional keys are not unknown flags.
  Rejected: a custom parser, per-command arity checks, and best-effort scanning of surplus tokens for a late =--format=.
- Keep blocker/issue add and remove singular; correct the ambiguous =[...]= quick reference. Duplicate additions are successful no-ops against the existing normalised stored token, not new errors. Skip saving on a duplicate; do not deduplicate old entries.
  Rejected: multi-ref operations and duplicate error codes.
- =--no-promote= is a boolean status option for explicit and cycled transitions. Default promotion stays unchanged; opt-out returns the existing empty =promoted= vector without a new field. Doctor stays unchanged.
  Rejected: interpreting parent-status restrictions as closure-only, persistent opt-out properties, and warning suppression.
- Remove global =--local <path>=; retain create's boolean =--local=. Separate the create selection boolean from options sent to protocol-path resolution. Keep internal path maps and create anchor precedence unchanged.
  Rejected: renaming either flag or a dual boolean/path argument syntax.
- Derive string defaults for positional mappings and value-taking options from registry data; explicit coercions win. Apply a consistent effective spec/coercion rule to command dispatch and pre-command options.
  Rejected: a create-only patch and hand-written per-option string coercions.
- Retain the documented dash-led body limit: use =--body=<text>=. Add a =known-limit:= comment where the retained parser limit is owned, naming the limit and reconsideration trigger. Numeric-looking body text is fixed; separate-argument dash-led bodies are not.
- Preserve existing TUI/overlay behaviour without adding no-promote controls. Add herdr-orch worker guidance in this change rather than a follow-up.

** Shipped

- MODIFIED =skills/org-tasks/SKILL.md= documents singular blocker/issue mutations and promotion opt-out; =skills/herdr-orch/SKILL.md= directs restricted workers to use =--no-promote=.

** Gotchas
- Raw positional fallback uses fixed indices, not compressed missing slots. A mapped key cannot free its raw index for another argument.
- Aliases before command names need the registry's aggregate alias map as well as its coercion map.
- Issue-token comparison uses complete parsed raw links so a description containing spaces remains one token; it does not require link-template resolution.
- Accepted limits: late options remain unparsed after surplus input; dash-led separate-argument bodies require the equals form; doctor can warn about intentional TODO ancestors; historical duplicate entries remain.
