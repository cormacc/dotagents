* Intent
Ship the repository's reusable Herdr persona definitions as part of the =herdr-subagents= skill and make them the lowest-precedence discovery source. Express packaged persona model choices through harness-agnostic weight aliases so projects and users retain deterministic definition and model-routing overrides without copying the defaults.

* Summary
*Level:* production · *Tests:* thorough · *Docs:* full

Persona discovery resolves Markdown definitions from project, home, and installed skill directories in descending precedence. Packaged definitions select =heavy=, =middle=, or =light=; the independently merged =roster.edn= chain translates those aliases for the already-resolved Pi, Claude, or Codex kind, with =feather= available as the unassigned fourth tier.

** Decisions
- Chose one ordered persona-path resolver shared by direct lookup, spawn-capability validation, and available-persona discovery :: a single source of precedence prevents direct spawn and nested =spawns:= validation from disagreeing.
  Rejected:
  - Copy defaults into =~/.agents/subagents= during installation: mutates user state and turns packaged updates into stale user overrides.
  - Search every discovered skill directory: broadens the namespace and makes duplicate ownership ambiguous; this CLI owns one packaged default directory beside its launcher.
- Derive the packaged definition directory from the resolved launcher path, matching =default-roster-path= :: preserves symlinked and bare-subtree deployment behavior without coupling defaults to the caller's repository layout.
  Rejected:
  - Derive defaults from =ledger/assignment-root=: fails when the CLI is installed globally and invoked from an unrelated project.
  - Hard-code =skills/herdr-subagents/subagents=: fails for relocated and bare-subtree installations.
- Add weight aliases as roster data rather than code branches :: keeps aliases overrideable and routes them through the existing kind-independent =resolve-model= → =model-args= flow.
  Rejected:
  - Interpret weight names in Clojure: duplicates data policy in code and bypasses roster overrides.
  - Encode per-harness values in persona frontmatter: couples packaged personas to harness dialects.
- Preserve the existing persona tier assignments while renaming selectors: =claude-fable= → =heavy=, =claude-opus= → =middle=, and =claude-sonnet= → =light=. =feather= ships as an available tier without assigning an existing packaged persona to it.
- Use the requested Claude =haiku= spelling for =feather= despite the previous table's conservative full-name spelling :: this record specifies emitted arguments, not a billable live compatibility claim.
- Keep existing canonical/versioned model rows alongside the four weight rows :: local callers and explicit =--model= requests remain compatible while packaged personas become provider-neutral.
- Keep =roster.edn= configuration loading separate from Markdown definition discovery :: both share directory names and precedence, but roster rows replace by ID while persona definitions shadow atomically by name.
- Remove the owner Home Manager projection of packaged definitions at =~/.agents/subagents= instead of repointing it :: packaged fallback makes the projection redundant and leaves the home path available for genuine overrides.
- Treat the task's =~/.agents/.subagents= spelling as a typo and retain the established =~/.agents/subagents= override path :: the task description, source, tests, and skill contract otherwise consistently use the latter.
