* Summary
Reverse the compact short-id work shipped in
[[plan:2026-05-19-ot-short-ids-and-bling.org][2026-05-19 ot short-ids and bling]]. The =prefix…suffix= input/output
path adds complexity (3-branch resolver, O(n²) edge-expansion loop,
=:shortIds= wire field, =ambiguous-id= disambiguation for short forms)
without meaningful human benefit: every =:CUSTOM_ID:= is a UUIDv4
generated by =ot uuid= / =ot create=, every lookup is owned by =ot=
itself or pi tooling. The remaining interactive affordance — unique
≥ 4-char prefix matching — survives untouched and continues to satisfy
copy-paste-from-=ot list= workflows.

** Decisions
- Drop compact-form input + display :: Remove =compact-id=,
  =build-short-ids=, =compact-form-input=, =compact-match?=, the
  =ellipsis= / =ascii-ellipsis= constants, the =max-edge-length=
  ceiling, and the compact branch of =resolve-id-candidate=. Supersedes
  the "Compact short-id shape" and "Short-id everywhere or nowhere"
  decisions in 2026-05-19.
- Keep prefix matching :: ≥ 4-char unique-prefix resolution stays. It
  costs one regex-free =filter= per resolution and is the only
  ergonomic affordance interactive callers actually need.
  =ambiguous-id= remains a valid error code (prefix collisions still
  apply).
- New =ot list= id column :: Display the first 8 characters of the
  =:CUSTOM_ID:= (e.g. =a6dbdacb=) — no ellipsis, no graph-wide
  collision loop. The displayed prefix is directly pasteable into
  =ot show <prefix>= because it satisfies the ≥ 4-char minimum. If two
  tasks in the loaded graph collide on the first 8 chars, the user
  gets =ambiguous-id= when they try to act on one; =ot doctor='s
  existing =:patterned-sibling-ids= warning already covers prevention.
- Wire envelope is narrowed, not versioned :: Remove =:shortIds= from
  =ot list= and =:shortId= from =ot show=. No external consumer exists
  (pi extensions, dashboards, and =tasks_*= tools all use full UUIDs).
  Audited before removal in plan task 2.
- Doctor checks stay :: =:non-uuid-v4-id= and =:patterned-sibling-ids=
  remain useful because prefix collisions still degrade UX. No change
  to =doctor.clj=.
- Pi extension untouched :: =ot.ts= already passes full UUIDs end to
  end. No code change required.

** Follow-ups
- =bb-cli= argument coercion of bare hex-with-=e= prefixes to floats is
  not specific to this change; if it becomes recurring friction, file a
  task to wrap =cli/dispatch= with a string-coercing reader for
  id-shaped arguments.

** Gotchas
- =bb-cli= coerces bare hexadecimal-with-=e= tokens like =29064e76= into
  floating-point numbers in scientific notation before they reach
  command handlers, surfacing as =unknown-task: No task with :CUSTOM_ID:
  2.9064E80=. Mitigation: pass at least one non-numeric character
  alongside the prefix (e.g. =29064e76-018e=) or use the full UUID.
  Affects only interactive CLI usage; pi tooling passes full UUIDs.
