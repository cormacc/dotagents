* Summary
Replaced =:ID:= with =:CUSTOM_ID:= and =#+PARENT_ID:= with a navigable =#+PARENT: [[file:...::#<uuid>][summary]]= link across the org-memory protocol so plan→task navigation is a clickable org link grounded in org's =::#anchor= resolution rules (which resolve only against =:CUSTOM_ID:=, not =:ID:=). One-shot migration across =~/dotfiles/agents-src=, =~/dotfiles=, and =~/nmd/products/connect/portal= with no legacy tolerance window.

** Decisions
- =:CUSTOM_ID:= replaces =:ID:= outright :: no dual-slot, no drift surface. The protocol's task graph maintains its own UUID index; org-id machinery is not a dependency.
- =#+PARENT:= carries an org link :: =[[file:<rel>/TASKS.org::#<uuid>][<summary>]]=. Relative prefix computed from =#+DEFAULT_PLAN_DIR= at scaffold time (default =design/log/= → =../../TASKS.org=). Link descriptions escaped/sanitised or omitted when unsafe.
- No legacy tolerance window :: three projects on one machine swept atomically; tolerant reader stays cheap to add later if a fourth project surfaces.
- Subtasks (level-3) also use =:CUSTOM_ID:= :: =#+PARENT:= is a plan-file keyword only; subtasks under a parent task don't need it.
- =TASKS.archive.org= included in migration :: archived UUIDs keep resolving.
- Plan files don't grow extra =:CUSTOM_ID:= entries beyond their existing task headings.

** Shipped
- Schema migration landed in =agents-src= commit =0981538= (parser/writer/scaffolder/archive behaviour, docs, fixtures, local content sweep).
- Companion content sweeps landed in =~/dotfiles= commit =b899243= and =~/nmd/products/connect/portal= commit =77d824d5=.
- Archiving rewrites a plan's =#+PARENT:= link target from =TASKS.org= to =TASKS.archive.org= when the parent task is archived.
- Jira extension user-facing strings updated to refer to =:CUSTOM_ID:=.
- One-shot migration script at =.agents/tmp/migrate-id-to-custom-id.ts= (supports =--dry-run=, refuses on unresolved =#+PARENT_ID:=).

** Gotchas
- =#+PARENT:= summary text goes stale if the parent task is later renamed; the UUID anchor still resolves so navigation works, only the human label drifts. A future doctor pass could refresh descriptions.
- Dropping =:ID:= means these headings are no longer targets for =[[id:UUID]]= links from outside the project. Not currently relied upon.
