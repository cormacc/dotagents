* Intent

Make an `oh` child that works in a managed checkout visible and safe in the Herdr surfaces: its worktree state shows on its sidebar row in the Herdr TUI and in herdr-app, and nothing but `oh` can remove its checkout through Git. `oh` keeps ownership of its checkouts and its ledger.

* Summary

*Level:* production · *Tests:* thorough · *Docs:* full

`oh` Git-locks every managed checkout it creates, so `git worktree remove` (and so Herdr's and herdr-app's remove actions) refuses it; `oh worktree remove` unlocks under its existing guards. `oh worktree list --all` is a read-only listing for callers with no parent session; it returns each worktree round with its reconciliation and a compact display string, and names unledgered checkouts. The herdr-orch plugin and the orch-spaces mod show the display string on agent rows. orch-spaces nests worktree spaces correctly in a submodule repository. Worktree children keep tab and split placement.

** Scope

*** In scope

- Git lock on managed checkouts at creation; unlock in `oh worktree remove` and in launch-failure cleanup; stale-registration recovery.
- `oh worktree list --all`: entries with reconciliation, join keys and display string; unledgered checkouts.
- A `$worktree` token on Herdr TUI agent rows, reported by the herdr-orch plugin.
- The display string on orch-spaces agent rows; the submodule fix to its linked-checkout test.
- Two upstream report drafts; the `hc` new-space test.
- Contract documents: the `#+SPEC:` files above, CLI help, and `herdr/config.toml`.

- Merge, rebase, push or branch deletion by `oh` (task e88e718e evaluates guarded integration).
- Removing split placement (task a21f1073).

- Any UI action that removes or unlocks a checkout.
- Changes to bundled herdr-app mods or to Herdr; filing the upstream reports.
- Remote (`--machine`) servers beyond what each surface supports today.

** Decisions

- No workspace placement :: worktree children keep tab and split placement, as the "third placement mode" exclusion of [[proj:design/log/2026-08-13-herdr-orch-worktree-backed-fan-out.org]] decided. An opt-in Herdr TUI `--workspace` (create-then-open) was built and verified, then reverted after a complexity review: it only grouped the child's space in Herdr's views, which the sidebar tree and the worktree token already cover, and it added three placement refusals, an `hc` asymmetry and a `workspace close --group` risk.
  Rejected:
  - Opt-in `--workspace` in the TUI runtime: about 180 lines of code, tests and docs for display only.
  - Workspace placement under `hc`: the space nests, but the child's agent row stays under its parent's space, and herdr-app's `Remove worktree` would end the child ([[file:2026-11-11-herdr-orch-worktree-integration/hc-new-space.md]]).
  - Workspace as the default for worktree children: a fan-out of N workers would make N spaces, and both sidebar trees nest a child under its parent.
- Lock every managed checkout :: Git refuses `worktree remove` and `remove --force` on a locked entry, so Herdr, herdr-app and a manual command cannot remove a checkout under a running child. Measured against Herdr 0.9.5: [[file:2026-11-11-herdr-orch-worktree-integration/placement-spike.md]].
  Rejected:
  - Detect after the fact (a drift report, or a plugin hook on `worktree.removed` that marks the ledger): the work is already lost, and the plugin writes no ledger.
  - Lock only checkouts that a UI shows as worktrees: `Open worktree...` can expose a tab-placed checkout too, and two cases are harder to document than one.
- One `oh` listing feeds both sidebars :: the plugin and the mod run `oh worktree list --all --format json`; reconciliation and the display string have one implementation.
  Rejected:
  - A shared namespace called in-process by the plugin: a refactor of `cli.clj` to save about 0.13 s of start time, and two call paths.
  - Each sidebar reads the ledger and runs Git: reconciliation rules written three times in two languages.
- The row shows counts, not the branch :: an `orch/*` branch has no upstream, so Git ahead/behind is empty; the branch name is always `orch/<task prefix>`. Counts are path counts against the recorded `:base`.
- The drift report is the `:unledgered` list only, with no flag :: reconciliation already reports a vanished checkout as `missing`. Its `git worktree list` took at most 0.01 s against about 0.3 s for the whole `oh worktree list --all`.

** Gotchas

- herdr-app does not reload a mod when its source changes. A live check in an app started before the mod change tests the old code: the first `hc` new-space run reported "no nesting" for that reason. Run `touch -h ~/.config/herdr-app/mods/<mod>` before a live check.
- In a submodule, the main checkout's common Git directory is `<super>/.git/modules/<name>`, not `<top>/.git`. Compare `git rev-parse --absolute-git-dir` with the common directory to tell a linked worktree from the main checkout.
- orch-spaces draws a nested worktree space after the main space's agent and tab rows, so it can look like a child of the last tab row.

** Risks

- herdr-app's bundled `Remove worktree` closes the space before it runs Git. With the lock the checkout survives, but a child that a user runs in that space ends; the herdr-app upstream draft names it.
- Row state changes when a plugin hook or a mod refresh fires, not while a child edits. Counts are current at the end of a turn.
- Reconcile cost grows with the number of present checkouts: one `oh` start and one Git status and diff for each. Revisit if the sidebar lags.
- `rm -rf` and a cleared `.tmp/` bypass the lock, and leave a locked registration until `oh worktree remove` or a manual unlock.
- The plugin and the mod run the home skill's `oh`. An older home skill does not know `--all`; the sidebars then show no worktree state.
- `oh worktree list --all` run inside a managed checkout resolves that checkout as the assignment root and returns no entries. The plugin merges the listings of every Git root in the session, so a child gets its token only while an agent in the main checkout is listed in the same session.

* Implementation

- `worktree list --all` binds `*read-only-git?*`, which runs Git with `GIT_OPTIONAL_LOCKS=0`, so that a listing does not refresh the index as a side effect of a status query.
- The lock reason is the fixed string `Managed by oh; use oh worktree remove`. `oh` unlocks only a lock with that reason, and locks the checkout again when `git worktree remove` fails after the unlock.
- The plugin resolves `oh` as `plugin_oh` in `herdr/plugins/herdr-orch/lib.sh` does: the home skill first, then this checkout. The mod uses the home skill only.
