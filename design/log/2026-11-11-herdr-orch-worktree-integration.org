* Intent

Make an `oh` child that works in a managed checkout visible and safe in the Herdr surfaces: its worktree state shows on its sidebar row in the Herdr TUI and in herdr-app, it can run in its own Herdr worktree workspace, and nothing but `oh` can remove its checkout through Git. `oh` keeps ownership of its checkouts and its ledger.

* Summary

*Level:* production · *Tests:* thorough · *Docs:* full

Planned state. `oh` Git-locks every managed checkout it creates, so `git worktree remove` (and so Herdr's and herdr-app's remove actions) refuses it; `oh worktree remove` unlocks under its existing guards. `oh worktree list --all` is a read-only listing for callers with no parent session; it returns each worktree round with its reconciliation and a compact display string, and names unledgered checkouts. `oh task run|start --workspace` places a non-shared worktree child in its own Herdr workspace, grouped with the caller's repository. The herdr-orch plugin and the orch-spaces mod show the display string on agent rows. orch-spaces nests worktree spaces correctly in a submodule repository.

** Scope

*** In scope

- Git lock on managed checkouts at creation; unlock in `oh worktree remove` and in launch-failure cleanup; stale-registration recovery.
- `oh worktree list --all`: entries with reconciliation, join keys and display string; unledgered checkouts.
- `--workspace` placement for the Herdr TUI runtime; a refusal under the `hc` runtime until the `hc` test decides otherwise.
- A `$worktree` token on Herdr TUI agent rows, reported by the herdr-orch plugin.
- The display string on orch-spaces agent rows; the submodule fix to its linked-checkout test.
- Two upstream report drafts; the `hc` new-space test.
- Contract documents: the `#+SPEC:` files above, CLI help, and `herdr/config.toml`.

*** Out of scope

- Merge, rebase, push or branch deletion by `oh` (task e88e718e evaluates guarded integration).
- Removing split placement (task a21f1073).
- A configuration key for workspace placement; a change to the default placement.
- Any UI action that removes or unlocks a checkout.
- Changes to bundled herdr-app mods or to Herdr; filing the upstream reports.
- Remote (`--machine`) servers beyond what each surface supports today.

** Decisions

- Workspace placement is opt-in and built as create-then-open :: `herdr workspace create --cwd <checkout> --label <oh label> --env ...`, then `herdr worktree open --workspace <caller workspace> --path <checkout>`, which adopts that workspace and groups it. This reverses the "third placement mode" exclusion of [[proj:design/log/2026-08-13-herdr-orch-worktree-backed-fan-out.org]]: a tab whose cwd is a checkout never counts as an open worktree in Herdr, so only a workspace reaches Herdr's worktree views.
  Rejected:
  - `worktree open` alone: it has no `--env`, and the child needs its protocol variables at pane creation.
  - `herdr worktree create`: Herdr would choose the path and branch, outside the managed root and the ledger identity.
  - Workspace as the default for worktree children: a fan-out of N workers would make N spaces, and both sidebar trees nest a child under its parent.
- Lock every managed checkout :: Git refuses `worktree remove` and `remove --force` on a locked entry, so Herdr, herdr-app and a manual command cannot remove a checkout under a running child. Measured against Herdr 0.9.5: [[file:2026-11-11-herdr-orch-worktree-integration/placement-spike.md]].
  Rejected:
  - Detect after the fact (a drift report, or a plugin hook on `worktree.removed` that marks the ledger): the work is already lost, and the plugin writes no ledger.
  - Lock only workspace-placed checkouts: `Open worktree...` can expose a tab-placed checkout too, and two cases are harder to document than one.
- One `oh` listing feeds both sidebars :: the plugin and the mod run `oh worktree list --all --format json`; reconciliation and the display string have one implementation.
  Rejected:
  - A shared namespace called in-process by the plugin: a refactor of `cli.clj` to save about 0.13 s of start time, and two call paths.
  - Each sidebar reads the ledger and runs Git: reconciliation rules written three times in two languages.
- The row shows counts, not the branch :: an `orch/*` branch has no upstream, so Git ahead/behind is empty; the branch name is always `orch/<task prefix>`. Counts are path counts against the recorded `:base`.
- A workspace-placed child is a root of its own space in the TUI tree :: `herdr-orch.tree/rows` joins parent and child only within one workspace. No new rule.
- The `hc` runtime is gated :: whether `hc run` can start a terminal in a new space rooted at a checkout is unverified and needs the user's app. Until tested, `--workspace` refuses there.
- The drift report is the `:unledgered` list only :: reconciliation already reports a vanished checkout as `missing`.

** Risks

- herdr-app's bundled `Remove worktree` closes the space before it runs Git. With the lock the checkout survives, but a running child in that space does not. Relevant only once `hc` workspace placement exists; the herdr-app upstream draft names it.
- `workspace close --group` on the parent workspace ends workspace-placed children. Herdr refuses the close without explicit group intent; checkouts, branches and published checkpoints survive.
- Row state changes when a plugin hook or a mod refresh fires, not while a child edits. Counts are current at the end of a turn.
- Reconcile cost grows with the number of present checkouts: one `oh` start and one Git status and diff for each. Revisit if the sidebar lags.
- `rm -rf` and a cleared `.tmp/` bypass the lock, and leave a locked registration until `oh worktree remove` or a manual unlock.
- The mark `⑂` (U+2442) can be absent from a font. It is one constant; each sidebar task checks the rendering and may replace it with an ASCII mark.
- The plugin and the mod run the home skill's `oh`. An older home skill does not know `--all`; the sidebars then show no worktree state.
- `oh worktree list --all` run inside a managed checkout resolves that checkout as the assignment root and returns no entries. The plugin merges the listings of every Git root in the session, so a child gets its token only while an agent in the main checkout is listed in the same session.
