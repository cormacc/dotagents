#+TITLE: General-purpose agent skills

These top-level skills are symlinked into =~/.agents/skills/= by the editable Home Manager route, or installed by an Agent Skills-compatible loader. They are harness-agnostic unless their own compatibility field says otherwise. Pi-only skills that require pi extensions live under [[file:../pi/skills/][../pi/skills/]].

The =org-tasks=, =org-plan=, and =org-jira= skills are also the generic-skill slice shipped by the =@cormacc/agent-org-memory= pi package alongside the =tasks=, =jira=, and =emacsclient= extensions. See [[file:../README.md][../README.md]] for exact package boundaries and install routes.

This inventory is mechanically checked by =npm run check:metadata=: every top-level =skills/*/SKILL.md= frontmatter name must appear exactly once below, and every listed file must exist.

** Vendored
Maintained upstream and re-synced rather than edited here. Do *not* apply local repository conventions to these bodies — no prose reflowing, style normalisation, or wording edits, because every local change is lost on the next sync and inflates the diff against upstream. Fix a problem upstream, or record it as a local task naming a non-vendored destination. The intended mechanism is =npx skills add= / =npx skills update=, which records each skill's source and content hash in =skills-lock.json=. Drift is then tracked by that content hash rather than by upstream commit: a source revision churns on every unrelated commit to the source repo while saying nothing about whether the skill itself moved. That migration is still outstanding — all four are currently hand-copied, and =Source= below is blank wherever provenance was not captured at adoption. Tracked as "Skill vendoring improvements" (=98cf369c=) in [[file:../TASKS.org][TASKS.org]], together with dropping vendored skills from the set this repo republishes.

=herdr= is a permanent exception to that mechanism, not merely un-migrated: upstream ships its =SKILL.md= at the repository root rather than under a =skills/= subdirectory, so =npx skills add ogulcancelik/herdr= resolves the skill to the whole repository and installs the entire Rust project (=Cargo.toml=, =flake.nix=, =src/=, =docs/=, =assets/=) into the skills directory. It is therefore hand-copied as a single file and carries an in-file vendor header recording its source, upstream commit, and re-sync command — the one place a commit is recorded here, because there is no lockfile entry to hold a content hash instead. Retire the exception if upstream repackages the skill under a subdirectory.
