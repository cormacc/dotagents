# Context modes

Read the relevant section before its launch or continuation action. The [mechanical contract](../scripts/docs/contract.md#context-modes) owns adapter mechanics.

## Launch modes

`--context fresh` is the default. A request to "spawn a subagent" means fresh context. A request to "fork a subagent" means `--context fork`: the child inherits your completed earlier turns, not the current turn that delegates (Pi callers and Pi children only; it never silently becomes a fresh child). Nothing after your last completed response is inherited, including `!` command output since then. Put the request and any findings from the current turn that the child needs in the assignment. A fork from your first turn refuses; use fresh context there. A persona named with `--context fork` replaces the role the fork would inherit. Name a roster persona for a role (`task run scout ...`), or omit the persona for a persona-less fresh child that receives the assignment, any explicit `--trait` selections, and the normal launcher guidance but no synthetic role. Absence of a persona is not authority: a persona-less child is a leaf unless the root grants `--spawns`, and below root only a named allow-listed persona may be launched. `--context measurement --measurement-config PATH` runs a Pi subject headless under a detached supervisor with only the configured treatment, tools and the literal assignment: no persona, `--trait`, `--prompt-extra`, `--retro`, `--no-retro` or `--spawns`, and no pane unless `--tab` or `--split` asks for a read-only monitor. The supervisor publishes the result, so `collect`, `collect --any` and `close` work as usual; `continue` and `poke` refuse, and execution success is not an answer-quality score. Detachment is Linux-only. Its request audit covers exactly four Pi APIs (`anthropic-messages`, `openai-completions`, `openai-responses`, `openai-codex-responses`) and any other API fails closed; fresh delegation and forks are unaffected. See [scripts/docs/contract.md#Measurement launch](../scripts/docs/contract.md#measurement-launch).

## Continuation

Continue when the follow-up depends on the child's existing context. Respawn for unrelated work, a different persona, or independent Class C validation. Before you continue a child, read its context use; above about 70%, close it and start a fresh worker with a handoff assignment instead. A `pi` child that has pi-context can compact only back to its current round's checkpoint, because an earlier target would remove the new assignment ([scripts/docs/contract.md#History compaction guidance](../scripts/docs/contract.md#history-compaction-guidance)). So when you expect to continue such a child, tell it in the assignment to compact to its round checkpoint before it publishes; the next round then starts from a smaller context. The 70% rule still applies when you continue. The CLI owns continuation preconditions and refuses unsafe reuse. See the [scripts/docs/contract.md#Continue](../scripts/docs/contract.md#continue).
