* Why this skill exists

Herdr supplies panes, tabs, and agent lifecycle operations, but not a delegation protocol: persona selection, naming, parent/child identity, durable completion, or safe pane disposal. Those mistakes are costly. A parent can mistake transcript text for completion or destroy work by closing a pane before capturing its result.

The skill therefore separates policy from mechanics. [[file:SKILL.md][SKILL.md]] carries the small runtime policy an agent needs, while the Babashka CLI makes identity, publication, validation, and ownership checks repeatable. The upstream [[https://github.com/ogulcancelik/herdr/blob/master/SKILL.md][Herdr skill]] remains the authority for direct pane and agent operations; this repository vendors a copy at [[file:../herdr/SKILL.md][skills/herdr/SKILL.md]], but the CLI path needs only the =herdr= binary and =HERDR_ENV=1=, so standalone installs of this skill work without it.

* Design rationale

** Harness-neutral roster and CLI

The packaged roster under [[file:subagents/][subagents/]] uses Markdown plus =name=/=description=/=kind=/=model= frontmatter. Persona definitions resolve project override (=<git-root>/.agents/subagents/=), then home override (=~/.agents/subagents/=), then this packaged directory; definitions shadow atomically by name. The resolved =kind= selects the child harness, so a parent is not restricted to its own harness. Keeping orchestration in a pi extension would have broken that property.

The separate =config.edn= chain has the same default ← home ← project order but a different merge rule: a home or project row replaces the full row with that model ID, including =heavy=, =middle=, =light=, or =feather=; it does not deep-merge or select a kind. Those aliases map only after kind selection: =heavy= → Pi =anthropic/claude-fable-5=, Claude =fable=, Codex =gpt-5.6-sol=; =middle= → Pi =anthropic/claude-opus-5=, Claude =opus=, Codex =gpt-5.6-sol=; =light= → Pi =anthropic/claude-sonnet-5=, Claude =sonnet=, Codex =gpt-5.6-terra=; =feather= → Pi =anthropic/claude-haiku-4-5=, Claude =haiku=, Codex =gpt-5.6-luna=.

The [[file:../../design/log/2026-07-24-herdr-subagent-skill-scripts.org][2026-07-24 change-record]] records the implementation choice: Babashka behind a thin launcher was preferred to a harness-specific extension or pure Bash. It provides vector argv, JSON handling, testable protocol logic, and atomic filesystem operations without adding Maven dependencies. Folding delegation into =ot= was rejected because task memory and terminal delegation are separate domains.

** Why mechanics belong in a CLI

The earlier prose-only protocol required the parent to perform label calculation, geometry selection, split/start/prompt operations, bounded waiting, envelope parsing, artifact checks, and pane closure by hand. Besides repeated model round-trips, partial compliance failed silently: identities could be mistyped, visible summaries substituted for result files, and panes closed before capture.

The CLI absorbs those operations behind one spawn/collect interface and returns the validated envelope inline. Capability probes add subprocess work before mutation, but convert unsupported-Herdr states into an actionable error before a pane or ledger assignment is partially created. Exact invocation counts are intentionally not frozen here because lifecycle hooks change; use the fake-Herdr log when evaluating current overhead.

** Optional process retrospectives

The [[file:../../design/log/2026-07-27-subagent-retrospectives.org][2026-07-27 change-record]] added child-side process learning without giving children persistence authority. A gated child scans context it already holds and can attach compact =signal → category → proposed rule= candidates to the durable result. The parent still verifies, deduplicates, routes, and seeks approval, so self-retro remains testimony rather than an automated write path.

=PROCESS:= was added as an optional trailing v1 annotation instead of a separate retro artifact or envelope v2. The position preserves existing v1 readers, omission preserves old output when there are no candidates, and the ledger already persists validated envelopes. =:child-session= complements this with a best-effort transcript reference for thin candidates or crash investigation. The exact grammar and degradation rules live only in [[file:scripts/docs/contract.md][contract.md]].

The =retro= skill is optional by design. Project/global skill resolution lets integrated installations enable it by default, while third-party installations without it continue delegating with no injected instruction. Only explicit =--retro= fails when the capability is absent because an operator request must not silently become a no-op. The live smoke follows the same rule and reports a skipped retro leg when the skill is unavailable.

** Per-persona spawn capability

The [[file:../../design/log/2026-07-27-subagent-per-persona-spawn-capability-re.org][2026-07-27 spawn-capability change-record]] replaced the prose-only planner exception with declared roster capability: a frontmatter =spawns:= allow-list resolved once at spawn (flag > frontmatter > default deny), recorded on the ledger as =:spawns=/=:spawns-source=, injected as =HERDR_ORCH_SPAWNS=, and enforced mechanically by the child CLI before preflight, ledger allocation, or pane mutation. Prompt-only enforcement was rejected because its failure modes are billable and pane-creating; child self-resolution from the roster was rejected because it cannot carry a per-spawn flag override and mid-flight roster edits would change a live child's capability. Any below-root spawn injects an empty grandchild policy with source =depth= — one nesting level absolutely, no depth counter — so labels stay display-only metadata. Below-root one-at-a-time cardinality deliberately remains prompt-strength doctrine.

* Review and maintenance notes

** Known regression boundaries

The regression suite names the important boundaries; preserve the tests rather than duplicating their mechanics here:

- =bounded-poll-timeout-without-result= must fail if the wait-loop sleep is removed.
- =launcher-matrix-selects-branch-and-preserves-cwd= must fail if launcher path canonicalisation or caller cwd preservation regresses.
- result capture must precede ownership-scoped pane closure, and foreign/unresolvable parent identity must retain the pane.
- retro tests must remain behavioural at prompt/CLI boundaries: frontmatter values are strings, value-less flags participate in two argv consumers, and optional annotations must not demote a valid result.
- live-smoke helper assertions are unit-tested because the billable smoke is never part of the standard suite.

All =herdr= calls in =src/= must remain vector argv. Keep the standalone launcher dependency-free beyond Babashka built-ins. When Herdr changes, review =required-capabilities= and the fake fixture's help output together.

** Test isolation caveat

=ORCH_ASSIGNMENT_ROOT= relocates project config lookup and all assignment state into each fixture. The CLI tests symlink both the tracked config and project =skills/= tree into that root. They also set =$HOME=, but Babashka's =System/getProperty("user.home")= comes from the JVM/OS property rather than the subprocess environment, so =$HOME= alone cannot hide the global config or skill probes. Tests of the no-global-skill branch therefore belong at the pure =core= policy boundary unless the process property itself is controlled.

A full =bb test= should create no entries under the repository's live =.agents/tmp/herdr-orch/= tree. When mutation-testing assignment-root or launcher behavior, set an override and inspect that tree afterwards.

** Reflexive changes

A child editing =scripts/= is modifying the same launcher used by its own =publish= and the parent's =collect=. Before delegating such work, copy a known-good scripts tree outside this repository and give the child its launcher as a fallback. Put the snapshot where the launcher's repository-root walk cannot rediscover this checkout's =bb.edn=; otherwise the supposed snapshot loads working-tree source.

Publication identity comes from injected =HERDR_ORCH_*= variables rather than the ledger, so an isolated snapshot can publish the assigned result. Verify the fallback before relying on it.

** Deployment and live smoke

=agents.nix= deploys =~/.agents/skills= as a directory symlink, which includes this skill's packaged =subagents/= directory. Launcher canonicalisation must therefore use physical paths when locating the repository configuration while retaining the absolute deployed launcher path injected into the child. Do not project packaged definitions into =~/.agents/subagents/=: that path is deliberately unmanaged and reserved for genuine home overrides; project overrides remain =<git-root>/.agents/subagents/=.

=bb smoke-subagent= is billable and guarded by =HERDR_ENV=1=, =ORCH_LIVE_SMOKE=1=, and =ORCH_LIVE_SMOKE_MODEL=. It calls =cli/execute= in-process and therefore cannot validate the Bash launcher. Launcher changes need a separate deployed-path smoke from a scratch project. The retrospective leg deliberately lets the child encounter an unannounced invalid command: announcing the trap turns it into a known one-off that the =retro= eligibility gate correctly rejects.

* Known gaps

- The CLI implements one child per invocation for =run=/=start=; multi-child fan-out scheduling (how many in flight, when to replace one) and resident lifecycle remain parent policy in [[file:SKILL.md][SKILL.md]] — no command spawns or schedules more than one child. Fan-in, however, now has a dedicated primitive: =collect --any= (see [[file:scripts/docs/contract.md][contract.md]] § Fan-in) captures whichever in-flight child of the caller's session publishes first, without scheduling anything itself.
- =HERDR_ORCH_BIN= intentionally carries the deployed absolute path rather than a canonical repository path; launcher-matrix coverage is its guard.
- =ot ready= cannot resolve blockers inside =#+IMPORT:=-linked plan files, so plan-internal dependencies report =[opaque]=. This is an org-tasks limitation, not a delegation issue.
