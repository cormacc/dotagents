* What is this?

A harness-agnostic orchestration framework for agent-assisted development. You define subagent personas and their interactions once, independently of the coding harness, so you can compare or change harnesses and keep your workflow. The bundled =oh= CLI does the mechanical work of delegation, which keeps token and tool-call overhead low.

- Define subagents per project (=<git-root>/.agents/subagents/=) or per user (=~/.agents/subagents/=).
- Define reusable prompt fragments (traits) per project (=<git-root>/.agents/traits/=) or per user (=~/.agents/traits/=).
- Use a trait in a subagent definition, or as =%my-trait= in an interactive prompt (pi only).
- Run parallel workers in separate git worktrees. The scripts create and reconcile the worktrees.

My own use is mostly human-in-the-loop and low fan-out: subagents manage context and token cost, not swarm development. That is preference, not prescription. Other orchestration models need only different persona definitions.

Developed against =pi=, and verified against Claude Code and Codex. Other harnesses are configurable ([[*Harness configuration]]). The scripts use Babashka (Clojure). =oh= has one delegation contract over two runtimes: Herdr TUI and local herdr-app / herdr-core (=hc=). Runtime facts are in [[file:scripts/docs/contract.md]] section 'Preconditions'.

* Subagent lifecycle

The parent owns both ends of a round: it chooses where the child works, and it owns everything the child produces.

- Target :: Before the child exists, the parent resolves one checkout: its own, an attached checkout in the same repository (=--worktree <path>=), or a new managed checkout (=--worktree new=). Without the flag, a read-only child or the first write-enabled child shares the caller's checkout, and each additional concurrent write-enabled child gets a managed one. A managed checkout starts from the source =HEAD= on branch =orch/<task-prefix>=, before any pane exists.
- Spawn :: =oh task run= blocks for the result. =oh task start= returns at once. The child's cwd is the resolved checkout. The persona does not describe the topology, and the child has no commit permission. The persona is optional: a persona-less child gets the assignment, any explicit =--trait= selections and the launcher guidance, but no role and no authority. =--context fresh= is the default ("spawn a subagent"); =--context fork= ("fork a subagent") starts a Pi child that inherits the completed earlier turns of the caller's own Pi session, not the current turn that delegates; the assignment carries any same-turn findings. On the TUI runtime only, =--context measurement= runs a headless Pi sample under a detached supervisor that publishes its result; it opens no pane unless =--tab= or =--split= asks for a read-only monitor.
- Publish :: =oh task publish= appends immutable items to the round's stream, including interim reports and monitor observations. A terminal status (=COMPLETE=, =BLOCKED=, =FAILED=) seals the round. In a non-shared checkout, publication commits pending non-ignored changes and records the tip as =CHECKPOINT=, so recovery does not depend on the child committing. In the shared checkout, publication does not touch Git. Publication from a read-only child with uncommitted changes is refused.
- Collect and reconcile :: =oh task collect= captures published items. =collect --any= takes the first in-flight child to publish. For a child with its own checkout, =collect=, =status=, and =oh worktree list= also report base, branch, tip, and checkout state, with committed, dirty, and ignored paths as separate sets.
- Close, continue, or tear down :: Capture never closes a pane. =oh task close= closes a settled child's pane. =oh task continue= gives the same child another round in the same checkout. =oh worktree remove= deletes only a managed checkout that is owned, unreferenced, and clean. A failed launch removes the pristine managed checkout that it created. The branch always stays.

The parent integrates. =oh= never merges, rebases, pushes, deletes a branch, or commits in the shared checkout. Isolation keeps concurrent writers out of each other's index, but does not prove that their edits compose, so remeasure the combined tree. =orch/*= branches stay until the parent integrates or deletes them.

[[file:references/workflow-recipes.md][references/workflow-recipes.md]] shows root-owned staging, independent validation, repeated headless measurements, evidence retention and the gated live context smoke.

[[file:scripts/docs/contract.md]] section 'Worktree reconciliation and teardown' gives the reconciliation shape, the removal guards, and recovery after =.tmp/= is cleared before a child publishes. Section 'Close' gives the close guards.

* How do I use it?

** Requirements

- [[https://babashka.org][Babashka]] on =PATH=.
- Herdr TUI with =HERDR_ENV=1= and Herdr 0.9.1 or newer on both client and running server, or local herdr-app with =HC_TERMINAL_ID=. The nearest host in process ancestry selects the runtime; mismatched addressing variables are refused. Variable presence alone does not select it. hc measurement and remote machines are out of scope.
- Pi 1.5.0 or newer, for a Pi parent or child. The repository SDK is pinned to 1.5.0; installed-runtime adapter tests verify provider request encoding separately.
- For subscription reporting, sign in through the harness whose credentials will be used: Pi by default for =oh usage=, or the destination harness for routing. The owned Babashka collector needs no npm package or setup step. See [[file:scripts/docs/contract.md]] section 'Usage' for supported stores and explicit native reporting.
- Optional: the =org-plan= and =org-tasks= skills in this repository.

The selected runtime is the authority for direct pane and agent operations. The [[https://github.com/ogulcancelik/herdr/blob/master/skills/herdr/SKILL.md][upstream Herdr skill]] is vendored at [[file:../herdr/SKILL.md][skills/herdr/SKILL.md]] for convenience. =oh= does not need it, so a standalone install works.

** Configuration file locations and fallback strategy

Three chains resolve project > home > packaged:

| What                                                | Locations, highest precedence first                                                |
|-----------------------------------------------------+------------------------------------------------------------------------------------|
| Persona definitions (=<name>.md=)                   | =<git-root>/.agents/subagents/=, =~/.agents/subagents/=, this skill's =subagents/= |
| Trait fragments (=<name>.md= or =<name>/prompt.md=) | =<git-root>/.agents/traits/=, =~/.agents/traits/=, this skill's =traits/=          |
| Model and harness config (=config.edn=)             | =<git-root>/.agents/subagents/=, =~/.agents/subagents/=, this skill's =subagents/= |

- A persona shadows by name: the highest-precedence file wins.
- A trait also shadows by name. In one layer, =<name>.md= wins over =<name>/prompt.md=.
- =config.edn= files merge ([[*Model configuration]]).

A missing override file is ignored. A missing packaged =config.edn= is fatal. =~/.agents/subagents/= holds only real home overrides: packaged definitions are never copied into it.

Assignment state (ledger, result files) lives under =<assignment-root>/.tmp/herdr-orch/=, never =.agents/= ([[file:design.org::*Where assignment state lives]]).

** Defining subagents

A persona is a Markdown file with frontmatter. The body is the persona's instructions.

#+begin_src markdown
---
name: scout
description: Fast codebase reconnaissance - maps existing code and conventions
model: light
effort: medium
kind: claude
spawns: scout
retro: false
timeout: 1200000
traits: [read-only]
---

# Scout Agent

<the persona's instructions>
#+end_src

The frontmatter parser reads one =key: value= per line and does not strip YAML comments, so do not put a comment on a key's line. Every key is optional:

- =name=, =description= :: Advisory. =oh roster= shows the description.
- =model= :: Weight alias or canonical ID ([[*Model configuration]]). Omit to inherit the parent's model (same kind only).
- =effort= :: Thinking or effort level. Omit to inherit the parent's level (same kind only), else =medium=.
- =kind= :: Harness. Omit to inherit the parent's harness.
- =spawns= :: Personas that this persona may spawn, separated by whitespace or commas. Omit for a leaf.
- =retro= :: =true= or =false=. Omit for the installation default.
- =timeout= :: Wait budget in milliseconds. Omit for 600000.
- =traits= :: Trait fragments to append, as =[name, ...]= ([[*Shared directives: traits]]).
- =extends= :: A base persona (below).

Usually omit =kind=: the child then runs the parent's observed harness from the selected runtime. =kind= is the only way to choose a harness, with no flag or environment variable, because the harness is a deployment property, not a per-assignment setting like =model=. To compare harnesses, write a definition that declares the other harness.

=extends: <base-name>= puts one base persona's body before the persona's own body. The base resolves through the same three layers. Only one level is allowed: a base that declares =extends:= is refused. The packaged =base-analyst= (read-only, a leaf) is the base for analysis personas, so they do not repeat its assignment, evidence, and uncertainty scaffold. [[file:scripts/docs/contract.md]] section 'Persona composition (`extends`)' gives the rules.

[[*Packaged personas]] lists the packaged roster. [[file:SKILL.md]] section 'Roster and routing' gives each persona's remit and delegation grant.

** Shared directives: traits

A trait is one directive, written once and shared by the personas that need it, for example "stay read-only" or "answer only what was asked". Without traits, each persona has its own copy, and the copies drift.

A trait is a Markdown fragment with optional frontmatter:

#+begin_src markdown
---
name: read-only
description: Write boundary
---

Do not create, modify, or delete repository files. Consume the worktree. Never mutate it.

- You may write only to a caller-provided artifact or report path and to =.tmp/=. Nothing that you write there ships.
- Do not run commands that mutate the repository tree.
#+end_src

A persona selects traits by name in one-line frontmatter. Every packaged persona does this:

#+begin_src markdown
---
name: advisor
model: middle
traits: [simple, read-only, focused]
---
#+end_src

The CLI appends each fragment after the persona body, in list order. Alternatively, put a =%<name>= token in the body where the directive belongs:

#+begin_src markdown
## Constraints

%read-only

- Do not broaden the design or replace the caller's implementation work.
#+end_src

At spawn, the CLI substitutes each token, writes the composed persona beside the round's result file, and gives the child that path. No packaged persona uses an inline token. Use one when the directive must sit in the section it governs.

Traits resolve like personas: =<git-root>/.agents/traits/=, then =~/.agents/traits/=, then =<skill>/traits/=. The first match wins, so a project can override a packaged trait by name.

Selections combine in this order: the base's =traits:= (with =extends:=), the persona's own =traits:=, then each =--trait NAME= on the spawn. Before you write a trait selection or an inline token, read [[file:scripts/docs/contract.md]] section 'Trait composition'. It owns the rules for unknown, short and repeated tokens, the regions that are not scanned, single-pass substitution and pass-through. [[file:references/traits.md][references/traits.md]] gives the admission bar for a new trait.

A trait has a cost: every child that carries it reads all of it. Add one only for a directive that two or more personas share, and test that it changes behaviour. Two of the three traits that predate =simple= failed an adversarial check at first. They worked only after a rewrite that removed the cause of the unwanted behaviour, instead of restating the prohibition.

*=#trait= versus =%trait=.*

- =#name= in a delegation request ("Spawn a light worker. #simple") asks the agent to add =--trait name= to that spawn. It is a convention, not syntax: the CLI parses no prose, and if the agent does not add the flag, the child does not get the trait.
- =%name= in your own pi prompt expands the fragment into that prompt before the session reads it ([[file:../../pi/extensions/traits/README.md][pi/extensions/traits/README.md]]). It expands into the session that types it, never into a child.

The idea comes from [[https://github.com/xificurC/ai-behaviors][ai-behaviors]] (MIT), which injects hashtag-referenced fragments into interactive Claude Code and ECA sessions through a =UserPromptSubmit= hook. A per-turn hook does not suit one-shot children, and its taxonomy of modes, qualities, and methods is more structure than this store needs. What carries over is the shape: small named fragments, layered override directories, and composition at the point of use. The =<name>/prompt.md= layout lets an ai-behaviors library work as a base layer unchanged.

** Model configuration

=config.edn= has two model levels, plus provider allowance settings (=:providers=), and harness invocation (=:harnesses=):

- =:aliases= maps a short name to a canonical model ID, or a weight name to a vector of ranked candidates =[{:model ".." :rank n} ..]=.
- =:models= maps a canonical ID to the native name that its own provider's harness wants.
- =:providers= maps a provider prefix to =:quota-provider= and optional =:reserve=. Legacy =:usage=, =:credentials= and =:cache-ttl-s= settings fail with a migration error. A kind's =:harnesses :providers= set lists the providers it can run.

Canonical IDs use pi's =<provider>/<model>= form. The packaged config covers the models on Anthropic and OpenAI subscriptions, and a local fallback. =heavy=, =middle=, =light=, and =feather= are the portable weight aliases. Each is a vector alias: at spawn, =oh= picks the lowest-ranked candidate whose subscription still has allowance, so a spawn does not land on an exhausted subscription. For pi, an explicit string alias or base canonical ID keeps that model, but =oh= routes it across the authenticated accounts for that model and queries their usage. Other kinds do not route it. =oh usage= shows the allowance that routing reads. [[*Packaged models]] lists the current mapping. [[file:scripts/docs/contract.md]] section 'Model resolution' gives the resolution rules.

*** The merge rule that catches people

An override row does not merge with the row it replaces. An override =:models= row replaces the whole packaged row, and an override =:harnesses= entry must restate =:model-flag=, =:effort-flag= and =:providers=. =:aliases= merges per key, so retargeting ="heavy"= takes one line. Read [[file:scripts/docs/contract.md]] section 'Model resolution' for the merge rules, and section 'Harness `:extra-args`' for the fields that an override entry must restate.

A weight name is an =:aliases= key, never a =:models= key. A key in both maps fails after the merge, with the key and the files that define it named. You see this error when you migrate an old override that has a full ="heavy"= row. A candidate that resolves to a vector alias, a candidate whose provider is absent from =:providers=, and a =:harnesses :providers= member absent from =:providers= fail the same way.

*** Worked example

A home override that pins =heavy= to one Claude release, and lets claude-kind and codex-kind children run unattended:

#+begin_src clojure
  {:aliases  {"heavy" "anthropic/claude-fable-5-20260714"}   ; a string alias: no vector routing
   :models   {"anthropic/claude-fable-5-20260714"
              {:claude "claude-fable-5-20260714"}}           ; pinned, not the floating alias; own provider only
   ;; Override the default permissions for more autonomous operation
   ;; We intentionally don't do this by default - it should be opt in
   :harnesses {:claude {:model-flag "--model"
                        :providers #{"anthropic"}     ; restated: the entry replaces the packaged one
                        :extra-args ["--permission-mode" "auto"]}
               :codex {:model-flag "--model"
                        :providers #{"openai-codex"}
                        :extra-args ["--ask-for-approval" "never"
                                     "--sandbox" "workspace-write"]}}}
#+end_src

The new canonical ID needs a row only because it is new. To point ="heavy"= at a packaged canonical ID, add only the =:aliases= entry.

There is no =:pi= column. An ID with no column for a kind falls through to the canonical ID, which is the pi spelling. Here pi gets =--model anthropic/claude-fable-5-20260714= and claude gets =--model claude-fable-5-20260714=. The =:providers= filter on a kind applies only to the candidates of a vector alias. A string alias or canonical ID passes through to every kind unchanged, so a codex-kind child told to run =heavy= (here a string alias) receives the Anthropic ID. Cross-provider equivalence is expressed as ranked candidates of a weight alias, not as a column. The example restates =:providers= because an override =:harnesses= entry replaces the packaged one, filter included.

** Harness configuration

=:harnesses= says how to invoke each kind:

- =:model-flag= is required in every entry, also in an entry that only adds =:extra-args=, because the entry replaces the packaged one.
- =:effort-flag= is optional. A kind without it gets no effort args.
- =:extra-args= lets an override relax a harness's command approval. Without it, claude and codex children stop at their first tool call, in a pane that nobody watches. Prefer a bounded grant to a full bypass. The home override at [[file:../../subagents/config.edn][subagents/config.edn]] records the reasoning and the rejected alternatives. [[file:scripts/docs/contract.md]] section 'Harness `:extra-args`' gives the validation rules.

The kind set is open: a new =:harnesses= entry needs no code change, and a kind with no entry gets no model args.

*** Upstream support is the real constraint

The selected runtime decides which kinds it can launch and recognise. This README does not copy its detection catalogue. For TUI, =herdr agent start --help= lists the current =--kind= values, and the remote detection manifest (=manifest_check= in =herdr --default-config=) can extend recognition without an upgrade.

A kind needs runtime support at both ends of a delegation:

- As a child, it must be startable and positively recognised in the addressed pane. An executable name alone is not proof of the expected kind.
- As the orchestrator, it must be recognised at the caller address selected by the ancestry gate. An unrecognised process cannot delegate. Parent kind and session identity follow the runtime table in [[file:scripts/docs/contract.md]] section 'Preconditions'; do not assume =HERDR_PANE_ID= in an hc terminal.

Publication and capture can work without agent recognition, but never bypass a runtime mismatch. =task publish= degrades open when caller identity cannot be resolved, so a finished result is not stranded. =task collect <full-task-uuid>= reports ="ownership": "foreign-parent-session"= instead of failing. A manually started, unrecognised child is not a supported delegation path: live listings can omit it, so fan-in and stale-round recovery cannot safely treat it as a recognised child. [[file:scripts/docs/contract.md]] section 'Preconditions' lists each identity-failure consequence.

** Child placement

Each delegated child gets a new tab in the caller's workspace or space, including below root. There is no other placement, so =--tab= is optional and a config =:defaults= key is refused.

In both runtimes a child's own tab carries its label, such as =worker-1-light=. When the root first delegates, =oh= names the root's tab =orch-0= (or the next free =orch-<n>= in that workspace or space), unless someone already named it. [[file:scripts/docs/contract.md]] section 'Labels and geometry' gives the rules.

The tab stays in the parent's workspace or herdr-app space and preserves focus. Children in both runtimes outlive their parent; =close= and =orphans --close= are the guarded cleanup paths. hc launch uses the environment wrapper, =--no-notify= and =--outlive-parent= specified in [[file:scripts/docs/contract.md]] section 'Start and prompt outcomes'. The ledger records =:placement= and =:tab-id= for audit. [[file:scripts/docs/contract.md]] section 'Placement' gives the details.

** Verifying a configuration change

=oh= parses and validates config before it allocates a ledger entry or touches a pane, and each failure names the file, so a bad override costs nothing billable. Closed maps such as =:providers= rows fail on an unknown key instead of ignoring it.

Preview a spawn without running it:

#+begin_src sh
oh task run scout --task x --model anthropic/claude-opus-5-5 --print-prompt
#+end_src

The preview reports:

- =kind=
- =model= (before the alias hop) and =model-canonical= (after it, or the routed choice for a vector alias)
- =model-route= (only for a vector alias): the alias, each candidate's rank, provider, allowance and status, the chosen canonical ID and the reason. Pi also reports each candidate's =account= and the selected =account= and =concrete= account/model ID; =model-canonical= and =model-args= carry that concrete selection. A preview of a vector alias collects the same current subscription evidence as a start, so name an explicit canonical ID to preview without collection
- =model-args=, the translated args that the harness receives
- =effort=, =effort-source=, and =effort-args=
- =placement=, =retro= and =retro-source=, and =spawns= and =spawns-source=

To find a model miss, compare the model fields. If =model-canonical= still shows your short name, no =:aliases= entry matched. If =model-canonical= is correct but =model-args= repeats it instead of a native name, the =:models= row has no column for that kind.

** Subscription allowance and model routing

A vector alias (=heavy=, =middle=, =light=, =feather=) is routed when a child launches. Fresh known effective scope evidence provides numeric credit; unknown remains eligible after Pi authentication and registered-model availability have been established. Pi expands candidates to account/model pairs, preserves the requested reasoning level and uses each account's own quota evidence. Equal pairs use the default account first, then sorted named identities. Native non-Pi harnesses retain one account context. =:quota-scope= is an exact reviewed scope, never a fuzzy model match, and =all_models= is the default. Give a model that has its own quota scope (for example =model:fable=) that selector, or it is routed on account-wide credit. The packaged provider map contains Anthropic, Codex and local Lemonade. Kimi, Qwen and Z.AI adapters are deferred. Fable selects =model:fable= explicitly; Opus, Sonnet and Haiku use =all_models=. [[file:scripts/docs/contract.md]] sections 'Routing' and 'Usage' own the evidence and process contract.

#+begin_src sh
oh usage                                    # owned providers array, using Pi credentials
oh usage --format markdown --detail         # scope bounds and reset times
oh usage --format status                    # one line for a status bar, e.g. anthropic 4%s 64%w (percent used)
oh usage --provider anthropic --fresh       # bypass successful cache TTL, not backoff
oh usage --harness codex --provider openai-codex  # explicit native credential context
#+end_src

Reporting reads the selected harness's credentials; routing uses the destination harness's store. Missing or expired selected credentials grant no numeric credit and never cause a fallback to another harness. The collector never refreshes or writes credentials, starts a vendor CLI or prompts for authentication; normal harness operation owns refresh. A credential-context cache provides TTL reuse, negative caching, provider backoff and concurrent request coalescing. Stale windows are diagnostic only. Native OS-store access is unavailable without prompting; see [[file:scripts/docs/contract.md]] section 'Owned credential boundary'. A string alias or canonical ID (=--model opus=, =--model anthropic/claude-opus-5-5=) is never routed and makes no usage call.

The selected account reaches fresh, forked and measurement Pi launches. Same-kind concrete inheritance retains it without rerouting. A named account is the Pi provider =anthropic-<N>=, with N a positive integer without leading zeros; the default =anthropic= account has no number. A credential under a retired =anthropic-account-<name>= key needs a one-off key rename in =auth.json= or a fresh login; [[file:../../pi/extensions/herdr-orch/README.md]] section 'Named Anthropic subscription accounts' gives the steps. Named accounts reuse the Herdr Pi extension's native OAuth registration, including in offline loaders; a bare skill without that extension's account module has no named account providers. No credential swapping or second token store is used.

=oh route --request PATH= exposes the same Babashka selection policy outside Herdr for primary-session callers. It accepts an alias or direct model, current pair, authenticated registered inventory, attempted pairs and requested reasoning. It prefers eligible same-model siblings during recovery, never escapes a direct model or configured alias, and reports exhaustion without launching or changing a session. [[file:scripts/docs/contract.md]] section 'Shared selection operation' owns the strict JSON request/response contract. The Pi extension supplies primary-session recovery through this policy; see [[file:scripts/docs/contract.md]] section 'Primary Pi recovery'.

*** Primary Pi selection and recovery

With the Herdr Pi extension loaded, use =/oh models= to list merged aliases, then =/oh tier light= (or another configured vector alias) while idle. It selects an authenticated registered account/model through the shared policy without changing startup defaults, including outside Herdr. Session resume restores the retained tier. A direct model/account change reported by Pi clears tier intent; =/oh tier clear= clears it without changing the concrete selection. Recovery-owned changes retain it. Bare =/oh tier= shows the retained tier.

Quota recovery tries eligible same-model sibling accounts first, then only candidates in the retained tier, including other providers. A direct selection cannot escape its model. Requested reasoning is preserved exactly; unsupported candidates are skipped. Authentication, permission and generic server failures do not trigger recovery. Each pair is attempted at most once in a finite initial inventory, up to 4096 pairs; exhaustion is reported. Completed tool results stay in native continuation context and the controller does not replay tools. Delegated children remain pinned, including forks with copied tier history.

The extension warns before an automatic native selection and keeps the warning until its setter settles. Abort stops automatic continuation, but a pending native setter can still change selection after abort or overwrite a newer manual selection. Avoid manual selection while the warning is visible. A cancelled switch reports the actual selected account/model; there is no automatic retry or rollback. Abort, new input and external model/account changes reported by Pi invalidate recovery. Pending requests and silent same-target/equal native selections may not cancel it; use explicit abort when cancellation is required. Native controls stay usable, but another =/oh tier= selection or clear is refused while a controller setter is unresolved.

Routing needs the shared CLI and writable system temporary storage. Warning and result text are user-only output, not model context; hosts without UI receive them on stderr. RPC clients must display the supported extension UI requests. Native rendered visual checks and authorised real-account login/selection smoke remain separate acceptance gates. [[file:../../pi/extensions/herdr-orch/README.md]] gives the operator steps and test entry points; [[file:scripts/docs/contract.md]] section 'Primary Pi recovery' owns the lifecycle and accepted public-API limits.

** Listing personas, traits, models, and workflows

=oh roster= lists what a spawn would resolve from the caller's checkout:

- each persona with its model, harness, traits, delegation grant, and source layer, or the error that a spawn would fail with
- each trait with its description and the personas that select it
- each model alias with the model name that each harness receives
- each ordinary skill that declares itself a workflow, with its name and description

Outside either runtime, it only reads files. Inside a host, the ancestry and mismatch gate still applies.

#+begin_src sh
oh roster                                 # JSON, for tools and agents
oh roster --format markdown               # every section, for a person
oh roster --format org --section models   # one section, as an org list or table
oh roster --format markdown --section workflows # self-declared workflow skills
oh roster --format markdown --detail      # add paths, timeouts, retro, every alias, and the layers
#+end_src

In pi, =/oh= shows the same listing in the session and does not add it to model context. =/oh personas=, =/oh traits=, =/oh models=, and =/oh workflows= show one section. The tool-output expand key (default =ctrl+o=) switches to the =--detail= form. See [[file:../../pi/extensions/herdr-orch/README.md][pi/extensions/herdr-orch/README.md]].

Workflow skills stay in their ordinary skill directories. To include one in the catalogue, add this YAML frontmatter metadata:

#+begin_src yaml
metadata:
  herdr-orch: workflow
#+end_src

The marker means catalogue membership, not a required dependency or permission to delegate. Higher-precedence skills resolve before this marker is checked, so an override without it removes that name from the catalogue. * Known gaps

- =run= and =start= spawn one child each. Fan-out scheduling (how many children are in flight, when to replace one) and resident lifecycle are parent policy in [[file:SKILL.md][SKILL.md]]. Fan-in has a primitive: =collect --any= captures the first in-flight child of the caller's session to publish ([[file:scripts/docs/contract.md]] section 'Fan-in'). Concurrent writers get separate checkouts ([[*Subagent lifecycle]]), but the parent decides how many run.
- =task close= waits for the child to settle (=ORCH_SETTLE_CLOSE_MS=, default 45 s), then tries to close once. A child that does not settle in time keeps its pane. Capture never closes anything.
- =close= refuses a foreign or unresolved parent, so it cannot close an orphan whose session has ended. =oh task orphans= lists such panes and =oh task orphans --close= closes them, with the same live child and pane match that =close= uses ([[file:scripts/docs/contract.md]] section 'Orphans'). Both are root-only, and the operator decides that a foreign session is dead.
- The advisor-tier convention holds only when a worker consults through =oh task run advisor=. A consult started with raw =herdr agent start= takes the default model, spends money that the ledger does not record, and orphans its pane. Ledger consult counts and advisor costs are therefore a lower bound.
- =HERDR_ORCH_BIN= holds the deployed absolute path, not a canonical repository path. Launcher-matrix tests guard it.
- =pi/extensions/herdr-agent-state.ts= is a verbatim copy of Herdr's managed Pi asset (=src/integration/assets/pi/herdr-agent-state.ts=, integration revision 9, commit =065ef9d6a531c49fb8bee7e818ef837065b21ee9=). Reinstalling the integration overwrites it, so it is never patched here. Its tests, in =pi/extensions/test/herdr-agent-state.test.ts=, drive it only through a disposable socket. The last refresh fixed only the RPC gate (=ctx.mode=, not =hasUI=). The =blocked= state still arrives on the =herdr:blocked= bus topic, not through Pi's =ui_prompt_start= and =ui_prompt_end= events, and its listeners are not disposed on reload. Both are upstream work, proposed separately from [[file:../../design/log/2026-09-17-herdr-orch-improvements-260917.org][herdr-orch improvements 260917]].
